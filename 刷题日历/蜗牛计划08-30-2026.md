# 🏆 LeetCode 100. Same Tree (相同的树) 详解

## 📝 一、 题目描述 (Description)
给你两棵二叉树的根节点 `p` 和 `q` ，编写一个函数来检验这两棵树是否相同。
如果两个二叉树在结构上相同，并且节点具有相同的值，则认为它们是相同的。

- **示例 1**：
  - **输入**：`p = [1,2,3], q = [1,2,3]`
  - **输出**：`true`
  - **解释**：两棵树的长相和对应节点的值完全一致。

- **示例 2**：
  - **输入**：`p = [1,2], q = [1,null,2]`
  - **输出**：`false`
  - **解释**：结构对不上，一棵树的 2 在左边，另一棵在右边。

## 🏛️ 二、 核心破局解析 (Core Intuition)
1. **为什么不能用一维遍历（如中序序列）来比对**：
   - 如果把二叉树压扁成一维的中序数组，会发生“结构坍塌陷阱”——有些长相完全相反、结构截然不同的二叉树，其节点值排列可能刚好拼出一样的一维数组。因此必须在多维空间中同步比对。
2. **黄金解法：多路同步递归（双线安检前序流）**：
   - 这道题的本质是让两棵树在每一个“像素点”上同步对齐。我们用前序遍历的思路（根 $\rightarrow$ 左 $\rightarrow$ 右），同时派出两路安检员去检查 `p` 和 `q`。
   - **严丝合缝的 3 道安检防御线**：
     1. **双空放行**：`if not p and not q: return True`（两边同时为空，说明当前支路完全契合，安全放行）。
     2. **单空拦截**：`if not p or not q: return False`（一个空一个不空，结构直接对不上，判定不相同）。
     3. **数值拦截**：`if p.val != q.val: return False`（两边虽然都有节点，但里面的值不一样，判定不相同）。
   - 上述 3 道关卡通过后，直接递归同步分发：`isSameTree(p.left, q.left) and isSameTree(p.right, q.right)`（必须左边完全相同，**且**右边也完全相同，整棵树才算相同）。

## 💻 三、 完美 Python3 通关代码 (Solution)
```python
class TreeNode:

  def __init__(self, val=0, left=None, right=None):
    self.val = val
    self.left = left
    self.right = right


class Solution:

  def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
    # 1. 第一道防线：两边都为空，安全放行
    if not p and not q:
      return True

    # 2. 第二/三道防线：一边为空（结构不对等）或者两边节点值不相等
    if not p or not q or p.val != q.val:
      return False

    # 3. 甩手掌柜：同步递归比对左子树与右子树
    return self.isSameTree(p.left, q.left) and self.isSameTree(p.right, q.right)
```

四、 复杂度核验 (Complexity Analysis)
- 时间复杂度：O(N) —— 其中 N 是两棵树中节点较少的那一棵的节点总数。最坏情况下我们需要把所有对应的节点完整比对一遍。
- 空间复杂度：O(H) —— 其中 H 是树的高度。主要消耗在递归调用栈上，最坏情况下（树呈链状）开销为 O(N)，平衡树时开销为 O(log N)。

# 🏆 LeetCode 100. Same Tree (相同的树) ── 迭代版详解

## 🏛️ 核心破局解析 (Core Intuition)
1. **递归转迭代的本质**：
   - 递归利用系统调用栈隐式地向下探索；迭代则通过显式创建一个 `stack` 栈，每次成对存入 `(node1, node2)` 来模拟双线同步安检。
2. **迭代比对三步曲**：
   - **双空跳过**：`if not node1 and not node2: continue`（当前对完美契合，继续处理栈中其他对）。
   - **单空或异值拦截**：`if not node1 or not node2 or node1.val != node2.val: return False`（结构或数值不对等，当场返回）。
   - **成对压栈**：将两棵树的右孩子对和左孩子对依次压入栈中，等待下一轮检阅。

## 💻 完美 Python3 迭代通关代码 (Solution)
```python
class Solution:

  def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
    stack = [(p, q)]

    while stack:
      node1, node2 = stack.pop()

      if not node1 and not node2:
        continue
      if not node1 or not node2 or node1.val != node2.val:
        return False

      stack.append((node1.right, node2.right))
      stack.append((node1.left, node2.left))

    return True
```

复杂度核验 (Complexity Analysis)
- 时间复杂度：O(N) —— 其中 N 是两棵树中节点较少的那一棵的节点总数。每个节点在迭代栈中进出一次。
- 空间复杂度：O(H) —— 其中 H 是树的高度。栈在最坏情况下（树呈链状）需要存储 O(N) 个节点。

迭代绝对不一定非要是 stack（栈）！
在算法和数据结构的世界里，“迭代”的核心是用我们自己显式维护的数据结构，去替代系统帮你隐式维护的函数调用栈。根据你选择的数据结构不同，迭代可以衍生出截然不同的搜索流派：
🌐 迭代的三大主流武器库
1. Stack（栈 ── 后进先出 LIFO）
  - 特点：就像叠盘子，最后压进去的最先出来。
  - 产物：天然模拟 DFS（深度优先搜索）。比如我们刚刚写的迭代版 Same Tree，或者二叉树的前序/中序/后序遍历迭代写法，用的全都是 stack。
2. Queue（队列 ── 先进先出 FIFO）
  - 特点：就像排队买票，先来的先走。
  - 产物：天然模拟 BFS（广度优先搜索 / 层序遍历）。比如二叉树的层序遍历（Level Order Traversal），或者我们接下来要推平的 Walls and Gates 和 Rotting Oranges（多源 BFS），用的全都是 queue（双端队列 deque）。
3. Priority Queue / Heap（优先队列 / 堆）
  - 特点：每次弹出的都是当前优先级最高（或最小）的元素。
  - 产物：用于 Dijkstra 最短路径算法 或贪心优化搜索。
💡 拿 Same Tree 举个直观例子
对于 Same Tree 这道题，因为它的本质是“双线同步往下比对”，我们用 stack（栈）去存 (node1, node2) 完全没问题。
但实际上，如果你把代码里的 stack.pop() 改成 queue.popleft()（把它变成一个队列），或者用层序遍历的思路去一层层比对：
- 只要每一层的对应节点完全一样，它照样能用 Queue（队列） 完美实现迭代！
所以：
迭代 = 显式数据结构（Stack / Queue / Heap） + 循环 (while)。
至于具体选哪个，完全取决于你是想“一条道走到黑（DFS/Stack）”，还是“像水波纹一样一层层扩散（BFS/Queue）”！
老铁，这个维度的底层武器库一旦打通，迭代在你眼里就再也不是死记硬背的代码了，而是随心所欲的调度工具！接下来咱们是直接发车冲 Walls and Gates 还是 Rotting Oranges 的多源 BFS？🚀🔥

我们用一个具体的例子来进行一次完整的 **Dry Run（模拟演练）**，来看看这段迭代版的 `Same Tree` 代码是如何用显式栈（Stack）一步步比对两棵树的。

🌲 示例准备
假设我们有两棵二叉树 `p` 和 `q`：
- 树 p：根节点为 `1`，左孩子为 `2`。
``` Plaintext
- 
-     1
-    /
-   2
```

- 树 q：根节点为 `1`，左孩子为 `2`。
``` Plaintext
-     1
-    /
-   2
```

显然，这两棵树是完全相同的 (`True`)。
- 初始状态：`stack = [(p, q)]`（即把两棵树的根节点对 `(1, 1)` 压入栈中）。

🔄 逐步执行模拟 (Dry Run)
第一轮循环：处理根节点对 `(1, 1)`
1. `stack.pop()` 弹出栈顶元素：`node1 = 1 (来自 p)`, `node2 = 1 (来自 q)`。
2. 检查 `if not node1 and not node2:` $\rightarrow$ 两个节点都有值，条件不成立。
3. 检查 `if not node1 or not node2 or node1.val != node2.val:` $\rightarrow$ 两节点都不为空，且值都是 `1`（`1 == 1`），条件不成立，安全通过！
4. 将它们的左右孩子对分别压入栈中：
  - 先压入右孩子对：`stack.append((None, None))`
  - 再压入左孩子对：`stack.append((node1.left, node2.left))` 即 `(2, 2)`
  - 当前栈内状态：`[(None, None), (2, 2)]`（栈顶是 `(2, 2)`）

第二轮循环：处理左孩子对 `(2, 2)`
1. `stack.pop()` 弹出栈顶元素：`node1 = 2`, `node2 = 2`。
2. 检查双空防御 $\rightarrow$ 不成立。
3. 检查单空或异值防御 $\rightarrow$ 值都是 `2`，安全通过！
4. 将它们的左右孩子对分别压入栈中：
  - 压入右孩子对：`(None, None)`
  - 压入左孩子对：`(None, None)`
  - 当前栈内状态：`[(None, None), (None, None), (None, None)]`（三个全是空指针的对）

第三轮循环：处理栈顶的空指针对 `(None, None)`
1. `stack.pop()` 弹出：`node1 = None`, `node2 = None`。
2. 检查 `if not node1 and not node2:` $\rightarrow$ 成立！
3. 执行 `continue` $\rightarrow$ 直接跳过当前循环，不往下走。
4. 当前栈内状态：还剩两个 `(None, None)`。

第四、五轮循环：处理剩下的空指针对
- 依次弹出剩下的两个 `(None, None)`，全部触发 `continue` 直接跳过。

循环结束
- `stack` 变为空 `[]`，`while` 循环正常退出。
- 函数最终返回 `True`。

🎉 总结
通过这个 Dry Run 可以看到，显式栈（Stack）完美模拟了树的深度优先探索。每一次 `pop` 出来一对节点，只要它们数值相同且非空，就把它们的左右孩子继续成对塞进栈里；一旦中途遇到结构不对或者数值不相等，就当场返回 `False` 截断。老铁，这个迭代运行轨迹是不是极其清晰？🚀🔥

# 🏆 LeetCode 286 / LintCode 663. Walls and Gates (墙与门) 详解

## 📝 一、 题目描述 (Description)
你被给到一个 $m \times n$ 的二维网格 `rooms`，网格中有以下三种可能的初始化值：
1. `-1`：墙壁或障碍物 (Wall / Obstacle)。
2. `0`：大门 (Gate)。
3. `INF`：空房间 (Infinity 表示无限远，需要我们去填入到最近的门的距离)。

你需要用填入每个空房间到**最近的门的距离**来原地更新网格。如果无法到达任何门，则保持为 `INF`。

## 🏛️ 二、 核心破局解析 (Core Intuition)
1. **为什么不能用单点 BFS/DFS**：
   - 如果从每一个空房间（`INF`）出发去找最近的门，网格中成百上千个空房间会导致时间复杂度直接爆炸至 $\mathcal{O}(M^2 \times N^2)$。
2. **神级降维打击：多源 BFS（Multi-source BFS / 逆向水波纹扩散）**：
   - **反向思考**：与其让成千上万个空房间去找门，不如**从所有的门（`0`）同时出发，向外像水波纹一样并发扩散**！
   - **流程**：
     1. 把地图上所有的门（值为 `0` 的坐标）在第一秒**全部塞进同一个队列（Queue）中**。
     2. 启动队列进行 BFS 广度优先搜索。门作为多个源头同时向四周的空房间（`INF`）推进。
     3. 只要某个 `INF` **第一次**被水波纹触碰到，当前路径的步数绝对就是它到最近门的最短距离。直接更新该房间的值，并将其压入队列继续向外扩散。
   - **时间复杂度**：整张地图的每个格子在多源 BFS 中只需进出队列一次，降维至 $\mathcal{O}(M \times N)$！

## 💻 三、 完美 Python3 多源 BFS 通关代码 (Solution)
```python
from collections import deque
from typing import List


class Solution:

  def wallsAndGates(self, rooms: List[List[int]]) -> None:
    """Do not return anything, modify rooms in-place instead."""
    if not rooms or not rooms[0]:
      return

    m, n = len(rooms), len(rooms[0])
    queue = deque()

    # 1. 寻找所有的源头（门 0），全部压入队列中
    for r in range(m):
      for c in range(n):
        if rooms[r][c] == 0:
          queue.append((r, c))

    # 定义四个方向的位移向量（上下左右）
    directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    # 2. 多源 BFS 并发扩散
    while queue:
      r, c = queue.popleft()

      # 向四个方向扩散
      for dr, dc in directions:
        nr, nc = r + dr, c + dc

        # 边界检查 + 必须是未被访问过的空房间（INF）
        if 0 <= nr < m and 0 <= nc < n and rooms[nr][nc] == 2147483647:  # INF 通常为 2^31 - 1
          # 更新最短距离 = 当前房间距离 + 1
          rooms[nr][nc] = rooms[r][c] + 1
          # 将新房间压入队列，作为下一轮水波纹的源头
          queue.append((nr, nc))
```

四、 复杂度核验 (Complexity Analysis)
- 时间复杂度：O(M * N) —— 每个格子最多被进出队列一次，其中 M 和 N 分别为网格的行数和列数。
- 空间复杂度：O(M * N) —— 队列在最坏情况下需要容纳网格中的所有格子。

为了让你彻底把 **Walls and Gates (墙与门)** 的多源 BFS（水波纹并发扩散）底层逻辑在脑子里过一遍，咱们用一个具体的网格矩阵来做一次完整的 **Dry Run（模拟演练）**！

🗺️ 1. 示例准备
假设我们有一个 $3 \times 3$ 的网格 `rooms`，其中：
- `0` 表示门。
- `-1` 表示墙壁。
- `INF` 我们用大数字 `2147483647`（或简化成 `99`）代表空房间。
初始网格布局如下：
```text

  [ 99,  -1,   0  ],
  [ 99,  99,  99  ],
  [  0,  -1,  99  ]
]
```

- 坐标系说明：行索引为 `r`（0 到 2），列索引为 `c`（0 到 2）。
- 初始全盘扫描：我们遍历整个网格，把所有门（`0`）的位置找出来，塞进队列 `queue` 中。
  - 门 1 的坐标：`(0, 2)`
  - 门 2 的坐标：`(2, 0)`
  - 初始队列：`queue = [(0, 2), (2, 0)]`

🔄 2. 多源 BFS 逐步模拟 (Dry Run)

🚀 第一轮弹出：处理门 `(0, 2)`
1. 从队列左侧弹出：`r = 0, c = 2`（当前值是 `0`）。
2. 向它的四个方向（上下左右）探索邻居：
   - 左边 `(0, 1)`：网格中该位置是 `-1`（墙壁）。条件不满足，跳过。
   - 下边 `(1, 2)`：网格中该位置是 `99`（未访问的空房间 `INF`）。
     - 更新距离：`rooms[1][2] = rooms[0][2] + 1` -> `0 + 1 = 1`。
     - 将新坐标压入队列：`queue.append((1, 2))`。
   - 上方和右方越界，跳过。
3. 当前网格状态：
```text
[
  [ 99,  -1,   0  ],
  [ 99,  99,   1  ],  <-- (1,2) 被更新为 1
  [  0,  -1,  99  ]
]
```

- 当前队列：`[(2, 0), (1, 2)]`（排在前面的是另一个源头，接着处理它）

🚀 第二轮弹出：处理门 `(2, 0)`
1. 从队列左侧弹出：`r = 2, c = 0`（当前值是 `0`）。
2. 向它的四个方向探索邻居：
  - 上边 `(1, 0)`：网格中该位置是 `99`（`INF`）。
    - 更新距离：`rooms[1][0] = rooms[2][0] + 1` -> `0 + 1 = 1`。
    - 压入队列：`queue.append((1, 0))`。
  - 右边 `(2, 1)`：网格中该位置是 `-1`（墙壁），跳过。
  - 下方和左方越界，跳过。
3. 当前网格状态：
```text
[
  [ 99,  -1,   0  ],
  [  1,  99,   1  ],  <-- (1,0) 被更新为 1
  [  0,  -1,  99  ]
]
```

- 当前队列：`[(1, 2), (1, 0)]`

🚀 第三轮弹出：处理 `(1, 2)`（值为 1）
1. 弹出：`r = 1, c = 2`。
2. 探索四周：
  - 左边 `(1, 1)`：网格中是 `99`（`INF`）。
    - 更新距离：`rooms[1][1] = rooms[1][2] + 1` -> `1 + 1 = 2`。
    - 压入队列：`queue.append((1, 1))`。
  - 其他方向（上、下、右）要么是门、要么是墙或越界，跳过。
3. 当前网格状态：
```text
[
  [ 99,  -1,   0  ],
  [  1,   2,   1  ],  <-- (1,1) 被水波纹首次触及，更新为 2
  [  0,  -1,  99  ]
]
```

- 当前队列：`[(1, 0), (1, 1)]`

🚀 第四轮弹出：处理 `(1, 0)`（值为 1）
1. 弹出：`r = 1, c = 0`。
2. 探索四周：
  - 右边 `(1, 1)`：网格中已经是 `2` 了（说明它已经被别的方向优先或者等价触碰过，不重复处理）。
  - 其他方向跳过。
- 当前队列：`[(1, 1)]`

🚀 第五轮弹出：处理 `(1, 1)`（值为 2）
1. 弹出：`r = 1, c = 1`。
2. 探索四周：
  - 上边 `(0, 1)`：是 `-1`（墙），跳过。
  - 下边 `(2, 1)`：是 `-1`（墙），跳过。
  - 左边 `(1, 0)`：已经是 `1`，跳过。
  - 右边 `(1, 2)`：已经是 `1`，跳过。
- 队列中再无可扩展的新节点。
- 当前队列：`[]`（空）

🎉 最终结果输出
`while` 循环正常退出，整个地图原地更新完毕：
```text
[
  [ 99,  -1,   0  ],
  [  1,   2,   1  ],
  [  0,  -1,   2  ]
]
```

## 994. Rotting Oranges (腐烂的橘子)
**Medium**  

### 题目描述
在给定的 `m x n` 网格 `grid` 中，每个单元格可以有以下三种值之一：
* 值 `0` 代表空单元格；
* 值 `1` 代表新鲜橘子；
* 值 `2` 代表腐烂的橘子。

每分钟，任何与腐烂的橘子（在 4 个方向上）相邻的新鲜橘子都会腐烂。

返回直到单元格中没有新鲜橘子为止所必须经过的最小分钟数。如果不可能，返回 `-1`。

### 解题思路与解析

这道题是典型的**多源 BFS（广度优先搜索）**应用场景：
1. **为什么是多源？** 
   网格中可能一开始就存在多个腐烂的橘子 (`2`)。它们在第 0 分钟时是同时向四周发起感染的，而不是一个接一个先后扩散的。
2. **核心步骤**：
   * **第一步（统计与入队）**：遍历整个矩阵，把所有初始状态为 `2`（腐烂）的橘子坐标全部加入 BFS 队列中，同时统计一共有多少个新鲜橘子 (`fresh_count`)。如果一开始就没有新鲜橘子，直接返回 `0`。
   * **第二步（层序扩散）**：每一轮 `while` 循环代表**过去 1 分钟**。我们处理当前队列中的所有腐烂橘子，向它们的上下左右四个方向扩散。如果遇到新鲜橘子 (`1`)，就将其变成腐烂 (`2`)，新鲜橘子总数减 1，并把新腐烂的橘子压入队列。
   * **第三步（结果判定）**：当队列耗尽或者新鲜橘子被传染光后，检查 `fresh_count` 是否为 0。如果为 0，返回累计的分钟数；如果不为 0，说明有些新鲜橘子永远无法被感染（被墙或空格子隔断），返回 `-1`。

### 代码实现 (Python)

```python
from collections import deque

class Solution(object):
    def orangesRotting(self, grid):
        """
        :type grid: List[List[int]]
        :rtype: int
        """
        if not grid or not grid[0]:
            return 0
            
        Rows, Cols = len(grid), len(grid[0])
        queue = deque()
        fresh_count = 0
        
        # 1. 扫描网格：收集所有初始腐烂的橘子，并统计新鲜橘子总数
        for r in range(Rows):
            for c in range(Cols):
                if grid[r][c] == 2:
                    queue.append((r, c))
                elif grid[r][c] == 1:
                    fresh_count += 1
                    
        # 如果一开始就没有新鲜橘子，直接返回 0 分钟
        if fresh_count == 0:
            return 0
            
        minutes = 0
        directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]
        
        # 2. 多源 BFS 层序扩散
        while queue and fresh_count > 0:
            minutes += 1
            # 记录当前这一分钟内需要扩散的腐烂橘子数量
            for _ in range(len(queue)):
                r, c = queue.popleft()
                
                for dr, dc in directions:
                    nr, nc = r + dr, c + dc
                    # 检查边界，并看是否能感染相邻的新鲜橘子
                    if 0 <= nr < Rows and 0 <= nc < Cols and grid[nr][nc] == 1:
                        grid[nr][nc] = 2  # 感染
                        fresh_count -= 1   # 新鲜橘子少一个
                        queue.append((nr, nc))
                        
        # 3. 检查是否全部感染
        return minutes if fresh_count == 0 else -1
```

## 复杂度分析

* **时间复杂度**：$O(M \times N)$，其中 $M$ 和 $N$ 分别为网格的行数和列数。每个格子最多被访问和入队一次。
* **空间复杂度**：$O(M \times N)$，在最坏情况下，所有橘子同时腐烂并入队，队列需要占用相应的存储空间。

---

从“求最短路径/最短距离”的本质来看，多源 BFS 是无法被纯递归 DFS 或其他非图论方法完美替代的。但为了把这个问题彻底盘透，我们需要从底层原理、为什么 DFS 会翻车、以及网格图论的真正武器库来拆解：

🛑 一、 为什么纯递归 DFS 无法替代多源 BFS？
有些同学可能会想：“既然 DFS 也能走遍整个矩阵，我从每个门出发用 DFS 深搜不也行吗？”
如果你尝试用纯递归 DFS 来解这类求最短距离的网格题，会遇到三个毁灭级的痛点：
1. 无法保证最优解（没有最短路性质）：
  - BFS 是靠“水波纹一层层扩散”天然保证第一次碰到的房间距离一定最短。
  - 而 DFS 是“一条道走到黑”。它可能绕了一个大圈子先到一个房间填了一个很大的数字，你必须把全图所有可能的迂回路径全部搜完、互相比较大小后才能确定最小值。这会导致时间复杂度直接退化成指数级或极其恐怖的阶乘级别。
2. 无限死循环（Cycle）与重复计算：
  - 在网格中，上下左右到处都是回路。DFS 如果没有极其严格且复杂的 visited 剪枝和回溯重置，分分钟就会陷入死循环。
3. 爆栈风险（Recursion Limit Exceeded）：
  - 矩阵稍微大一点（比如 $100 \times 100$），递归调用的函数栈深度就会直接触碰 Python 的系统极限，当场抛出 RecursionError。

🔄 二、 那有没有“其他方法”可以替代或对标多源 BFS？
虽然纯递归 DFS 不行，但在高级图论和网格搜索的领域里，确实有几种特殊的替代方案，它们在特定的业务场景下可以和多源 BFS 掰手腕：
1. Dijkstra 算法（优先队列 / 小顶堆）
- 适用场景：适用于边权不均等（带权图）的多源最短路问题。
- 底层降维：如果网格里每个格子的“通行代价”不一样（比如有的格子过路费是 1，有的是 5），此时标准的 BFS（步数永远加 1）就会失效。我们就必须换用 Priority Queue（小顶堆），演变成 Dijkstra 算法。
- 关系：当所有边的权重都为 1 时，Dijkstra 就会完美退化成多源 BFS。
2. 动态规划（DP） / 两次扫描法 (Two-pass DP)
- 适用场景：某些特殊的网格最短距离问题（例如经典的 01 矩阵问题，每个格子到最近 0 的距离）。
- 底层原理：利用网格的局部最优性，分别从“左上到右下”扫一遍，再从“右下到左上”扫一遍。通过前置状态的递推来更新距离。
- 局限性：它只适用于能严格划分无后效性、且方向受限的距离推导。对于 Walls and Gates 这种四面八方水波纹自由扩散的网格，DP 的状态转移会变得极其混乱，远不如多源 BFS 直观和通用。

💡 核心总结
在算法的武器库里：
- 求无权图的最短距离（如 Walls and Gates、腐烂的橘子）：多源 BFS（Queue） 永远是不可撼动的降维打击之王。
- 递归 DFS 适合做“全图遍历、连通块计数、岛屿淹没（如 LeetCode 200 / 695）”，但在“求最短步数”的战场上，它必须让位给 BFS。

# 🏆 LeetCode 130. Surrounded Regions (被围绕的区域) 详解

## 📝 一、 题目描述 (Description)
给你一个 m x n 的矩阵 `board`，由若干 `'X'` 和 `'O'` 组成。
你需要找到所有被 `'X'` 周围包围的 `'O'`，并将其全部转化为 `'X'`。

**被包围的区间不会存在于边界上**，也就是说，任何处于边界上的 `'O'` 或与边界上的 `'O'` 相连的 `'O'` 都**不会**被填充为 `'X'`。所有不处于边界上、且无法逃逸到边界的 `'O'` 都会被填充为 `'X'`。

## 🏛️ 二、 核心破局解析：逆向思维与“边缘特权流” (Core Intuition)
1. **顺向思考的痛点**：
   - 如果你在矩阵内部遍历每个 `'O'`，去判断它能不能走到边界，过程会极其繁琐且容易陷入重复搜索的陷阱。
2. **神级逆向思维（反其道而行之）**：
   - 题目说：“所有跟边界上的 `'O'` 相连的 `'O'` 都是自由民，不能被消灭。”
   - 换句话说，**我们真正要消灭的，是那些被死死关在内部、与边界外面的世界完全失联的“孤岛 O”**。
   - **三步走大招**：
     1. **第一步（特赦边缘）**：只扫描矩阵的**四条最外圈边界**。如果发现 `'O'`，立刻以此为源头，发动 DFS 或 BFS，把所有和它连通的内部 `'O'` 全部标记为一种特殊状态（例如临时改成 `'E'` 表示 Escaped 逃逸者）。
     2. **第二步（全盘清剿）**：扫描整个矩阵，把剩下的所有真正的孤岛 `'O'` 统统变成 `'X'`。
     3. **第三步（恢复特赦民）**：把刚才特赦的 `'E'` 重新恢复为 `'O'`。

## 💻 三、 完美 Python3 工业级标准代码 (Solution)
```python
from typing import List


class Solution:

  def solve(self, board: List[List[str]]) -> None:
    """Do not return anything, modify board in-place instead."""
    if not board or not board[0]:
      return

    m, n = len(board), len(board[0])

    def dfs(r: int, c: int):
      # 越界或者当前不是 O，直接返回
      if r < 0 or r >= m or c < 0 or c >= n or board[r][c] != 'O':
        return
      # 将当前边界连通的 O 标记为逃逸状态 'E'
      board[r][c] = 'E'
      # 向上下左右四个方向递归渗透
      dfs(r - 1, c)
      dfs(r + 1, c)
      dfs(r, c - 1)
      dfs(r, c + 1)

    # 1. 从四条边上的 'O' 开始出发，特赦所有与边缘连通的 'O'
    for r in range(m):
      if board[r][0] == 'O':
        dfs(r, 0)
      if board[r][n - 1] == 'O':
        dfs(r, n - 1)

    for c in range(n):
      if board[0][c] == 'O':
        dfs(0, c)
      if board[m - 1][c] == 'O':
        dfs(m - 1, c)

    # 2. 全局清剿与恢复
    for r in range(m):
      for c in range(n):
        if board[r][c] == 'O':
          board[r][c] = 'X'  # 孤岛被消灭
        elif board[r][c] == 'E':
          board[r][c] = 'O'  # 逃逸者恢复原样
```

四、 复杂度核验 (Complexity Analysis)
- 时间复杂度：O(M * N) —— 每个格子在整个过程中最多被 DFS 访问或遍历常数次，其中 M 和 N 分别为网格的行数和列数。
- 空间复杂度：O(M * N) —— 在最坏情况下（整个矩阵全都是 'O'），递归函数栈的深度会达到矩阵的最大深度，即 O(M * N)。
