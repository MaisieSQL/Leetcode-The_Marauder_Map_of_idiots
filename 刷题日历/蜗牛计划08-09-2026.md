# LeetCode 1768. 交替合并字符串 (Merge Strings Alternately) ── 完整解析与通关源码

## 一、 题目大意与核心直觉

给你两个字符串 word1 和 word2。请你从 word1 开始，按交替顺序把字符添加合并到新字符串中。如果其中一个字符串比另一个长，将多出来的字符串直接拼在合并后的字符串末尾。

- 物理直觉：
  - 这就像两条拉链互相交错合拢（A1, B1, A2, B2, A3, B3...）。
  - 如果有一条拉链长出一截，最后把长出来的那截直接接上就行。

## 二、 核心解题思路：同向双指针齐头并进流

1. 指针定义：
   - 用两个独立的指针 i 和 j 分别去遍历 word1 和 word2。
2. 循环扫描：
   - 用一个 while 循环，只要两个指针中至少有一个还没到底（即 `i < len(word1) or j < len(word2)`），就继续交替抓取字符：
     - 如果 i 还没超界，先把 word1[i] 拿过来，然后 `i += 1`。
     - 如果 j 还没超界，先把 word2[j] 拿过来，然后 `j += 1`。
3. 闭环组装：
   - 用 Python 的列表把抓出来的字符收集起来，最后通过 `"".join(res)` 瞬间组合成最终字符串。

## 三、 Python3 完美通关代码 (Solution)

```python
class Solution:
    def mergeAlternately(self, word1: str, word2: str) -> str:
        i, j = 0, 0
        res = []
        len1, len2 = len(word1), len(word2)
        
        # 只要有一条字符串还没走完，就继续交替合并
        while i < len1 or j < len2:
            if i < len1:
                res.append(word1[i])
                i += 1
            if j < len2:
                res.append(word2[j])
                j += 1
                
        return "".join(res)
```

```python
class Solution(object):
    def mergeAlternately(self, word1, word2):
        """
        :type word1: str
        :type word2: str
        :rtype: str
        """
        res = []
        i = 0
        len1, len2 = len(word1), len(word2)
        # 获取两个字符串中的最大长度作为循环次数
        max_len = max(len1, len2)

        # 遍历到最长字符串的末尾
        while i < max_len:
            # 如果 i 还在 word1 范围内，添加字符
            if i < len1:
                res.append(word1[i])
            # 如果 i 还在 word2 范围内，添加字符
            if i < len2:
                res.append(word2[i])
            i += 1
        
        # 将列表合并为字符串返回
        return "".join(res)
```

## 四、 复杂度核验 (Complexity Analysis)

- 时间复杂度：O(N + M)
  - 其中 N 和 M 分别是两个字符串的长度。两个指针各自完整遍历自己的字符串一遍，绝对的线性时间。
- 空间复杂度：O(N + M)
  - 用于存储最终合并出来的字符列表及结果字符串，空间开销随输入规模线性增长。

# LeetCode 1011. 在 D 天内送达包裹的能力 (Capacity To Ship Packages Within D Days) ── 完整解析与通关源码

## 一、 题目大意与核心直觉

传送带上的包裹具有重量 weights，第 i 个包裹的重量为 weights[i]。每一天，我们都会按次序往传送带上装载包裹。装载的重量不能超过船的最大运载能力。
请你返回能在 D 天内将传送带上的所有包裹送达的最低运载能力。

- 物理直觉：
  - 如果船的运载能力设得极小（比如刚好等于单个包裹的最大重量），你需要的天数就会非常多。
  - 如果船的运载能力设得极大（等于所有包裹的总重量），你只需要 1 天就能运完。
  - 降维打击秘籍：【二分答案 (Binary Search on Answer) + 贪心判定】。
  - 运载能力 capacity 必然在一个明确的闭区间 [left, right] 内单调：
    - 最小值 left：数组中的最大单个包裹重量（max(weights)），因为船连单个最重的包裹都装不下的话，根本没法开船。
    - 最大值 right：所有包裹的总重量（sum(weights)），即 1 天之内全部运完的极限运载能力。
  - 既然满足条件的运载能力在这个区间内单调，我们就可以用二分查找不断猜测一个“船载重量（mid）”，然后用贪心策略去检验：在这个阈值限制下，运完所有包裹究竟最少需要几天？
    - 如果所需天数 <= D，说明当前的 mid 可行（甚至可能还能调小），我们尝试往左边收缩找更小的载重 (right = mid)。
    - 如果所需天数 > D，说明当前的 mid 太小了，时间不够，必须增大载重 (left = mid + 1)。

## 二、 核心解题思路：二分答案 + 贪心判定

1. 确定二分边界：
   - left = max(weights)
   - right = sum(weights)
2. 编写贪心验证函数 countDays(capacity)：
   - 设定当前船的最大运载能力为 capacity。
   - 从左到右扫描包裹，用一个累加器 current_weight 尝试把尽可能多的包裹塞进当天的船里。
   - 一旦加上下一个包裹超过了 capacity，就必须把船发走（天数 d 加 1），然后把超重的这个包裹留到新的一天。
   - 遍历结束后，返回总共需要的天数是否小于等于 D。
3. 二分收敛：
   - 当 left == right 时，二分结束，此时的 left 就是全场最优解。

## 三、 Python3 完美通关代码 (Solution)

```python
class Solution:
    def shipWithinDays(self, weights: List[int], days: int) -> int:
        # 1. 确定二分查找的上下界
        left = max(weights)
        right = sum(weights)
        
        # 2. 贪心判定函数：检验在船载重为 capacity 的情况下，运完所有包裹需要几天
        def countDays(capacity: int) -> int:
            d = 1
            current_weight = 0
            for w in weights:
                if current_weight + w > capacity:
                    d += 1
                    current_weight = w
                else:
                    current_weight += w
            return d

        # 3. 标准二分答案框架
        while left < right:
            mid = left + (right - left) // 2
            
            if countDays(mid) <= days:
                # 运输天数 <= days，说明 capacity 可行，尝试向左寻找更小的最小运载能力
                right = mid
            else:
                # 运输天数 > days，说明 capacity 太小了，必须向右增大载重
                left = mid + 1
                
        return left
```

### 四、 复杂度核验 (Complexity Analysis)

* **时间复杂度**：O(N log Sum)
  * 其中 N 是包裹数组的长度，Sum 是所有包裹重量的总和。
  * 二分搜索的次数是 `O(log Sum)` 级别的，每次二分内部需要用 `O(N)` 的线性贪心扫描去统计天数。总体效率极高，完全可以秒杀大规模数据。
* **空间复杂度**：O(1)
  * 整个算法只使用了常数个辅助指针和变量（`left`、`right`、`mid`、`d`、`current_weight`），没有开辟任何额外的辅助空间，做到了极致的空间优化。

# 为什么二分内部必须使用贪心算法？（通俗解析）

在前面讲 1011 题（在 D 天内送达包裹的能力）和 410 题（分割数组最大值）时，我们提到在二分内部需要用一个**“贪心判定函数”**去数一数到底需要几天。
你可能会纳闷：“为什么在二分里面验算时，必须用贪心策略（从左到右能塞多少就塞多少），而不是用别的笨办法或者动态规划呢？”
我们用最通俗的物理直觉，把为什么这里**必须且只能用贪心**彻底盘明白：

## 📦 1. 什么是这道题里的“贪心策略”？

我们的贪心逻辑非常简单粗暴（从左到右扫描包裹）：

* 设定每天船的最大运载能力上限是 `capacity`。
* 我从第一个包裹开始，左手拿一个、右手拿一个，往船里拼命塞：`current_weight += w`。
* 只要船还没超载（没有超过 `capacity`），我就绝不停手，继续装下一个。
* 一旦发现塞进下一个包裹会超载，好，当机立断：“今天船满了，发船！”把超重的这个留到明天，天数 `d += 1`。

## 🎯 2. 为什么在这里必须用贪心？（核心原因）

### ① 顺序不能打乱，从左到右是唯一的物理流向
题目规定包裹的先后顺序是绝对不能改变的（你不能把第 5 个包裹拿过来跟第 1 个拼）。这就好比流水线上已经排好队的货物，你只能按部就班地搬运。

### ② 为了“在给定载重下，榨干每一天的运力，凑出最少的天数”
我们的目标是验证：“在船载重为 `capacity` 的前提下，最少需要几天能运完？”
要想让天数最少，每一天的船必须装得越满越好！

* 如果你明明还能多塞一个包裹，却因为“好玩”或者“瞎猜”非要提前把船发走，这就导致当天的船载重量不够饱和，运力被白白浪费了。
* 运力浪费的后果就是：**总天数凭空变多了！** 原本 5 天能运完的货物，因为你没贪婪地塞满，变成了 6 天。
* 这样一来，明明这个载重 `capacity` 理论上可以达标，却因为你的“不贪心”导致验算失败，最终误导二分去搜索更大的载重，破坏了二分的准确性！

👉 所以，为了验证某个载重 `capacity` 的极限潜力，你必须用最贪婪的方式——只要还能装得下，就绝不提前开船，从而榨干每一天的最大容量，算出“最少需要的天数”。

## ❌ 3. 为什么不用动态规划（DP）？

你可能会想：“既然要分配，那用动态规划去试探所有可能的切法行不行？”

* 如果用 DP，你需要去计算“前 i 个包裹在 j 天内运完的最优解”，状态转移会变得极其繁琐。
* 更重要的是：**完全没必要！** 因为在这道题里，由于包裹顺序固定，局部贪心（能塞就塞）天然就等于全局最优（在当前载重下用最少天数运完）。局部的贪婪选择没有任何后效性，不会影响后面的大局。

## 💡 核心总结

老铁，理清这个逻辑链条：

* **二分查找**负责在宏观上“猜一个船载重的数字”。
* **贪心策略**负责在微观上“用最省心、最榨干运力的方式去检验这个数字需要几天”。

# LeetCode 81. 搜索旋转排序数组 II (Search in Rotated Sorted Array II) ── 完整解析与通关源码

## 一、 题目大意与核心直觉

已知存在一个按非降序排列的整数数组 nums，在传递给函数之前，nums 在预先未知的某个下标 k 上进行了旋转（例如，[0,1,2,4,4,4,5,6,6,7] 旋转后可能变成 [4,5,6,6,7,0,1,2,4,4]）。
给你旋转后的数组 nums 和一个目标值 target。请你编写一个函数，如果 target 存在于数组中返回 true，否则返回 false。

- 物理直觉与核心难点：
  - 如果数组里没有重复数字（类似 LeetCode 33），我们只要看 nums[left] <= nums[mid] 就能一眼分清哪半边是有序的。
  - 但当数组中充斥着大量重复数字时（例如 [1, 0, 1, 1, 1]），如果遇到 `nums[left] == nums[mid] == nums[right]` 的极端撞车情况，我们就会彻底抓瞎：根本无法通过边界值判断究竟哪边是有序的。
  - 降维打击秘籍：【去重收缩 (Duplicates Shrinking) + 二分查找】。
  - 遇到左右两端和中间全相等、分不清有序性时，直接把左右边界往中间悄悄缩进一步（`left += 1` 且 `right -= 1`），剥离掉干扰项，然后再继续走二分逻辑。

---

## 二、 核心解题思路：分类讨论 + 重复去重收缩

1. 二分查找框架：
   - 定义 left = 0, right = len(nums) - 1，在 `left <= right` 的循环里找 mid。
2. 命中目标直接返回：
   - 如果 `nums[mid] == target`，直接返回 true。
3. 处理无法判定有序的重复项：
   - 如果 `nums[left] == nums[mid] and nums[mid] == nums[right]`，直接执行 `left += 1` 和 `right -= 1` 剥离干扰。
4. 判断哪一边是有序的：
   - 情况 A：左半边有序 (`nums[left] <= nums[mid]`)
     - 如果 target 落在左半边的闭区间内（`nums[left] <= target < nums[mid]`），把 `right = mid - 1`。
     - 否则，把 `left = mid + 1`。
   - 情况 B：右半边有序 (`nums[left] > nums[mid]`)
     - 如果 target 落在右半边的闭区间内（`nums[mid] < target <= nums[right]`），把 `left = mid + 1`。
     - 否则，把 `right = mid - 1`。

---

## 三、 Python3 完美通关代码 (Solution)

```python
class Solution:
    def search(self, nums: List[int], target: int) -> bool:
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = left + (right - left) // 2
            
            # 1. 找到了直接返回 True
            if nums[mid] == target:
                return True
            
            # 2. 核心难点：遇到左中右三者相等的情况，无法判断有序性，必须去重收缩
            if nums[left] == nums[mid] and nums[mid] == nums[right]:
                left += 1
                right -= 1
                continue
                
            # 3. 判断左半边是否有序
            if nums[left] <= nums[mid]:
                # 目标落在有序的左半区间内
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1
            # 4. 否则，右半边必然有序
            else:
                # 目标落在有序的右半区间内
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1
                    
        return False
```

### 四、 复杂度核验 (Complexity Analysis)

* **时间复杂度**：
  * **平均情况**：$\mathcal{O}(\log N)$。每次二分都能砍掉一半的搜索空间。
  * **最坏情况**：$\mathcal{O}(N)$。当数组中充满了大量重复数字时，`left` 和 `right` 可能会被连续的 `left += 1` 和 `right -= 1` 退化成线性扫描。
* **空间复杂度**：$\mathcal{O}(1)$
  * 只使用了常数个辅助指针变量（`left`、`right`、`mid`），做到了空间优化的极致。

# 为什么 LeetCode 81 不能直接用暴力遍历？（面试底层逻辑）

我们把这背后的“面试官套路”和“算力现实”一讲，你立刻就能拍大腿：

如果你写：

class Solution:

```

# 为什么面试官还要考二分？

在 LeetCode 的评测机上：

* **能过吗？** 能过！而且对于绝大多数日常业务开发、甚至 LeetCode 这道题的普通测试用例，效能完全够用。
* **为什么要考？** 因为面试官要的是 $\mathcal{O}(\log N)$ 的工业级效率，而不是 $\mathcal{O}(N)$ 的暴力遍历！

### 💡 生活中的比喻

就像去图书馆找一本书：一共有 1000 万本书，虽然你可以一本一本从头摸到尾（线性扫描），但如果这堆书是有规律的，管理员显然希望你用二分对半切的办法瞬间定位。

## 🚨 二、 为什么直接遍历在面试里会被“降维打击”？

### 大厂面试的红线
旋转排序数组（不论是第 33 题还是第 81 题）在标签里被归类为 **Binary Search（二分查找）**。

如果面试官出了这道题，你直接用了个 `for` 循环或者 `target in nums`（底层也是线性遍历），面试官会直接笑眯眯地看着你：

> “小伙子，这题的数据量如果有 100 亿，或者系统要求在实时高并发下保证亚毫秒级响应，你的线性扫描直接就让服务器超时崩溃了。请用二分写一个。”

### 出题人的初心
数组虽然被旋转错位了，但它依然保留了“二分”的底子。面试官就是要看你能不能在“局部有序”的杂乱环境中，通过精妙的边界判断，依然压榨出对半砍（$\mathcal{O}(\log N)$）的高效算力。

# LeetCode 33题 vs 第81题：核心区别解析

在 LeetCode 中，**第 33 题（搜索旋转排序数组）** 和 **第 81 题（搜索旋转排序数组 II）** 的解题逻辑有着本质上的差异。

---

## 核心区别一览表

| 比较维度 | 第 33 题：搜索旋转排序数组 | 第 81 题：搜索旋转排序数组 II |
| :--- | :--- | :--- |
| **数组元素特点** | 数组中的元素**互不相同**（无重复值） | 数组中**可能包含重复元素** |
| **二分边界判定** | 简单清晰：`nums[l] <= nums[mid]` 必定能明确区分哪一边是有序的 | **失效风险**：当 `nums[l] == nums[mid] == nums[r]` 时，无法判断哪边有序 |
| **最坏时间复杂度** | 严格的 $\mathcal{O}(\log N)$ | 退化为 $\mathcal{O}(N)$（当有大量重复元素时） |
| **处理手段** | 不需要去重处理 | 必须增加指针收缩逻辑（如 `l++` 或 `r--`）来跨过重复值 |

---

## 为什么“重复元素”会击溃标准二分？

在 **第 33 题** 中，只要切一刀（`mid`），通过比较 `nums[l]` 和 `nums[mid]`，**必然能准确知道左半段和右半段哪一个是严格单调递增的**。

但在 **第 81 题** 中，如果遇到这样的极端测试用例：
`nums = [1, 0, 1, 1, 1]`

* 当 `l = 0`，`r = 4`，`mid = 2` 时：
  * `nums[l]` 是 `1`
  * `nums[mid]` 是 `1`
  * `nums[r]` 是 `1`
* 此时：`nums[l] == nums[mid] == nums[r]`。
* **灾难发生**：你根本无法分辨究竟是左边有序、右边被旋转过，还是整个区间全都是重复数字。

## 代码应对策略的不同

### 1. 第 33 题的常规二分写法（无重复）
```python
def search(nums: list[int], target: int) -> int:
    l, r = 0, len(nums) - 1
    while l <= r:
        mid = (l + r) // 2
        if nums[mid] == target:
            return mid
        
        # 明确判断左半段是否有序
        if nums[l] <= nums[mid]:
            if nums[l] <= target < nums[mid]:
                r = mid - 1
            else:
                l = mid + 1
        # 否则右半段有序
        else:
            if nums[mid] < target <= nums[r]:
                l = mid + 1
            else:
                r = mid - 1
    return -1
```

### 2. 第 81 题的破解之道（处理重复）
面对重复元素导致的边界模糊，唯一的破解办法就是在进入二分逻辑前，先收缩由于重复值带来的干扰：

```python
def search(nums: list[int], target: int) -> bool:
    l, r = 0, len(nums) - 1
    while l <= r:
        # 去重核心：当左右两端和中点值相同时，收缩边界以避开重复干扰
        while l < r and nums[l] == nums[mid := (l + r) // 2] and nums[r] == nums[mid]:
            l += 1
            r -= 1
            
        mid = (l + r) // 2
        if nums[mid] == target:
            return True
            
        if nums[l] <= nums[mid]:
            if nums[l] <= target < nums[mid]:
                r = mid - 1
            else:
                l = mid + 1
        else:
            if nums[mid] < target <= nums[r]:
                l = mid + 1
            else:
                r = mid - 1
    return False
```

# 表达式深度拆解

这句话 `nums[l] == nums[mid := (l + r) // 2] and nums[r] == nums[mid]` 是 Python 中非常经典的“**海象运算符（Walrus Operator `:=`）**”的高效连写。

为了方便理解，我们可以把它拆解成以下几个步骤：

### 1. 拆解为标准写法

这段代码如果还原成传统的、不使用海象运算符的写法，等价于：

```python
# 第一步：先算出 mid 的位置
mid = (l + r) // 2

# 第二步：检查左端点、中点、右端点的值是否全部相等
if nums[l] == nums[mid] and nums[r] == nums[mid]:
    # 进去之后执行收缩逻辑
    l += 1
    r -= 1
```

### 2. 逐个符号看它在干什么

* **`mid := (l + r) // 2` （海象运算符 `:=`）**
  * **作用**：在表达式内部给变量赋值，同时把计算结果返回。
  * **为什么要这么写**：因为我们在判断 `nums[l] == nums[mid]` 之前，必须先算出当前的 `mid` 是多少。如果在外面单独算一行 `mid = ...`，代码会显得冗长。用 `:=` 就可以边算 `mid`，边拿它去比较。
* **`nums[l] == nums[...]`**
  * **作用**：检查最左边的元素 (`nums[l]`) 和刚刚算出来的中间元素 (`nums[mid]`) 是不是一样大。
* **`and nums[r] == nums[mid]`**
  * **作用**：在左边相等的前提下，再检查最右边的元素 (`nums[r]`) 是不是也和中间元素 (`nums[mid]`) 一样大。

### 3. 为什么一定要这三个同时相等才处理？

只有当 `nums[l] == nums[mid] == nums[r]` 三者全部相等时，才真正触发了二分查找的“灾难盲区”——此时你根本无法判断左边有序还是右边有序。

* 如果**只是** `nums[l] == nums[mid]`（比如 `[3, 1, 3, 3, 3]`），左半部分虽然首尾相同，但右半部分并不完全相等，依然可以通过 `nums[l] <= nums[mid]` 准确判定哪边是有序的。
* 只有当左右两端和中间全卡死在同一个数字上时，才必须靠 `l += 1` 和 `r -= 1` 往中间缩一步，强行把这个重复的干扰项剔除掉。
