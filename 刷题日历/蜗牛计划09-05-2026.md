# 743. Network Delay Time (网络延迟时间)

- **难度**：Medium
- **标签**：图论、最短路、Dijkstra 算法、堆（优先队列）
- **LeetCode 链接**：[LeetCode 743. Network Delay Time](https://leetcode.com/problems/network-delay-time/)

### 一、 题目描述

有 `n` 个网络节点，标记为 `1` 到 `n`。

给你一个列表 `times`，表示信号经过 **有向** 边的传递时间。 `times[i] = (u_i, v_i, w_i)`，其中：
* `u_i` 是源节点
* `v_i` 是目标节点
* `w_i` 是一个信号从源节点传递到目标节点的时间

现在，我们从某个节点 `k` 发出一个信号。需要多久才能使所有节点都收到信号？如果不能使所有节点收到信号，返回 `-1`。

### 二、 核心解题切入点

**“信号同时向外广播，多久能传遍所有节点？”**
* 信号从起点 `k` 出发到达任意一个节点 `x` 的时间，本质就是从 `k` 到 `x` 的**最短路径长度**（最短时间）。
* 当所有节点都收到信号时，总耗时取决于**最后收到信号的那个节点**。
* 因此题目要求的就是：**从起点 `k` 出发，到达所有可达节点的最短路径中，取一个最大值（$\max$）**。如果存在某些节点根本无法到达，则返回 `-1`。

因为边权全部为非负数（$w_i \ge 0$），这是最标准的 **单源最短路径算法：堆优化版 Dijkstra**。

### 三、 Dijkstra 算法核心心法（贪心 + 堆）

Dijkstra 的本质是**按距离从小到大逐步确认各节点的最短路**：

1. **距离数组 `dist`**：记录起点 `k` 到每个节点当前已知的最短距离，初始时除了 `dist[k] = 0`，其余全为 $\infty$。
2. **小顶堆 (Priority Queue)**：里面存放元组 `(当前累积耗时, 当前节点)`。堆顶永远是最早被信号到达的节点。
3. **松弛操作 (Relaxation)**：
   * 从堆顶弹出耗时最小的节点 `(d, u)`。
   * **跳过冗余**：如果弹出的 `d > dist[u]`，说明之前已经找到过到达 `u` 的更优路径，直接 `continue`。
   * **向外扩散**：遍历 `u` 的所有邻居 `v`，如果经由 `u` 到达 `v` 的新耗时 `d + weight < dist[v]`，就更新 `dist[v] = d + weight`，并把新距离入堆。

### 四、 Python 3 最优解实现

```python
from collections import defaultdict
import heapq

class Solution:

  def networkDelayTime(self, times: list[list[int]], n: int, k: int) -> int:
    # 1. 建立有向带权图邻接表: u -> list of (v, weight)
    graph = defaultdict(list)
    for u, v, w in times:
      graph[u].append((v, w))

    # 2. 距离字典: 存储从起点 k 到各节点的最短耗时
    # 也可以用 list: dist = [float('inf')] * (n + 1)
    dist = {}

    # 3. 最小堆: 存 (当前累积时间, 当前节点)，初始放入起点 k
    min_heap = [(0, k)]

    while min_heap:
      time, u = heapq.heappop(min_heap)

      # 如果该节点已经确定过最短路，跳过（因为堆顶弹出的顺序保证了第一次弹出就是全局最短）
      if u in dist:
        continue

      # 第一次弹出，锁定该节点的最短时间
      dist[u] = time

      # 遍历邻居，尝试松弛推进
      for v, weight in graph[u]:
        if v not in dist:
          heapq.heappush(min_heap, (time + weight, v))

    # 4. 结果判断
    # 若被确定的节点数量小于 n，说明有节点无法到达
    if len(dist) < n:
      return -1

    # 全部节点都收到信号的时间，取决于最慢到达的那个
    return max(dist.values())
```

### 五、 复杂度分析

* **时间复杂度**：$O(E \log E)$ 或 $O(E \log V)$，其中 $E$ 是边的总数（`len(times)`），$V$ 是节点数 $n$。
  * 每条边最多被推入堆一次，堆的大小上限为 $E$。堆的每次弹出与插入耗时为 $O(\log E)$。在 LeetCode 数据规模下运行仅需十几毫秒。
* **空间复杂度**：$O(V + E)$。
  * 邻接表占用 $O(V + E)$ 空间，堆与 `dist` 字典最多存储 $O(V + E)$ 个状态。

### Dijkstra 算法中的“贪心”体现在哪里？

Dijkstra 的贪心体现在：**每一次从堆顶弹出当前累积距离最小的未访问节点时，就敢直接断言——该节点的最短路径已被永久确定，后续绝不可能有任何其他路径比它更短。**

#### 一、 贪心的核心逻辑：为什么它“敢”直接下结论？

**贪心选择成立的唯一铁律：边权全部非负（$\ge 0$）。**

假设当前堆里距离起点最近的未确定节点是 $u$，距离为 $d(u) = 3$；堆里其他候选节点到起点的距离都比它大，例如节点 $v$ 的距离是 $d(v) = 5$。

此时算法直接盖章确认：**从起点到 $u$ 的全局最短路径就是 $3$。**

为什么未来绝不可能存在一条“先绕道去 $v$，再从 $v$ 走到 $u$”的更短路径？
1. 起点要走到 $v$，已经至少需要花费 $5$。
2. 图中**没有任何负权边**（每走一步的代价都 $\ge 0$）。
3. 从 $v$ 继续往前走任何路径到达 $u$，总代价必然是：$5 + \text{非负边权} \ge 5$。
4. 一个至少为 $5$ 的数字，在数学上绝不可能反超已经拿到手的 $3$。

**局部当下最小（堆顶），在非负边权的世界里直接锁死了全局最优。** 这种“每一步只选眼前累积代价最小的点，一旦选定永不回头反悔”的策略，就是最纯粹的贪心思想。

#### 二、 堆在贪心策略中的角色

* **贪心策略需要极值**：贪心每一步都必须严格拿到当前所有边缘节点中“累积距离最小”的那一个。
* **小顶堆是最高效的极值提取器**：如果用普通数组扫描，找最小值需要 $O(V)$；借助**小顶堆（Priority Queue）**，可以在 $O(\log V)$ 复杂度内把最小值送到堆顶供贪心算法提取。

#### 三、 反例：为什么图里有“负权边”时贪心会彻底失效？

如果允许边权为负数（例如从 $v$ 到 $u$ 有一条权重为 $-4$ 的边）：
* 起点走到 $v$ 依然花了 $5$。
* 但从 $v$ 跨到 $u$ 扣除了 $4$，总耗时变成了 $5 + (-4) = 1$。
* 此时 $1 < 3$，之前贪心提前锁定的“$u$ 的最短路径是 3”就被推翻了。

这就是为什么**负权图不能用基于贪心的 Dijkstra**，而**只要边权全为非负数，Dijkstra 的贪心证明就坚不可摧**。

# 负权图最短路核心速记（常识存档）

当图中出现负权边时，Dijkstra 的贪心策略失效（因为后面的负数会让已经确定的路径变得更小）。此时核心思路转向**允许反复更新的动态规划与松弛算法**。

---

### 一、 核心解法：Bellman-Ford 算法

不找最小值，而是**对全图所有的边暴力松弛 $V - 1$ 轮**。

* **理论依据**：包含 $V$ 个节点的图，最短路最多经过 $V - 1$ 条边。松弛 $V - 1$ 轮后，所有最短路径必定被完全更新到位。
* **负权环检测**：如果跑完第 $V - 1$ 轮后，**第 $V$ 轮还能继续把距离变小**，说明图中存在无限打折兜圈的“负权环”。
* **复杂度**：时间 $O(V \times E)$，空间 $O(V)$。

```python
def bellman_ford(n: int, edges: list[list[int]], start: int):
  dist = [float('inf')] * (n + 1)
  dist[start] = 0

  # 1. 严格松弛 n - 1 轮
  for _ in range(n - 1):
    for u, v, w in edges:
      if dist[u] != float('inf') and dist[u] + w < dist[v]:
        dist[v] = dist[u] + w

  # 2. 第 n 轮检测负权环
  for u, v, w in edges:
    if dist[u] != float('inf') and dist[u] + w < dist[v]:
      return "存在负权环，最短路无意义"

  return dist
```

### 二、 队列优化版：SPFA 算法

Bellman-Ford 每一轮都盲目遍历所有边，效率较低。

* **优化思路**：只有上一轮距离变小了的节点，它的邻居才有变小的可能。
* **做法**：用一个 **FIFO 普通队列**，谁被改小了谁就进队，去更新它的邻居。
* **特点**：节点可以多次入队、反复松弛；若某节点入队达 $V$ 次，判定为存在负权环。

### 三、 四大最短路算法选型对照表

| 算法 | 边权适用场景 | 核心思想 | 时间复杂度 | 面试考察定位 |
| :--- | :--- | :--- | :---: | :--- |
| **Dijkstra** | **仅限非负权图** | 贪心 + 小顶堆 | $O(E \log V)$ | **绝对的核心主力，95% 实际考察此项** |
| **Bellman-Ford** | **任意边权（含负权）** | 暴力松弛 $V - 1$ 轮 | $O(V \times E)$ | 常作为“口头原理回答”与“负权环检测”考察 |
| **SPFA** | **任意边权（含负权）** | 队列启发式松弛 | 平均 $O(E)$，最坏 $O(VE)$ | 竞赛常见，工业与面试了解思想即可 |
| **Floyd** | **任意边权（含负权）** | 三重循环求任意两点间距离 | $O(V^3)$ | 极小数据范围（$N \le 200$）的多源最短路 |
