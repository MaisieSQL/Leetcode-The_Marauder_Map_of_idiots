# 🗺️ LeetCode 数组（Array）6 大核心题型全景图谱

## 1. 🪟 滑动窗口流 (Sliding Window)

* **物理直觉**：当题目要求我们在一个连续区间（子数组 / 子字符串）内寻找满足某种条件的最长/最短/特定子区间时，如果用暴力双循环，时间复杂度会飙到 $\mathcal{O}(N^2)$。滑动窗口通过维护一个大小可变的“窗口”（用左右指针 `left` 和 `right`），像毛毛虫一样向前蠕动，将复杂度硬生生压成线性的 $\mathcal{O}(N)$。
* **经典母题**：
  - LeetCode 3. 无重复字符的最长子串 (Longest Substring Without Repeating Characters)
  - LeetCode 209. 长度最小的子数组 (Minimum Size Subarray Sum)
* **核心破局点**：区分“固定窗口”还是“可变窗口”。可变窗口的精髓在于：`right` 负责不断扩充、寻找可行解；当违反条件时，`left` 开始追赶、收缩窗口。

## 2. 🔀 双指针夹逼与快慢流 (Two Pointers & Fast-Slow Pointers)

* **物理直觉**：数组如果是有序的，或者需要我们在原地（In-place）对元素进行搬运、去重、筛选，单指针往往捉襟见肘。这时候就要祭出双指针：
  - **对撞指针（左右夹逼）**：从两端向中间靠拢（典型如两数之和、盛最多水）。
  - **快慢指针**：一个在前探路，一个在后清理（典型如原地移除元素、移动零）。
* **经典母题**：
  - LeetCode 11. 盛最多水容器 (Container With Most Water)
  - LeetCode 27. 移除元素 (Remove Element)
* **核心破局点**：利用数组的有序性或特定规则，通过指针的单向或相向移动，跳过无数次无用的无效遍历。

## 3. ➕ 前缀和与差分数组流 (Prefix Sum & Difference Array)

* **物理直觉**：
  - **前缀和**：如果一个数组需要频繁、多次查询某一个闭区间 `[i, j]` 的元素总和，如果每次都用 `for` 循环去加，单次查询是 $\mathcal{O}(N)$，总查询代价巨大。通过提前“打表”算出前缀和数组，可以将区间求和降维到 $\mathcal{O}(1)$！
  - **差分数组**：反过来，如果题目要求频繁对某一个区间整体加上或减去某个值，差分数组能在 $\mathcal{O}(1)$ 时间内搞定打标，最后统一做一次前缀和还原。
* **经典母题**：
  - LeetCode 560. 和为 K 的子数组 (Subarray Sum Equals K)
  - LeetCode 303. 区域和检索 - 数组不可变 (Range Sum Query - Immutable)
* **核心破局点**：前缀和的核心公式：$\text{Sum}(i, j) = \text{Prefix}[j+1] - \text{Prefix}[i]$。遇到“连续子数组和等于 K”的题目，立刻条件反射想到：前缀和 + 哈希表优化。

## 4. 📈 贪心与单调队列/单调栈流 (Greedy & Monotonic Stack/Queue)

* **物理直觉**：处理数组中的极值问题（如：接雨水、求每个滑动窗口的最大值、买卖股票的最佳时机）。这类题目通常要求我们在线性时间内做出最优决策，或者借助一个“单调递减/递增”的容器把无用的小不点提前淘汰。
* **经典母题**：
  - LeetCode 42. 接雨水 (Trapping Rain Water)
  - LeetCode 239. 滑动窗口最大值 (Sliding Window Maximum)
* **核心破局点**：单调栈/队列里存的往往不是元素本身，而是元素的下标（Index），通过维持队列的单调性，实现每个元素进出栈均摊 $\mathcal{O}(1)$。

## 5. 🔄 矩阵与空间降维流 (Matrix & In-place Simulation)

* **物理直觉**：二维数组（矩阵）的题目。核心难点不在于算法多难，而在于坐标映射、边界控制、以及空间复杂度能否压到 $\mathcal{O}(1)$ 的原地旋转/修改。
* **经典母题**：
  - LeetCode 48. 旋转图像 (Rotate Image)
  - LeetCode 54. 螺旋矩阵 (Spiral Matrix)
* **核心破局点**：寻找矩阵翻转的数学对称规律（如：先沿主对角线翻转，再左右翻转），或者严格控制四个边界指针（`top`, `bottom`, `left`, `right`）。

## 6. 🏛️ 原地哈希与置换流 (In-place Hashing / Cyclic Sort)

* **物理直觉**：当题目明确要求：**“必须在 $\mathcal{O}(N)$ 时间内完成，且空间复杂度必须是 $\mathcal{O}(1)$（不能开辟额外的哈希表或布尔数组）”**时，这就是原地哈希的主战场。
* **经典母题**：
  - LeetCode 41. 缺失的第一个正数 (First Missing Positive)
  - LeetCode 448. 找到所有数组中消失的数字 (Find All Numbers Disappeared in an Array)
* **核心破局点**：利用数组自身的索引作为哈希桶，通过不断的“乾坤大挪移”（交换元素），把数字 $x$ 强行赶到它理应呆的索引位置（如数值 $x$ 放到下标 $x-1$ 处）。

# 🎯 LeetCode 27. 移除元素 (Remove Element) —— 物理直觉与快慢指针通关全解

## 一、 题目大意与核心约束
- **题目描述**：给你一个数组 `nums` 和一个值 `val`，你需要**原地（In-place）**移除所有数值等于 `val` 的元素，并返回移除后数组的新长度。
- **约束条件**：
  - 不能使用额外的辅助数组（即空间复杂度必须是 O(1) 额外空间）。
  - 元素的顺序可以改变，超出新长度后面的元素是什么不重要。

## 二、 思考演进：从暴力法到双指针的破局

### 1. 暴力挪动法（直觉思考）
- **思路**：从左到右扫描数组，一旦发现当前元素等于 `val`，就触发内层循环，把后面所有的元素整体往前挪动一位。
- **复杂度代价**：
  - **时间复杂度**：最坏情况下（例如数组里大部分都是要删除的元素），每次都要触发整体搬运，时间复杂度会飙升到 O(N^2)，面对大厂数据规模必然超时。
  - **空间复杂度**：由于是在原数组上挪动，不需要额外开辟空间，满足 O(1)。但时间代价无法接受。

### 2. 快慢指针降维打击（安检员与占坑员模型）
- **核心物理直觉**：
  - 为什么暴力法慢？因为同一个元素被反复搬运了多次。
  - 我们可以把整个过程想象成一个**“安检流程”**：
    - **快指针（`fast`）**：充当不知疲倦的**安检员**，从头到尾只扫一遍数组，负责开路查验。
    - **慢指针（`slow`）**：充当**占坑员**，死死守在后面等待“好宝贝”入驻。
  - **动态交接**：当 `fast` 扫到一个**不是 `val`** 的元素时（安检通过，是个好宝贝），立刻把它覆写到 `slow` 当前守着的坑里，随后 `slow` 往前挪一格。如果遇到 `val`（坏蛋），`fast` 自己默默走开，`slow` 原地不动等待覆盖。

### 3. 具体沙盘推演：以 [3, 2, 2, 3], val = 3 为例

- 初始状态：`slow = 0`, `fast = 0`。
- **fast = 0**：`nums[0] = 3`（等于 val，安检不通过）。`fast` 前进一步，`slow` 原地不动（依然守在 0）。
- **fast = 1**：`nums[1] = 2`（不等于 val，安检通过！是个好宝贝）。
  - 执行 `nums[slow] = nums[fast]`（即 `nums[0] = 2`）。
  - `slow` 前进一步（变为 1），`fast` 前进一步（变为 2）。
  - 数组变为 `[2, 2, 2, 3]`。
- **fast = 2**：`nums[2] = 2`（不等于 val，好宝贝）。
  - 执行 `nums[slow] = nums[fast]`（即 `nums[1] = 2`）。
  - `slow` 前进一步（变为 2），`fast` 前进一步（变为 3）。
  - 数组变为 `[2, 2, 2, 3]`。
- **fast = 3**：`nums[3] = 3`（等于 val，安检不通过）。`fast` 前进，`slow` 原地不动。
- **循环结束**：`slow` 停在 **2**。这意味着前面整整齐齐地挤压出了 2 个有效元素。最后直接返回 `slow`（即新长度 2）。

## 三、 Python3 高效通关源码

```python
class Solution(object):
    def removeElement(self, nums, val):
        """
        :type nums: List[int]
        :type val: int
        :rtype: int
        """
        slow = 0
        for fast in range(len(nums)):
            # 只有当 fast 扫到的不是 val 时，才将其覆写到 slow 坑位，并将 slow 推进
            if nums[fast] != val:
                nums[slow] = nums[fast]
                slow += 1
        return slow
```

### 四、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：O(N)，其中 N 是数组 `nums` 的长度。快慢指针各自最多把数组完整遍历一遍，没有重复搬运。
- **空间复杂度**：O(1)，只声明了固定常数个整型指针变量（`slow`、`fast`），没有开辟任何额外的辅助内存空间。

# 🧩 LeetCode 238. 除自身以外数组的乘积 (Product of Array Except Self) —— 前缀积与空间降维流全解

## 一、 题目大意与核心约束
- **题目描述**：给你一个整数数组 `nums`，返回一个数组 `answer`，其中 `answer[i]` 等于 `nums` 中除 `nums[i]` 之外其余各元素的乘积。
- **核心硬约束**：
  - **不能使用除法**（防止 `0` 带来的数学死锁以及违规投机）。
  - 时间复杂度必须达到 **O(N)**。
  - 空间复杂度要求达到 **O(1) 额外空间**（除了返回值输出数组外，不能开辟多余的辅助数组）。

按照这道题的核心特征（要求算出除自身以外其余元素的乘积，且时间复杂度为 O(N)，不能用除法），它在物理本质上，最契合图谱里的哪一个大类流派（或者是由哪个大类演变而来的变体）？

- **门派归类**：**前缀和与差分数组流（变体：前缀积流）**。
- **物理直觉**：
  - 对于数组中的任意位置 `i`，除开它自己之外，总乘积天然可以拆分为两部分：
    1. **左前缀积**：它左侧所有元素的连乘积。
    2. **右后缀积**：它右侧所有元素的连乘积。
  - **最终答案** = `左前缀积` $\times$ `右后缀积`。

## 三、 沙盘推演：以 [1, 2, 3, 4] 为例

### 1. 两步走空间压缩核心思想
- 如果分别开辟两个新数组存左右两侧的积，空间复杂度是 O(N)，达不到面试官要求的 O(1) 额外空间。
- **极致优化方案**：
  1. **第一步（正向扫描）**：利用输出结果数组 `res`，从左往右打表存下每个位置的**左前缀积**。
  2. **第二步（反向扫描）**：用一个动态滚动变量 `right_prod` 从右往左实时累乘**右后缀积**，并直接乘进 `res` 中，彻底省去了右侧的辅助数组！



### 2. 模拟运行轨迹
- 原数组：`nums = [1, 2, 3, 4]`
- **正向遍历（算左前缀积）**：
  - 初始 `left_prod = 1`
  - 遍历完后，`res` 数组保存了各位置的左侧积：`[1, 1, 2, 6]`
- **反向遍历（滚算右后缀积并相乘）**：
  - 初始 `right_prod = 1`
  - 从右往左倒着扫，用 `right_prod` 实时乘以当前元素并更新 `res[i]`。
  - 最终得出完美结果：`[24, 12, 8, 6]`。

## 四、 Python3 高效通关源码

```python
class Solution(object):
    def productExceptSelf(self, nums):
        """
        :type nums: List[int]
        :rtype: List[int]
        """
        n = len(nums)
        res = [1] * n
        
        # 1. 正向遍历：计算左侧前缀积，直接存入结果数组 res
        left_prod = 1
        for i in range(n):
            res[i] = left_prod
            left_prod *= nums[i]
            
        # 2. 反向遍历：动态计算右侧后缀积，并与 res 中的左侧前缀积实时相乘
        right_prod = 1
        for i in range(n - 1, -1, -1):
            res[i] *= right_prod
            right_prod *= nums[i]
            
        return res
```

在这个阶段，`right_prod` 从右往左滚动，代表“当前位置右边所有数字的乘积”。我们把它直接乘进已经有左前缀积的 `res[i]` 里。

- **初始状态**：`right_prod = 1`
- **当 `i = 3` 时（倒数第一个元素，`nums[3] = 4`）**：

  - `res[2] *= right_prod` $\rightarrow$ `res[2] = 2 * 4 = 8` （此时 `res` 为 `[1, 1, 8, 6]`）
  - `right_prod *= nums[2]` $\rightarrow$ `right_prod = 4 * 3 = 12`
- **当 `i = 1` 时（倒数第三个元素，`nums[1] = 2`）**：
  - `res[1] *= right_prod` $\rightarrow$ `res[1] = 1 * 12 = 12` （此时 `res` 为 `[1, 12, 8, 6]`）
  - `right_prod *= nums[1]` $\rightarrow$ `right_prod = 12 * 2 = 24`
- **当 `i = 0` 时（倒数第四个元素，`nums[0] = 1`）**：
  - `res[0] *= right_prod` $\rightarrow$ `res[0] = 1 * 24 = 24` （此时 `res` 为 `[24, 12, 8, 6]`）
  - `right_prod *= nums[0]` $\rightarrow$ `right_prod = 24 * 1 = 24`

# 🧩 算法核心概念沉淀：Prefix（前缀）与数组乘积降维

## 一、 究竟什么是 Prefix（前缀）？

在计算机科学和数学中，**Prefix（前缀）的核心含义是：“从头开始，一直切到某个位置（包含这个位置）的那一段。”**

我们可以把它想象成一条**排好队的军列**：
假设队伍里有 5 个人，分别编为位置 `0, 1, 2, 3, 4`：
* 如果有人问你：**“以位置 2 结尾的前缀（Prefix）是谁？”**
* 答案就是：**从开头（位置 0）一直到位置 2** 这一整段的人！

### 💡 常见应用场景：
1. **字符串的前缀**：
   - 比如单词 `"algorithm"`。
   - 长度为 3 的前缀是 `"alg"`。
   - **核心特征**：必须是从**最左边的第一个字符**开始起步，中间不能断档。从中间或后面切出来的叫后缀或子串。
2. **数组的前缀和 / 前缀积**：
   - 假设原数组是 `nums = [1, 2, 3, 4]`。
   - 索引 `2` 处的**前缀和**：从开头一直加到索引 `2` 为止的总和（`1 + 2 + 3 = 6`）。
   - 索引 `2` 处的**前缀积**：从开头一直乘到索引 `2` 为止的连乘积（`1 * 2 * 3 = 6`）。

## 二、 为什么程序员这么喜欢用“前缀（Prefix）”？
前缀最大的特异功能就是：**“提前打表，省去重复计算！”**
* 比如你想求数组里从索引 `1` 到索引 `3` 的区间和。如果每次都用 `for` 循环从头加到尾，数据量大了必然超时。
* 但如果你提前算好了**前缀和数组**（即每个位置的前缀总和）：
  - 索引 3 的前缀和减去 索引 0 的前缀和，**O(1) 的时间就能瞬间得出答案！**

# 🚀 数组大厂面试通关：6 大核心题型全景图谱

把这 6 大核心题型全景图谱的适用场景和解决问题盘清楚，相当于直接拿到了大厂数组面试的“降维打击密码簿”！

下面将这六大流派的江湖定位、出场暗号、适用场景和解决的终极问题进行全景式拆解：

### 1. 滑动窗口流 (Sliding Window)
- **江湖定位**：连续区间的“毛毛虫”伸缩扫描器。
- **核心特征**：处理的对象必须是**连续子数组/子串**，要求满足某种单调性或包含特定条件（如“和大于等于 S”、“包含全部特定字符”）。
- **解决什么问题**：
  - 求满足特定条件的**最长/最短连续子数组**长度。
  - 替代暴力的嵌套循环（把 O(N^2) 的暴力扫描降维成 O(N) 的单次线性扫描）。
  - 经典代表：无重复字符的最长子串、长度最小的子数组。

### 2. 双指针夹逼与快慢流 (Two Pointers: Opposing & Fast-Slow)
- **江湖定位**：数组有序化后的“对撞收割机”或原地筛选的“安检员”。
- **核心特征**：分为两类：
  - **夹逼（对撞）指针**：主要针对**有序数组**，一头一尾向中间靠拢。
  - **快慢指针**：在同一个方向一前一后，用于原地清洗、去重、移动元素。
- **解决什么问题**：
  - **夹逼**：解决有序数组中的查找问题，如两数之和、三数之和、盛最多水的容器。
  - **快慢指针**：解决原地修改、原地删除（如 LeetCode 27 移除元素、删除有序数组中的重复项），做到 O(1) 额外空间。

### 3. 前缀和与差分数组流 (Prefix Sum & Difference Array)
- **江湖定位**：频繁区间查询与批量区间修改的“预处理打表神器”。
- **核心特征**：
  - **前缀和（含前缀积）**：针对**静态数组**，用来把“反复求某个区间和/积”的 O(N) 运算，瞬间优化成 O(1) 的数学减法/除法。
  - **差分数组**：针对需要**频繁对数组某个区间批量加上/减去某个数**的场景。
- **解决什么问题**：
  - 消除重复计算，快速获取任意子数组的累加/累乘结果（如 LeetCode 238 除自身以外数组的乘积）。
  - 解决“多次区间增减修改，最后统一查验”的问题。

### 4. 贪心与单调队列/单调栈流 (Greedy, Monotonic Queue & Stack)
- **江湖定位**：局部最优解的推导器，或在滑动过程中“秒杀历史最大/最小值”的黑科技。
- **核心特征**：
  - **贪心**：每一步都做出当前看起来最好的选择，从而推导全局最优。
  - **单调栈/队列**：当需要找**“每个人左边/右边第一个比他大或小的元素”**时出场。
- **解决什么问题**：
  - **贪心**：跳跃游戏、买卖股票的最佳时机。
  - **单调栈**：下一个更大元素、柱状图中最大的矩形。
  - **单调队列**：滑动窗口最大值（能在 O(1) 均摊时间拿到窗口内的极值）。

### 5. 矩阵与空间降维流 (Matrix & Space Dimension Reduction)
- **江湖定位**：二维空间的降维打击与边界剥离大师。
- **核心特征**：面对复杂的二维矩阵（Matrix）遍历、旋转、螺旋打印，或者需要将多维状态压缩到一维以节省空间的场景。
- **解决什么问题**：
  - 矩阵的旋转（顺时针 90 度）、螺旋矩阵遍历。
  - 动态规划中的空间优化（滚动数组，把二维 DP 降维成一维空间）。

### 6. 原地哈希与置换流 (In-place Hashing & Cyclic Sort)
- **江湖定位**：当题目死活不让开辟额外哈希表（要求 O(1) 空间），且元素数值范围有特殊限制时（比如 1 到 N）的极限操作。
- **核心特征**：利用数组自身的**索引（Index）和数值（Value）**之间的映射关系，把数组本身当成一个“天然的哈希表”来用。
- **解决什么问题**：
  - 寻找数组中缺失的数字、重复的数字（如：长度为 N 的数组，数字都在 1 ~ N 范围内，找出所有消失的数字）。通过让 `nums[abs(nums[i]) - 1]` 取负数来打标记，实现零额外空间的哈希查找。
