## **LeetCode 21. 合并两个有序链表** (Merge Two Sorted Lists)

* **难度**：简单
* **题目描述**：
  将两个升序链表合并为一个新的 **升序** 链表并返回。新链表是通过拼接给定的两个链表的所有节点组成的。

* **示例 1**：
  * **输入**：`l1 = [1,2,4], l2 = [1,3,4]`
  * **输出**：`[1,1,2,3,4,4]`

* **示例 2**：
  * **输入**：`l1 = [], l2 = []`
  * **输出**：`[]`

* **示例 3**：
  * **输入**：`l1 = [], l2 = [0]`
  * **输出**：`[0]`

* **提示**：
  * 两个链表的节点数目范围是 `[0, 50]`
  * `-100 <= Node.val <= 100`
  * `l1` 和 `l2` 均按 **非递减顺序** 排列

## 解题思路与解析

1. **核心思想**：迭代法（双指针法）。通常使用迭代法更为直观且节省栈空间。
2. **具体步骤**：
   * 创建一个虚拟头节点（Dummy Head）`dummy`，用来简化边界条件的处理（避免处理头节点为空的繁琐逻辑），并用一个指针 `current` 指向当前合并后链表的末尾。
   * 使用两个指针 `p1` 和 `p2` 分别遍历 `l1` 和 `l2`。
   * 比较 `p1.val` 和 `p2.val` 的大小：
     * 如果 `p1.val <= p2.val`，将 `p1` 接到 `current` 后面，然后 `p1` 向后移动一位。
     * 否则，将 `p2` 接到 `current` 后面，然后 `p2` 向后移动一位。
     * 每次操作后，`current` 指针也向后移动一位。
   * 当其中一个链表遍历完后，只需将另一个未遍历完的链表直接接在 `current` 的后面即可。
   * 返回 `dummy.next` 作为合并后的链表头节点。

## 答案代码 (Python)

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def mergeTwoLists(self, list1: ListNode, list2: ListNode) -> ListNode:
        # 创建虚拟头节点
        dummy = ListNode(-1)
        current = dummy
        
        p1 = list1
        p2 = list2
        
        # 遍历两个链表，直到其中一个为空
        while p1 and p2:
            if p1.val <= p2.val:
                current.next = p1
                p1 = p1.next
            else:
                current.next = p2
                p2 = p2.next
            current = current.next
            
        # 拼接剩余未遍历完的链表
        if p1:
            current.next = p1
        if p2:
            current.next = p2
            
        return dummy.next
```

复杂度分析：
- **时间复杂度**：O(n+m)，其中 n 和 m 分别为两个链表的长度。因为每次循环都会将 `p1` 或 `p2` 向后移动一位，最多循环 $n+m$ 次。
- **空间复杂度**：O(1)，只需要常数级别的额外指针空间。

在这道题中使用**虚拟头节点（Dummy Head）**，主要是为了**简化链表操作的边界条件**，避免处理“空链表”时的繁琐逻辑。

具体原因可以从以下几个方面来理解：

1. **避免对“新链表头部”进行单独的特殊判断**
   * **如果没有 Dummy**：
     当我们开始合并时，新链表的头节点（`head`）还不确定是来自 `l1` 还是 `l2`。我们必须写一段额外的代码来初始化第一个节点：
     ```python
     if l1.val <= l2.val:
         head = l1
         l1 = l1.next
     else:
         head = l2
         l2 = l2.next
     current = head  # 之后才能开始用 current 往下接
     ```
     而且还要时刻担心 `l1` 或 `l2` 一开始就是空链表（`None`）的情况，这会让代码充斥着各种 `if-else`。
   * **如果使用了 Dummy**：
     我们可以先创建一个值为 `-1`（或者任意值）的临时节点 `dummy`，让 `current` 指向它。
     ```python
     dummy = ListNode(-1)
     current = dummy
     ```
     此时，无论后面的节点怎么接，`current.next = ...` 永远都有地方可挂。最后只需要返回 `dummy.next` 即可，**完全不需要关心最终的头节点究竟是 `l1` 还是 `l2`**。

2. **统一操作逻辑，让代码更整洁**
   有了 `dummy` 之后，整个 `while` 循环里的逻辑变得完全一致：
   * 比较大小
   * `current.next` 指向较小的那个节点
   * `current` 向后移动
   
   如果没有 `dummy`，在处理第一个节点和后续节点时，逻辑会分裂成两套代码。

3. **安全处理空链表的情况**
   如果输入的 `l1` 或 `l2` 本身就是空链表 `[]`：
   * 如果没有 `dummy`，初始化 `head` 时就会直接报错（因为尝试访问空指针的 `.val`）。
   * 如果有了 `dummy`，`while p1 and p2` 循环直接跳过，最后直接执行 `current.next = p1 or p2`（或者代码里的 `if p1: current.next = p1` 等），完美兼容空链表的边界情况。

> **总结**：`dummy` 就像是一个“锚点”或“哨兵”，它让我们可以放心地把后续所有的操作都当成常规的链表拼接来处理，极大减少了边界判断的负担。


# LeetCode 21（合并两个有序链表）与 LeetCode 88（合并两个有序数组）的异同对比

老铁！刚刚我们盘完了这两道题。它们堪称算法面试里的**“绝代双骄”**：表面上看都在做同一件事（把两个有序序列合二为一），但由于底层**数据结构（链表 vs 数组）**完全不同，导致它们的解题思路有着**本质的对立**！

整套高频考点对比已经为你精心整理成纯净的 Markdown 格式，可直接一键复制到你的笔记中：👇

## 🥊 一、 核心维度终极对决表

| 维度对比 | LeetCode 21. 合并两个有序链表 | LeetCode 88. 合并两个有序数组 |
| :--- | :--- | :--- |
| **数据载体** | **链表 (Linked List)** | **数组 (Array)** |
| **物理内存特点** | 节点散落各处，靠指针（`next`）手拉手串联。 | 内存空间必须**连续紧挨着**。 |
| **空间痛点** | 无法随机访问，不能直接通过下标修改。 | `nums1` 前面装数据，后面**预留了巨大的空位（全是 0）**。 |
| **指针移动方向** | **从前往后（正向双指针）** | **从后往前（逆向双指针）** |
| **核心解题大招** | 虚拟头节点（Dummy） + 正向比对串链条 | 逆向双指针 + 利用末尾大空位倒着塞 |

## 🔍 二、 核心异同深度剖析

### 1. 相同点（它们的底层共性）
* **目标一致**：都是将两个已经按升序排好序的序列，合并成一个最终依然保持升序的完整序列。
* **双指针流派**：都离不开**双指针（Two Pointers）**的协同扫描，通过不断比对当前元素的大小来决定谁先“入驻”最终结果。
* **线性极速**：两道题的时间复杂度都达到了完美的 $\mathcal{O}(N + M)$ 线性效率。

### 2. 不同点（由于数据结构不同导致的战术对立）

* **第 21 题（链表）为什么必须“从前往后”？**
  * 链表的节点本来就散落在内存里，新生成的结果链表可以通过虚拟头节点（Dummy）从左到右一步步“凭空串起来”。
  * 因为不需要在原地覆盖旧数据，所以正向遍历、谁小挂谁，顺理成章。

* **第 88 题（数组）为什么必须“从后往前（偷家）”？**
  * 数组的内存是**紧密相连的**。`nums1` 为了实现原地修改（In-place），后面提前留好了 `n` 个大空位（全是 `0`）。
  * 如果你从前往后比大小、把 `nums2` 的大数硬塞到前面，`nums1` 原本右边的有效数字就会直接被**覆盖湮灭**！
  * 所以我们必须把指针按在两边有效数据的末尾，**谁大就往 `nums1` 右侧的大空位倒着填**，这样既不占用额外空间，又绝不会伤害左边还没比拼的数据。

## 💡 三、 核心口诀总结

* **链表合并（第 21 题）**：**“正向双指针 + 哑节点”**。从前往后，谁小串谁。
* **数组合并（第 88 题）**：**“逆向双指针 + 填大空位”**。从后往前，谁大往右边塞。
