# LeetCode 141. 环形链表 (Linked List Cycle)

## 1. 题目描述

给你一个链表的头节点 `head` ，判断链表中是否有环。

如果链表中存在环，则返回 `true` 。 否则，返回 `false` 。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（索引从 0 开始）。**注意：`pos` 不作为参数进行传递**。仅仅是为了标识链表的实际情况。

如果链表中存在环，则返回 `true` 。 否则，返回 `false` 。

### 示例 1
* **输入：** `head = [3,2,0,-4], pos = 1`
* **输出：** `true`
* **解释：** 链表中有一个环，其尾部连接到第二个节点。

### 示例 2
* **输入：** `head = [1,2], pos = 0`
* **输出：** `true`
* **解释：** 链表中有一个环，其尾部连接到第一个节点。

### 示例 3
* **输入：** `head = [1], pos = -1`
* **输出：** `false`
* **解释：** 链表中没有环。

### 提示
* 链表中节点的数目范围是 `[0, 10^4]`
* `-10^5 <= Node.val <= 10^5`
* `pos` 为 `-1` 或者链表中的一个 **有效索引** 。

## 2. 解题思路

解决这道题最经典且高效的方法是**快慢指针法**（也称龟兔赛跑算法 / Floyd判圈算法）。

### 方法：快慢指针
1. **定义两个指针**：`slow`（慢指针）和 `fast`（快指针），初始时它们都指向链表的头节点 `head`。
2. **移动规则**：
   * 慢指针 `slow` 每次向前移动一步 (`slow = slow.next`)。
   * 快指针 `fast` 每次向前移动两步 (`fast = fast.next.next`)。
3. **判断过程**：
   * 如果链表中**没有环**，快指针会先到达链表的末尾（即 `fast` 或 `fast.next` 为 `null`），此时循环结束，返回 `false`。
   * 如果链表中**有环**，快指针会在环中循环，而慢指针也会进入环。因为快指针的速度比慢指针快，所以在进入环后，快指针最终一定会“追上”慢指针（即 `slow == fast`），此时说明有环，返回 `true`。

### 复杂度分析
* **时间复杂度**：$O(N)$，其中 $N$ 是链表中的节点数。当链表中没有环时，快指针走完链表需要线性时间；当链表中有环时，最坏情况下快指针追赶慢指针也只需要在环内走完一圈。
* **空间复杂度**：$O(1)$，只需要常数级别的额外空间来存储两个指针。

## 3. 代码实现

### Python 3
```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None

class Solution:
    def hasCycle(self, head: ListNode) -> bool:
        if not head or not head.next:
            return False
        
        slow = head
        fast = head
        
        while fast and fast.next:
            slow = slow.next          # 慢指针走一步
            fast = fast.next.next     # 快指针走两步
            
            if slow == fast:          # 相遇则说明有环
                return True
                
        return False                  # 快指针到达末尾，无环

```

## 常见疑问解答

* **这道题需要使用虚拟头节点（Dummy Head）吗？**
  * **不需要。** 虚拟头节点通常用于需要**修改链表结构**（如插入、删除、翻转）的场景，用来简化头节点边界处理。而本题是一道**只读判断**题目，只需遍历和比较指针，原链表结构完全不会被改变，因此几个简单的边界 `if` 判断就足够了。
 
* **时间复杂度：** $O(N)$
  其中 $N$ 是链表的节点数。当链表无环时，快指针遍历完整个链表，耗时 $O(N)$；当链表有环时，快慢指针在环内追赶的最大步数也与环的长度成正比，因此总体时间复杂度仍然是线性级别。
* **空间复杂度：** $O(1)$
  整个算法运行过程中，只额外创建了 `slow` 和 `fast` 两个指针变量，它们占用的是常数级别的固定内存空间，不随链表长度 $N$ 的增长而增长。

把代码里的 `slow == fast` 改成 `slow is fast` 是完全可以的，而且在 Python 中更加推荐！

### 为什么 `is` 完全可以，甚至更好？

1. **`is` 比较的是内存地址（对象身份）**：
   在链表中，每一个节点（`ListNode`）都是堆内存中的一个独立对象。我们判断快慢指针是否相遇，本质上是想看 **`slow` 和 `fast` 是不是指向了内存中的同一个节点对象**。`is` 正是用来检查两个变量是否指向同一个内存地址的。
2. **`==` 比较的是值**：
   在 Python 中，`==` 默认会去调用对象的 `__eq__` 方法来比较它们的值（`val` 和 `next`）。虽然如果你没有自定义 `__eq__`, Python 默认也会退化为比较内存地址，但 `==` 在语义上不够精准。
3. **性能微调**：
   `is` 是 Python 的底层运算符（直接比较指针地址），它的执行速度比 `==` 略快一点点。

我们可以用一个生活中的生动比喻来理解：

### 💡 通俗比喻：双胞胎与身份证

* **内存地址（对象身份，`is`）**：相当于**身份证号**或**本人**。
  * 世界上有两个长得一模一样的双胞胎，他们穿一样的衣服，名字也一样。如果用 `==`（比值）去看，他们“相等”。但如果你问“这是同一个人吗？”，答案是“不是”——因为他们拥有两张不同的身份证号，住在不同的地方。
* **值（对象内容，`==`）**：相当于**长相、身高、穿的衣服**。
  * 只要两个独立的对象内部的数据长得一模一样，`==` 就会返回 `True`。

### 💻 在代码中的具体区别

#### 1. 内存地址（`is` / `id()`）
内存地址是对象在计算机内存（RAM）中的实际物理存储位置。你可以用内置的 `id()` 函数来查看它。

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)  # True （因为它们里面的数字一模一样）
print(a is b)  # False！（因为它们是内存中两个独立创建的列表对象，住在不同的房间）
print(a is c)  # True！（因为 c 直接指向了 a 所在的房间）

print(id(a))  # 例如输出: 140123456789
print(id(b))  # 例如输出: 140123457123 (地址不同)
print(id(c))  # 例如输出: 140123456789 (地址和 a 相同)
```

# LeetCode 141. 环形链表 — 经典 Follow-up 汇总

## 1. Follow-up 1：环形链表 II (LeetCode 142) —— 寻找入环的第一个节点

### 题目描述
给定一个链表的头节点 `head` ，返回链表开始入环的第一个节点。 如果链表无环，则返回 `null`。

### 核心解法与数学推导
1. **第一阶段（判断是否有环并找到相遇点）**：
   * 使用快慢指针 `slow` 和 `fast`，`slow` 每次走 1 步，`fast` 每次走 2 步。
   * 若它们相遇，说明有环；若 `fast` 走到头（`null`），说明无环。
2. **第二阶段（寻找入环点）**：
   * 当快慢指针在环中相遇时，**让 `slow` 重新回到链表头部 `head`**。
   * `fast` 保持在相遇点不动。
   * 随后，`slow` 和 `fast` **同时每次向前移动一步**。
   * 它们再次相遇的那个节点，就是**环的起始入环节点**。

### 数学原理简析
* 设头节点到入环点的距离为 $a$，入环点到相遇点的距离为 $b$，环中剩下部分的距离为 $c$。
* 当快慢指针相遇时：
  * 慢指针走过的距离：$a + b$
  * 快指针走过的距离：$a + n(b + c) + b$ （$n$ 为快指针在环内转的圈数）
* 因为快指针速度是慢指针的两倍，所以：$2(a + b) = a + n(b + c) + b$
* 化简可得：$a = c + (n - 1)(b + c)$
* 这意味着：从头节点出发的指针（走 $a$ 步）与从相遇点出发的指针（走 $c$ 步加上若干整圈环），最终会在入环点相遇。

# LeetCode 142. 环形链表 II (Linked List Cycle II)

## 1. 题目描述

给定一个链表的头节点  `head` ，返回链表开始入环的第一个节点。 如果链表无环，则返回 `null`。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（索引从 0 开始）。**注意：`pos` 不作为参数进行传递**。仅仅是为了标识链表的实际情况。

**不允许修改** 链表。

### 示例 1
* **输入：** `head = [3,2,0,-4], pos = 1`
* **输出：** 返回索引为 1 的节点（即值为 `2` 的节点）
* **解释：** 链表中有一个环，其尾部连接到第二个节点。

### 示例 2
* **输入：** `head = [1,2], pos = 0`
* **输出：** 返回索引为 0 的节点（即值为 `1` 的节点）
* **解释：** 链表中有一个环，其尾部连接到第一个节点。

### 示例 3
* **输入：** `head = [1], pos = -1`
* **输出：** `null`
* **解释：** 链表中没有环。

### 提示
* 链表中节点的数目范围在 `[0, 10^4]` 内
* `-10^5 <= Node.val <= 10^5`
* `pos` 的值为 `-1` 或者链表中的一个有效索引

## 2. 解题思路

这道题是 LeetCode 141 的升级版。最经典且满足 $O(1)$ 空间复杂度的解法依然是**快慢指针法（Floyd 判圈算法）**，但需要结合精妙的**数学推导**。

### 核心步骤
1. **第一阶段：判断是否有环并寻找相遇点**
   * 定义 `slow`（慢指针）和 `fast`（快指针），初始时都指向 `head`。
   * `slow` 每次走 1 步，`fast` 每次走 2 步。
   * 如果 `fast` 走到 `null`，说明链表无环，直接返回 `null`。
   * 如果 `slow == fast`，说明快慢指针在环内相遇，此时跳出循环，进入第二阶段。
2. **第二阶段：寻找入环的第一个节点**
   * 当它们在环中相遇时，**让 `slow` 重新回到链表头部 `head`**。
   * `fast` 保持在当前的相遇点不动。
   * 随后，`slow` 和 `fast` **同时每次向前移动一步**。
   * 它们再次相遇的那个节点，就是**环的起始入环节点**。

## 3. 数学原理推导

* 设头节点到入环点的距离为 $a$。
* 设入环点到快慢指针相遇点的距离为 $b$。
* 设相遇点继续顺着环走到入环点的距离为 $c$（因此整个环的周长等于 $b + c$）。

当快慢指针第一次相遇时：
* 慢指针走过的总距离：$a + b$
* 快指针走过的总距离：$a + n(b + c) + b$ （其中 $n$ 为快指针在环内转的圈数，$n \ge 1$）

因为快指针的速度是慢指针的两倍，所以快指针走过的距离等于慢指针的两倍：
$$2(a + b) = a + n(b + c) + b$$

化简该方程：
$$2a + 2b = a + b + n(b + c)$$
$$a + b = n(b + c)$$
$$a = n(b + c) - b$$
$$a = (n - 1)(b + c) + c$$

### 结论含义：
* $a$ 是从头节点走到入环点的距离。
* $(n - 1)(b + c) + c$ 是从相遇点出发，走完 $(n-1)$ 圈环之后，再走 $c$ 步到达入环点的距离。
* 这意味着：**从 `head` 出发一个指针，从相遇点出发一个指针，以相同的速度前进，它们必然会在入环点相遇。**

## 4. 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是链表中的节点数。不论是否有环，快慢指针遍历链表的时间都是线性的。
* **空间复杂度**：$O(1)$，只使用了两个固定指针变量，占用常数级空间。

## 5. 代码实现

### Python 3
```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None

class Solution:
    def detectCycle(self, head: ListNode) -> ListNode:
        slow = head
        fast = head
        
        # 第一阶段：寻找相遇点
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            
            if slow == fast:  # 相遇
                # 第二阶段：slow 回到头部，fast 原地不动，同速前进
                slow = head
                while slow != fast:
                    slow = slow.next
                    fast = fast.next
                return slow  # 再次相遇点即为入环第一个节点
                
        return None  # fast 遇到 null 说明无环
```

## 2. Follow-up 2：如何计算环的长度？

### 核心解法
1. 先利用快慢指针法找到链表中的一个**相遇节点**（任意一个相遇点即可）。
2. 从这个相遇节点出发，固定一个指针，让另一个指针开始沿着 `next` 指针继续在环中遍历，并用一个计数器 `count` 记录步数。
3. 当遍历的指针**重新回到**起始的相遇节点时，停止计数。
4. 此时的 `count` 值就是**环的长度**。

# 算法扩展：如何计算链表中环的长度？

## 1. 题目与背景描述
在通过快慢指针判断链表存在环（LeetCode 141）或者找到入环节点（LeetCode 142）之后，有时面试官会进一步追问：**如果链表有环，如何计算这个环的长度（即环中有多少个节点）？**

## 2. 解题思路

计算环的长度的核心逻辑非常直观，建立在快慢指针相遇的基础之上：

1. **第一步（定位相遇点）**：
   * 使用标准的快慢指针（`slow` 和 `fast`）遍历链表。当它们在环中相遇时，停在当前的**相遇节点**（Meeting Point）上。
2. **第二步（环内计数环游）**：
   * 从这个相遇节点出发，固定一个指针，让另一个指针顺着 `next` 指针继续在环中遍历。
   * 同时使用一个计数器 `count`（初始值为 1）。
   * 当遍历的指针**重新回到**那个相遇节点时，停止遍历。
   * 此时计数器 `count` 记录的步数，就是**环的长度**。

## 3. 代码实现

### Python 3
```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None

class Solution:
    def getCycleLength(self, head: ListNode) -> int:
        slow = head
        fast = head
        has_cycle = False
        
        # 1. 快慢指针寻找相遇点
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:  # 推荐使用 is 比较对象身份
                has_cycle = True
                break
                
        # 如果没有环，长度为 0
        if not has_cycle:
            return 0
            
        # 2. 从相遇点出发，绕环一圈统计长度
        current = slow.next
        length = 1
        
        while current is not slow:
            length += 1
            current = current.next
            
        return length
```

### 复杂度分析

* **时间复杂度**：$O(N)$。其中寻找相遇点需要 $O(N)$，在环中转一圈统计长度需要 $O(K)$（$K$ 为环的长度，且 $K \le N$），总体时间复杂度仍为线性级别。
* **空间复杂度**：$O(1)$。只使用了几个固定的指针和计数变量，不随链表规模增加而增加。

## 3. Follow-up 3：复杂场景 —— 有环链表与无环链表的相交问题

### 核心解法（分步降维）
如果链表可能带环，并且涉及两个链表相交（类似 LeetCode 160 的升级版）：
1. **先判断各自是否有环**：分别对两个链表使用快慢指针，确定各自的入环点（如果无环则返回 `null`）。
2. **分类讨论相交情况**：
   * **情境 A（两个链表均无环）**：转化为经典的“相交链表”问题（双指针法对齐长度遍历）。
   * **情境 B（一个有环，一个无环）**：它们**不可能相交**（因为无环链表的末尾是 `null`，无法连接到一个无限循环的环中），直接返回 `null`。
   * **情境 C（两个链表都有环）**：
     * 如果它们的入环点是同一个，可以截断环或者把问题转化为求环前普通链表的交点。
     * 如果入环点不同但有交点，沿着其中一个链表的环转一圈能遇到另一个链表的入环点。

# 算法扩展：有环链表与无环链表的相交问题（LeetCode 160 进阶版）

## 1. 题目与背景描述
在掌握了单链表判断环（LeetCode 141）和寻找入环节点（LeetCode 142）之后，面试中可能会遇到更复杂的综合题：**给定两个可能带环的单链表，编写代码找到它们相交的起始节点。如果两个链表没有交点，则返回 `null`。**

## 2. 解题思路（分步降维）

解决这类复杂相交问题，最清晰的策略是**“分步降维”**——先分别检测两个链表各自的状态，然后将各种组合情况分类讨论。

### 核心步骤
1. **第一步：检测各自是否有环**
   * 分别对链表 `headA` 和 `headB` 使用快慢指针（或 LeetCode 142 的逻辑），分别求出它们的**入环节点** `nodeA` 和 `nodeB`。
   * 若链表无环，其入环节点为 `null`。

2. **第二步：分类讨论相交情况**
   根据两个链表各自是否有环、以及入环节点的位置，主要分为以下几种情境：

   * **情境 A：两个链表均无环**
     * **处理方式**：直接退化为经典的 **LeetCode 160（相交链表）** 问题。
     * **解法**：使用双指针法（指针 `pA` 遍历完 A 后转去遍历 B，指针 `pB` 遍历完 B 后转去遍历 A，若相交会在交点相遇；若不相交最后会同时到达 `null`）。

   * **情境 B：一个有环，另一个无环**
     * **处理方式**：**绝对不可能相交**，直接返回 `null`。
     * **原因**：无环链表的末尾终点是 `null`（终结指针），而有环链表内部是一个无限循环的闭环。一个有限且终结的结构不可能连到一个无限循环的结构上。

   * **情境 C：两个链表都有环**
     * 此情境下又细分为两种子情况：
       1. **入环节点相同 (`nodeA == nodeB`)**：
          * 说明两个链表在进入环之前就已经相交，或者在环的入口处相交。
          * **解法**：可以把入环节点当作链表的虚拟“终点”（暂时将 `nodeA.next` 设为 `null` 或限制遍历边界），然后将问题转化为求普通无环链表的交点，最后再恢复原链表结构即可。
       2. **入环节点不同 (`nodeA != nodeB`)**：
          * 说明它们共用同一个环，但进入环的位置不同。
          * **解法**：从 `nodeA` 出发，沿着环转一圈。如果在回到 `nodeA` 之前遇到了 `nodeB`，说明它们相交，此时返回 `nodeA`（或 `nodeB` 均可，具体取决于题目要求的返回哪个链表上的节点）；如果转了一圈也没遇到 `nodeB`，说明它们虽然都有环但各不相交，返回 `null`。

## 3. 代码实现 (Python 3)

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None

class Solution:
    def getIntersectionNodeInCycle(self, headA: ListNode, headB: ListNode) -> ListNode:
        if not headA or not headB:
            return None
        
        # 1. 获取两个链表的入环节点
        nodeA = self.getCycleNode(headA)
        nodeB = self.getCycleNode(headB)
        
        # 情境 B：一个有环，一个无环，不可能相交
        if (nodeA is None) ^ (nodeB is None):
            return None
            
        # 情境 A：两个均无环
        if nodeA is None and nodeB is None:
            return self.getIntersectionNoCycle(headA, headB)
            
        # 情境 C：两个都有环
        if nodeA is nodeB:
            # 入环点相同，把入环点当做终点，求普通相交节点
            return self.getIntersectionNoCycle(headA, headB, tail=nodeA)
        else:
            # 入环点不同，从 nodeA 出发转一圈看能否遇到 nodeB
            curr = nodeA.next
            while curr is not nodeA:
                if curr is nodeB:
                    return nodeB  # 或者返回 nodeA，通常返回其中一个交点
                curr = curr.next
            return None

    # 辅助函数 1：获取入环节点（LeetCode 142）
    def getCycleNode(self, head: ListNode) -> ListNode:
        slow = head
        fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:
                slow = head
                while slow is not fast:
                    slow = slow.next
                    fast = fast.next
                return slow
        return None

    # 辅助函数 2：求无环链表交点（可指定虚拟终点 tail，用于有环链表降维）
    def getIntersectionNoCycle(self, headA: ListNode, headB: ListNode, tail: ListNode = None) -> ListNode:
        pA, pB = headA, headB
        while pA is not pB:
            pA = pA.next if pA is not tail else headB
            pB = pB.next if pB is not tail else headA
        return pA
```

### 复杂度分析

* **时间复杂度**：$O(N + M)$，其中 $N$ 和 $M$ 分别为两个链表的长度。寻找入环点、对齐遍历或环内遍历都只需要线性的时间开销。
* **空间复杂度**：$O(1)$。全程只使用了常数级别的指针变量，没有借助额外的哈希表或集合。

## 4. Follow-up 4：空间复杂度权衡与非指针解法

虽然快慢指针已经达到了 $O(1)$ 空间，但在面试或工程发散中，常会被问到其他替代方案：

### 方案 A：哈希表法 (HashSet)
* **做法**：遍历链表时，将每个访问过的节点指针存入 `HashSet`。若遇到已经存在于 Set 中的节点，说明有环。
* **复杂度**：时间 $O(N)$，**空间 $O(N)$**。
* **优缺点**：直观易写，但违背了 $O(1)$ 空间限制，通常仅作为暴力对比解法提出。

### 代码实现 (Python 3)
```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None

class Solution:
    def hasCycleHashSet(self, head: ListNode) -> bool:
        visited = set()
        curr = head
        
        while curr:
            if curr in visited:
                return True
            visited.add(curr)
            curr = curr.next
            
        return False
```

优缺点评估优点：逻辑极其直观、容易想到，代码编写零失误，不容易陷入复杂的指针边界陷阱。缺点：违背了面试官对环形链表题目通常要求的 $O(1)$ 空间限制。适用场景：面试时作为方案对比的切入点（先说哈希表法，再主动优化成快慢指针法），或者在空间非常充裕且追求极简开发的业务临时脚本中。


### 方案 B：修改节点值法（破坏性解法）
* **做法**：在遍历时，把经过的节点的值修改为一个特殊标记（如 `null` 或一个不可能出现的极端值）。如果在遍历中遇到某个节点的 `val` 已经被修改过，说明有环。
* **复杂度**：时间 $O(N)$，**空间 $O(1)$**。
* **优缺点**：不占用额外空间，但**会破坏原链表的结构**。在实际工程或面试中通常是**大忌**（除非面试官明确允许修改原数据）。

### 代码实现 (Python 3)
```python
class Solution:
    def hasCycleDestructive(self, head: ListNode) -> bool:
        curr = head
        # 假设题目数值范围外的一个特殊标记
        VISITED_MARKER = "VISITED"
        
        while curr:
            if curr.val == VISITED_MARKER:
                return True
            curr.val = VISITED_MARKER
            curr = curr.next
            
        return False
```

### 优缺点评估
* **优点**：空间复杂度为 $O(1)$，不需要额外分配内存空间。
* **缺点**：**严重破坏了原链表的结构与数据！** 遍历完后原链表的所有节点值都被篡改了。
* **适用场景**：在实际工程中通常是绝对的大忌（会导致其他依赖该数据的模块崩溃）。但在某些底层系统编程、单线程垃圾回收标记、或者面试官明确提示“允许修改节点内容”时，可以作为一种剑走偏锋的极客解法提出。

### 4. 方案对比总结

| 方案 | 时间复杂度 | 空间复杂度 | 对原数据影响 | 面试推荐度 |
| :--- | :--- | :--- | :--- | :--- |
| **快慢指针法 (Floyd)** | $O(N)$ | $O(1)$ | **无损**（最优解） | ⭐⭐⭐⭐⭐（标准答案） |
| **哈希表法 (HashSet)** | $O(N)$ | $O(N)$ | **无损** | ⭐⭐⭐（适合作为引子） |
| **修改节点值法** | $O(N)$ | $O(1)$ | **破坏性修改** | ⭐（仅用于极端的发散讨论） |

# LeetCode 767. 重构字符串 (Reorganize String)

## 1. 题目描述

给定一个字符串 `s` ，检查是否能重新排布其中的字母，使得相邻的两个字母不同。

如果可行，输出任意可能的重构后的字符串。如果不可行，返回空字符串 `""`。

### 示例 1
* **输入：** `s = "aab"`
* **输出：** `"aba"`

### 示例 2
* **输入：** `s = "aaab"`
* **输出：** `""`

### 提示
* `1 <= s.length <= 500`
* `s` 只包含小写英文字母

## 2. 核心思路与前置校验

在动手写具体解法之前，有一个非常关键的**数学性质（频次上限判定）**可以帮我们直接拦截掉无解的情况：
* 设字符串总长度为 $n$，某个字符出现的最大频次为 $\text{maxFreq}$。
* 如果某一个字符实在太多了，即使我们把它“隔开”放到极致，也无法避免相邻：
  $$\text{maxFreq} > \frac{n + 1}{2}$$
* **结论**：只要满足上式，就**绝对无解**，直接返回 `""`（例如 `s = "aaab"`，长度 $n=4$，最大频次 `maxFreq = 3`，而 $\frac{4+1}{2} = 2.5$，因为 $3 > 2.5$，直接判错返回 `""`）。

当通过校验后，我们来看两种主流的高效解法。

## 3. 解法一：贪心 + 最大堆（优先队列）

### 核心思路
1. 统计每个字符出现的频次。
2. 将所有字符及其频次放入一个**最大堆**中（Python 中用负数模拟最大堆，频次最高的排在堆顶）。
3. 每次贪心地从堆中取出当前**剩余频次最高**的两个不同字符进行拼接（确保相邻不同），然后将它们剩余的频次减 1 后重新压回堆中。
4. 为了防止同一个字符连续使用，采用“延迟入堆（冷却机制）”或每次安全弹出两个字符的策略。

### 代码实现 (Python 3)
```python
from collections import Counter
import heapq

class Solution:
    def reorganizeString(self, s: str) -> str:
        count = Counter(s)
        n = len(s)
        
        # 前置校验：最大频次是否超过极限阈值
        max_freq = max(count.values())
        if max_freq > (n + 1) // 2:
            return ""
            
        # 构建最大堆（Python 中用负数表示频率）
        max_heap = [(-freq, char) for char, freq in count.items()]
        heapq.heapify(max_heap)
        
        res = []
        # 用于记录上一次使用过的字符及其剩余频次（冷却机制）
        prev_freq, prev_char = 0, ""
        
        while max_heap:
            freq, char = heapq.heappop(max_heap)
            res.append(char)
            
            # 如果上一步有字符还在冷却中（即频次还没减到0），现在可以放回堆里了
            if prev_freq < 0:
                heapq.heappush(max_heap, (prev_freq, prev_char))
                
            # 更新当前字符进入冷却
            prev_freq = freq + 1
            prev_char = char
            
        return "".join(res)
```

### 4. 解法二：奇偶位交替放置法（最优解）

#### 核心思路
这是更优雅、性能更高的数学解法：
1. 同样先统计频次，并按频次从高到低对字符进行排序。
2. 频次最高的字符必须优先被放置，为了保证不相邻，我们可以**优先填满所有的偶数位**（索引 `0, 2, 4, ...`），当偶数位填满后，再回过头去**填奇数位**（索引 `1, 3, 5, ...`）。
3. 由于满足 $\text{maxFreq} \le \frac{n + 1}{2}$ 的前提，高频字符绝对不会在奇偶交替中发生冲突。

#### 代码实现 (Python 3)
```python
from collections import Counter

class Solution:
    def reorganizeString(self, s: str) -> str:
        count = Counter(s)
        n = len(s)
        
        # 前置校验
        max_freq = max(count.values())
        if max_freq > (n + 1) // 2:
            return ""
            
        # 按频次降序排序字符
        sorted_chars = sorted(count.keys(), key=lambda x: -count[x])
        
        res = [''] * n
        idx = 0
        
        for char in sorted_chars:
            freq = count[char]
            for _ in range(freq):
                res[idx] = char
                idx += 2
                # 当偶数位填满（超出或等于 n）时，重置指针到奇数位起点 1
                if idx >= n:
                    idx = 1
                    
        return "".join(res)
```

在这段代码中，`idx`（index 的缩写）是一个**指针/索引变量**，它的核心作用是：**指示当前要把字符填入结果数组 `res` 的哪一个具体位置（下标）**。

为了让你更直观地理解它的妙用，我们可以把它拆解为以下三个关键点：

### 1. 为什么要用 `idx`？
我们要把原本乱序、带有不同频次的字符重新排列成一个“相邻字符不重复”的新字符串。
`res = [''] * n` 是一个长度为 $n$ 的空槽位数组。`idx` 就是我们在往这些槽位里填字时的**光标**。

### 2. `idx` 是怎么移动的？（步长为 2）
代码中有关键的一句：`idx += 2`。
* **为什么每次要 `+2`？**
  因为我们要保证**相邻的字符绝对不能相同**。如果我们把一个字符填在索引 `0`，下一个同类字符（或紧接着的字符）必须隔开至少一个位置，填在索引 `2`、`4`、`6`……以此类推。这样就天然地用物理位置把相同的字符隔开了。

### 3. `idx` 什么时候会“折返”？（奇偶交替的精髓）
代码中还有一句关键判断：
```python
if idx >= n:
    idx = 1
```

* **前半程（填偶数位）**：
  `idx` 从 `0` 开始，每次 `+2`（走 `0 -> 2 -> 4 -> 6...`），把所有**偶数位**填满。
* **触发折返**：
  当 `idx` 走到头超出了字符串总长度 $n$（比如 $n=5$，`idx` 变成了 `6`）时，说明**所有的偶数位已经全部被高频字符占满了**！
  此时，代码立刻把 `idx` 重置为 `1`。
* **后半程（填奇数位）**：
  `idx` 从 `1` 开始，继续每次 `+2`（走 `1 -> 3 -> 5...`），去把剩下的**奇数位**填满。

### 🎯 总结一句话
`idx` 就像一个**智能跳空格的笔尖**：先在偶数格（`0, 2, 4...`）里跳着写，偶数格写完了，笔尖自动跳回第一个奇数格（`1`），继续在奇数格（`1, 3, 5...`）里跳着写，直到把所有的格子完美填满且互不打扰。


### 5. 两种解法对比

| 维度 | 解法一：贪心 + 最大堆 | 解法二：奇偶位交替放置法 |
| :--- | :--- | :--- |
| **核心思路** | 维护最大堆，每次动态取出当前剩余最多的字符交替拼接。 | 利用高频字符的数学性质，直接按规律“插空”填入偶数/奇数位。 |
| **时间复杂度** | $O(N \log K)$（$K$ 为字符集大小，常数 26） | **$O(N)$**（省去了堆维护的开销，效率更高） |
| **空间复杂度** | $O(K)$ 或 $O(N)$ | $O(N)$（需要构建结果数组） |
| **面试推荐度** | 符合直觉，适合考察通用贪心与数据结构（优先队列）的应用。 | **最优解**，代码更简洁、性能更极致，面试加分项。 |

### 复杂度分析

* **时间复杂度**：
  * **解法一**：$O(N \log K)$，其中 $N$ 是字符串长度，$K$ 是字符集大小（英文字母最多 26 个）。堆的操作规模受限于 $K$。
  * **解法二**：$O(N)$，只需进行频次统计、排序（$K \log K$）以及一次线性遍历填入数组，整体效率更高。
* **空间复杂度**：$O(N)$ 或 $O(K)$，用于存储频次哈希表、堆结构以及最终构造的结果数组空间。

# LeetCode 1405. 最长快乐字符串 (Longest Happy String)

## 1. 题目描述

如果字符串中不包含任何 `'aaa'`、`'bbb'` 或 `'ccc'` 这样的字符串作为子串，那么该字符串就是一个“**快乐字符串**”。

给你三个整数 `a`、`b` 和 `c`，它们分别代表字母 `'a'`、`'b'` 和 `'c'` 可以在快乐字符串中出现的次数。

返回 **任意** 最长的快乐字符串 `s`。如果不存在这样的快乐字符串，返回 `""`。

### 示例 1
* **输入：** `a = 1, b = 1, c = 7`
* **输出：** `"ccaccbcc"`
* **解释：** `"ccaccbcc"` 也是一个正确答案，但 `"ccbccacc"` 也是正确的。

### 示例 2
* **输入：** `a = 7, b = 1, c = 0`
* **输出：** `"aabaa"`
* **解释：** 字母 `'a'` 最多出现 7 次，`'b'` 最多出现 1 次。

### 提示
* `0 <= a, b, c <= 100`
* `a + b + c > 0`

## 2. 核心思路与解题策略

这道题是前面我们学的 **LeetCode 767（重构字符串）** 的亲兄弟/进阶版！
* 共同点：它们都要求**相邻字符不能相同**（这里限制更具体：**不能出现连续三个相同的字符**，即不能有 `"aaa"`, `"bbb"`, `"ccc"`）。
* 不同点：这里字符只有 `'a'`、`'b'`、`'c'` 三种，且数量是作为参数给出的。

### 贪心策略（每次都优先消耗最多的字符）
1. 我们希望字符串尽可能长，因此每次都应该**贪心地优先选择当前剩余数量最多的字符**放入结果中。
2. **冲突处理（防连续三个相同）**：
   * 如果结果字符串的最后两个字符已经是要放入的这个字符了（即会构成 `“xxx”` 的非法结构），我们就不能再放它了。
   * 此时退而求其次，选择**当前剩余数量第二多**的那个字符放入。
   * 如果连第二多的字符也没有，或者所有候选字符都无法安全放入，说明已经到了极限，循环结束。

## 3. 代码实现 (Python 3)

```python
class Solution:
    def longestDiverseString(self, a: int, b: int, c: int) -> str:
        # 将字符和对应的剩余数量打包放入列表中，方便按数量动态排序
        curr = [
            [a, 'a'],
            [b, 'b'],
            [c, 'c']
        ]
        
        res = []
        
        while True:
            # 每次循环前，把当前剩余数量从大到小排序（保证每次都拿最多的前两个）
            curr.sort(key=lambda x: x[0], reverse=True)
            
            # 标志位：记录本轮是否成功放入了字符
            added = False
            
            for i in range(3):
                count, char = curr[i]
                
                # 如果这种字符已经用完了，跳过
                if count <= 0:
                    continue
                    
                # 冲突检查：如果结果集最后两个字符都是当前字符，会导致出现 "xxx"
                if len(res) >= 2 and res[-1] == char and res[-2] == char:
                    continue  # 不合法，尝试换第二多的字符
                    
                # 校验通过，安全放入
                res.append(char)
                curr[i][0] -= 1  # 数量减 1
                added = True
                break  # 成功放入一个字符后，跳出 for 循环，重新排序再拿
                
            # 如果遍历了一整轮发现没有任何字符可以放（说明都被限制了或者用光了），跳出主循环
            if not added:
                break
                
        return "".join(res)
```

### 4. 详细 Dry Run（模拟演练）

我们以 **`a = 1, b = 1, c = 7`** 为例进行模拟：

* **初始状态**：`curr = [[7, 'c'], [1, 'a'], [1, 'b']]`（已按数量降序排序），`res = []`

#### 🔄 第 1 轮循环
* 排序后 `curr`：`[[7, 'c'], [1, 'a'], [1, 'b']]`
* 尝试第 1 个：`count = 7, char = 'c'`。`res` 为空，不冲突。
* **动作**：`res.append('c')` $\rightarrow$ `res = ['c']`，`c` 的数量变为 `6`。
* `curr` 更新为：`[[6, 'c'], [1, 'a'], [1, 'b']]`

#### 🔄 第 2 轮循环
* 尝试放 `'c'`：`res = ['c', 'c']`（数量变为 `5`）。
* 尝试放 `'c'` 时：`res` 最后两个是 `['c', 'c']`，如果再放 `'c'` 就会变成 `“ccc”` 冲突！**触发 `continue` 拦截**。
* 循环切换到第 2 个候选：`count = 1, char = 'a'`。不冲突。
* **动作**：`res.append('a')` $\rightarrow$ `res = ['c', 'c', 'a']`，`a` 的数量变为 `0`。

#### 🔄 持续进行...
* 接下来会交替消耗 `'c'` 和 `'b'`，直到 `'c'` 消耗完、`'b'` 消耗完。
* **最终拼接出来的结果如**：**`"ccaccbcc"`**（满足任意连续字符不超过 2 个）。

### 5. 复杂度分析

* **时间复杂度**：$O(A + B + C)$。其中 $A, B, C$ 分别是三个字符的初始数量。因为每次循环最多消耗一个字符，且每次排序只有 3 个元素（常数级时间 $O(1)$），所以总耗时与字符总数呈线性正比。
* **空间复杂度**：$O(A + B + C)$，用于存储最终输出的字符串结果数组。

### 为什么上面不用最大堆？

由于题目明确规定只有 3 种字符（`'a'`、`'b'`、`'c'`），候选元素的数量极少。
对一个长度恒定为 3 的数组进行排序的时间复杂度是 $O(1)$。因此，在 Python 中直接写 `curr.sort()` 非常轻量且直观。

但如果你想在面试中展示更通用、更标准的数据结构能力（特别是当字符种类不仅限于 3 种，而是 26 个字母时），**最大堆（Max-Heap）是更标准和普适的解法。**

### 🚀 最大堆（Max-Heap）解法代码实现

下面我为你提供真正的**最大堆解法**的 Markdown，它的思路和 **LeetCode 767 重构字符串** 的最大堆解法如出一辙：

### 最大堆 (Max-Heap) 解法

#### 核心思路
1. 将所有数量大于 0 的字符及其对应的数量放入一个最大堆中（Python 中通过存入负数实现最大堆，数量最多的在堆顶）。
2. 每次从堆顶弹出一个剩余数量最多的字符：
   * 如果该字符与当前结果 `res` 的最后两个字符相同（即将构成 `"xxx"` 冲突），说明我们暂时不能用它了。
   * 此时，我们需要再从堆中弹出**数量第二多**的字符，放入结果集。放完后，将这个第二多的字符剩余数量减一，如果还不为 0，则重新压回堆中。
   * 最后，别忘了把刚开始那个“被限制”的最多的字符也原封不动地重新压回堆中（等下次再用）。
3. 如果在发生冲突时，堆已经空了（没有第二多的字符可以救场了），说明无法继续构造，直接跳出循环。

#### 代码实现 (Python 3)
```python
import heapq

class Solution:
    def longestDiverseString(self, a: int, b: int, c: int) -> str:
        # 1. 初始化最大堆（只将数量大于 0 的字符入堆）
        # Python 中用元组 (-数量, 字符) 模拟最大堆
        max_heap = []
        if a > 0: heapq.heappush(max_heap, (-a, 'a'))
        if b > 0: heapq.heappush(max_heap, (-b, 'b'))
        if c > 0: heapq.heappush(max_heap, (-c, 'c'))
        
        res = []
        
        # 2. 贪心构造结果字符串
        while max_heap:
            # 弹出当前数量最多的字符
            count1, char1 = heapq.heappop(max_heap)
            
            # 冲突检查：如果最后两个字符与当前字符相同，会构成 "xxx"
            if len(res) >= 2 and res[-1] == char1 and res[-2] == char1:
                
                # 如果此时堆空了，说明没有其他字符可以打破僵局，只能提前结束
                if not max_heap:
                    break
                
                # 弹出数量第二多的字符救场
                count2, char2 = heapq.heappop(max_heap)
                res.append(char2)
                
                # 消耗掉一个后，如果还有剩余，重新压回堆中
                if count2 + 1 < 0:
                    heapq.heappush(max_heap, (count2 + 1, char2))
                    
                # 刚才那个被限制的最多字符 char1 原样压回去，等下轮再用
                heapq.heappush(max_heap, (count1, char1))
                
            else:
                # 不冲突，安全放入当前数量最多的字符
                res.append(char1)
                
                # 消耗掉一个后，如果还有剩余，重新压回堆中
                if count1 + 1 < 0:
                    heapq.heappush(max_heap, (count1 + 1, char1))
                    
        return "".join(res)
```

### 复杂度分析

* **时间复杂度**：$O(A + B + C)$。每次堆的 `pop` 和 `push` 操作的时间复杂度是对数级别，但由于最多只有 3 种字符，堆的大小最多为 3，堆操作时间可以视为常数 $O(1)$。总体循环执行次数与字符总数呈线性正比。
* **空间复杂度**：$O(1)$ 额外空间（堆的大小恒定为 3 以内），加上 $O(A + B + C)$ 的结果数组存放空间。

说这两道题（**LeetCode 767. 重构字符串** 和 **LeetCode 1405. 最长快乐字符串**）是“一样的解法”，主要是因为它们的**核心思想、底层逻辑以及贪心策略**完全一致。

我们可以从以下几个维度来看它们的相同之处：

### 1. 核心贪心策略完全相同
* **共同逻辑**：两道题的目标都是要重排字符，避免“不该相邻的字符挨在一起”。为了让字符串尽可能长（或成功重排），它们都采用了**“贪心法则”**——**每次都优先消耗当前剩余数量最多的字符**。
* **数据结构的选择**：因为都需要动态获取“当前最多”的元素，它们都可以完美地使用**最大堆（Max-Heap / 优先队列）**来解决。每次从堆顶取出最多的字符进行拼接。

### 2. 冲突处理（冷却机制）的思想一致
* **LeetCode 767** 的要求是：**相邻的两个字符不能相同**（即不能连续 2 个相同）。
  * 它的处理方式是：每次安全地取出一个最多的字符，把它加入结果后让它进入“冷却”（或者每次安全取出两个不同的字符交替拼接）。
* **LeetCode 1405** 的要求是：**不能出现连续三个相同的字符**（即不能有 `"aaa"`, `"bbb"`, `"ccc"`）。
  * 它的处理方式是：如果当前堆顶最多的字符和结果集的最后两个字符相同（会构成 `"xxx"` 冲突），我们就**退而求其次，弹出堆中数量第二多的字符**去救场。

### 3. 本质上的数学抽象
从算法模型的角度来看，它们都属于**“多元素频次受限的序列重构问题”**。
* 767 题是限制连续相同长度 $\ge 2$。
* 1405 题是限制连续相同长度 $\ge 3$。

正因为它们的解题骨架高度一致（都是通过最大堆维护频次、动态选择、处理冲突），所以它们在算法分类上被视为**同一类经典贪心题目**。掌握了其中一题的贪心与优先队列套路，另一题就能触类旁通。

---

最大堆（Max-Heap）的底层思路是高度相通的，但在**“具体冲突处理的细节”**上有所不同。

我们可以用一句话概括它们的异同：**骨架完全相同（都是用最大堆动态贪心拿最高频字符），但肌肉细节不同（应对限制冲突的策略不一样）。**

### 相同点：骨架与核心思想是一致的

在这两道题中，最大堆的核心作用完全一样：
1. **统一的数据结构**：都把字符和它们的剩余频次放入最大堆中，确保每次 `heappop` 拿出来的都是**当前剩余数量最多的字符**。
2. **贪心驱动**：不走复杂的全局回溯，只看眼前，每次都优先消耗最多的，从而最大化利用字符。

### 不同点：处理相邻冲突的“战术”不同

因为两道题的限制条件（LeetCode 767 是**不能连续 2 个相同**，LeetCode 1405 是**不能连续 3 个相同**），它们在使用最大堆时的应对策略有明显区别：

#### 1. LeetCode 767（重构字符串：严禁相邻 2 个相同）
* **策略**：**每次必须拿两个字符交替拼接（或使用延迟入堆/冷却机制）**。
* **为什么？** 如果你只拿一个最高频的字符，由于它占据了最大份额（$\text{maxFreq} \le \frac{n+1}{2}$），如果你紧接着再拿它自己，必然会和自己相邻。
* **堆操作方式**：每次从堆里弹出**两个**不同的字符（`char1` 和 `char2`），拼到结果里，把它们的频次各自减 1 后，如果还不为 0 再一起压回堆中。

#### 2. LeetCode 1405（最长快乐字符串：允许连续 2 个，严禁连续 3 个）
* **策略**：**按需单拿，遇到连续 2 个相同就拿第二多的“救场”**。
* **为什么？** 允许连续出现两个相同的字符（例如 `"cc"` 是合法的），所以我们可以放心地先连续用两次最高频的字符。只有当结果集的最后两个字符和当前堆顶字符相同时（即马上要凑成 `"ccc"` 了），才触发冲突处理。
* **堆操作方式**：每次只从堆顶弹出一个最多的字符。如果不冲突就直接用；如果冲突了，再弹出一个**第二多**的字符救场，用完后再把第一多的字符原封不动压回堆中。

### 💡 总结

* 如果把 LeetCode 1405 的限制条件改成“绝对不能连续 2 个相同”，那它的最大堆解法就会和 LeetCode 767 **完全一模一样**。
* 正是因为 1405 允许连续 2 个，它的最大堆代码中才出现了“弹出第二多字符救场（`char2`）”的特殊逻辑。两者的最大堆思路是一脉相承的“动态优先队列贪心”。

## 在计算机科学和实际软件工程中，**“数学推导法”**（比如 767 题的奇偶位插空）和**“堆/优先队列法”**（工程思维）有着截然不同的哲学：

### 1. 为什么说数学方法“不好推广”？
* **脆弱的假设**：像 767 题的奇偶插空，依赖于一个非常完美的数学边界：$\text{maxFreq} \le \frac{n + 1}{2}$。它刚好卡死在“最多允许连续相同 1 个”的前提下。
* **规则一变，数学就失效了**：如果产品经理明天突然改需求，说：“我们现在要搞推荐系统，规则变了：同一个标签最多连续出现 2 次，但另一个标签最多连续 3 次，而且总权重还要满足某种动态权重比……”
* 此时，你之前推导的那些优美公式和奇偶位下标计算，瞬间全部作废。你得重新去解数学方程、重新推导边界。这在多变、复杂的真实业务场景中是无法维护的。

### 2. 为什么说“Heap（堆）”代表了真正的工程思维？
* **通用性与扩展性（Generalization）**：堆和贪心策略本质上是一个**黑盒调度器**。它不管你的限制条件有多奇葩，它永远只认两件事：**“当前谁的优先级最高（剩余最多）”** 和 **“谁当前违规了（触发了冷却或冲突拦截）”**。
* **业务变更极其优雅**：
  * 如果限制从“不能连续 2 个”变成“不能连续 3 个”（像 1405 题），工程代码只需要改一下冲突检查的长度判断（`len(res) >= 2` 改成更通用的规则），核心的调度框架**完全不用动**。
  * 如果未来要引入权重、时间戳、甚至动态衰减因子，你只需要把堆里的排序 Key（比如从 `-count` 改成一个复杂的评分函数）换掉即可。

### 💡 极客视角的总结
* **竞赛/面试突击**：大家喜欢追求数学方法，因为代码短、常数小、$O(N)$ 极致优雅。
* **真实系统/工程架构**：**更青睐 Heap（优先队列）这种模拟/调度思维**。因为它把复杂的业务约束转化为**“动态优先级调度问题”**，具备极强的鲁棒性（Robustness）和应对需求变更的能力。

# LeetCode 51. N 皇后 (N-Queens)

---

## 1. 题目描述

按照国际象棋的规则，皇后可以攻击与之处在同一行、同一列或同一斜线上的棋子。

**n 皇后问题** 研究的是如何将 `n` 个皇后放置在 `n × n` 的棋盘上，并且使皇后彼此之间不能相互攻击。

给你一个整数 `n`，返回所有不同的 **n 皇后问题** 的解决方案。

每一种解法包含一个不同的 **n 皇后问题** 的棋盘放置方案，该方案中 `'Q'` 和 `'.'` 分别代表了皇后和空位。

### 示例 1
* **输入：** `n = 4`
* **输出：** `[[".Q..","...Q","Q...","..Q."],["..Q.","Q...","...Q",".Q.."]]`
* **解释：** 4 皇后问题存在两个不同的解法。

### 示例 2
* **输入：** `n = 1`
* **输出：** `[["Q"]]`

### 提示
* `1 <= n <= 9`

---

## 2. 核心思路与算法本质：回溯与剪枝

N 皇后问题是计算机科学中**回溯算法（Backtracking）**的经典之作。要在 $n \times n$ 的棋盘上放置 $n$ 个互相不攻击的皇后，我们需要解决两个核心问题：**如何搜索** 和 **如何高效判断冲突**。

### 2.1 递归与回溯框架
* 我们按行进行放置：从第 0 行开始，每一行必须且只能放一个皇后，然后递归去放下一行。
* 如果在某一行发现所有列都无法安放，说明当前路径走不通，触发**回溯**：撤销上一步的选择，退回上一行，换一个格子继续尝试。

### 2.2 巧妙的数学空间映射（$O(1)$ 冲突检测）
两个皇后不能在同一行、同一列、同一斜线上：
1. **行冲突**：因为我们是“每一行严格放一个皇后”并向下递归，所以行冲突天然被规避。
2. **列冲突**：同一列不能有两个。用一个集合 `cols` 记录已经被占用的列。
3. **主对角线冲突**（左上到右下）：在同一条主对角线上，所有格子的 **`row - col`** 是一个定值。用集合 `diag1` 记录。
4. **副对角线冲突**（右上到左下）：在同一条副对角线上，所有格子的 **`row + col`** 是一个定值。用集合 `diag2` 记录。

通过这三个集合，每次判断某个格子是否安全的时间复杂度直接降为 **$O(1)$**。

---

## 3. 代码实现 (Python 3)

```python
class Solution:
    def solveNQueens(self, n: int) -> list[list[str]]:
        res = []
        
        # 用于记录已经被占用的列和对角线状态
        cols = set()       # 列冲突
        diag1 = set()      # 主对角线 (row - col)
        diag2 = set()      # 副对角线 (row + col)
        
        def backtrack(row: int, current_board: list[str]):
            # 终止条件：当行数到达 n 时，说明 n 个皇后已成功全部安放
            if row == n:
                res.append(list(current_board))
                return
                
            # 遍历当前行的每一列
            for col in range(n):
                # 剪枝：如果当前列、主对角线或副对角线已被占用，直接跳过
                if col in cols or (row - col) in diag1 or (row + col) in diag2:
                    continue
                    
                # 1. 做选择：将皇后放入 (row, col)
                cols.add(col)
                diag1.add(row - col)
                diag2.add(row + col)
                
                # 构造当前行的字符串表现形式并加入棋盘
                row_str = '.' * col + 'Q' + '.' * (n - 1 - col)
                current_board.append(row_str)
                
                # 2. 递归进入下一行
                backtrack(row + 1, current_board)
                
                # 3. 撤销选择（回溯的关键：恢复现场，保证退回上一层时不影响其他分支）
                current_board.pop()
                cols.remove(col)
                diag1.remove(row - col)
                diag2.remove(row + col)

        backtrack(0, [])
        return res
```

### 4. 详细 Dry Run（以 $n = 4$ 为例）

1. **第 0 行 (`row = 0`)**：
   * 尝试 `col = 0`：放入 `'Q'`。集合记录 `cols = {0}`, `diag1 = {0}`, `diag2 = {0}`。棋盘状态：`[".Q.."]`（此处简化展示）。
2. **第 1 行 (`row = 1`)**：
   * 尝试 `col = 0`：冲突（`cols` 已有 0）。
   * 尝试 `col = 1`：冲突（`diag2 = 1 + 1 = 2`，但主对角线或列也可能冲突）。
   * 尝试 `col = 2`：安全！放入。记录状态，棋盘变为 `[".Q..", "..Q."]`。
3. **深入递归直至死胡同**：
   * 当走到某一行发现无处可落脚时，触发递归终止或循环结束，开始层层 `pop` 和 `remove` 恢复现场，回溯到上一行更换位置（例如把第 1 行的皇后挪到 `col = 3`），继续探索其他分支。
4. **收集所有解**：最终遍历完整棵搜索树，收集到所有合法的棋盘组合。

### 5. 复杂度分析

* **时间复杂度**：$O(N!)$。在第一行有 $N$ 种放法，第二行最多有 $N-2$ 种放法，以此类推。虽然是阶乘级，但由于对角线和列剪枝的存在，实际执行效率远低于纯暴力穷举。
* **空间复杂度**：$O(N)$。递归调用的最大深度为 $N$（对应棋盘行数），记录状态的 `cols`、`diag1`、`diag2` 集合大小最多也为 $N$ 级别。
