# LeetCode 1094: Car Pooling (拼车)

## 📌 题目描述

车上最初有 `capacity` 个空座位。车只能向一个方向行驶（即不能回头或改变方向）。

给定一个整数 `capacity` 和一个数组 `trips`，其中 `trips[i] = [numPassengers_i, from_i, to_i]` 表示第 `i` 次行程，有 `numPassengers_i` 位乘客在 `from_i` 位置上车，并在 `to_i` 位置下车。

如果可以在所有给定的行程中顺畅乘客且**不超载**，返回 `true`；否则，返回 `false`。

## 💡 核心思路：差分数组 (Difference Array)

### 为什么用差分数组？
对于每一个行程 `[passengers, start, end]`，这意味着在区间 **`[start, end - 1]`** 的每一段路上，车上都要增加 `passengers` 个乘客。
* 如果用**暴力模拟**：每次拿到行程都去遍历区间 `[start, end - 1]` 逐个加人数，整体时间复杂度会达到 $O(N \times \text{Distance})$，容易超时。
* 如果用**差分数组**：
  * 在 `start` 站：`diff[start] += passengers`（表示从这一站开始，车上增加了这么多乘客）。
  * 在 `end` 站：`diff[end] -= passengers`（表示在这一站乘客已经下车，车上减少了这么多乘客）。
  * 每次修改的时间复杂度仅为 **$O(1)$**。

处理完所有行程后，我们对差分数组求一次**前缀和（累加值）**，即可得到车在每一站的实际乘客数。只要过程中任何一站的乘客数超过 `capacity`，直接返回 `false`。

## 🐍 Python 3 完整代码

```python
class Solution:
    def carPooling(self, trips: list[list[int]], capacity: int) -> bool:
        # 根据题目数据范围，车站最大下标不超过 1000
        # 创建大小为 1001 的差分数组
        diff = [0] * 1001
        
        # 1. 记录每个行程的上下车变动
        for passengers, start, end in trips:
            diff[start] += passengers  # 上车
            diff[end] -= passengers    # 下车
            
        # 2. 前缀和还原每一站的实际人数
        current_passengers = 0
        for num in diff:
            current_passengers += num
            # 如果某一段路程的人数超过容量上限，返回 False
            if current_passengers > capacity:
                return False
                
        return True
```

### 复杂度分析

- **时间复杂度**：$O(N + M)$
  - $N$ 为 trips 的数量，遍历行程数组登记上下车变动需要 $O(N)$。
  - $M$ 为车站的最大范围（本题固定为 1001），扫描前缀和需要 $O(M)$。
  - 整体耗时极低，线性时间解决。
- **空间复杂度**：$O(M)$
  - 只需要一个固定大小的差分数组存储各个车站的人数变动，空间开销为常量级别 $O(1001) = O(1)$。

# LeetCode 78: Subsets (子集)

## 📌 题目描述

给你一个整数数组 `nums`，数组中的元素 **互不相同**。返回该数组所有可能的子集（幂集）。

解集 **不能** 包含重复的子集。你可以按 **任意顺序** 返回解集。

## 💡 核心思路：回溯算法 (Backtracking)

求子集问题本质上是一个**“选与不选”**或者**“组合构建”**的过程。
* 数组中的每个元素都有两种状态：**加入当前子集** 或者 **不加入**。
* 我们可以通过**回溯算法（深度优先搜索 DFS）**来遍历整棵决策树。
* 与普通的组合问题（只在叶子节点收集结果）不同，求子集时，**决策树上的每一个节点（包括根节点、中间节点、叶子节点）都是一个合法的子集**，因此每到一个新节点，我们都可以直接收集当前路径。

为了避免产生重复的子集（例如 `[1, 2]` 和 `[2, 1]` 视为同一个），我们在递归时需要传入一个 `start` 指针，规定每次只能从当前位置及之后的元素中选择。

## 🐍 Python 3 完整代码

```python
class Solution:
    def subsets(self, nums: list[int]) -> list[list[int]]:
        res = []
        
        def backtrack(start: int, path: list[int]):
            # 每一个节点（包括空集和中间状态）都是一个合法子集，将其加入结果集
            res.append(list(path))
            
            # 从 start 开始遍历，选择下一个加入子集的元素
            for i in range(start, len(nums)):
                # 1. 做选择
                path.append(nums[i])
                # 2. 递归深入（从 i + 1 开始，避免重复组合）
                backtrack(i + 1, path)
                # 3. 撤销选择（回溯）
                path.pop()
                
        backtrack(0, [])
        return res
```

### 复杂度分析

- 时间复杂度：$O(N \cdot 2^N)$
  - 对于长度为 $N$ 的数组，总共有 $2^N$ 个不同的子集。
  - 每次将子集加入结果集时，复制 path 需要消耗 $O(N)$ 的时间。
  - 因此总时间复杂度为 $O(N \cdot 2^N)$。
- 空间复杂度：$O(N)$
  - 递归调用的栈深度最多为 $N$（即数组的长度）。
  - 临时路径 path 占用空间最大为 $O(N)$。
  - （注意：如果不计算存储最终返回结果所需的空间，辅助空间复杂度为 $O(N)$）。

# LeetCode 78: Subsets (子集) 完整 Dry Run 轨迹推演

以输入 **`nums = [1, 2]`** 为例，我们来看看代码是如何一步步运作的。

## 🌳 决策树结构

我们可以把 `path` 的变化和 `res` 的收集过程想象成一棵决策树：

```text
                  [ ] (根节点: start=0)
                 /   \
          i=0   /     \  i=1
               /       \
            [1]         [2] (i=1, start=1)
           /
    i=1   /
         /
      [1, 2]
```

🎬 详细执行步骤（Dry Run Trace）

🚀 主函数入口
- 调用 `backtrack(0, [])`，初始 `path = []`，`res = []`。

第一层递归：`backtrack(0, [])`
1. 收集当前节点：`res.append(list([]))` $\rightarrow$ `res = [[]]`
2. 进入 `for i in range(0, 2)` 循环：
  - 轮次 `i = 0` (选取 `nums[0] = 1`)：
    - 做选择：`path.append(1)` $\rightarrow$ `path = [1]`
    - 递归：调用 `backtrack(1, [1])`
  - 👇 进入第二层递归：`backtrack(1, [1])`
    1. 收集当前节点：`res.append(list([1]))` $\rightarrow$ `res = [[], [1]]`
    2. 进入 `for i in range(1, 2)` 循环：
      - 轮次 `i = 1` (选取 `nums[1] = 2`)：
        - 做选择：`path.append(2)` $\rightarrow$ `path = [1, 2]`
        - 递归：调用 `backtrack(2, [1, 2])`
      - 👇 进入第三层递归：`backtrack(2, [1, 2])`
        1. 收集当前节点：`res.append(list([1, 2]))` $\rightarrow$ `res = [[], [1], [1, 2]]`
        2. 进入 `for i in range(2, 2)` 循环：范围为空，循环不执行。
        3. 函数返回，回到第二层递归。
      - 撤销选择（回溯）：`path.pop()` $\rightarrow$ 弹出 `2`，`path` 恢复为 `[1]`。
      - 第二层 `for` 循环（`i = 1`）结束。
    3. 第二层函数返回，回到第一层递归。
  - 撤销选择（回溯）：`path.pop()` $\rightarrow$ 弹出 `1`，`path` 恢复为 `[]`。
  - 轮次 `i = 1` (选取 `nums[1] = 2`)：
    - 做选择：`path.append(2)` $\rightarrow$ `path = [2]`
    - 递归：调用 `backtrack(2, [2])`
  - 👇 进入第二层递归：`backtrack(2, [2])`
    1. 收集当前节点：`res.append(list([2]))` $\rightarrow$ `res = [[], [1], [1, 2], [2]]`
    2. 进入 `for i in range(2, 2)` 循环：范围为空，循环不执行。
    3. 函数返回，回到第一层递归。
  - 撤销选择（回溯）：`path.pop()` $\rightarrow$ 弹出 `2`，`path` 恢复为 `[]`。
  - 第一层 `for` 循环（`i = 1`）结束。

🏁 程序结束
- 返回最终结果：`res = [[], [1], [1, 2], [2]]`。

💡 核心观察总结
1. 收集时机：每次刚进入 `backtrack` 函数时，第一时间把当前的 `path` 拷贝一份压入 `res`。因为树上的每一个节点都是一个合法的子集。
2. `start` 的作用：防止回头选之前的数字，从而天然避开了产生 `[2, 1]` 这种与 `[1, 2]` 重复的组合。
3. `path.pop()` 的作用：保证在处理完 `[1, 2]` 后，能够干净地把 `2` 拿掉变回 `[1]`，再把 `1` 拿掉变回 `[]`，从而不影响后面单独选择 `[2]` 的过程。
