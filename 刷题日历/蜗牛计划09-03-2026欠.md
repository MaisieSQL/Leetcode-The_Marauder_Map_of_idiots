# LeetCode 572. 另一棵树的子树 (Subtree of Another Tree)

## 📝 1. 题目描述 (Description)
给你两棵二叉树的根节点 `root` 和 `subRoot` 。如果 `root` 中包含和 `subRoot` 具有相同结构和节点值的子树，返回 `true` ；否则，返回 `false` 。

二叉树 `tree` 的一棵子树包括 `tree` 的某个节点和这个节点的所有后代节点。`tree` 也可以看作它比较自身的子树。

## 🏛️ 解法一：双重递归流（常规标杆解法）

### 💡 核心思路
1. **外层递归 (`isSubtree`)**：遍历主树 `root` 的每一个节点，将每个节点都当成“潜在的子树根节点”。
2. **内层递归 (`isSameTree`)**：一旦定位到某个节点，严格比对以该节点为根的二叉树是否与 `subRoot` 完全同构（LeetCode 100 相同树）。

### 💻 Python3 代码实现

```python
from typing import Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right


class Solution:

  def isSubtree(
      self, root: Optional[TreeNode], subRoot: Optional[TreeNode]
  ) -> bool:
    # 边界情况：如果主树已经空了，连找都没得找，直接返回 False
    if not root:
      return False

    # 1. 核心判定：以当前 root 为根的子树，是否和 subRoot 完全相同？
    if self.isSameTree(root, subRoot):
      return True

    # 2. 如果当前不一样，那就去主树的“左子树”或者“右子树”里继续碰运气！
    return self.isSubtree(root.left, subRoot) or self.isSubtree(
        root.right, subRoot
    )

  # 辅助函数：精准比对两棵树是否完全相同（LeetCode 100 相同树）
  def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
    # 两个都为空，说明完美匹配到底了，返回 True
    if not p and not q:
      return True
    # 一个空一个不空，或者值不相等，说明不一样，返回 False
    if not p or not q or p.val != q.val:
      return False

    # 递归比对：当前值相等的话，左边和右边必须同时一样
    return self.isSameTree(p.left, q.left) and self.isSameTree(p.right, q.right)
```

## ⚡ 解法二：树的序列化 + KMP 算法（线性时间降维打击）

### 💡 核心思路
1. **二叉树序列化（拍扁成字符串）**：
   - 使用带空节点占位符（如 `"#"`）的前序/后序遍历，将二叉树 `root` 和 `subRoot` 分别序列化为字符串 $S_{main}$ 和 $S_{sub}$。
   - **关键防错设计**：节点值左右必须加上分隔符（如 `^` 和 `,`），防止数值拼接产生歧义（例如区分节点值 `12` 与 `1` 和 `2`）。
2. **KMP 字符串匹配**：
   - 将问题转化为：求模式串 $S_{sub}$ 是否为文本串 $S_{main}$ 的子串。
   - 利用 KMP 构建 `next` 数组（前缀表），在 $\mathcal{O}(M + N)$ 线性时间内完成匹配。

### 💻 Python3 代码实现

```python
from typing import List, Optional


class SolutionKMP:

  def isSubtree(
      self, root: Optional[TreeNode], subRoot: Optional[TreeNode]
  ) -> bool:
    # 1. 序列化二叉树（前序遍历，带空节点占位符）
    def serialize(node: Optional[TreeNode]) -> List[str]:
      if not node:
        return ["#"]
      # 加上特定标识符，避免数值混淆
      return (
          ["^" + str(node.val)]
          + serialize(node.left)
          + serialize(node.right)
      )

    s1 = serialize(root)
    s2 = serialize(subRoot)

    # 2. 手写 KMP 算法，在 s1 中匹配 s2
    return self.kmpSearch(s1, s2)

  def kmpSearch(self, text: List[str], pattern: List[str]) -> bool:
    if not pattern:
      return True
    if not text:
      return False

    # 2.1 构建 next 数组 (LPS: Longest Prefix Suffix)
    next_arr = [0] * len(pattern)
    j = 0
    for i in range(1, len(pattern)):
      while j > 0 and pattern[i] != pattern[j]:
        j = next_arr[j - 1]
      if pattern[i] == pattern[j]:
        j += 1
      next_arr[i] = j

    # 2.2 主匹配过程
    j = 0
    for i in range(len(text)):
      while j > 0 and text[i] != pattern[j]:
        j = next_arr[j - 1]
      if text[i] == pattern[j]:
        j += 1
```

### ⏱️ 复杂度核验 (Complexity Analysis)

| 解法流派 | 时间复杂度 | 空间复杂度 | 核心优势 / 适用场景 |
| :--- | :--- | :--- | :--- |
| **双重递归流** | $\mathcal{O}(M \times N)$ | $\mathcal{O}(H_{main})$ | 代码简洁，思维直观。在树深度较小、重复节点少时运行极快，是面试中最推荐的标准解法。 |
| **序列化 + KMP 降维流** | $\mathcal{O}(M + N)$ | $\mathcal{O}(M + N)$ | 严格线性时间复杂度。打破了双递归在最坏极端数据下的性能瓶颈，展现极高的算法深度。 |

# 399. Evaluate Division (除法求值) - DFS 路径相乘解法

- **难度**：Medium
- **分类**：图论 (Graph) / 深度优先搜索 (DFS) / 广度优先搜索 (BFS) / 带权并查集 (Weighted DSU)
- **LeetCode 链接**：[LeetCode 399. Evaluate Division](https://leetcode.com/problems/evaluate-division/)

---

### 题目描述

给你一个变量对数组 `equations` 和一个实数数组 `values` 作为已知条件，其中 `equations[i] = [Ai, Bi]` 和 `values[i]` 共同表示等式 $A_i / B_i = values[i]$。每个 $A_i$ 或 $B_i$ 是一个表示单个变量的字符串。

另给你一个数组 `queries`，其中 `queries[j] = [Cj, Dj]` 表示第 $j$ 个查询，你需要求出 $C_j / D_j = ?$ 的值。

返回所有查询的答案。如果某个答案无法根据已知条件计算得出，请返回 `-1.0`。

**说明**：
* 输入总是有效的。你可以假设除法运算中不会出现除以 0 的情况，且等式之间不存在矛盾。
* 变量如果从未在 `equations` 中出现过，则视为未定义，无法计算其答案。

---

### 示例

#### 示例 1
* **输入**：
  * `equations = [["a","b"],["b","c"]]`
  * `values = [2.0, 3.0]`
  * `queries = [["a","c"],["b","a"],["a","e"],["a","a"],["x","x"]]`
* **输出**：`[6.00000, 0.50000, -1.00000, 1.00000, -1.00000]`
* **解释**：
  * 给定：$a / b = 2.0,\ b / c = 3.0$
  * 查询：
    * $a / c = (a / b) \times (b / c) = 2.0 \times 3.0 = 6.0$
    * $b / a = 1 / (a / b) = 1 / 2.0 = 0.5$
    * $a / e = -1.0$（变量 `e` 未定义）
    * $a / a = 1.0$
    * $x / x = -1.0$（变量 `x` 未定义）

#### 示例 2
* **输入**：
  * `equations = [["a","b"],["b","c"],["bc","cd"]]`
  * `values = [1.5, 2.5, 5.0]`
  * `queries = [["a","c"],["c","b"],["bc","cd"],["cd","bc"]]`
* **输出**：`[3.75000, 0.40000, 5.00000, 0.20000]`

#### 示例 3
* **输入**：
  * `equations = [["a","b"]]`
  * `values = [0.5]`
  * `queries = [["a","b"],["b","a"],["a","c"],["x","y"]]`
* **输出**：`[0.50000, 2.00000, -1.00000, -1.00000]`

### 提示约束

* $1 \le \text{equations.length} \le 20$
* $\text{equations}[i].\text{length} == 2$
* $1 \le A_i.\text{length}, B_i.\text{length} \le 5$
* $\text{values.length} == \text{equations.length}$
* $0.0 < \text{values}[i] \le 20.0$
* $1 \le \text{queries.length} \le 20$
* $\text{queries}[i].\text{length} == 2$
* $1 \le C_j.\text{length}, D_j.\text{length} \le 5$
* $A_i, B_i, C_j, D_j$ 仅由小写英文字母与数字组成。

### 一、 题意与图论建模大白话

题目给出已知除法算式：
* $a / b = 2.0$
* $b / c = 3.0$

**在图论中，这对应带权重的有向边**：
* 从 $a$ 走向 $b$，倍率是 $\times 2.0$（即 $a = 2.0 \times b$）。
* 隐含反向关系：$b / a = 1 / 2.0 = 0.5$，即从 $b$ 走向 $a$ 权重为 $0.5$。
* 同理，$b \to c$ 权重为 $3.0$；反向 $c \to b$ 权重为 $1 / 3.0$。

求 $a / c$ 本质是在有向图中寻找一条从 $a$ 到 $c$ 的路径，并将沿途边权累乘：

$$a \xrightarrow{\times 2.0} b \xrightarrow{\times 3.0} c \implies a / c = 2.0 \times 3.0 = 6.0$$

### 二、 边界判死规则（返回 `-1.0`）

1. **未定义变量**：查询的起点或终点未在已知条件中出现。
2. **非连通分量**：起点与终点分属不同连通块，路径无法到达。

### 三、 Python 标准实现（DFS 路径相乘）

```python
from collections import defaultdict


class Solution:

  def calcEquation(
      self,
      equations: list[list[str]],
      values: list[float],
      queries: list[list[str]],
  ) -> list[float]:
    # 1. 构建邻接表：graph[u] = [(v, weight), ...]
    # u / v = val  =>  u 到 v 的权重是 val；v 到 u 的权重是 1.0 / val
    graph = defaultdict(list)
    for (u, v), val in zip(equations, values):
      graph[u].append((v, val))
      graph[v].append((u, 1.0 / val))

    # 2. DFS 搜索函数：从 curr 出发找 target，同时累乘倍率
    def dfs(curr: str, target: str, visited: set) -> float:
      if curr == target:
        return 1.0

      visited.add(curr)

      for neighbor, weight in graph[curr]:
        if neighbor not in visited:
          sub_result = dfs(neighbor, target, visited)
          if sub_result != -1.0:
            return weight * sub_result

      return -1.0

    # 3. 处理每个 query
    results = []
    for u, v in queries:
      if u not in graph or v not in graph:
        results.append(-1.0)
      elif u == v:
        results.append(1.0)
      else:
        results.append(dfs(u, v, set()))

    return results
```

### 四、 复杂度分析

* **时间复杂度**：O(E + Q * (V + E))
  * 建图耗时 $O(E)$，其中 $E$ 为方程总数。
  * 单次 DFS 最坏需遍历当前连通图，耗时 $O(V + E)$；共有 $Q$ 次查询。
* **空间复杂度**：$O(V + E)$，用于存储图邻接表与 DFS 递归调用栈。

# 399. Evaluate Division (除法求值) - 示例 1 Dry Run 全流程追踪

### 一、 输入条件

* **已知方程**：`equations = [["a", "b"], ["b", "c"]]`
* **方程取值**：`values = [2.0, 3.0]`
* **待查列表**：`queries = [["a", "c"], ["b", "a"], ["a", "e"], ["a", "a"], ["x", "x"]]`

### 二、 阶段一：建图 (Graph Construction)

遍历每一组等式并录入正反双向带权边：

1. **处理 `["a", "b"]`, `val = 2.0`**：
   * 正向：$a \to b$，权重为 $2.0$（即 $a = 2.0 \times b$）
   * 反向：$b \to a$，权重为 $1.0 / 2.0 = 0.5$
   * `graph["a"].append(("b", 2.0))`
   * `graph["b"].append(("a", 0.5))`

2. **处理 `["b", "c"]`, `val = 3.0`**：
   * 正向：$b \to c$，权重为 $3.0$
   * 反向：$c \to b$，权重为 $1.0 / 3.0 \approx 0.3333$
   * `graph["b"].append(("c", 3.0))`
   * `graph["c"].append(("b", 0.3333...))`

**最终构建完成的邻接表 `graph`**：
```text
"a": [ ("b", 2.0) ]
"b": [ ("a", 0.5), ("c", 3.0) ]
"c": [ ("b", 0.3333...) ]
```

### 三、 阶段二：查询逐个追踪 (Queries Dry Run)

#### 查询 1：`["a", "c"]`
* **前置检查**：`"a"` 和 `"c"` 均在 `graph` 中，且 `"a" != "c"`，进入 DFS。
* **执行栈追踪**：
  * `dfs(curr="a", target="c", visited=set())`
  * `visited.add("a")` $\to$ `visited = {"a"}`
  * 遍历 `"a"` 的邻居：`("b", 2.0)`
  * `"b"` 未访问，发起递归：`dfs(curr="b", target="c", visited={"a"})`
    * `visited.add("b")` $\to$ `visited = {"a", "b"}`
    * 遍历 `"b"` 的邻居：
      * 邻居 1：`"a"` 已在 `visited` 中，跳过。
      * 邻居 2：`("c", 3.0)` 未访问，发起递归：`dfs(curr="c", target="c", visited={"a", "b"})`
        * 触发 Base Case：`curr == target`（`"c" == "c"`），直接返回 `1.0`。
    * 回到节点 `"b"`：收到子递归结果 `sub_result = 1.0`。
    * 节点 `"b"` 计算并返回：`3.0 * 1.0 = 3.0`。
  * 回到节点 `"a"`：收到子递归结果 `sub_result = 3.0`。
  * 节点 `"a"` 计算最终结果：`2.0 * 3.0 = 6.0`。
* **该项结果**：`6.0`

#### 查询 2：`["b", "a"]`
* **前置检查**：`"b"` 和 `"a"` 均在 `graph` 中，且 `"b" != "a"`，进入 DFS。
* **执行栈追踪**：
  * `dfs(curr="b", target="a", visited=set())`
  * `visited.add("b")` $\to$ `visited = {"b"}`
  * 遍历 `"b"` 的邻居：第一个邻居为 `("a", 0.5)`
  * `"a"` 未访问，发起递归：`dfs(curr="a", target="a", visited={"b"})`
    * 触发 Base Case：`curr == target`（`"a" == "a"`），直接返回 `1.0`。
  * 回到节点 `"b"`：收到子递归结果 `sub_result = 1.0`。
  * 计算最终结果：`0.5 * 1.0 = 0.5`。
* **该项结果**：`0.5`

#### 查询 3：`["a", "e"]`
* **前置检查**：
  * `"a"` 在 `graph` 中。
  * 命中分支：`"e" not in graph`，变量 `e` 未定义。
* **直接判定**：无需搜索，直接记录 `-1.0`。
* **该项结果**：`-1.0`

#### 查询 4：`["a", "a"]`
* **前置检查**：
  * `"a"` 存在于 `graph` 中。
  * 命中分支：`u == v`（`"a" == "a"`）。
* **直接判定**：已知变量自除恒为 `1.0`，直接记录 `1.0`。
* **该项结果**：`1.0`

#### 查询 5：`["x", "x"]`
* **前置检查**：
  * 命中首要分支：`u not in graph or v not in graph`（`"x"` 从未在任何方程中出现）。
* **直接判定**：直接记录 `-1.0`。
* **该项结果**：`-1.0`

第一次看到这道题的人，几乎没有不震惊的——一个做加减乘除的小学算术题，怎么会和走迷宫的 DFS 扯上关系？！

这正是 LeetCode 经典题最“贼”的地方：给题目套上一层厚厚的业务外衣（算术、求值），把图论的骨架死死藏在里面。

### 1. 为什么你的大脑第一反应不是 DFS？

* **习惯性思维定势**：看到 $a / b = 2.0$ 和 $b / c = 3.0$，正常人的第一直觉是代数消元法或者解多元一次方程组，想着用数学库或解方程思维去做。
* **信息隔阂**：如果只有 3 个变量，心算代入一秒就出来了；但如果给你 20 个变量：
  * $a / b = 2$
  * $b / c = 3$
  * $c / d = 4$
  * $x / y = 5$
  * 问你：$a / d = ?$，$a / y = ?$
* 这时候你其实在做的动作是：**顺着 $a$ 去找谁跟它有关系，找到 $b$，再顺着 $b$ 找谁跟它有关系，找到 $c$，再找 $d$……**
* “顺藤摸瓜，一条路走到黑，走不通换一条路”——这不就是图的深度优先搜索（DFS）的本质吗？

### 2. 数学等式在计算机里的“图论真身”

只要把“除法”翻译成“地图”，整件事就豁然开朗：

* **变量名（$a, b, c$）** $\to$ **地图上的城市（节点）**
* **等式（$a / b = 2.0$）** $\to$ **连接两座城市的单向收费公路（带权重的边）**
  * 从 $a$ 到 $b$，过路费是“乘以 2.0”
  * 从 $b$ 到 $a$，过路费是“乘以 0.5”（倒数反向边）
* **提问（$a / c = ?$）** $\to$ **问你能不能从城市 $a$ 开车到城市 $c$？如果能，沿途过路费一共是多少？**

一旦看穿了这个映射，所谓“求除法”，彻底变成了**“在有向图里找一条连通路径，并把沿途边权乘起来”**。而找路径最原汁原味的做法，就是 DFS。

### 3. 这类“披着羊皮的狼”有什么通用识别特征？

以后在面试中遇到满足以下两个特征的题，直接在脑子里亮起“图论 / 搜索”的红灯：

* **两两关系传递**：题目给出成对的二元关系（如 $A \to B$，$B \to C$），且这种关系具有传递性（汇率兑换、亲戚血缘、先修课程、除法倍率）。
* **多源多查询**：给你一堆已知对，然后抛出任意两点让你求关系或求通路。

这道题是把“汇率兑换模型”（1 美元换 7 人民币，1 人民币换 20 日元，求 1 美元换多少日元）换成了除法符号。拆穿这层伪装后，它就只是一道平平无奇的图遍历模版题了。

# 图论核心分类与 5 大经典模型

在刷题和面试体系中，图论如果剥离掉纯粹的爆搜（DFS/BFS/回溯），剩下的核心题型边界非常清晰，主要被划分为以下 5 大经典模型：

| 分类 | 核心解决的问题 | 典型算法与数据结构 | 高频代表题 |
| :--- | :--- | :--- | :--- |
| **1. 连通性与动态并集** | 动态加边、判环、图连通块合并、传递闭包 | **并查集 (DSU)** / 矩阵连通分量 | 684 冗余连接、721 账户合并、200 岛屿数量 |
| **2. 依赖顺序与可达性** | 有向无环图 (DAG) 判环、线性依赖排序、分层推进 | **拓扑排序 (Kahn BFS / DFS 三色标记)** | 207/210 课程表、310 最小高度树、802 安全状态 |
| **3. 最短路径问题** | 带权图中“代价最小 / 距离最短 / 概率最高”的通路 | **Dijkstra** (正权堆优化) / **Bellman-Ford / SPFA** / **Floyd-Warshall** | 743 网络延迟时间、787 K站中转便宜航班、1334 阈值距离内邻居最少城市 |

### 5 大模型背后的题型识别直觉

* **并查集模型（连通性 / 朋友圈）**：
  * **题面暗号**：“谁和谁属于同一个群体”、“加了这条边会不会闭环”、“合并两个账号/网络”。
  * **核心思维**：只需要维护**“谁和谁是一伙的”**，不关心路径具体怎么走。只要看到无向图、动态加边、求连通块个数，优先调取并查集。

* **拓扑排序模型（依赖 / 穿衣上课）**：
  * **题面暗号**：“做 B 之前必须先做 A”、“先后工序排期”、“树的层层剪枝（洋葱剥皮）”。
  * **核心思维**：面向**有向无环图 (DAG)**。找“入度为 0”（没有前置阻碍）的节点开始消耗，消除后暴露出下一批入度为 0 的节点。

* **最短路径模型（导航 / 最小花费）**：
  * **题面暗号**：“从 A 到 B 至少耗时多久”、“经过最多 K 次中转的最便宜价格”、“成功概率最高的一条路”。
  * **核心思维**：边上带有**非负权重**（时间、费用、距离）。
    * 单源单终点、非负边权 $\to$ **Dijkstra + 优先队列（堆）**；
    * 有步数限制或存在负权边 $\to$ **Bellman-Ford / 动态规划**；
    * 全源所有点对之间的距离（点很少） $\to$ **Floyd-Warshall 三层循环**。

* **最小生成树模型（修路修水管）**：
  * **题面暗号**：“把所有城市用电缆连起来，求最低造价”、“保证所有点连通，砍掉最昂贵的多余边”。
  * **核心思维**：全图所有点必须连通，一共选出 $N-1$ 条边，且权重和最小。
    * 绝大多数题目直接用 **Kruskal（边权升序排序 + 并查集贪心选边判环）** 搞定。

* **二分图模型（非友即敌 / 阵营划分）**：
  * **题面暗号**：“把所有人分成两组，使得同一组内的人互不喜欢”、“能否用两种颜色涂满整个图且相邻节点颜色不同”。
  * **核心思维**：用 1 和 -1 两种标记给邻居交替染色。如果染色过程中发现相邻节点已经被涂成了同一种颜色，说明图里存在**奇数长度的环**，二分图失败。

### 399. Evaluate Division 属于哪类经典模型？

这道题在本质上横跨并贯通了两个经典模型：

* **首要归属：模型 3【最短路径 / 路径乘积传递问题】（对应图遍历 / DFS / Floyd 解法）**
  * **为什么算这个模型**：虽然题目求的是“乘积”而非“求和”，但数学上取对数后 $\log(a/b) = \log(a) - \log(b)$，就彻底退化成了标准的**带权有向图路径问题**。
  * **解法映射**：在图上顺藤摸瓜找一条从起点到终点的通路，并沿途累乘权重，本质就是在求**全源连通路径的权值传递**（因此可以直接套用 Floyd-Warshall 跑全源传递闭包）。

* **进阶归属：模型 1【连通性与动态并集】（对应带权并查集 Weighted DSU 解法）**
  * **为什么算这个模型**：换个视角，所有能相互通过除法算出来的变量（如 $a, b, c$），其实同属于**同一个连通块（同一个帮派）**。
  * **解法映射**：带权并查集不仅维护“谁和谁是一伙的”，还在每个节点上挂一个相对大掌门的“倍率权重”。查询时只要看两节点是否在同一集合，若是，直接用两者对根节点的权值相除即可 $O(1)$ 得出答案。

> **一句话定性**：如果按纯图论算法的主流分类，它最核心的骨架是**带权图的连通路径权值计算（模型 3 的变体）**；如果按高级数据结构解法划分，它是经典的**带权并查集（模型 1 的进阶版）**。

### LeetCode 310. 最小高度树 (Minimum Height Trees)

#### 📝 题目描述
树是一个无向图，其中任何两个节点只通过一条路径连接。换句话说，一个没有简单环的连通图都是一棵树。

给你一个包含 `n` 个节点的树，标记为 `0` 到 `n - 1`。给定数字 `n` 和一个边数组 `edges`（其中 `edges[i] = [a_i, b_i]` 表示树中节点 `a_i` 和 `b_i` 之间存在一条无向边）。

你可以选择树中任何一个节点作为根。当选择节点 `x` 作为根节点时，设其树的高度为 `h`。在所有可能的树中，具有最小高度的树（即 $\min(h)$）被称为 **最小高度树 (Minimum Height Trees, MHTs)**。

请你找到所有的最小高度树并按任意顺序返回其根节点列表。返回的节点编号可以以任何顺序排列。

#### 💡 题目解析与核心思路

1. **树的中心理论**：
   * 能够成为“最小高度树”的根节点，必然是整棵树的**“中心”**（Center）。
   * 一棵无向树的中心最多只有 **2 个**（如果直径上有奇数个节点，中心有 1 个；如果有偶数个节点，中心有 2 个）。

2. **剥洋葱法（拓扑排序 / BFS 优化）**：
   * 树的**叶子节点**（度数 $\le 1$）离中心最远，它们绝不可能成为最小高度树的根。
   * 我们可以模仿拓扑排序的思路，从外向内**一层一层剥去叶子节点**：
     * 先找到所有度数等于 1 的初始叶子节点，放入队列。
     * 每次把当前层的叶子节点弹出，并将其连接的邻居节点的度数减 1。
     * 如果邻居节点的度数减到 1，说明它也变成了新的叶子节点，加入队列。
     * 重复这个过程，直到**剩下的节点数 $\le 2$**。此时剩下的节点就是整棵树的“中心”，直接返回即可！

下面为你详细拆解 **“剥洋葱法”（最优解）** 和你提到的 **“每个节点跑一遍 BFS 的暴力解”**，并附上完整的代码和复杂度对比。

### 方法一：剥洋葱法（拓扑排序 / BFS 优化）—— 最佳解法

#### 💡 核心思路
1. **寻找树的中心**：最小高度树的根节点必然是整棵树的“中心”，而树的中心最多只有 2 个。
2. **层层剥离**：度数为 1 的节点是“叶子节点”，它们离中心最远，绝不可能成为最小高度树的根。我们可以像剥洋葱一样：
   - 先把所有初始叶子节点放入队列。
   - 每次把当前层的叶子剥掉，将其邻居的度数减 1。
   - 如果邻居的度数减到 1，说明它也变成了新叶子，加入队列。
   - 循环直到剩下的节点数 $\le 2$，剩下的就是中心节点。

#### 💻 完整代码
```python
from collections import deque

class Solution:
    def findMinHeightTrees(self, n: int, edges: list[list[int]]) -> list[int]:
        # 边界情况：节点数少于等于 2 时，所有节点都是根
        if n <= 2:
            return [i for i in range(n)]
        
        # 1. 构建邻接表和度数记录
        adj = [set() for _ in range(n)]
        for u, v in edges:
            adj[u].add(v)
            adj[v].add(u)
            
        # 2. 找到所有初始的叶子节点（度数为 1）
        leaves = deque([i for i in range(n) if len(adj[i]) == 1])
        
        # 3. 开始“剥洋葱”
        remaining_nodes = n
        while remaining_nodes > 2:
            leaves_count = len(leaves)
            remaining_nodes -= leaves_count  # 减去当前层剥掉的叶子数
            
            for _ in range(leaves_count):
                leaf = leaves.popleft()
                neighbor = adj[leaf].pop()  # 获取叶子的唯一邻居
                adj[neighbor].remove(leaf)  # 从邻居中删掉这个叶子
                
                # 如果邻居变成了新叶子，加入队列
                if len(adj[neighbor]) == 1:
                    leaves.append(neighbor)
                    
        # 队列中剩下的就是最小高度树的根
        return list(leaves)
```

### 方法二：你的“笨办法”（暴力遍历每一个节点）

#### 💡 核心思路
1. 既然题目要求“以每个节点为根，求出对应的树高，并找出高度最小的根”，那我们就老老实实地把每个节点都当成一次根。
2. 对每个节点跑一遍 BFS（广度优先搜索），计算出从它出发的整棵树的最大深度（高度）。
3. 记录所有节点中的最小高度，把高度等于最小值的节点收集起来返回。

#### 💻 完整代码
```python
from collections import deque

class Solution:
    def findMinHeightTrees(self, n: int, edges: list[list[int]]) -> list[int]:
        if n <= 2:
            return [i for i in range(n)]
        
        # 1. 构建邻接表
        adj = [[] for _ in range(n)]
        for u, v in edges:
            adj[u].append(v)
            adj[v].append(u)
            
        # 2. 辅助函数：以特定 root 为根，用 BFS 计算树的高度
        def get_height(root):
            visited = [False] * n
            queue = deque([root])
            visited[root] = True
            height = 0
            
            while queue:
                level_size = len(queue)
                for _ in range(level_size):
                    curr = queue.popleft()
                    for neighbor in adj[curr]:
                        if not visited[neighbor]:
                            visited[neighbor] = True
                            queue.append(neighbor)
                if queue:
                    height += 1  # 还有下一层，高度 +1
            return height

        min_height = float('inf')
        ans = []
        
        # 3. 对每一个节点都跑一遍 BFS（暴力遍历）
        for i in range(n):
            h = get_height(i)
            if h < min_height:
                min_height = h
                ans = [i]  # 发现更小高度，清空旧结果
            elif h == min_height:
                ans.append(i)  # 高度相同，加入结果集
                
        return ans
```

| :--- | :--- | :--- | :--- |
| **方法一（剥洋葱法）** | $O(N)$ | $O(N)$ | **秒过**（每个节点和边只被遍历常数次） |

## 什么是拓扑排序

简单来说，**拓扑排序（Topological Sorting）**是针对**有向无环图（DAG, Directed Acyclic Graph）**的一种排序方法。它能将图中的所有节点排成一个线性序列，使得图中任意一条有向边 $(u \to v)$，起点 $u$ 总是排在终点 $v$ 的前面。

### 1. 一个生活中的直观比喻：穿衣服或大学选课

想象你在上大学选课：
* 选《机器学习》之前，你必须先修完《线性代数》和《Python编程》。
* 选《Python编程》之前，你可能不需要任何前置课。

这些课程和它们的先修关系组合起来，就形成了一个**有向图**（箭头指向后续课程）。拓扑排序做的事情，就是给你排出一张**合法的课程表**（例如：先上 Python $\to$ 再上线性代数 $\to$ 最后上机器学习），让你在学习任何一门课时，它的所有前置课程都已经学过了。

### 2. 拓扑排序的硬性条件

要想对一个图进行拓扑排序，必须满足两个前提：
1. **必须是有向图（Directed Graph）**：边是有方向的（A 必须在 B 之前）。
2. **绝对不能有环（Acyclic）**：如果图中存在环（例如：A 依赖 B，B 依赖 C，C 又依赖 A），那就变成了“死锁”，连先后顺序都无法确定，因此**有环的图无法进行拓扑排序**。

### 3. 最常用的实现方法：“入度表法”（Kahn 算法）

在代码中，我们通常用 **BFS（广度优先搜索）** 配合**入度（In-degree）**来实现拓扑排序。步骤非常直观：

1. **计算入度**：统计每个节点的“入度”（即有几条边直接指向它。入度为 0，代表没有任何前置任务）。
2. **寻找起点**：把所有入度为 0 的节点放入队列中（这些是可以直接开始做的事情）。
3. **开始剥离**：
   * 从队列中弹出一个节点，把它放入结果集中。
   * 顺着这个节点出发，找到它指向的所有邻居节点，把这些邻居节点的**入度减 1**（相当于它的一个前置任务完成了）。
   * 如果某个邻居的入度减到 0 了，说明它的所有前置任务都已清空，把它也加入队列。
4. **循环往复**：直到队列为空。

> **💡 环的检测**：如果最后发现结果集里的节点总数小于图中实际的节点总数，说明图里有环（有些节点的入度永远无法减到 0），拓扑排序失败。

### 它和我们刚才做的 310 题有什么联系？

你刚才在做 **310. Minimum Height Trees（最小高度树）** 时用到的“剥洋葱法”，其实就是借用了拓扑排序的思想：
* 虽然 310 题是个无向图，但我们通过不断剥离“度数为 1 的叶子节点”（类似于入度为 1 的节点），一层一层往里推进，最终找到树的核心。
* 它们的核心逻辑都是：**利用“度数（Degree / In-degree）”的变化，像多米诺骨牌一样从外向内层层处理！**
