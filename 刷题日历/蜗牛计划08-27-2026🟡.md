# 145. Binary Tree Postorder Traversal (二叉树的后序遍历)

## 题目描述
给你一棵二叉树的根节点 `root` ，返回其节点值的 **后序遍历** 序列。

- **后序遍历顺序**：`左子树 -> 右子树 -> 根节点`（Left -> Right -> Root）

## 核心解法

### 方法一：递归法 (Recursion)

#### 1. 思路分析
递归是树结构遍历最直接的方式。按照后序遍历的定义，先递归访问左子树，再递归访问右子树，最后将当前节点的值存入结果列表。

#### 2. Python 3 代码实现
```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        res = []
        
        def dfs(node: Optional[TreeNode]):
            if not node:
                return
            dfs(node.left)    # 遍历左子树
            dfs(node.right)   # 遍历右子树
            res.append(node.val)  # 访问根节点
            
        dfs(root)
        return res
```

#### 3. 复杂度分析
- **时间复杂度**：$O(n)$，其中 $n$ 为二叉树的节点数，每个节点被访问一次。
- **空间复杂度**：$O(n)$，最坏情况下（树呈链状）递归栈深度为 $O(n)$；平均情况下树高为 $O(\log n)$。

### 方法二：前序遍历变形反转法 (Iterative - Reverse Preorder)

#### 1. 思路分析
- 标准前序遍历顺序为：`根 -> 左 -> 右`
- 如果我们将压栈/遍历顺序微调为：`根 -> 右 -> 左`
- 将得到的结果序列进行整体反转（Reverse），顺序变为：`左 -> 右 -> 根`，恰好对应**后序遍历**。

#### 2. Python 3 代码实现
```python
class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []
        
        stack = [root]
        res = []
        
        while stack:
            node = stack.pop()
            res.append(node.val)
            # 先压左节点，再压右节点；弹栈时就是 右节点 先出
            if node.left:
                stack.append(node.left)
            if node.right:
                stack.append(node.right)
                
        # 将 [根 -> 右 -> 左] 反转为 [左 -> 右 -> 根]
        return res[::-1]
```

#### 3. 复杂度分析
- **时间复杂度**：$O(n)$，遍历所有节点耗时 $O(n)$，反转列表耗时 $O(n)$。
- **空间复杂度**：$O(n)$，显式栈保存节点的最大深度为 $O(n)$。

### 方法三：单栈通用迭代法（记录最近访问节点）

#### 1. 思路分析
如果不使用反转技巧，真正的后序遍历迭代需要保证：**只有当一个节点的左子树和右子树都已被访问处理后，该节点才能出栈并访问**。
- 维护指针 `curr` 沿左路一直向下压栈。
- 到达最左端后查看栈顶节点：
  - 如果栈顶节点的右子树存在且**未被访问过**，则将指针移到右子树继续处理。
  - 如果栈顶节点没有右子树，或者右子树**刚刚被访问过**（通过记录 `prev` 节点判断），则说明当前节点的子树已全部处理完毕，可以安全出栈并记录其值。

#### 2. Python 3 代码实现
```python
class Solution:
    def postorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        res = []
        stack = []
        curr = root
        prev = None  # 记录上一个被访问并记录的节点
        
        while curr or stack:
            # 一路向左压栈
            while curr:
                stack.append(curr)
                curr = curr.left
                
            node = stack[-1]
            # 如果右子树存在且未访问，转向右子树
            if node.right and node.right != prev:
                curr = node.right
            else:
                # 右子树为空或已被访问过，弹出当前节点并记录
                stack.pop()
                res.append(node.val)
                prev = node # 标记当前节点为“刚刚被访问过”
                
        return res
```

#### 3. 复杂度分析
- **时间复杂度**：$O(n)$，每个节点最多进栈出栈两次。
- **空间复杂度**：$O(n)$，显式栈空间取决于树高。

简单一句话概括它们的区别：
- `curr = curr.left` 是在**“向左下无脑探底”**。
- `curr = node.right` 是在**“左边彻底走不通、准备转战右边”**。

咱们把它们各自出没的场景和背后的物理逻辑彻底拆解开：

### 1. 为什么会有 `curr = curr.left`？（向左狂飙）
- **出现位置**：在内层的 `while curr:` 循环里。
- **物理动作**：
```python
  while curr:
      stack.append(curr)
      curr = curr.left  # <-- 就是这里
```

- **背后的逻辑**：
  后序遍历的铁律是 【左 $\rightarrow$ 右 $\rightarrow$ 根】。这意味着，无论走到哪一棵局部子树，最先要被处理的永远是它的最左边。
- 所以，当我们在主流程中拿到一个节点 `curr` 时，我们要以它为根，无限向左深入：把沿途所有的根节点统统压入栈（`stack.append(curr)`），然后指针立刻向左滑（`curr = curr.left`），直到滑到一个节点的左边为空（`curr` 变成 `None`、撞墙停下为止）。

### 2. 为什么又会有 `curr = node.right`？（转向右边）
- **出现位置**：在左边撞墙停下之后，我们查看栈顶的 `node = stack[-1]`。
- **物理动作**：
  ```python
  if node.right and prev != node.right:
      curr = node.right  # <-- 就是这里
  ```

- **背后的逻辑**：
  当内层循环因为 `curr` 变成 `None` 而退出时，说明当前子树的“左路”已经全部探到底、压完栈了。
  按照 【左 $\rightarrow$ 右 $\rightarrow$ 根】 的顺序：
  1. “左”已经处理完了。
  2. 接下来该轮到 “右” 了！
  3. 所以我们需要检查栈顶这个节点有没有右子树。如果有，并且右子树还没被访问过，我们就不能急着弹出这个根节点，而是必须把指针切到右边（`curr = node.right`）。
  4. 一旦把 `curr` 赋值为 `node.right`，大循环再次转起来时，就会带着这个右孩子重新触发上面的第一步（向左狂飙）！

### 🗺️ 用“走迷宫”来打个通俗的比方：
把整套迭代过程想象成你在走一个复杂的地下迷宫：
1. **`curr = curr.left`**：你进到一个新房间，发现有左手边通道，你二话不说就往左走，并且在路口做好标记（压栈），直到左边再也没有路（`curr` 为空）。
2. **`curr = node.right`**：左边彻底走不通了，你退回上一个路口（查看栈顶 `node`）。这时候你环顾四周，发现：“哎，我右边好像还有一条没走过的新通道耶！”于是你把指针拨向右边（`curr = node.right`），去探索右边的世界。
3. **`stack.pop()`（结算根）**：如果左边也走完了，右边也探索回来并做完了标记（`prev == node.right`），说明这个房间的左右两边全部大功告成。此时，你才正式把这个房间从脑海中抹去（`stack.pop()` 弹出并收集值）。

所以，它们两个一个是“顺着左边无限深入”的推进器，另一个是“左边探索完毕、寻找右边新出路”的变道器！老铁，这么一串联，是不是瞬间豁然开朗了？🔥


## 方案对比

| 解法 | 优点 | 缺点 | 面试推荐度 |
| :--- | :--- | :--- | :---: |
| **递归法** | 代码极其精炼，易于书写与理解 | 树极深时存在调用栈溢出风险 | ⭐️⭐️⭐️⭐️ |
| **前序变形反转法** | 易于记忆，代码结构与前序迭代完全一致 | 并非严格的原生自底向上遍历 | ⭐️⭐️⭐️⭐️⭐️ |
| **单栈通用追踪法** | 严格按照真实后序顺序自底向上执行 | 边界与 `prev` 状态转移逻辑较多 | ⭐️⭐️⭐️⭐️ |

# 417. Pacific Atlantic Water Flow (太平洋大西洋水流问题)

## 题目描述
给定一个 $m \times n$ 的非负整数矩阵 `heights` 表示大陆各单元格的海拔高度。
- **太平洋 (Pacific Ocean)** 处于大陆的 **左边界** 和 **上边界**。
- **大西洋 (Atlantic Ocean)** 处于大陆的 **右边界** 和 **下边界**。

雨水只能向 **高度小于或等于** 当前单元格的相邻（上下左右）单元格流动。返回所有既可以流动到太平洋、又可以流动到大西洋的单元格坐标列表。

## 核心解题思路：逆向思维（由海向陆反向搜索）

### 为什么不推荐正向搜索？
如果遍历每个格子并尝试寻找它是否能流向两洋，许多路径会重复遍历，复杂度高达 $O((m \cdot n)^2)$，极易超时（TLE）。

### 逆向反推法（由低到高）
- **正向水流**：高 $\to$ 低（或等高）
- **逆向反推**：从海洋边界出发，**低 $\to$ 高（或等高）** 进行反向渗透。
1. 从所有**紧邻太平洋的边界单元格**出发做搜索（DFS 或 BFS），记录所有能够被太平洋水反向逆流到达的格子集合 `pacific_reachable`。
2. 从所有**紧邻大西洋的边界单元格**出发做搜索，记录所有能够被大西洋水反向逆流到达的格子集合 `atlantic_reachable`。
3. 两个集合的**交集**即为所求坐标。

## 代码实现

### 方法一：逆向深度优先搜索 (DFS)

```python
class Solution:
    def pacificAtlantic(self, heights: List[List[int]]) -> List[List[int]]:
        if not heights or not heights[0]:
            return []
        
        m, n = len(heights), len(heights[0])
        pacific_reachable = set()
        atlantic_reachable = set()
        
        def dfs(r: int, c: int, reachable: set):
            reachable.add((r, c))
            for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
                nr, nc = r + dr, c + dc
                # 检查越界
                if 0 <= nr < m and 0 <= nc < n:
                    # 逆流条件：目标高度 >= 当前高度，且未被访问过
                    if (nr, nc) not in reachable and heights[nr][nc] >= heights[r][c]:
                        dfs(nr, nc, reachable)
        
        # 1. 左右两列边界出发
        for i in range(m):
            dfs(i, 0, pacific_reachable)        # 左侧：太平洋
            dfs(i, n - 1, atlantic_reachable)   # 右侧：大西洋
            
        # 2. 上下两行边界出发
        for j in range(n):
            dfs(0, j, pacific_reachable)        # 上侧：太平洋
            dfs(m - 1, j, atlantic_reachable)   # 下侧：大西洋
            
        # 3. 求解交集
        return [[r, c] for (r, c) in (pacific_reachable & atlantic_reachable)]
```

### 方法二：逆向广度优先搜索 (BFS)

```python
from collections import deque

class Solution:
    def pacificAtlantic(self, heights: List[List[int]]) -> List[List[int]]:
        if not heights or not heights[0]:
            return []
        
        m, n = len(heights), len(heights[0])
        
        def bfs(starts: list) -> set:
            queue = deque(starts)
            reachable = set(starts)
            
            while queue:
                r, c = queue.popleft()
                for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < m and 0 <= nc < n:
                        if (nr, nc) not in reachable and heights[nr][nc] >= heights[r][c]:
                            reachable.add((nr, nc))
                            queue.append((nr, nc))
            return reachable
        
        # 收集太平洋和大西洋的初始边界点
        pacific_starts = [(i, 0) for i in range(m)] + [(0, j) for j in range(n)]
        atlantic_starts = [(i, n - 1) for i in range(m)] + [(m - 1, j) for j in range(n)]
        
        pacific_reachable = bfs(pacific_starts)
        atlantic_reachable = bfs(atlantic_starts)
        
        return [[r, c] for (r, c) in (pacific_reachable & atlantic_reachable)]
```

## 复杂度分析

- **时间复杂度**：$O(m \times n)$
  每个网格单元最多被访问常数次（太平洋遍历一次，大西洋遍历一次）。
- **空间复杂度**：$O(m \times n)$
  存储可达集合 `set` 以及递归调用栈/队列所需的空间在最坏情况下为 $O(m \times n)$。

## 核心考点与技巧总结

| 维度 | 关键点 |
| :--- | :--- |
| **思维模型** | **逆向扩散（Flood Fill 逆流）**：多源搜索从边界汇聚点反推更高效 |
| **避坑指南** | 逆流合法条件是 `heights[nr][nc] >= heights[r][c]`（只能往高处或等高走） |
| **集合操作** | 利用 Python 的 `set & set` 可以极快提取双洋交集 |

# LeetCode 207. Course Schedule (课程表) 详解

## 📝 一、 题目描述 (Problem Description)
你这个学期必须选修 `numCourses` 门课程，记为 `0` 到 `numCourses - 1`。在选修某些课程之前需要一些先修课程。例如，想要学习课程 `0` ，你需要先完成课程 `1` ，用一个匹配表示：`[0, 1]`。

给定课程总量以及它们的先修课程对列表 `prerequisites`，请你判断是否可能完成所有课程的学习？如果可以，返回 `true`；否则，返回 `false`。

* **示例 1**：
  * **输入**：`numCourses = 2, prerequisites = [[1, 0]]`
  * **输出**：`true`
  * **解释**：总共有 2 门课程。学习课程 1 之前，你需要完成课程 0。所以这是可能的。

* **示例 2**：
  * **输入**：`numCourses = 2, prerequisites = [[1, 0], [0, 1]]`
  * **输出**：`false`
  * **解释**：学习课程 1 之前，你需要先完成课程 0；并且学习课程 0 之前，你也需要先完成课程 1。两门课互相依赖，**陷入因果死锁（环）**，绝对无法完成。

## 🏛️ 二、 物理直觉与核心解法：图论的因果死锁判定
* **物理翻译**：别被数字骗了。这根本不是纯数组题目，而是一张**【有向图 (Directed Graph)】**[cite: 4]！
  * `numCourses` 是图的 **顶点（Vertices）**[cite: 4]。
  * `prerequisites = [cur, pre]` 代表一根带有箭头的因果铁链：`pre ➔ cur`（想上 `cur` 必须先上 `pre`）[cite: 4]。
* **终极核心矛盾**：这张有向图里，到底有没有存在**“环 (Cycle)”**？[cite: 4]
  * 如果有环（死锁），课程互相套娃，根本没人能当“第一个吃螃蟹的人”，直接返回 `false`[cite: 4]。
  * 如果无环，说明存在合法的学习先后顺序（拓扑序列），返回 `true`[cite: 4]。

业内针对这道题有两种绝杀流派：**BFS 拓扑排序（入度表流）** 和 **DFS 三色状态机（染色判环流）**。

## 💻 三、 解法一：BFS 拓扑排序（入度表流 —— 最直观、最符合现实逻辑）

### 核心思想：
1. **统计入度**：建一个 `indegree` 数组，记录每一门课有多少个“前置爹”要当。再建一个邻接表 `adj` 记录谁指向谁。
2. **寻找零入度节点**：把所有**入度为 0（即没有任何前置限制、随时可以开学）**的课程全部塞进 BFS 队列里[cite: 3]。
3. **剥洋葱平推**：队列里的课出队，代表它被学完了。被学完后，所有受它影响的“后置课程”的入度纷纷 `-1`。一旦某个后置课程的入度减到 `0`，代表它的所有前置课都清空了，立刻入队[cite: 3]！
4. **终极验收**：统计总共学了多少门课。如果学完的数量等于 `numCourses`，说明无环全通关；否则说明有漏网之鱼被环卡住了[cite: 3]。

### Python3 代码：
```python
from collections import deque
from typing import List

class Solution:
    def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool:
        # 1. 初始化邻接表和入度数组
        adj = [[] for _ in range(numCourses)]
        indegree = [0] * numCourses
        
        # 2. 填充图与入度：prerequisites = [cur, pre] 代表 pre -> cur
        for cur, pre in prerequisites:
            adj[pre].append(cur)  # pre 指向 cur
            indegree[cur] += 1    # cur 的入度 +1
            
        # 3. 把所有入度为 0 的课程（没有任何前置限制、随时可以开学）丢进队列
        queue = deque([i for i in range(numCourses) if indegree[i] == 0])
        
        # 4. 开始 BFS 拓扑排序剥洋葱
        count = 0
        while queue:
            node = queue.popleft()
            count += 1
            
            # 遍历当前课程的所有“后置课程”
            for neighbor in adj[node]:
                indegree[neighbor] -= 1
                # 如果后置课程的前置全清空了，入队
                if indegree[neighbor] == 0:
                    queue.append(neighbor)
                    
        # 如果学完的课程数等于总课程数，说明无环，全部通关
        return count == numCourses
```

### 💻 四、 解法二：DFS 三色状态机（染色判环流 —— 面试高频炫技流）

**核心思想**：
利用三色标记数组 `visited`：
- **0 (白色)**：从未访问过的节点。
- **1 (灰色)**：当前递归栈中正在探索的祖先节点（如果在搜索后代时再次撞见 `1`，说明当场抓到了环）。
- **2 (黑色)**：已经安全走完、确认无环的安全节点。

**Python3 代码**：
```python
class Solution(object):
    def canFinish(self, numCourses, prerequisites):
        # 1. 建立邻接表
        adj = [[] for _ in range(numCourses)]
        for cur, pre in prerequisites:
            adj[pre].append(cur)
            
        # 2. 三色标记数组：0=未访问, 1=访问中(递归栈中), 2=已安全
        visited = [0] * numCourses
        
        def dfs(node):
            if visited[node] == 1:  # 撞见正在递归中的祖先，发生回溯死锁！
                return False
            if visited[node] == 2:  # 已经查过安全的节点，直接放行
                return True
                
            # 标记为“正在冲锋中（灰色）”
            visited[node] = 1
            
            # 递归遍历所有后置课程
            for neighbor in adj[node]:
                if not dfs(neighbor):
                    return False
                    
            # 递归顺利到底，安全核销，标记为“已安全（黑色）”
            visited[node] = 2
            return True
            
        # 3. 对每一门课都发起一次 DFS（防止图是不连通的孤岛）
        for i in range(numCourses):
            if visited[i] == 0:
                if not dfs(i):
                    return False
                    
        return True
```

### ⏱️ 五、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：O(V + E)
  - 其中 V 是课程数（顶点数），E 是先修条件数（边数）。每一门课和每一条因果依赖边都最多被遍历访问一次。
- **空间复杂度**：O(V + E)
  - 用于存储邻接表 `adj`、状态数组以及递归调用栈的内存开销。

 # LeetCode 127. Word Ladder (单词接龙) 详解

## 📝 一、 题目描述 (Description)
字典 `wordList` 中从单词 `beginWord` 和 `endWord` 的 **转换序列** 是一个按下述规格形成的序列 `beginWord -> s1 -> s2 -> ... -> sk`：
* 每一对相邻的单词只差一个字母。
* 对于 `1 <= i <= k` 时，每个 `si` 都在 `wordList` 中。注意，`beginWord` 不需要在 `wordList` 中。
* `sk == endWord`

给你两个单词 `beginWord` 和 `endWord` 和一个字典 `wordList` ，返回 *从 `beginWord` 到 `endWord` 的**最短转换序列中的单词数目***。如果不存在这样的转换序列，返回 `0`。

* **示例 1**：
  * **输入**：`beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log","cog"]`
  * **输出**：`5`
  * **解释**：一个最短转换序列是 `"hit" -> "hot" -> "dot" -> "dog" -> "cog"`，返回它的长度 5。

## 🏛️ 二、 核心物理直觉 (Core Intuition)
1. **物理翻译**：标准的**隐式图最短路径问题**。每一个单词是一个节点，若两个单词只差一个字母，它们之间就有一条无向边。
2. **为什么用 BFS**：广度优先搜索（BFS）天然具备“逐层平推”的特权。在无权图中，**第一次撞见 `endWord` 时的步数，必定是全局最短的转换序列长度**。
3. **搜索优化技巧**：为了避免每次遍历整个 `wordList` 去检查谁和当前单词相差一个字母（太慢了），我们直接对当前单词的每一个字符位置进行 26 个字母的**“原地替换变身”**，看变出来的 `next_word` 是否在哈希集合中。如果在，立刻将其加入队列并从集合中剔除（防止重复访问陷入死循环）。

## 💻 三、 完美 Python3 通关代码 (Solution)
```python
from collections import deque
from typing import List

class Solution:
    def ladderLength(self, beginWord: str, endWord: str, wordList: List[str]) -> int:
        wordSet = set(wordList)
        if endWord not in wordSet:
            return 0
            
        # BFS 队列，存储元组 (当前单词, 当前步数)
        queue = deque([(beginWord, 1)])
        
        while queue:
            word, steps = queue.popleft()
            if word == endWord:
                return steps
                
            # 对当前单词的每一个位置进行 26 个字母的替换尝试
            for i in range(len(word)):
                for c in 'abcdefghijklmnopqrstuvwxyz':
                    next_word = word[:i] + c + word[i+1:]
                    if next_word in wordSet:
                        wordSet.remove(next_word)  # 访问过立刻注销，防止死循环
                        queue.append((next_word, steps + 1))
                        
        return 0
```

### ⏱️ 四、 复杂度核验 (Complexity Analysis)
- **时间复杂度**：O(M^2 * N)
  - 其中 M 是单词的长度，N 是 `wordList` 中单词的总数。总共有 N 个单词，每个单词有 M 个位置，每个位置尝试 26 种可能，字符串切片拼接耗时 O(M)。
- **空间复杂度**：O(M * N)
  - 哈希集合 `wordSet` 存储所有单词以及 BFS 队列在峰值时的空间开销。

# 为什么隐式图不需要一开始就建好邻接表和入度数组？

为什么会有这种“隐式图必须一开始就建好邻接表和入度数组”的错觉？因为我们在学数据结构时，课本上教的几乎全是**“显式图（Explicit Graph）”**：
老师发给你一张现成的表格、或者一张存了所有邻居的 `adj` 矩阵，告诉你“图长这样，你拿去遍历吧”。这种属于明牌开局。

但到了像 **127. 单词解龙 (Word Ladder)** 这种高难度题目里，考官根本不按套路出牌，直接给你来了一局**“战争迷雾（Fog of War）”**：
- 考官只给了你一个起点 `"hit"`、一个终点 `"cog"`，以及一堆零散的单词库。
- 整张图的连线在哪里？全在空气中！
- 它的邻接关系并不是“提前写在内存里的数据”，而是由“每次只能改动一个字母、且必须在字典里”这条物理规则动态决定的。

## 💡 隐式图的本质区别

| 特征维度 | 显式图（如课程表 207） | 隐式图（如单词解龙 127） |
| :--- | :--- | :--- |
| **图的结构** | **明牌**。节点和边老老实实写在 `prerequisites` 里，你必须先建好邻接表和入度数组。 | **暗牌**。没有边，没有邻居列表，只有一套**“变身规则”**。 |
| **怎么找到邻居？** | 查邻接表 `adj[node]` 就能直接知道谁和谁相连。 | **现场盲猜**。通过对当前节点做 26 个字母的“原地替换”，去字典里查一下谁活下来了，活下来的那个才临时和它连上一条边。 |

所以，“隐式”的意思就是：图本来就在那，但它没有被实例化建表。你需要一边用 BFS 走路，一边用算法规则去**“凭空探测和生成”**它的邻居！
