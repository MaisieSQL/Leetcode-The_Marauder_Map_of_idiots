## 🗺️ 第一部分：面对一道新题目，如何像侦探一样“找出所有解法”？

### 解法流派一：暴力穷举流 (Brute Force)
* **物理直觉**：不管三七二十一，能不能用最笨的 `for` 循环、双层嵌套把所有情况都试一遍？
* **作用**：它是保底防线。只要能写出暴力解，你就至少拿到了 $\mathcal{O}(N^2)$ 或 $\mathcal{O}(2^N)$ 的基础分，并且彻底摸清了题目的输入输出边界。

### 解法流派二：空间换时间流 (Hash / Cache / Space-Time Trade-off)
* **物理直觉**：如果暴力遍历太慢，是因为重复计算了，或者每次找数据都要挨个搜。我能不能多开辟一点内存（比如用哈希表、集合、前缀和数组）把中间结果存起来？
* **作用**：这是从 $\mathcal{O}(N^2)$ 跃迁到 $\mathcal{O}(N)$ 的最常见手段（例如两数之和用哈希表代替双循环）。

### 解法流派三：秩序与单调性利用流 (Sorting / Binary Search / Two Pointers)
* **物理直觉**：如果题目给的数组是乱的，我能不能先排序？或者利用“单调性”上场，用二分查找或双指针把复杂度压到 $\mathcal{O}(N \log N)$ 或 $\mathcal{O}(\log N)$？

# LeetCode 704. 二分查找 (Binary Search) ── 全解法对比与最优解锁定剖析

我们将严格按照你的要求：发散所有解法 ➔ 横向优劣对比 ➔ 演示如何通过罗盘瞬间锁定最优解 ➔ 最终呈现通关路径与源码。全程拒绝废话，直接上干货！

## 🧭 第一步：审题与破局罗盘快速扫描

1. **看数据规模 ($N$)**：题目给出的数组长度通常在 $1 \sim 10^4$ 量级，且数组是升序排列的。
2. **看关键词信号（Keywords）**：看到“有序数组 (Sorted Array)”和“查找目标值 (Search Target)”，脑子里的罗盘瞬间发出信号：**二分查找门派，闭眼直接上！**

## 🔍 第二步：全解法发散（从笨到精）

面对这道题，我们能想到以下三种解法：

### 1. 解法流派一：暴力穷举流 (Linear Search)
* **物理直觉**：不管三七二十一，用 `for` 循环从头到尾一个一个数去比对，直到找到 `target`。
* **复杂度**：时间复杂度 $\mathcal{O}(N)$，空间复杂度 $\mathcal{O}(1)$。
* **缺点**：根本没有利用题目给的“有序”这一大前提，在大数据量下效率极低。

### 2. 解法流派二：哈希表空间换时间流 (Hash Map)
* **物理直觉**：既然要频繁查找，我一开始用一个哈希集合把所有数字存起来，以后每次查 `target` 只要 $\mathcal{O}(1)$。
* **复杂度**：时间复杂度预处理 $\mathcal{O}(N)$、查询 $\mathcal{O}(1)$，但空间复杂度直接飙升到 $\mathcal{O}(N)$。
* **缺点**：杀鸡用牛刀，多开辟了不必要的内存空间。

### 3. 解法流派三：秩序与单调性利用流 ── 标准二分查找 (Binary Search)
* **物理直觉**：既然数组已经从小到大排好序了，每次取中间的数比大小：如果比目标大，说明目标在左边，直接把右半边全部抛弃（对半砍）！
* **复杂度**：时间复杂度 $\mathcal{O}(\log N)$，空间复杂度 $\mathcal{O}(1)$。
* **优点**：时间和空间全部压榨到极致，工业界的绝对最优解。

## ⚔️ 第三部分：全解法横向对比矩阵

| 评估维度 | 暴力穷举流 (Linear Search) | 哈希表流 (Hash Map) | 二分查找流 (Binary Search) |
| :--- | :--- | :--- | :--- |
| **时间复杂度** | $\mathcal{O}(N)$（太慢） | 预处理 $\mathcal{O}(N)$ / 查询 $\mathcal{O}(1)$ | **$\mathcal{O}(\log N)$（最快）** |
| **空间复杂度** | $\mathcal{O}(1)$ | $\mathcal{O}(N)$（浪费内存） | **$\mathcal{O}(1)$（极致轻量）** |
| **是否利用有序性** | ❌ 没有利用 | ❌ 没有利用 | **✅ 完美利用** |
| **评判结论** | 被淘汰 | 被淘汰 | **🏆 唯一的绝对最优解** |

## 🎯 第四部分：最优解路径确认与慢动作拆解

既然通过罗盘锁定了二分查找，在写代码时，最容易翻车的是什么？——**边界条件（`left <= right` 还是 `left < right`？ `right = mid - 1` 还是 `right = mid`？）**。

我们用经典的**【左闭右闭区间 `[left, right]`】**模板来完美收网：
1. **初始化**：`left = 0`, `right = len(nums) - 1`（区间两端都包住）。
2. **循环条件**：`while left <= right`（只要区间里还有格子，就继续找）。
3. **中间指针计算**：`mid = left + (right - left) // 2`（防止数字太大相加溢出）。
4. **收缩指针**：
   * 如果 `nums[mid] == target`，直接返回 `mid`。
   * 如果 `nums[mid] < target`，说明目标在右边，`left = mid + 1`。
   * 如果 `nums[mid] > target`，说明目标在左边，`right = mid - 1`。

## 💻 第五部分：Python3 完美通关代码 (Solution)

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = left + (right - left) // 2
            
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
                
        return -1
```

### 📊 第六部分：复杂度核验 (Complexity Analysis)

* **时间复杂度**：$\mathcal{O}(\log N)$。每次循环把搜索区间对半砍，效率呈指数级上升。
* **空间复杂度**：$\mathcal{O}(1)$。只用了常数个指针变量（`left`, `right`, `mid`），没有占用额外的动态内存。

写二分查找之所以容易写出 Bug 甚至陷入万劫不复的死循环，根本原因就在于：你的“区间定义（区间语义）”和你的“边界收缩逻辑、循环条件”没有对齐！

二分查找在工业界和面试中，最主流的写法其实有两大宗派：
* **第一派：左闭右闭区间 `[left, right]`**
* **第二派：左闭右开区间 `[left, right)`**

咱们今天把这两大流派的代码实现、物理直觉、边界对齐逻辑以及它们的优劣对比，用最透彻的大白话一次性彻底盘个底朝天！


## 🛡️ 流派一：左闭右闭区间 `[left, right]` ── “稳健严谨流”

### 1. 物理直觉与核心定义
* **定义**：`left` 和 `right` 都指向数组中真实存在的、合法的有效格子。
* **初始化**：`left = 0`, `right = len(nums) - 1`（两端全部包住）。
* **循环条件**：`while left <= right`
  * *为什么可以用 `<=`？* 因为当 `left == right` 时，区间 `[left, right]` 里其实还剩最后一个数字没有被检测过（比如 `[3, 3]` 代表数组下标 3 那个格子）。如果写成 `<`，这个最后的格子就会被漏掉！
* **边界收缩逻辑**：
  * 如果 `nums[mid] < target`，说明目标在 `mid` 的右边。因为 `mid` 已经被确认不是目标了，所以左边界要跨过 `mid`，即：`left = mid + 1`。
  * 如果 `nums[mid] > target`，说明目标在 `mid` 的左边，右边界收缩：`right = mid - 1`。

### 2. 代码实现

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = left + (right - left) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
                
        return -1
```

### 🚀 流派二：左闭右开区间 `[left, right)` —— “激进前卫流”

#### 1. 物理直觉与核心定义

* **定义**：`left` 指向合法的格子，而 `right` 指向一个“永远取不到的越界虚拟边界”（即区间包含 `left`，但不包含 `right`）。
* **初始化**：`left = 0`, `right = len(nums)`（注意：`right` 是数组长度，直接指向尾部的下一个空气位）。
* **循环条件**：`while left < right`
  * **为什么只能用 `<`？** 因为当 `left == right` 时（比如 `[2, 2)`），左闭右开区间里已经没有任何合法的格子了（左边闭合、右边开区间等于什么都没夹住），此时循环必须立刻终止。如果你写了 `<=`，会导致死循环或者数组越界！
* **边界收缩逻辑**：
  * 如果 `nums[mid] < target`，左边界更新：`left = mid + 1`。
  * 如果 `nums[mid] > target`，因为右边界本来就是开区间（取不到），所以可以直接把 `right` 赋值为 `mid`，即：`right = mid`。
 

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums)
        
        while left < right:
            mid = left + (right - left) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid  # 注意这里没有 -1
                
        return -1
```

⚔️ 两大流派横向深度对比矩阵

| 维度对比 | 左闭右闭流 `[left, right]` | 左闭右开流 `[left, right)` |
| :--- | :--- | :--- |
| **区间初始化** | `right = len(nums) - 1`（指向最后一个元素） | `right = len(nums)`（指向长度，即越界位） |
| **循环条件** | `while left <= right`（包含等于号） | `while left < right`（不含等于号） |
| **当 `nums[mid] > target` 时** | `right = mid - 1` | `right = mid` |
| **思维负担** | 极低。符合人类直觉（两边都是真实的边界） | 略高。需要时刻记住 `right` 指向的是空气 |
| **适用场景** | 绝大多数基础二分查找、寻找单一精确值 | 查找左边界 / 右边界的变体题（如 LeetCode 34） |
