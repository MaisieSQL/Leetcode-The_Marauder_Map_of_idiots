# LeetCode 622. Design Circular Queue (设计循环队列)

## 📋 一、 官方题目描述 (Problem Description)

设计你的循环队列实现。循环队列是一种线性数据结构，其操作表现基于 FIFO（先进先出）原则并且队尾被连接在队首之后以形成一个循环。它也被称为“环形缓冲器”。

支持以下实现：
- `MyCircularQueue(k)`: 构造器，设置队列的大小为 `k`。
- `Front`: 从队首获取元素。如果队列为空，返回 `-1`。
- `Rear`: 获取队尾元素。如果队列为空，返回 `-1`。
- `enQueue(value)`: 向循环队列插入一个元素。如果成功插入则返回真。
- `deQueue()`: 从循环队列中删除 an 元素。如果成功删除则返回真。
- `isEmpty()`: 检查循环队列是否为空。
- `isFull()`: 检查循环队列是否已满。

## 🏛️ 二、 核心物理直觉：大巴士环形转圈与取模控盘
工业级单向队列如果频繁出队，前面的内存空间会产生严重的“空间碎片黑洞”。我们需要用**固定长度的数组首尾缝合，手操一辆在内存里死循环转圈的无尽大巴士**。

* **指针设计**：使用 `head`（车头指针）和 `tail`（车尾指针），并利用求余运算 `% capacity` 实现无缝循环。
* **容量策略**：为了完美区分“队列完全空”和“队列完全满”，我们可以多开辟一个物理格子（实际数组大小为 `k + 1`），或者维护一个当前元素计数器 `count`。

## 💻 三、 Python3 工业级标准实现 (Solution)

```python
class MyCircularQueue(object):

    def __init__(self, k):
        """
        :type k: int
        """
        self.capacity = k + 1
        self.queue = [0] * self.capacity
        self.head = 0
        self.tail = 0

    def enQueue(self, value):
        """
        :type value: int
        :rtype: bool
        """
        if self.isFull():
            return False
        self.queue[self.tail] = value
        self.tail = (self.tail + 1) % self.capacity
        return True

    def deQueue(self):
        """
        :rtype: bool
        """
        if self.isEmpty():
            return False
        self.head = (self.head + 1) % self.capacity
        return True

    def Front(self):
        """
        :rtype: int
        """
        if self.isEmpty():
            return -1
        return self.queue[self.head]

    def Rear(self):
        """
        :rtype: int
        """
        if self.isEmpty():
            return -1
        # tail 指向的是下一个写入的位置，因此真正的队尾是 (tail - 1) % capacity
        return self.queue[(self.tail - 1) % self.capacity]

    def isEmpty(self):
        """
        :rtype: bool
        """
        return self.head == self.tail

    def isFull(self):
        """
        :rtype: bool
        """
        return (self.tail + 1) % self.capacity == self.head```
```

四、 复杂度核验 (Complexity Analysis)
- 时间复杂度：$O(1)$，所有操作（`enQueue`、`deQueue`、`Front`、`Rear`、`isEmpty`、`isFull`）均为常数时间。
- 空间复杂度：$O(K)$，其中 $K$ 为队列的指定容量。

# LeetCode 235. Lowest Common Ancestor of a Binary Search Tree (二叉搜索树的最近公共祖先)

## 📋 一、 官方题目描述 (Problem Description)
给定一个二叉搜索树（BST），找到该树中两个指定节点的最近公共祖先。
百度百科中最近公共祖先的定义为：“对于有根树 T 的两个节点 p、q，最近公共祖先表示为一个节点 x，满足 x 是 p、q 的祖先且 x 的深度尽可能大（一个节点也可以是它自己的祖先）。”

## 🪓 二、 核心物理直觉：BST 黄金二分导航塔
这道题比普通二叉树的最近公共祖先（LeetCode 236）简单得多！因为这是一棵二叉搜索树（BST）：
- 左子树的所有节点值都小于当前节点值。
- 右子树的所有节点值都大于当前节点值。

因此，我们根本不需要后序遍历盲目上报，直接靠数值大小一路向下“二分导航”：
1. 如果 `p.val` 和 `q.val` 都比当前节点小，说明它们全在左边，无脑左转（`root = root.left`）。
2. 如果 `p.val` 和 `q.val` 都比当前节点大，说明它们全在右边，无脑右转（`root = root.right`）。
3. 如果一个在左、一个在右（或者其中一个正好等于当前节点），说明当前节点就是它们分道扬镳的“分水岭”，也就是我们要找的最近公共祖先！

## 💻 三、 Python3 工业级标准实现 (Solution)

```python
# Definition for a binary tree node.
# class TreeNode(object):
#     def __init__(self, x):
#         self.val = x
#         self.left = None
#         self.right = None

class Solution(object):
    def lowestCommonAncestor(self, root, p, q):
        """
        :type root: TreeNode
        :type p: TreeNode
        :type q: TreeNode
        :rtype: TreeNode
        """
        curr = root
        while curr:
            # 如果 p 和 q 的值都小于当前节点，向左子树走
            if p.val < curr.val and q.val < curr.val:
                curr = curr.left
            # 如果 p 和 q 的值都大于当前节点，向右子树走
            elif p.val > curr.val and q.val > curr.val:
                curr = curr.right
            else:
                # 遇到分叉点，当前节点即为最近公共祖先
                return curr
        return None
```

⏱️ 四、 复杂度核验 (Complexity Analysis)
- 时间复杂度：$O(H)$，其中 $H$ 是树的高度。在最坏情况下（链状树），时间复杂度为 $O(N)$；在平衡 BST 中，时间复杂度为 $O(\log N)$。
- 空间复杂度：$O(1)$（迭代写法只用了常数级别的指针变量，极度优雅）。

这个问题问得太透彻、太踩在算法核心上了！🔥 

咱们把这两个问题拆开来看：**第一，为什么查找 LCA 的时间复杂度刚好等于“树的高度 $H$”？第二，为什么在理想平衡状态下，树的高度 $H$ 会等于 $\log N$？**

### 🏛️ 一、 为什么时间复杂度是树的高度 $H$？

在二叉搜索树（BST）中寻找两个节点的最近公共祖先时，我们写的是一个 `while curr:` 循环：
* 每循环一次，`curr` 指针就会往下走一层（要么 `curr = curr.left`，要么 `curr = curr.right`）。
* 我们**绝对不会**回头往上走，也**不会**在同一层横向乱晃。
* 从根节点（Root）出发，最倒霉的情况是什么？就是一路向下，一直走到整棵树的最深处（叶子节点）。

这就好比你在爬一座山，每一步都必须往下迈一层台阶。当你从山顶走到最底部的叶子节点时，你一共走了多少步？**不多不少，刚好就是这座山的高度（Height，即 $H$）！** 
所以，最坏情况下的步数，直接决定了时间复杂度就是 $\mathcal{O}(H)$。

### 📐 二、 为什么平衡树的高度 $H$ 会等于 $\log N$？

这就必须请出经典的**“二分思想（Binary Splitting）”**了。

想象一下，如果这棵树是一棵**完美的平衡二叉搜索树（Balanced BST）**（就像 AVL 树或红黑树那样，左右两边的子树高度极其对称）：
1. **第一层（根节点）**：管辖全场的 $N$ 个节点。
2. **第二层**：一分为二，每边管辖 $\frac{N}{2}$ 个节点。
3. **第三层**：再一分为二，每边管辖 $\frac{N}{4}$ 个节点。
4. **第 $H$ 层**：一直往下分，直到每个叶子节点只剩下最后 1 个元素。

我们用数学公式把这个过程倒过来推导：
- 每一层节点数翻倍，经过 $H$ 层后，总节点数 $N$ 可以表示为：
  $$2^H \approx N$$
- 两边同时取以 2 为底的对数（$\log_2$）：
  $$H \approx \log_2(N)$$

这就是 $\log N$ 的物理本质！它代表的是**“对折的次数”**或者**“把 $N$ 个元素对半切、不断缩小范围，切多少次才能切到只剩 1 个”**的次数。

### ⚠️ 三、 极端情况的反例警示

不过，这里必须加一个非常重要的前提：**$\log N$ 只有在树是“平衡”的时候才成立。**

* **平衡状态（Balanced BST）**：树高 $H = \log N$。时间复杂度是 $\mathcal{O}(\log N)$。
* **极端退化状态（Skewed Tree / 链状树）**：如果插入的数字是有序的（比如 1, 2, 3, 4, 5 全往右边插），这棵树就会退化成一根**单向的链表**。
  - 此时，高度 $H$ 直接等于节点总数 $N$。
  - 时间复杂度也会从 $\mathcal{O}(\log N)$ 退化成 $\mathcal{O}(N)$。

这就是为什么高级数据结构（如红黑树）在插入和删除时必须要进行“旋转（Rotation）”来维持平衡——**它的核心目的，就是死死把树高 $H$ 压在 $\log N$ 的量级，保证任何查找操作永远都能享受对数级别的极速降维打击！** 🚀🔥
