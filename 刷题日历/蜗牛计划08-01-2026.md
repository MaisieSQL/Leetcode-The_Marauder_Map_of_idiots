### 169. Majority Element (多数元素)

* **难度**: 🟢 Easy
* **LeetCode 链接**: [Link](https://leetcode.com/problems/majority-element/)

### 💡 核心解法：Boyer-Moore 投票算法 (最优解)
由于题目说明“多数元素一定会存在且占据数组的一半以上（$> \lfloor n/2 \rfloor$）”，我们可以用计数抵消的思想：
1. **候选人 (`candidate`) 与 票数 (`count`)**：
   * 遍历数组，如果 `count == 0`，则将当前元素设为新的候选人。
   * 如果当前元素等于候选人，`count += 1`；如果不等于，`count -= 1`。
2. **原理**：由于多数元素的数量超过了一半，它最终留下的“投票”一定能胜过所有其他元素的抵消，成为最后的胜利者。

### 💻 Python 代码实现

```python
class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        count = 0
        candidate = None
        
        for num in nums:
            if count == 0:
                candidate = num
            count += (1 if num == candidate else -1)
            
        return candidate
```

⏱ 复杂度分析
* **时间复杂度**: $O(N)$，只需对整个数组进行一次线性扫描。
* **空间复杂度**: $O(1)$，只需要常数级别的额外变量（`count` 和 `candidate`）来记录状态。

### 189. Rotate Array (轮转数组)

* **难度**: 🟡 Medium
* **LeetCode 链接**: [Link](https://leetcode.com/problems/rotate-array/)

### 暴力解法: 💡 数组切片法（Python 经典解法）

```python
class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        k %= n
        # Python 的切片本质上就是在做“移位和拼接”
        nums[:] = nums[-k:] + nums[:-k]
```

`nums[-k:]`（最后 $k$ 个元素）正好就是“超出部分被剪掉放到最前面”的那截，而 `nums[:-k]` 就是剩下的部分。两边一拼接，完美解决！

---

### ⚖️ 该方法的优缺点分析

* **优点（极其直观）**：
  * 逻辑完全符合人类的正向思维。
  * 不需要动用数学对称性魔术（三次翻转），脑子里想象一下就能写出来，代码极度简短。

* **缺点（空间开销）**：
  * 需要在内存中开辟新空间来存储拼接后的结果。
  * 时间复杂度为 $O(N)$（复制元素），但空间复杂度也达到了 $O(N)$。

### 🎯 为什么面试中会被追问？

LeetCode 对 189. Rotate Array 的进阶要求是：使用 $O(1)$ 的原地空间复杂度（In-place）。

* **面试策略**：在真实面试中，如果一开始提出这个“切片拼接”的方法，面试官会非常认可你的逻辑，因为它清晰、正确率高，能快速通过。
* **进阶追问**：但随后，面试官通常会追问一句：“能不能不占用额外的内存，直接在原数组上修改？”
* 这时候，就是我们前面讨论的**“三次翻转法（Three-Reversal Method）”**登场的最佳时机了。

### 💡 核心解法：三次翻转法 (Three-Reversal Method) —— $O(1)$ 空间最优解
为了满足题目要求的 **$O(1)$ 原地空间复杂度**，我们可以利用“三次局部翻转”的对称性魔术，在不借助额外数组的情况下实现向右滚动 $k$ 位。

#### 🪄 三步翻转逻辑：
1. **整体反转** (`0` 到 `n-1`)：把整个数组倒过来，让原本在右侧的后 $k$ 个元素整体甩到最左边。
2. **翻转前 $k$ 个** (`0` 到 `k-1`)：让最前面这 $k$ 个元素“正过脸来”，恢复正确顺序。
3. **翻转剩下的** (`k` 到 `n-1`)：让后面大半截元素也“正过脸来”，恢复正确顺序。

### 💻 Python 代码实现

```python
class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        k %= k and n  # 防止 k 大于数组长度
        
        # 定义双指针原地翻转函数
        def reverse(start: int, end: int):
            while start < end:
                nums[start], nums[end] = nums[end], nums[start]
                start, end = start + 1, end - 1
                
        # 三步翻转法
        reverse(0, n - 1)     # 1. 整体翻转
        reverse(0, k - 1)     # 2. 翻转前 k 个
        reverse(k, n - 1)     # 3. 翻转剩下的
```

⏱ 复杂度分析
* **时间复杂度**: $O(N)$，每个元素在翻转过程中大约被访问和交换常数次，总共进行三次线性扫描级别的操作。
* **空间复杂度**: $O(1)$，只使用了几个指针变量，完全在原数组上进行原地修改。

### 881. Boats to Save People (救生艇)

* **难度**: 🟡 Medium
* **LeetCode 链接**: [Link](https://leetcode.com/problems/boats-to-save-people/)

从直观的**暴力模拟（Simulation / Brute Force）**角度出发，我们可以把“从大到小遍历、寻找最优配对”的过程直接写成代码。

### 🔨 暴力模拟核心思路

1. **从大到小排序**：
   * 将所有人按体重从重到轻排序。
2. **依次安顿每个人**：
   * 遍历每个人（从最重的开始）。如果这个人还没上过船，他就要占一艘船。
   * **暴力搜索配对**：为了让这艘船尽可能载两个人，我们在**剩下的人当中**去暴力扫描/搜索：有没有谁能跟他一起坐船（即体重相加 $\le \text{limit}$）？
   * 如果找到了合适的人，就把那个人也标记为“已上船”；如果找不到，就让他独自单走。

### 💻 Python 代码实现（暴力模拟版）

```python
class Solution:
    def numRescueBoats(self, people: List[int], limit: int) -> int:
        # 1. 从大到小排序
        people.sort(reverse=True)
        n = len(people)
        visited = [False] * n  # 记录每个人是否已经上船
        boats = 0
        
        # 2. 依次处理每个人
        for i in range(n):
            if visited[i]:
                continue
            
            # 当前最重的人上船，船数 +1
            visited[i] = True
            boats += 1
            
            # 3. 暴力内层循环：在剩余的人中寻找一个能和他拼船的人
            # 从数组尾部（最轻的区域）开始往前找
            best_match = -1
            for j in range(n - 1, i, -1):
                if not visited[j] and people[i] + people[j] <= limit:
                    best_match = j
                    break  # 找到一个合法的就停下
            
            # 如果找到了搭档，标记对方也已上船
            if best_match != -1:
                visited[best_match] = True
                
        return boats
```

⏱ 复杂度分析
* **时间复杂度**: $O(N^2)$。因为外层循环需要遍历每个人（$N$ 次），而内层循环为了找搭档又需要进行线性扫描（最坏情况下也要扫 $N$ 次），导致总开销达到平方级别。当数据量很大时会超时。
* **空间复杂度**: $O(N)$。需要额外的 `visited` 数组来记录每个人的上船状态。

### 💡 核心解法：排序 + 左右双指针贪心

这道题的规则是：每艘船最多载 **两人**，且总重量不能超过 `limit`。要求用最少的船送所有人过河。

#### 🧠 贪心策略与思路：
1. **优先安顿“最重的人”**：
   * 数组里体重最大的人最难找到搭档。我们每次都用当前最重的人去和**全场最轻的人**尝试组队。
2. **双指针夹击**：
   * `left` 指向最轻的人，`right` 指向最重的人。
   * 如果 `people[left] + people[right] <= limit`：太棒了，最轻的和最重的成功拼船，`left += 1`, `right -= 1`，船数 `+1`。
   * 如果总重量超限：说明最重的人哪怕和全场最轻的搭伙也超载了，证明**没有任何人能带得动他**。只能让他自己单走一艘船，`right -= 1`，船数 `+1`。

### 💻 Python 代码实现

```python
class Solution:
    def numRescueBoats(self, people: List[int], limit: int) -> int:
        people.sort()
        left, right = 0, len(people) - 1
        boats = 0
        
        while left <= right:
            # 如果最轻的和最重的加起来小于等于 limit，两人共用一艘船
            if people[left] + people[right] <= limit:
                left += 1
            # 无论能不能共用，最重的那个人肯定是要上船的（要么双人，要么单人）
            right -= 1
            boats += 1
            
        return boats
```

⏱ 复杂度分析
* **时间复杂度**: $O(N \log N)$，主要耗时在最初对 `people` 数组的排序上，随后的双指针线性扫描是 $O(N)$。
* **空间复杂度**: $O(1)$ 或 $O(N)$，取决于底层排序算法所使用的额外空间。
