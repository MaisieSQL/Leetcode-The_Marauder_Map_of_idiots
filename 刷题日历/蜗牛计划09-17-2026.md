# 867. 转置矩阵 (Transpose Matrix)

## 📝 1. 题目描述 (Description)
给你一个二维整数数组 `matrix`，返回 `matrix` 的 **转置矩阵** 。
矩阵的 **转置** 是指将矩阵的主对角线翻转，交换行索引与列索引（即 $matrix[i][j]$ 变成 $matrix[j][i]$）。

* **示例 1**：
  * **输入**：`matrix = [[1,2,3],[4,5,6],[7,8,9]]`
  * **输出**：`[[1,4,7],[2,5,8],[3,6,9]]`

* **示例 2**：
  * **输入**：`matrix = [[1,2,3],[4,5,6]]`
  * **输出**：`[[1,4],[2,5],[3,6]]`

## 🏛️ 2. 核心物理直觉与避坑指南 (Core Intuition)
* **为什么不能原地修改（In-place）？**
  * 如果矩阵不是方阵（例如 $2 \times 3$ 变成 $3 \times 2$），直接在原矩阵上用 `matrix[i][j] = matrix[j][i]` 会发生**数组下标越界**。
  * 即使是方阵，如果在原矩阵内部盲目互换，上半部分和下半部分的数据会互相覆盖，导致转置失败。
* **终极正解（开辟新矩阵流）**：
  * 原矩阵的大小是 $M \times N$，转置后的新矩阵大小必然是 $N \times M$。
  * 我们只需要新建一个大小为 $N \times M$ 的新矩阵，然后通过完美的坐标倒置：`res[j][i] = matrix[i][j]`，就能稳妥、安全地把数据填进去！

## 💻 3. Python 3 工业级标准实现 (Solution)

```python
class Solution:
    def transpose(self, matrix: list[list[int]]) -> list[list[int]]:
        m, n = len(matrix), len(matrix[0])
        
        # 创新一个大小为 (n x m) 的新矩阵，初始值填 0
        res = [[0] * m for _ in range(n)]
        
        for i in range(m):
            for j in range(n):
                # 完美的坐标倒置：原图的 [i][j] 扔到新图的 [j][i]
                res[j][i] = matrix[i][j]
                
        return res
```

📊 复杂度核验 (Complexity Analysis)

复杂度分析 (Complexity Analysis)时间复杂度：O(M x N) — 矩阵一共有 M x N 个格子，我们双重循环对其进行了全量线性扫描，每个格子刚好被搬运一次，这是理论上的极限速度。
 
空间复杂度：O(M x N) — 题目要求的返回值本身就是一个新矩阵（尺寸为 N x M），这部分空间是合法且不可省去的输出开销。

# 134. 加油站 (Gas Station) - 各种解法全解析

## 📝 1. 题目描述 (Description)
在一条环路上有 `n` 个加油站，其中第 `i` 个加油站有汽油 `gas[i]` 升。
你有一辆油箱容量无限的汽车，从第 `i` 个加油站开往第 `i+1` 个加油站需要消耗汽油 `cost[i]` 升。你从其中的一个加油站出发，开始时油箱为空。
给定两个整数数组 `gas` 和 `cost`，如果你可以按顺序绕环路行驶一周，则返回出发时加油站的编号，否则返回 `-1`。如果存在解，则 **保证** 它是 **唯一** 的。

* **示例 1**：
  * **输入**：`gas = [1,2,3,4,5]`, `cost = [3,4,5,1,2]`
  * **输出**：`3`


## 🛠️ 2. 解法一：暴力模拟流 (Brute Force Simulation)
### 🪓 核心设计
* **直觉思路**：最符合人类直觉的解法——既然我们不知道从哪出发能跑完一圈，那干脆**把每一个加油站都当成起点尝试一遍**！
* **具体做法**：
  1. 用外层循环枚举每一个可能的起点 `start`（从 `0` 到 `n-1`）。
  2. 用内层循环模拟从当前起点出发，顺时针开满 `n` 个站。
  3. 途中如果油箱结余小于 `0`，说明此路不通，直接跳出内层循环；如果能安然无恙跑完 `n` 圈回到起点，直接返回当前 `start`。
  4. 如果所有起点都试过了依然无解，返回 `-1`。

### 💻 Python 3 代码实现
```python
class Solution:
    def canCompleteCircuit(self, gas: list[int], cost: list[int]) -> int:
        n = len(gas)
        
        # 遍历每一个加油站作为起点
        for start in range(n):
            current_tank = 0
            success = True
            
            # 模拟从 start 出发走完一圈
            for step in range(n):
                curr_station = (start + step) % n  # 环形数组取模
                current_tank += gas[curr_station] - cost[curr_station]
                
                # 如果油量不够去下一站，说明该起点失败
                if current_tank < 0:
                    success = False
                    break
                    
            if success:
                return start
                
        return -1
```

### ⏱️ 复杂度分析
- **时间复杂度**：$\mathcal{O}(N^2)$ — 外层循环执行 $N$ 次，内层模拟跑圈最多执行 $N$ 次，双重循环在大数据量下会直接超时。
- **空间复杂度**：$\mathcal{O}(1)$ — 只使用了常数个指针变量。

### 🛠️ 3. 解法二：工业级满分解法 ── 贪心“黑白魔双账本”与断层枪毙流 (Greedy & Deficit Drop)

#### 🪓 核心设计
利用贪心思维对暴力法进行降维打击，完美避开重复验证：

* **白魔账本（大盘总账）**：全场所有的 `sum(gas)` 加起来，要是连总消耗 `sum(cost)` 都干不过，说明物质不灭定律锁死，这个大盘本身就是个亏本买卖，谁去都得破产，直接当场熔断吐出 `-1`！
* **黑魔账本（实时小账本与断层枪毙）**：
  * 只要总油量够，全场铁证如山必然存在一个真命起点。我们带上零初始油（`current_tank = 0`）假设从 `0` 站盲目出发平推。
  * 一路上只要走到某站 $i$ 突然 `current_tank < 0` 破产了，贪心资本家冷笑一声：
    > *“前面所有站积攒的油水带到这里都撑不过去，说明从最初起点到当前站 $i$ 之间的所有人全都是内鬼！谁当起点谁破产！”*
  * **一枪封喉（断层枪毙）**：根本不回头验证，起点直接大跨步跳到 $i + 1$，油箱倒干清空，拉起新团队重新开拔！

### 💻 Python 3 代码实现
```python
class Solution:
    def canCompleteCircuit(self, gas: list[int], cost: list[int]) -> int:
        # 白魔检验：总油量如果小于总消耗，直接熔断返回 -1
        if sum(gas) < sum(cost):
            return -1
            
        current_tank = 0
        start_station = 0
        
        for i in range(len(gas)):
            current_tank += gas[i] - cost[i]
            
            # 一旦黑魔小账本爆成负数，说明从 start 到 i 之间的所有站全是内鬼
            if current_tank < 0:
                start_station = i + 1   # 断层枪毙，起点大跨步移到下一站
                current_tank = 0        # 油箱清空归零
                
        return start_station
```

### ⏱️ 复杂度分析
- **时间复杂度**：O(N) — 全程只需要对数组进行单趟线性扫描（部分总和校验 + 一轮指针平推），速度达到理论极限。
- **空间复杂度**：O(1) — 仅使用了常数个指针与计数变量，没有额外开辟动态内存空间。

### ⚖️ 4. 总结与最优解判定
- **最优解**：解法二（贪心双账本流）。
- **降维原因**：通过贪心策略将暴力枚举的 O(N^2) 降维到了绝对线性的 O(N)，在时间与空间上都达到了该问题的理论极限。

### 🛠️ 核心规律与演进脉络

1. **单向自由延伸（55 & 45 题）**
   * **特点**：只要能往前跳，跳多远由你定（上限内）。
   * **本质**：不需要 DP 状态数组，单纯靠一个向右滚雪球的 `max_reach` 变量就能用贪心轻松降维。

2. **双向跳转与图连通性（1306 & 1345 题）**
   * **特点**：允许往回跳（如 III 题减去 `arr[i]`），或者可以瞬移到任何数值相同的远方（如 IV 题）。
   * **本质**：数组退化成了**隐式图 (Implicit Graph)**，必须引入图论里的最短路或遍历思维（BFS/DFS），核心在于处理好状态判重与同质跳转的剪枝。

3. **严格区间步长限制（1696 & 1871 题）**
   * **特点**：步长被锁死在 `[min, max]` 或 `[1, k]` 这样的固定区间内，过去的纯贪心失效。
   * **本质**：属于**动态规划 + 窗口降维**。当内层遍历区间导致时间复杂度退化为 O(N²) 时，必须借助**单调队列**（求区间最大值）或**滑动窗口计数**（求区间可达性）将内层查询优化到 O(1)。


### 🛠️ 这一类“跳跃/可达”问题的通用解题模版

面对一维数组上的所有“跳跃与可达”类问题（Jump Game 系列），其本质都是在寻找**状态转移的递推关系**或**图的连通性**。你可以按照以下**“四步降维法”**迅速建立解题框架：

#### 📌 第一步：审题分类（定基调）
拿到题目先看**步长限制**和**可跳跃的方向**：
1. **任意自由步长（上限内）** $\rightarrow$ **贪心法 (Greedy)**
   * 特征：能往前跳任意步，只要不超过最大限制。
   * 策略：不需 DP 数组，直接用一个向右滚雪球的 `max_reach` 变量维护边界。
2. **双向跳转或隐式瞬移** $\rightarrow$ **图论搜索 (BFS / DFS)**
   * 特征：允许往回跳，或存在“跳到所有数值相同位置”的超长距离传送。
   * 策略：数组退化为隐式图，核心在于 `visited` 判重与同质跳转剪枝。
3. **严格区间步长限制（受限于 `min/max` 或最大步数 $k$）** $\rightarrow$ **动态规划 + 窗口降维**
   * 特征：步长被锁死在一个固定区间内，过去的纯贪心失效。
   * 策略：定义 $dp[i]$，核心攻坚点在于如何把内层区间查询优化到 O(1)。

#### ⚡ 第二步：识别瓶颈与降维（破 O(N²) 魔咒）
如果写出朴素解法后发现时间复杂度达到 **O(N²)**（即每个点都要内层循环扫描一段区间或同值元素），立刻应用以下降维武器：
* **求区间可达性 / 计数** $\rightarrow$ **滑动窗口 / 前缀和**（如 Jump Game VII）。
* **求区间最值（最大得分 / 最小步数）** $\rightarrow$ **单调队列 / 单调栈**（如 Jump Game VI）。
* **多对多等值跳转** $\rightarrow$ **哈希表记录 + “用完即焚”**（如 Jump Game IV，清空对应列表防止重复扫描）。

#### 🎯 第三步：定义状态与核心变量
根据题型选择最轻量的状态维护方案：
* **贪心型**：`max_reach`（最远触及位置）、`steps`（步数）、`end`（当前步边界）。
* **DP 窗口型**：`dp[]` 数组、`reachable_count`（窗口内合法起跳点计数）或单调双端队列 `dq`。
* **图论搜索型**：`queue`（BFS 队列）、`visited`（已访问集合）、`val_to_indices`（值到下标的映射字典）。

#### 🛡️ 第四步：边界特判与死锁剪枝
在动笔或敲代码前，务必排查以下陷阱：
1. **终点直接被封死**：例如终点处的值为障碍物（如 `s[-1] == '1'`），直接秒判 `False` 或返回 `-1`。
2. **起点越界与单元素特判**：数组长度为 1 或起点本身就是终点时，步数直接为 0。
3. **循环死锁防范**：图论搜索中必须严格保证每个节点入队时立即加入 `visited`。

### 🚀 进阶路线：如何彻底掌握该系列？

如果你想把这类题型彻底吃透，可以向以下两个方向继续拓展：

* **方向一：引入图论视角（Jump Game III & IV）**
  * **LeetCode 1306 (Jump Game III)**：数组中每个位置可以向左或向右跳 `arr[i]` 步。此时数组变成了**隐式图 (Implicit Graph)**，直接上 **BFS 或 DFS** 加上 `visited` 数组判重即可。
  * **LeetCode 1345 (Jump Game IV)**：不仅能往前跳，还能跳到所有值相同的节点。这需要用 **BFS 求最短路**，并且要对相同值的节点进行哈希表索引，同时做一次性遍历剪枝（避免重复扫描相同值的整个列表导致超时）。
* **方向二：区间极值与线段树思维**
  * 当步长限制变得非常动态、或者代价带权（比如每跳一步有不同的消耗），滑动窗口不再适用时，可以尝试用**线段树 (Segment Tree)** 或**单调队列**来维护区间最值，这是处理更高级跳跃/路径题目的终极武器。

### 🚀 1871. Jump Game VII —— 今日攻坚作战计划

既然今天的主题是 **Jump Game VII (LeetCode 1871)**，结合我们刚刚盘点完的全系列通关框架，这道题正好卡在**“严格区间步长限制 + 动态规划窗口降维”**的模版上！

无需多言，直接开启今日的**“黑白魔双账本/滑动窗口”**实战演练：

### 📝 1. 题目速览与核心痛点
* **题目简述**：给你一个下标从 $0$ 开始的二进制字符串 `s` 和两个整数 `minJump` 与 `maxJump`。一开始你在下标 `0` 处。每一步，你可以从下标 `i` 跳到 `i + jump`，满足 `minJump <= jump <= maxJump` 且 `s[i + jump] == '0'`。问是否能到达最后一位 (`n - 1`)。
* **核心痛点**：如果对每个可达位置都去内层循环遍历区间 `[i + minJump, i + maxJump]`，时间复杂度会直接飙升到 **O(N · (maxJump - minJump))**，遇到大数据量直接超时 (TLE)。

### 🛠️ 2. 降维打击：动态规划 + 滑动窗口优化 (DP + Sliding Window)
* **状态定义**：$dp[i]$ 表示能否到达下标 $i$（布尔值 `True/False`）。
* **核心优化**：我们不需要每次都去遍历区间，而是**维护一个滑动窗口，用来统计当前区间内有多少个合法起跳点**（即有多少个满足条件的 `dp` 值为 `True`）。
* **窗口维护规则**：
  * 当窗口右边界向右滑动时：将 `i - minJump` 处的 `dp` 状态纳入窗口。
  * 当窗口左边界向右滑动时：将 `i - maxJump - 1` 处的 `dp` 状态移出窗口。
  * 只要当前格子 `s[i] == '0'` 且当前滑动窗口内的合法起跳点个数 `reachable_count > 0`，说明从前面某个位置跳得过来，当前位置可达 ($dp[i] = True$)。

### 💻 3. 工业级满分解法源码

```python
class Solution:
    def canReach(self, s: str, minJump: int, maxJump: int) -> bool:
        # 边界特判：如果终点本身就被堵死（是 '1'），直接宣判死刑
        if s[-1] == '1':
            return False
            
        n = len(s)
        dp = [False] * n
        dp[0] = True
        
        # 维护一个滑动窗口中可以作为起跳点的合法个数
        reachable_count = 0
        
        for i in range(1, n):
            # 1. 窗口右边界推进：纳入 i - minJump 处的起跳状态
            if i >= minJump:
                reachable_count += int(dp[i - minJump])
                
            # 2. 窗口左边界推进：移出 i - maxJump - 1 处的起跳状态
            if i > maxJump:
                reachable_count -= int(dp[i - maxJump - 1])
                
            # 3. 状态转移：当前位置是 '0' 且窗口内有合法起跳点
            if s[i] == '0' and reachable_count > 0:
                dp[i] = True
                
        return dp[-1]
```

4. 复杂度分析

时间复杂度：O(N) — 每一个位置都只进出滑动窗口一次，将原本嵌套的区间查询彻底降维成了纯线性扫描。

空间复杂度：O(N) — 使用了大小为 N 的 dp 数组存储可达状态。

### 🔍 为什么滑动窗口能工作？（原理深度拆解）

这段代码之所以显得巧妙，核心在于我们把**“寻找合法起跳点”**的过程，从一个需要反复遍历的动态区间，优化成了一个**固定大小视窗的“增量维护”**过程。

#### 1. 核心不等式：我们到底在找什么？
当我们在计算当前格子 `i` **能不能到达**时，我们需要回头看：
> **“在它前面的一段距离里，有没有任何一个格子是已经被点亮（`dp = True`）的合法起跳点？”**

根据题目要求的步长限制 `[minJump, maxJump]`，能跳到当前位置 `i` 的前置格子索引 `j` 必须满足：
`minJump <= i - j <= maxJump`

把这个不等式变换一下，求出前置格子 `j` 的范围：
`i - maxJump <= j <= i - minJump`

这意味着：**对于当前的 `i` 来说，它的合法起跳点范围是一个连续的区间：`[i - maxJump, i - minJump]`。**

#### 2. 为什么需要“滑动窗口”？
随着循环进行，`i` 每次向右移动一步（变成 `i + 1`），这个合法的起跳区间 `[i - maxJump, i - minJump]` 也会**整体向右平移一格**。

如果每次求 `i` 时，都用一个内层循环去重新数一遍这个区间里有多少个 `True`，时间复杂度就会变成 O(N × 窗口大小)，遇到大数据量直接超时。

所以，我们用一个变量 `reachable_count`（滑动窗口内的合法起跳点总数）来**动态维护**这个区间。当 `i` 往右移动时，我们只需要**“迎新送旧”**：
1. **右边新进来了谁？**（把刚进入射程的远端格子加进来）
2. **左边淘汰了谁？**（把超出了最大射程的过时格子踢出去）

#### 3. 逐行拆解那三步代码

当我们要计算当前格子 `i` 时，代码分成了三步：

##### 步骤一：右边界推进（新成员加入窗口）
```python
if i >= minJump:
    reachable_count += int(dp[i - minJump])
```

含义：随着 i 往右走，离它最近的起跳点是 i - minJump。这个位置现在正式进入了我们的射程范围。

如果 dp[i - minJump] 是 True（即 1），说明这个新成员是个合格的起跳板，我们的 reachable_count 就把它加进来（+= 1）。

##### 步骤二：左边界推进（老成员离开窗口）
```Python
if i > maxJump:
    reachable_count -= int(dp[i - maxJump - 1])
```
含义：离 i 最远的起跳极限是 i - maxJump。那么比这个极限还要左边一个的位置，也就是 i - maxJump - 1，现在太远了，跳不到了。

既然它超出了最大射程，我们就必须把它从窗口里踢出去。如果它之前是 True，现在就要从总数里减掉 (-= 1)。

##### 步骤三：状态判定
```Python
if s[i] == '0' and reachable_count > 0:
    dp[i] = True
```
含义：经过前两步的调整，现在的 reachable_count 刚好精准代表了区间 [i - maxJump, i - minJump] 里有多少个合法的起跳点。

如果当前位置本身是个坑（s[i] == '0'）并且窗口里至少有一个合法的起跳板（reachable_count > 0），那么当前位置 dp[i] 就可以被点亮为 True！

### 💡 关于 `int(dp[i - minJump])` 的运作原理

**完全正确！** 

在 Python 中：
* 布尔值 `True` 等价于整数 `1`
* 布尔值 `False` 等价于整数 `0`

所以写成 `int(dp[i - minJump])` 的作用就是：
* 如果 `dp[...]` 是 `True`，转成整数就是 `1`，执行 `reachable_count += 1`（把这个合法的起跳点算进窗口总数里）。
* 如果 `dp[...]` 是 `False`，转成整数就是 `0`，执行 `reachable_count += 0`（相当于什么都没加，不影响总数）。

这样写不仅代码极其简洁，而且省去了写 `if-else` 分支判断的麻烦，是算法题中非常经典的小技巧！
