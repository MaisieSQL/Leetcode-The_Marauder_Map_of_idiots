# LeetCode 338. Counting Bits (比特位计数)

## 📌 题目描述
给你一个整数 $n$，计算从 $0$ 到 $n$ 的每个数字 $i$ 的二进制表示中 **$1$ 的个数**，返回一个长度为 $n + 1$ 的数组 `ans` 作为答案。

* **示例 1**:
  * **输入**: `n = 2`
  * **输出**: `[0, 1, 1]`
  * **解释**:
    * $0 \to 0$ (0 个 1)
    * $1 \to 1$ (1 个 1)
    * $2 \to 10$ (1 个 1)
* **示例 2**:
  * **输入**: `n = 5`
  * **输出**: `[0, 1, 1, 2, 1, 2]`
  * **解释**:
    * $0 \to 0$ (0)
    * $1 \to 1$ (1)
    * $2 \to 10$ (1)
    * $3 \to 11$ (2)
    * $4 \to 100$ (1)
    * $5 \to 101$ (2)
* **数据范围**:
  * $0 \le n \le 10^5$
* **进阶要求 (Follow-up)**:
  * 能否在 $O(n)$ 线性时间、单趟扫描内搞定，且不调用任何内置函数（如 `__builtin_popcount`）？

## 💡 核心考点与降维直觉

题目禁止使用库函数，若对每个数字独立调用一次 Brian Kernighan 算法（`x & (x - 1)`）统计 $1$ 的个数，单次耗时 $O(\log n)$，整体时间复杂度为 $O(n \log n)$。

要想突破至 **$O(n)$ 线性单趟**，必须借助 **动态规划（DP）**，利用二进制位操作从“已经算好的较小数值”直接递推得出：

### 核心观察（最低有效位转移）

任意一个正整数 i：
1. **i >> 1（等价于整除 2）**：在二进制形态下相当于**向右平移一位、丢弃最低位**。
2. **i & 1（等价于模 2）**：用来提取**最低位是否为 1**。
3. 因此：**i 中 1 的个数，等于 i >> 1 中 1 的个数加上最低位本身**。


### 递推公式
dp[i] = dp[i >> 1] + (i & 1)

* 举例：
  * 5 的二进制为 101
  * 5 >> 1 = 2（二进制 10），此时已在前面算好 dp[2] = 1
  * 5 & 1 = 1
  * dp[5] = dp[2] + 1 = 1 + 1 = 2

由于递推依赖的 $i >> 1 < i$，从小到大遍历即可保证每个子问题在被引用前已计算完毕。

## 💻 Python 3 工业级标准实现

```python
class Solution:
    def countBits(self, n: int) -> list[int]:
        # 开辟大小为 n + 1 的 dp 数组，初始全为 0
        dp = [0] * (n + 1)
        
        # 从 1 到 n 单趟递推
        for i in range(1, n + 1):
            dp[i] = dp[i >> 1] + (i & 1)
            
        return dp
```

## ⏱️ 复杂度分析

* **时间复杂度**：$O(n)$。从 $1$ 到 $n$ 只进行单趟线性循环，每次状态转移仅包含一次位移和一次按位与操作（均为 $O(1)$ 常数时间）。
* **空间复杂度**：$O(1)$。除了用于返回结果所必须开辟的长度为 $n + 1$ 的数组外，没有分配任何额外辅助空间（若计入输出数组则为 $O(n)$）。

# 什么是 Brian Kernighan 算法？

Brian Kernighan 算法是一种用于在计算机底层统计一个整数二进制表示中 **1 的个数（汉明重量 Hamming Weight）** 的最优位运算技巧。

它的核心只有一句话：**每次执行 `n & (n - 1)`，可以在常数时间内精准抹掉二进制表示中最右侧的那个 1**。

### 1. 为什么 n & (n - 1) 能抹掉最右边的 1？

我们从二进制减法借位的原理来看：
* 当一个数减 1（即 `n - 1`）时，它最右侧的那个 1 会借位变成 0，而这个 1 右边所有的 0 都会变成 1。
* 这个 1 左边的高位则完全不受影响。
* 此时执行按位与 `n & (n - 1)`：
  * 最右边的 1 变成了 0，与原本的 1 相与结果为 0；
  * 右侧原本为 0 的位置与翻转后的 1 相与依然为 0；
  * 左边未变化的高位全部保留。

**实操演示（以数字 10 为例）**：
* 10 的二进制是 `1010`
* 10 - 1 = 9，其二进制为 `1001`
* * 执行 `1010 & 1001`：得到 `1000`（最右边的那个 1 直接被精准消除）

# 为什么 1010 & 1001 算出来是 1000？

这里的 `&` 是计算机底层的 **按位与（Bitwise AND）运算**。

按位与的判定规则：**将两个二进制数对应位置上下对齐，只有当“上下全都是 1”时，结果才为 1；只要其中有一个 0，结果就是 0。**

* 1 & 1 = 1
* 1 & 0 = 0
* 0 & 1 = 0
* 0 & 0 = 0

### 竖式逐位对齐推演

把数字 10 和 9 的二进制形式上下对齐：

```text
  1 0 1 0   (这是 10)
& 1 0 0 1   (这是 9)
---------
  1 0 0 0   (运算结果)
```

从左到右逐位结算：

* 第 1 位（最左）：1 & 1 -> 两个都是 1，结果是 1。
* 第 2 位：0 & 0 -> 结果是 0。
* 第 3 位：1 & 0 -> 上面是 1 下面是 0，结果是 0。
* 第 4 位（最右）：0 & 1 -> 上面是 0 下面是 1，结果是 0。
四位组合起来，得到运算结果：1000。

### 为什么说“最右边的 1 被精准消除了”？
对比运算前后的二进制结构：

* 运算前（10）：1 0 1 0（一共含有两个 1：一个在最左端，一个在倒数第二位）
* 运算后（8）： 1 0 0 0

最左边的 1 保持不变，而原本处于最右侧的那个 1（倒数第二位），在执行 & 之后直接变成了 0。

### 3. 底层借位原理：为什么 n & (n - 1) 永远能抹掉最右边的 1？
这是由于二进制减法借位的天然特性决定的：

* 当一个数字减去 1（n - 1）时，它最右侧的第一个 1 会因为借位而变成 0。
* 这个 1 右边原有的所有 0，会因为借位全部翻转变成 1。
* 这个 1 左侧所有更高位置的数字，完全不发生任何改变。

再以 10（1010）为例回看借位过程：

* 倒数第二位的 1 是全数最靠右侧的 1。
* 减 1 之后，这一位的 1 变成 0，而它右边的 0 翻转为 1，变成 1001。
* 此时执行 n & (n - 1) 对齐相与：
  * 左侧未变的高位：1 & 1 依然是 1。
  * 发生借位的关键位：原数是 1，减 1 后的数是 0，1 & 0 变成了 0。
  * 右侧翻转的低位：原数是 0，减 1 后的数是 1，0 & 1 依然是 0。

因此，无论整数数值多大、二进制有多长，只要执行一次 n & (n - 1)，就能在常数时间内精准消去二进制中处于最右侧的那个 1。

### 2. 标准代码实现 (Python 3)

只要 n > 0，每执行一次 `n = n & (n - 1)`，计数器就加 1，直到 n 变成 0 为止：

```python
def count_ones(n: int) -> int:
    count = 0
    while n > 0:
        n &= (n - 1)  # 抹掉最右侧的一个 1
        count += 1
    return count
```

### 3. 它比普通逐位右移好在哪？

* **普通解法（逐位右移）**：用 `n >> 1` 配合 `n & 1` 检查每一位。对于标准 32 位整型，无论里面有几个 1，循环必须死跑 **32 次**。
* **Brian Kernighan 算法**：**二进制里有几个 1，循环就只跑几次**。
  * 若输入为 8（二进制 `1000`，只有 1 个 1），循环只跑 1 次；
  * 时间复杂度严格为 O(k)，其中 k 为数字中 1 的个数，效率远高于固定 32 次遍历。

### 4. 经典高频衍生应用

除了在 LeetCode 191（位 1 的个数）中统计 1 的个数之外，它在大厂面试中最常见的变体是**判断一个数是不是 2 的幂次方**：

* **原理**：如果一个数是 2 的幂次方（如 2、4、8、16），其二进制表示中**有且仅有 1 个 1**（例如 8 为 `1000`）。
* **代码**：

```python
def is_power_of_two(n: int) -> bool:
    return n > 0 and (n & (n - 1)) == 0
```

# 为什么单次调用 Brian Kernighan 算法是 O(log n)？

这里的 O(log n) 来自于：**一个数值大小为 n 的正整数，转换为二进制后的“总位数”大约只有 log2(n) 位。**

### 1. 为什么一个数的二进制位数是 log2(n)？

以十进制为例，每增加一位，数值上限扩大 10 倍：
* 1 位数：最大到 9
* 2 位数：最大到 99（约 10^2）
* 3 位数：最大到 999（约 10^3）
* 数值 X 在十进制下的位数大约是：log10(X)

计算机二进制同理，每增加一位，表示范围翻 2 倍：
* 1 位二进制：最大表示 1 (2^1 - 1)
* 2 位二进制：最大表示 3 (2^2 - 1)
* 3 位二进制：最大表示 7 (2^3 - 1)
* k 位二进制：最大能表示到 2^k - 1

因此：**如果数值是 n，它需要的二进制位数 k 满足 2^k ≈ n，总位数即为 k ≈ log2(n)。**

* 举例验证：
  * n = 8：二进制是 1000，长度为 4 位，log2(8) = 3（约 4 位）。
  * n = 1000：二进制是 1111101000，长度为 10 位，log2(1000) ≈ 9.96（约 10 位）。

### 2. Brian Kernighan 算法的循环次数与单次耗时

Brian Kernighan 算法的核心规则是：**二进制里有几个 1，while 循环就执行几次**。

* **最好情况**：数字是 2 的幂（如 n = 8，二进制 1000），仅有 1 个 1，循环只跑 1 次。
* **最坏情况**：该数字在二进制下每一位全部都是 1（例如 n = 7，二进制 111；或 n = 15，二进制 1111）。
  * 最坏情况下，1 的个数等于**其二进制总位数**。
  * 而数值 n 的二进制总位数上限就是 log2(n)。

因此，单次调用 Brian Kernighan 算法的最坏时间复杂度为 **O(log n)**。

### 3. 为什么整体计算会变成 O(n log n)？

在 LeetCode 338 中，要求计算从 0 到 n 共计 (n + 1) 个数字的比特位：
* 外层循环遍历 0 到 n，共进行 n 次循环。
* 若对每一个数字都独立运行一遍 Brian Kernighan 算法，每个数字需耗费 O(log n)。
* 总计算量 = (外层遍历次数 n) × (单次内层最坏耗时 log n) = **O(n log n)**。

这就是为什么进阶要求（Follow-up）提出必须使用**动态规划（DP）**递推，利用状态转移将单次获取 1 的个数压缩至 O(1)，从而使整体总耗时达到线性 **O(n)**。
