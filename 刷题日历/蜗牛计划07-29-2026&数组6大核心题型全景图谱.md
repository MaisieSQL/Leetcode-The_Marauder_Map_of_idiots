# 🗺️ LeetCode 数组（Array）6 大核心题型全景图谱

## 1. 🪟 滑动窗口流 (Sliding Window)
* **物理直觉**：当题目要求我们在一个连续区间（子数组 / 子字符串）内寻找**满足某种条件的最长/最短/特定子区间**时，如果用暴力双循环，时间复杂度会飙到 $O(N^2)$。滑动窗口通过维护一个大小可变的“窗口”（用左右指针 `left` 和 `right`），像毛毛虫一样向前蠕动，将复杂度硬生生压成线性的 $O(N)$。
* **经典母题**：
  * LeetCode 3. 无重复字符的最长子串 (Longest Substring Without Repeating Characters)
  * LeetCode 209. 长度最小的子数组 (Minimum Size Subarray Sum)
* **核心破局点**：区分“固定窗口”还是“可变窗口”。可变窗口的精髓在于：`right` 负责不断扩充、寻找可行解；当违反条件时，`left` 开始追赶、收缩窗口。

---

## 2. 🔀 双指针夹逼与快慢流 (Two Pointers & Fast-Slow Pointers)
* **物理直觉**：数组如果是**有序的**，或者需要我们**在原地（In-place）对元素进行搬运、去重、筛选**，单指针往往捉襟见肘。这时候就要祭出双指针：
  * **对撞指针（左右夹逼）**：从两端向中间靠拢（典型如两数之和、盛最多水)。
  * **快慢指针**：一个在前探路，一个在后清理（典型如原地移除元素、移动零）。
* **经典母题**：
  * LeetCode 11. 盛最多水 (Container With Most Water)
  * LeetCode 27. 移除元素 (Remove Element)
* **核心破局点**：利用数组的有序性或特定规则，通过指针的单向或相向移动，跳过无数次无用的无效遍历。

---

## 3. ➕ 前缀和与差分数组流 (Prefix Sum & Difference Array)
* **物理直觉**：
  * **前缀和**：如果一个数组需要**频繁、多次查询某一个闭区间 `[i, j]` 的元素总和**，如果每次都用 `for` 循环去加，单次查询是 $O(N)$，总查询代价巨大。通过提前“打表”算出前缀和数组，可以将区间求和降维到 $O(1)$！
  * **差分数组**：反过来，如果题目要求**频繁对某一个区间整体加上或减去某个值**，差分数组能在 $O(1)$ 时间内搞定打标，最后统一做一次前缀和还原。
* **经典母题**：
  * LeetCode 560. 和为 K 的子数组 (Subarray Sum Equals K)
  * LeetCode 303. 区域和检索 - 数组不可变 (Range Sum Query - Immutable)
* **核心破局点**：
  * 前缀和的核心公式：`Sum(i, j) = Prefix[j+1] - Prefix[i]`。
  * 遇到“连续子数组和等于 K”的题目，立刻条件反射想到：**前缀和 + 哈希表优化**。

## 4. 📈 贪心与单调队列/单调栈流 (Greedy & Monotonic Stack/Queue)
* **物理直觉**：处理数组中的**极值问题**（如：接雨水、求每个滑动窗口的最大值、买卖股票的最佳时机）。这类题目通常要求我们在线性时间内做出最优决策，或者借助一个“单调递减/递增”的容器把无用的小不点提前淘汰。
* **经典母题**：
  * LeetCode 42. 接雨水 (Trapping Rain Water)
  * LeetCode 239. 滑动窗口最大值 (Sliding Window Maximum)
* **核心破局点**：单调栈/队列里存的往往不是元素本身，而是**元素的下标（Index）**，通过维持队列的单调性，实现每个元素进出栈均摊 $O(1)$。

## 5. 🔄 矩阵与空间降维流 (Matrix & In-place Simulation)
* **物理直觉**：二维数组（矩阵）的题目。核心难点不在于算法多难，而在于**坐标映射、边界控制、以及空间复杂度能否压到 $O(1)$ 的原地旋转/修改**。
* **经典母题**：
  * LeetCode 48. 旋转图像 (Rotate Image)

* **核心破局点**：寻找矩阵翻转的数学对称规律（如：先沿主对角线翻转，再左右翻转），或者严格控制四个边界指针（`top`, `bottom`, `left`, `right`）。

## 6. 🏛️ 原地哈希与置换流 (In-place Hashing / Cyclic Sort)
* **物理直觉**：当题目明确要求：**“必须在 $O(N)$ 时间内完成，且空间复杂度必须是 $O(1)$（不能开辟额外的哈希表或布尔数组）”**时，这就是原地哈希的主战场。
* **经典母题**：
  * LeetCode 41. 缺失的第一个正数 (First Missing Positive)
  * LeetCode 448. 找到所有数组中消失的数字 (Find All Numbers Disappeared in an Array)
* **核心破局点**：利用数组自身的索引作为哈希桶，通过不断的“乾坤大挪移”（交换元素），把数字 `x` 强行赶到它理应呆的索引位置（如数值 `x` 放到下标 `x-1` 处）。

# [242. Valid Anagram](https://leetcode.com/problems/valid-anagram/)

**Difficulty:** Easy  
**Topics:** Hash Table, String, Sorting  

## 题目描述 (Problem Description)

Given two strings `s` and `t`, return `true` if `t` is an anagram of `s`, and `false` otherwise.

### Example 1:
* **Input:** `s = "anagram", t = "nagaram"`
* **Output:** `true`

### Example 2:
* **Input:** `s = "rat", t = "car"`
* **Output:** `false`

### Constraints:
* `1 <= s.length, t.length <= 5 * 10^4`
* `s` and `t` consist of lowercase English letters.

### Follow up:
What if the inputs contain Unicode characters? How would you adapt your solution to such a case?

## 解题思路 (Intuition)

判断两个字符串是否互为字母异位词（Anagram），核心逻辑是**“频次抵消”**：
1. **长度先行判断：** 如果 `s` 和 `t` 的长度不相等，直接返回 `false`。
2. **频次统计与抵消：** 
   - 统计 `s` 中各字符出现的次数。
   - 遍历 `t` 的同时，将对应字符的频次减一。若中途发现频次不足或字符不存在，直接返回 `false`。

## 代码实现 (Python 3)

### 方法一：定长数组法（最优解：针对小写英文字母优化）
利用固定大小为 26 的数组代替哈希表，省去哈希计算开销，空间常数极致。

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
            
        count = [0] * 26
        for i in range(len(s)):
            count[ord(s[i]) - ord('a')] += 1
            count[ord(t[i]) - ord('a')] -= 1
            
        for c in count:
            if c != 0:
                return False
                
        return True
```

方法二：单哈希表法（通用解：支持 Unicode 字符）
当字符集扩展到全球 Unicode（如中文、Emoji）时，改用动态哈希表（字典）。

```Python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
            
        count = {}
        for char in s:
            count[char] = count.get(char, 0) + 1
            
        for char in t:
            if char not in count or count[char] == 0:
                return False
            count[char] -= 1
            
        return True
```

### 方法三：双哈希表对比法（直观易懂）

如果你觉得“边加边减”需要实时检查状态略显繁琐，也可以分别统计出 `s` 和 `t` 各自的字符频次字典，最后直接比较两个字典是否完全相等。

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
            
        dict_s, dict_t = {}, {}
        
        for char in s:
            dict_s[char] = dict_s.get(char, 0) + 1
            
        for char in t:
            dict_t[char] = dict_t.get(char, 0) + 1
            
        # 直接比较两个哈希表是否一模一样
        return dict_s == dict_t
```

用 collections.Counter(s) == Counter(t) 来做，可以说是 Python 程序员在日常开发和刷题中最偷懒、最优雅的终极武器了！

我们可以来看看它的全貌、底层原理以及在面试中的优缺点：

```python
from collections import Counter

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        
        # 一行代码搞定频次统计与比对
        return Counter(s) == Counter(t)
```

### 复杂度分析

* **时间复杂度：** $O(N)$
  * 需要完整遍历字符串来构建哈希表。
* **空间复杂度：**
  * 如果是 LeetCode 原题那种限定了小写英文字母的场景，因为最多只有 26 种字符，哈希表大小有上限，空间复杂度可以算作 $O(1)$（常数空间）。
  * 如果是面对通用的 Unicode 字符扩展（Follow-up），空间复杂度则是 $O(\Sigma)$（其中 $\Sigma$ 代表字符串中不同字符的种类数）。

### 二、 底层是怎么运行的？

1. **`Counter(s)` 和 `Counter(t)`：** 
   它们分别会遍历两个字符串，生成两个基于哈希表（`dict`）的频次统计字典。例如 `Counter("anagram")` 会变成 `{'a': 3, 'n': 1, 'g': 1, 'r': 1, 'm': 1}`。
2. **`==` 比较：** 
   Python 的 `dict`（包括 `Counter`）支持直接用 `==` 比较。它会逐个检查两个字典里的**键是否完全相同**，并且**每个键对应的频次数值也必须完全一致**。

### 三、 优缺点分析

| 维度 | 特点 | 说明 |
| :--- | :--- | :--- |
| **代码量** | 🟢 **极致简短** | 仅需一行核心逻辑，代码可读性极高。 |
| **执行性能** | 🟢 **非常快** | `collections` 模块是 C 语言底层实现的，虽然在 Python 里调用，但循环和哈希计算速度极快。 |
| **通用性** | 🟢 **完美支持 Unicode** | 和普通哈希表一样，天然支持中文、Emoji 和任意全球字符。 |
| **面试建议** | 🟡 **需谨慎使用** | 如果在面试中直接写这一行，面试官可能会觉得你“只会用库函数，没懂底层原理”。建议作为“拓展解法”提出来，或者先手写出哈希表/数组版，最后补充一句：“当然，在实际开发中用 `Counter` 最方便。” |

### 四、 核心要点总结

* **原理：** `Counter` 底层是用 C 语言实现的哈希频次统计类。`Counter(s) == Counter(t)` 会直接比对两边的键值对是否完全一致。
* **优缺点：** 代码极为优雅、执行速度快、支持 Unicode；但在技术面试中，建议先手写哈希表或数组版以展示基本功，再将 `Counter` 作为 Pythonic 的高级写法展示。


### 几种常见解法对比

| 解法名称 | 底层数据结构 | 适用场景 | 时间复杂度 | 空间复杂度 | 核心优缺点 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **定长数组法** | 固定大小数组 `[0] * 26` | 仅限小写英文字母 | $O(N)$ | $O(1)$ | 极致性能，无哈希开销；扩展性差 |
| **单哈希表法** | 动态字典 `dict` | 任意字符集（支持 Unicode） | $O(N)$ | $O(\Sigma)$ | 工业级通用，支持早期短路退出 |
| **双哈希表法** | 两个字典比对 | 任意字符集（支持 Unicode） | $O(N)$ | $O(\Sigma)$ | 逻辑直观，但略耗内存 |
| **内置库偷懒法** | `collections.Counter` | 日常刷题与脚本开发 | $O(N)$ | $O(\Sigma)$ | 代码极简，一行搞定 |

*(注：$\Sigma$ 代表字符串中不同字符的种类数。)*

### 复杂度分析

* **时间复杂度：** $O(N)$ —— 其中 $N$ 为字符串的长度。我们只需单向遍历字符串并进行 $O(1)$ 的哈希/数组读写。
* **空间复杂度：** $O(1)$ 或 $O(\Sigma)$ —— 定长数组为常数空间 $O(1)$；动态哈希表在字符种类固定或有限时占用 $O(\Sigma)$。

# [122. Best Time to Buy and Sell Stock II](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/)

**Difficulty:** Medium  
**Topics:** Greedy, Array, Dynamic Programming  

## 题目描述 (Problem Description)

You are given an integer array `prices` where `prices[i]` is the price of a given stock on the $i$-th day.

On each day, you may decide to buy and/or sell the stock. You can only hold at most one share of the stock at any time. However, you can buy it then immediately sell it on the **same day**.

Find and return the **maximum profit** you can achieve.

### Example 1:
* **Input:** `prices = [7,1,5,3,6,4]`
* **Output:** `7`
* **Explanation:** Buy on day 2 (price = 1) and sell on day 3 (price = 5), profit = 5-1 = 4.
  Then buy on day 4 (price = 3) and sell on day 5 (price = 6), profit = 6-3 = 3.
  Total profit is 4 + 3 = 7.

### Example 2:
* **Input:** `prices = [1,2,3,4,5]`
* **Output:** `4`
* **Explanation:** Buy on day 1 (price = 1) and sell on day 5 (price = 5), profit = 5-1 = 4.
  Total profit is 4.

### Example 3:
* **Input:** `prices = [7,6,4,3,1]`
* **Output:** `0`
* **Explanation:** There is no way to make a positive profit, so we never buy the stock to achieve the maximum profit of 0.

### Constraints:
* `1 <= prices.length <= 3 * 10^4`
* `0 <= prices[i] <= 10^4`

## 解题思路与数学证明 (Intuition & Proof)

### 1. 贪心策略
表面上看，这道题需要我们去寻找长线交易中的“波谷买入、波峰卖出”。但通过贪心思想，我们可以简化为：**只要今天比昨天贵（即产生正收益），我们就把这段差价收入囊中。**

### 2. 为什么贪心是正确的？（裂项相消法）
假设我们在一个上升区间内，在第 $i$ 天买入，在第 $j$ 天卖出（$P_i < P_{i+1} < \dots < P_j$），这笔长线交易的总利润为：
$$\text{Profit} = P_j - P_i$$

根据数学上的裂项相消（Telescoping Sum，类似于微积分中的定积分累加）：
$$P_j - P_i = (P_j - P_{j-1}) + (P_{j-1} - P_{j-2}) + \dots + (P_{i+1} - P_i)$$

这说明：**任何一段长线交易的利润，完全等于这一段里面所有“相邻两天正收益”的简单相加。** 
因此，局部贪心地收集每一个正收益，在数学上完全等价于全局的最优解，我们无需费心去寻找绝对的波谷和波峰。

## 代码实现 (Python 3)

```python
class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        profit = 0
        for i in range(1, len(prices)):
            # 只要今天比昨天高，就收集这部分的差价（贪心）
            if prices[i] > prices[i - 1]:
                profit += prices[i] - prices[i - 1]
        return profit
```

### 复杂度分析

* **时间复杂度：** $O(N)$ —— 其中 $N$ 是数组的长度。我们只需要对整个 `prices` 数组进行一次线性扫描。
* **空间复杂度：** $O(1)$ —— 只需要常数级别的额外变量来累加利润，不需要额外的存储空间。

股票系列（Best Time to Buy and Sell Stock）是 LeetCode 中层层递进、非常经典的 **Follow-up 宇宙**。

既然我们刚刚攻克了不限交易次数（第 122 题），面试中顺理成章的 **Follow-up 演进路线** 通常有以下三道核心好题。它们每增加一个限制条件，思维模式就要从“纯贪心”升级到**动态规划（DP）**或**状态机设计**：

### 1. 经典进阶一：限制最多完成 $K$ 笔交易
* **对应题目：** [LeetCode 188. Best Time to Buy and Sell Stock IV](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-iv/)（以及简化版的 [LeetCode 123. Best Time to Buy and Sell Stock III](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-iii/) —— 最多买卖 2 次）
* **核心变化：** 交易次数被严格限制在最多 $K$ 次。
* **思维跃迁：** 
  * 当 $K$ 很大（比如大于 $N/2$）时，退化为我们刚才的无限制贪心。
  * 但当 $K$ 是一个较小的固定值时（如 $K=2$），贪心失效，必须引入**动态规划**。我们需要定义两个状态：`buy[j]`（第 $j$ 次买入后的最大收益）和 `sell[j]`（第 $j$ 次卖出后的最大收益），通过两层循环递推。

### 2. 经典进阶二：加入“冷冻期”（Cooldown）
* **对应题目：** [LeetCode 309. Best Time to Buy and Sell Stock with Cooldown](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-cooldown/)
* **核心变化：** 卖出股票后，你无法在第二天买入股票（即必须冷冻一天）。
* **思维跃迁：**
  * 贪心彻底失效，因为“隔天冷冻”打破了局部的独立性。   
  * 这道题是标准的**状态机 DP（State Machine DP）**。每一天可以划分成三种明确的状态：
    * `hold`：当前持有股票。
    * `sold`：今天刚卖出股票（进入冷冻期前置态）。
    * `reset`：当前不持有股票且不在冷冻期（可以随时买入）。   
  * 通过维护这三种状态的每日状态转移方程即可完美解决。

### 3. 经典进阶三：加入“手续费”（Transaction Fee）
* **对应题目：** [LeetCode 714. Best Time to Buy and Sell Stock with Transaction Fee](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-transaction-fee/)
* **核心变化：** 每次买卖交易都需要支付手续费 `fee`。
* **思维跃迁：**   
  * 如果手续费很高，频繁像第 122 题那样“只要涨就买卖”就会因为手续费被薅光。
  * 这道题既可以用**动态规划**（维护 `cash` 和 `hold` 两个状态），也可以用一种带缓冲区的贪心策略去跟踪当前的有效买入成本。

# [229. Majority Element II](https://leetcode.com/problems/majority-element-ii/)

**Difficulty:** Medium  
**Topics:** Array, Hash Table, Counting, Sorting  


## 题目描述 (Problem Description)

Given an integer array of size `n`, find all elements that appear more than `⌊ n/3 ⌋` times.

### Example 1:
* **Input:** `nums = [3,2,3]`
* **Output:** `[3]`

### Example 2:
* **Input:** `nums = [1]`
* **Output:** `[1]`

### Example 3:
* **Input:** `nums = [1,2]`
* **Output:** `[1,2]`

### Constraints:
* `1 <= nums.length <= 5 * 10^4`
* `-10^9 <= nums[i] <= 10^9`

## 解题思路 (Intuition)

1. **哈希表计数 (Counter Approach):**
   * 利用 Python 的 `collections.Counter` 快速统计数组中每个元素出现的频次。
   * 阈值为 `len(nums) // 3`。
   * 遍历计数结果，筛选出出现次数**严格大于**阈值的元素并放入结果列表。
2. **数学原理 (Pigeonhole Principle):**
   * 根据鸽巢原理，出现次数超过 $\lfloor n/3 \rfloor$ 的元素**最多只有 2 个**。因此结果集的大小永远不会超过 2。

## 代码实现 (Python 3)

```python
from collections import Counter
from typing import List

class Solution:
    def majorityElement(self, nums: List[int]) -> List[int]:
        if not nums:
            return []

        threshold = len(nums) // 3
        counts = Counter(nums)

        res = []
        for num, freq in counts.items():
            if freq > threshold:
                res.append(num)
                
        return res
```

### 复杂度分析

* **时间复杂度：$O(N)$**
  * 遍历一次数组构建哈希表（`Counter`）需要 $O(N)$ 的时间。
  * 随后遍历哈希表的键值对进行筛选也需要 $O(N)$ 的时间。
  * 总时间复杂度为 **$O(N)$**。

* **空间复杂度：$O(N)$**
  * 哈希表需要存储数组中的不重复元素。在最坏情况下（所有元素各不相同），占用 $O(N)$ 的空间。
  * 根据鸽巢原理，结果集的大小最多为 2（占用 $O(1)$ 空间），因此空间瓶颈主要在于哈希表。
  * 总空间复杂度为 **$O(N)$**（若元素种类数远小于 $N$，实际空间复杂度为 $O(U)$，其中 $U$ 为不重复元素的个数）。

# [560. Subarray Sum Equals K](https://leetcode.com/problems/subarray-sum-equals-k/)

从 LeetCode 560 开始，我们就正式跨入了 **“前缀和 + 哈希表优化”** 这一经典算法模型。

我们可以分两部分来彻底拆解：为什么 560 题必须/最适合用前缀和？以及什么类型的题目应该第一时间联想到前缀和？

## 一、 为什么 LeetCode 560 要用前缀和？

### 1. 暴力解法的痛点：重复计算
求“连续子数组的和”，最直观的想法是双指针或两层循环，穷举所有可能的起点 $i$ 和终点 $j$，然后把中间的元素加起来。
* 这样做的代价是：每次计算子数组和都要重新累加，时间复杂度会飙升到 $O(N^2)$ 甚至 $O(N^3)$。

### 2. 前缀和的数学降维打击
如果我们预先计算好**前缀和 (Prefix Sum)**——即从数组开头到当前位置的总和 $P[j] = \sum_{i=0}^{j} \text{nums}[i]$，那么：
* 任意一段从 $i$ 到 $j$ 的连续子数组和，都可以瞬间表示为两个前缀和的差：
  $$\text{SubarraySum}(i, j) = P[j] - P[i-1]$$

### 3. 终极结合：前缀和 + 哈希表（Two Sum 的变体）
题目要求找到有多少对 $(i, j)$ 满足：
$$P[j] - P[i-1] = k$$
移项变形一下：
$$P[i-1] = P[j] - k$$

这就是它封神的地方！当我们从左到右遍历数组、边累加当前的前缀和 $P[j]$ 时：
* 我们其实是在问：**“在我之前走过的历史中，有没有哪个历史前缀和刚好等于 $P[j] - k$ ？”**
* 如果有用哈希表记录过历史前缀和出现的次数，我们就能以 $O(1)$ 的时间直接知道有多少个合法的起点。
* 于是，原本需要两层循环的查找，被压缩到了单层循环的 **$O(N)$**。

## 二、 什么类型的题目要用前缀和？

当你看到题目中带有以下特征时，脑子里应该立刻亮起**“前缀和”**的红灯：

### 1. 静态区间的“频繁求和”查询
* **特征：** 给定一个固定数组，会进行非常多次查询，每次问你“区间 $[L, R]$ 的和是多少”。
* **原理：** $O(N)$ 预处理前缀和数组，之后每次查询只需 $O(1)$ 计算（$P[R] - P[L-1]$）。

### 2. 寻找满足特定条件的“连续子数组 (Subarray)”
* **特征：** 题目涉及连续区间，且条件跟“和”有关。
  * **等于目标值 $k$**：如 LC 560。
  * **是某个数 $k$ 的倍数**：如 LC 974（利用同余定理：$(P[j] - P[i]) \pmod k == 0 \implies P[j] \pmod k == P[i] \pmod k$）。
  * **和的最大值/最小值**：如求和大于等于 $k$ 的最短子数组（LC 209，通常配合滑动窗口或单调队列）。

### 3. “区间和”变相转化为“两数之和 (Two Sum)”
* **特征：** 本质上是查找两个历史状态之间的某种算术关系（差值等于 $k$、倍数关系等）。前缀和把“区间”问题巧妙地降维成了“点与点之间的差值”问题，从而可以直接套用哈希表。

> **💡 一句话总结：**
> 只要题目出现 **“连续子数组”** 且考核 **“区间和满足某种数学关系（等于 $k$、是某数倍数等）”**，不要犹豫，10次里有9次都是 **前缀和 + 哈希表** 的主场！
