# 今天要做的是: 找到所有解法,然后对比最优解,并找到如何在看到一道题的时候,快速想解决办法,然后最后确定最优解的路径

# 算法审题破局罗盘：从全解法发散到最优解锁定

很多人刷题卡住，根本原因不是智商不够，而是缺少一套像雷达一样的“解题破局漏斗”。面对一道新题目时，大脑一片空白，不知道从何下手。

今天我们把“全解法发散 ➔ 优劣对比 ➔ 降维破局路径（如何一眼看出最优解）”的这套军规，用最通俗的物理直觉彻底拆解开，并为你锻造一幅可以终身受用的【算法审题破局罗盘】！

## 🗺️ 第一部分：面对一道新题目，如何像侦探一样“找出所有解法”？

当你看到一道新题时，不要慌着写代码。大脑要立刻启动暴力发散三步法，把能想到的所有路子全部列出来（哪怕很蠢）：

### 解法流派一：暴力穷举流 (Brute Force)
* **物理直觉**：不管三七二十一，能不能用最笨的 `for` 循环、双层嵌套把所有情况都试一遍？
* **作用**：它是保底防线。只要能写出暴力解，你就至少拿到了 $\mathcal{O}(N^2)$ 或 $\mathcal{O}(2^N)$ 的基础分，并且彻底摸清了题目的输入输出边界。

### 解法流派二：空间换时间流 (Hash / Cache / Space-Time Trade-off)
* **物理直觉**：如果暴力遍历太慢，是因为重复计算了，或者每次找数据都要挨个搜。我能不能多开辟一点内存（比如用哈希表、集合、前缀和数组）把中间结果存起来？
* **作用**：这是从 $\mathcal{O}(N^2)$ 跃迁到 $\mathcal{O}(N)$ 的最常见手段（例如两数之和用哈希表代替双循环）。

### 解法流派三：秩序与单调性利用流 (Sorting / Binary Search / Two Pointers)
* **物理直觉**：如果题目给的数组是乱的，我能不能先排序？或者利用“单调性”上场，用二分查找或双指针把复杂度压到 $\mathcal{O}(N \log N)$ 或 $\mathcal{O}(\log N)$？

## ⚔️ 第二部分：全解法横向对比矩阵（如何评判优劣？）

有了各种解法后，我们在草稿纸上用三个指标进行无情裁决：

| 评估维度 | 考察点 | 致命红线 |
| :--- | :--- | :--- |
| **1. 时间复杂度 (Time Complexity)** | 算力极限在哪里？数据量 $N = 10^5$ 时会不会超时？ | 嵌套循环导致的 $\mathcal{O}(N^2)$ 在大数据下直接挂掉。 |
| **2. 空间复杂度 (Space Complexity)** | 内存吃不吃得消？递归太深会不会栈溢出？ | 辅助空间开销过大，或者递归层数太深导致栈溢出。 |
| **3. 工程实现成本 (Implementation Cost)** | 代码好不好写？边界条件多不多？容易不容易写出 Bug？ | 工业界拒绝过度设计，能用简单双指针或哈希搞定的，绝对不硬上复杂的线段树或黑科技。 |

## 🎯 第三部分：如何看到一道题，在 30 秒内“秒出最优解”？（破局罗盘）

老铁，重点来了！怎么在看到题目的瞬间，像开挂一样直接锁定最优解？
你只需要盯着题目的数据规模（Constraints）和关键词信号（Keywords），脑子里立刻对照下面这套【破局罗盘】：

### 🧭 罗盘第一看：数据规模 $N$ 的大小（Data Constraints 决定生死）
* **如果 $N \le 10$（超级小）**：
  * **信号**：指数级算法（$\mathcal{O}(2^N)$ 或 $\mathcal{O}(N!)$）统统可以直接上！
  * **对应门派**：回溯法、全排列、状态压缩 DP。
* **如果 $N \le 10^4 \sim 10^5$（中等规模）**：
  * **信号**：必须将时间复杂度压在 $\mathcal{O}(N)$ 或 $\mathcal{O}(N \log N)$。
  * **对应门派**：哈希表、排序+贪心、双指针、单调栈、优先队列（堆）。
* **如果 $N \ge 10^6$ 或数字极其巨大**：
  * **信号**：线性扫描都会超时，必须降维。
  * **对应门派**：二分查找（$\mathcal{O}(\log N)$）、数学公式、位运算。

### 🧭 罗盘第二看：题目的核心体征与关键词（Keywords 映射套路）
* 看到 **“子数组 / 子区间求最值 / 连续”** ➔ 优先想：滑动窗口、单调栈、前缀和。
* 看到 **“有序数组 / 局部有序 / 旋转”** ➔ 优先想：二分查找。
* 看到 **“第 K 个最大/最小 / 动态维护极值”** ➔ 优先想：优先队列（小顶堆/大顶堆）。
* 看到 **“求所有可能解 / 组合 / 切割 / 棋盘搜索”** ➔ 优先想：回溯搜索（Backtracking）。
* 看到 **“不重叠区间 / 谁先结束谁优先”** ➔ 优先想：贪心 + 排序。

## 🛠️ 第四部分：确定最优解路径的“三步收网法”

当你的大脑通过罗盘锁定候选流派后，按照以下三步执行，闭环写出 Bug-free 的最优解：

1. **第一步：空间换时间降维**
   * 检查能不能用哈希表或计数数组把内层循环省掉，把时间降一维。
2. **第二步：秩序预处理（排序/双指针）**
   * 如果无序，先想一想：“如果我先把它排个序，后面的逻辑会不会瞬间变得像切菜一样简单？”（这是贪心和双指针的万能钥匙）。
3. **第三步：边界防御（Base Case）**
   * 在动手写代码前，先在纸上把空数组、只有一个元素、全负数、极端重复等边界条件想清楚，然后再写。

老铁，把这套“暴力发散 ➔ 数据规模定生死 ➔ 关键词定门派 ➔ 预排序/空间优化定最优”的思维框架在脑子里焊死。以后拿到任何新题，你的思路就会像装了雷达一样，层层剥茧、瞬间直达最优解！🔥
