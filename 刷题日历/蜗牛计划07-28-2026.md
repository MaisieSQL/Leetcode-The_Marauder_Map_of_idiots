# LeetCode 49. 字母异位词分组 (Group Anagrams) 专题通关卡片

## 🎯 一、 核心考点与物理直觉

* **题目大意**：给你一个字符串数组 `strs`，请你将 **字母异位词** 组合在一起。可以按任意顺序返回结果列表。
  * **什么是字母异位词**：字母相同、但排列不同的字符串（例如 `"eat"`、`"tea"`、`"ate"` 互为异位词）。
* **物理直觉**：
  * 如果我们能为每一个字符串找到一个**“唯一的身份证号（Key）”**，只要它们的身份证号一样，不管它们的字母顺序怎么乱，最后都把它们塞进同一个哈希表的列表里！
  * **身份证号的两种经典生成思路**：
    1. **排序法（Sort Key）**：把字符串内部的字母按字典序从小到大排序。比如 `"eat"` 排序后变成 `"aet"`，`"tea"` 排序后也是 `"aet"`。它们排序后的形态完全一致！
    2. **计数法（Count Key）**：统计每个字符串中 26 个英文字母各自出现的次数，用一个固定格式的元组（或字符串）来代表频率。比如 `"eat"` 的 `'a':1, 'e':1, 't':1`。这种方法连排序的 O(L log L) 都可以省掉！

## 💻 二、 Python 高效通关代码 (Solution)

### 解法一：排序指纹法（最直观、工业界最常用）
利用 `tuple(sorted(s))` 作为哈希表的 Key。

```python
from collections import defaultdict
from typing import List

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        ans = defaultdict(list)
        for s in strs:
            key = tuple(sorted(s))
            ans[key].append(s)
        return list(ans.values())
```
❌ 错在哪？双 Bug 精准定位

1. 第一个 Bug：`key = sorted(i)` 导致 `TypeError: unhashable type: 'list'`
   - **原因**：在 Python 中，`sorted(s)` 返回的是一个列表（List）（例如 `['a', 'e', 't']`）。而在 Python 的字典（Dictionary）中，字典的键（Key）必须是“可哈希的（Hashable）”。
   - 列表是可变对象（Mutable），因此是不可哈希的。如果你直接把列表当成字典的 key，Python 会立刻报错：`TypeError: unhashable type: 'list'`。
   - **解法**：必须把排序后的列表用 `tuple()` 包装成元组（或者用 `"".join()` 拼回字符串），因为元组是不可变的、可哈希的！
   - 改为：`key = tuple(sorted(i))` 或者 `key = "".join(sorted(i))`。
  

### 解法二：26个字母计数指纹法（极致性能流）
通过统计词频生成不可变元组作为 Key。

```python
from collections import defaultdict
from typing import List

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        ans = defaultdict(list)
        for s in strs:
            count = [0] * 26
            for char in s:
                count[ord(char) - ord('a')] += 1
            key = tuple(count)
            ans[key].append(s)
        return list(ans.values())
```

📊 三、 复杂度核验 (Complexity Analysis)

- 时间复杂度：
  - 排序法：O(N * L log L)，其中 N 是字符串数组长度，L 是字符串的最大长度。
  - 计数法：O(N * L)，省去了排序的对数开销。
- 空间复杂度：O(N * L)，用于存储哈希表中的所有字符串。

# LeetCode 36. 有效的数独 (Valid Sudoku) 专题通关卡片

## 🎯 一、 核心考点与物理直觉

* **题目大意**：
  判断一个 9 x 9 的数独面板是否有效。只需要根据以下三条规则验证已经填入的数字是否有效即可（不需要填满，也不需要求解）：
  1. 数字 1-9 在每一行只能出现一次。
  2. 数字 1-9 在每一列只能出现一次。
  3. 数字 1-9 在每一个以粗实线分隔的 3 x 3 宫（Sub-box）内只能出现一次。
 
# LeetCode 36. 有效的数独 (Valid Sudoku) 示例与棋盘解析

## 🎯 数独示例结构 (Example Board)

在 LeetCode 36 题中，输入的数独是一个 $9 \times 9$ 的二维数组（字符类型），其中空白格子用 `"."` 表示。以下是一个典型的有效数独示例：

```text
board = [
    ["5", "3", ".", ".", "7", ".", ".", ".", "."],
    ["6", ".", ".", "1", "9", "5", ".", ".", "."],
    [".", "9", "8", ".", ".", ".", ".", "6", "."],
    ["8", ".", ".", ".", "6", ".", ".", ".", "3"],
    ["4", ".", ".", "8", ".", "3", ".", ".", "1"],
    ["7", ".", ".", ".", "2", ".", ".", ".", "6"],
    [".", "6", ".", ".", ".", ".", "2", "8", "."],
    [".", ".", ".", "4", "1", "9", ".", ".", "5"],
    [".", ".", ".", ".", "8", ".", ".", "7", "9"]
]
```

* **物理直觉与“指纹识别”降维打击**：
  * 暴力的想法是为每一行、每一列、每一个小方格分别开辟哈希表。但其实，我们可以用一个统一的哈希集合（Set）来容纳所有维度的“身份指纹”。
  * 当我们遍历到矩阵坐标 `(i, j)` 且数字为 `val` 时，它同时身处三个组织：
    1. **行组织**：属于第 `i` 行，身份指纹为 `(i, val)`。
    2. **列组织**：属于第 `j` 列，身份指纹为 `(val, j)`。
    3. **3 x 3 宫组织**：它属于哪个宫呢？数学上有一个极妙的映射公式：`i // 3` 和 `j // 3`。比如整张大图被切成 3 x 3 的大宫格，左上角是 `(0, 0)`，右下角是 `(2, 2)`。它的身份指纹为 `(i // 3, j // 3, val)`。

  只要我们在遍历时，发现这三个维度的任意一个指纹已经提前存在于 `seen` 集合中，说明出现了冲突重复，数独直接判负，返回 `false`！

## 💻 二、 Python 高效通关代码 (Solution)

```python
from typing import List

class Solution:
    def isValidSudoku(self, board: List[List[str]]) -> bool:
        seen = set()
        
        for i in range(9):
            for j in range(9):
                val = board[i][j]
                # 空白格直接跳过
                if val == '.':
                    continue
                
                # 构造三个维度的唯一身份指纹（利用元组的不可变性存入 Set）
                r_key = (i, val)              # 行视角
                c_key = (val, j)              # 列视角
                b_key = (i // 3, j // 3, val) # 3x3宫视角
                
                # 如果指纹已经在集合中，说明重复，数独无效
                if r_key in seen or c_key in seen or b_key in seen:
                    return False
                
                # 登记指纹
                seen.add(r_key)
                seen.add(c_key)
                seen.add(b_key)
                
        return True
```

三、 复杂度核验 (Complexity Analysis)

- 时间复杂度：O(1)。因为数独的尺寸是永远固定的 9 x 9 = 81 个格子，双重循环最多执行 81 次，属于常数级时间开销。
- 空间复杂度：O(1)。seen 集合中最多也只会存储 81 x 3 = 243 个元组指纹，内存占用也是恒定的常量。

# 🧩 LeetCode 36. 有效的数独 —— 三个维度的物理直觉与 Dry Run 详解

## 一、 为什么必须检查“三个维度（三个视角）”？

数独的规则是：**同行、同列、同宫内都绝对不能出现重复的数字 1-9。**

计算机是个憨憨，它不懂什么是行、列、方格，它只认哈希集合（Set）里的“指纹”。如果我们只检查某一个维度（比如只检查行），就会导致严重的漏洞：
- 假设我们在第 2 行填了个数字 `5`。
- 随后我们在第 5 行、第 3 列又填了一个数字 `5`。
- 如果不检查列和 3x3 小方格，代码会认为“第 5 行没出现过 5”，从而判定合法。
- **但是！** 假如这个 `5` 和第 2 行的 `5` 在同一个 $3 \times 3$ 的宫格里，这在数独里就是违规的。

因此，矩阵中的每一个非空数字 `val`（坐标为 `i, j`），在落笔或检查时，必须同时向三个组织注册自己的**“身份指纹”**：
1. **行视角**：`r_key = (i, val)` —— 代表“第 `i` 行里，数字 `val` 出现过没？”
2. **列视角**：`c_key = (val, j)` —— 代表“第 `j` 列里，数字 `val` 出现过没？”
3. **3x3 宫视角**：`b_key = (i // 3, j // 3, val)` —— 代表“我所属的那个 3x3 小方格里，数字 `val` 出现过没？”

---

## 二、 什么是 Dry Run（空转/手动走查）？

**Dry Run** 是程序员和算法高手在不依赖编译器的情况下，拿着草稿纸和笔（或在脑海中），把自己当成计算机，带入具体测试数据，**一步一步手动模拟代码执行全过程**的基本功。

- **为什么叫 Dry Run（干跑）？**
  - 对比消防演练：“Wet Run”是真喷水，“Dry Run”是不喷水、只做阀门和动作的模拟演练。
  - 在编程中，“Wet Run”是直接跑编译器，而 **Dry Run** 是用脑子或手推演代码逻辑。
- **为什么大厂面试极其看重它？**
  - 面试手写代码时，主动对面试官说：“让我用这个测试用例做一下 Dry Run。” 能够瞬间向面试官展示你严谨的代码掌控力，并能自己提前揪出 90% 的边界 Bug（如死循环、索引越界、变量写错等）。

👟 2. Step-by-Step Dry Run（手把手演练）

- 【第一步：遍历到 i = 0, j = 0】
  - 当前格子：`board[0][0] = "5"`
  - 提取数字：`val = "5"`（不是 `.`，开始生成三个视角的身份指纹）
  - 计算指纹：
    1. 行指纹：`r_key = (0, "5")`
    2. 列指纹：`c_key = ("5", 0)`
    3. 宫指纹：`b_key = (0 // 3, 0 // 3, "5")` $\rightarrow$ 即 `(0, 0, "5")`
  - 检查 seen 集合：
    - 此时 `seen` 是空的，这三个指纹都不在里面。**安全！**
  - 登记入库：
    - `seen.add((0, "5"))`
    - `seen.add(("5", 0))`
    - `seen.add((0, 0, "5"))`
  - 当前 `seen` 状态：`{(0, "5"), ("5", 0), (0, 0, "5")}`

- 【第二步：遍历到 i = 0, j = 1】
  - 当前格子：`board[0][1] = "3"`
  - 提取数字：`val = "3"`
  - 计算指纹：
    1. 行指纹：`r_key = (0, "3")`
    2. 列指纹：`c_key = ("3", 1)`
    3. 宫指纹：`b_key = (0, 0, "3")`
  - 检查 seen 集合：
    - `seen` 里没有它们。**安全！**
  - 登记入库：
    - `seen` 增加：`((0, "3"), ("3", 1), (0, 0, "3"))`

- 【第三步：遍历到 i = 0, j = 2】
  - 当前格子：`board[0][2] = "."`
  - 动作：遇到 `.`，代码执行 `if val == '.': continue`。直接跳过！不登记任何指纹。

- 【第四步：遍历到 i = 1, j = 0】
  - 当前格子：`board[1][0] = "6"`
  - 提取数字：`val = "6"`
  - 计算指纹：
    1. 行指纹：`r_key = (1, "6")`
    2. 列指纹：`c_key = ("6", 0)` ⚠️ **注意观察这里！** 刚才第一步时，第 0 列已经存过 `("5", 0)` 了，现在第 0 列来了一个 `"6"`，指纹是 `("6", 0)`。它们数字不同，所以不冲突。
    3. 宫指纹：`b_key = (0, 0, "6")`
  - 检查 seen 集合：
    - 均不在 `seen` 中。**安全！**
  - 登记入库：
    - `seen` 登记这三个新指纹。

- 【第五步：如果我们恶意修改一下测试数据（制造一个冲突的 Bug）】
  - 假设原本在 `board[2][1] = "9"`，但我们在第 2 行、第 2 列不小心又填了一个 `"3"`（即 `board[2][2] = "3"`）：
  - 当代码遍历到 `i = 2, j = 2` 且 `val = "3"` 时：
  - 它的行指纹计算出来是：`r_key = (2, "3")`
  - 它的列指纹计算出来是：`c_key = ("3", 2)`
  - 它的宫指纹计算出来是：`b_key = (2 // 3, 2 // 3, "3")` $\rightarrow$ 即 `(0, 0, "3")` ⚠️ **轰炸！重磅炸弹！**
  - 我们在 **【第二步】** 时，已经把 `(0, 0, "3")` 这个宫指纹稳稳当当存进过 `seen` 集合里了！
