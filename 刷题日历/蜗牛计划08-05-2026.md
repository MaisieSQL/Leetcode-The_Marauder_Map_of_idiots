# 🧱 单调栈（Monotonic Stack）算法

## 一、 什么是单调栈？

**单调栈**本质上是一个普通的栈（遵循 **先进后出 LIFO** 的原则），但它的规矩极严：**栈里存放的元素（或元素对应的索引、数值）必须永远保持严格的单调递增或单调递减。**

在算法面试中，只要遇到**“寻找数组中每一个元素右边（或左边）第一个比它大（或比它小）的元素”**这类需求，单调栈就是绝对的降维打击利器！



### 💡 核心运转逻辑与降维打击的秘密
1. **暴力解法的痛点**：如果用两层循环去挨个往后数，时间复杂度会拉满到 $\mathcal{O}(N^2)$。
2. **单调栈的魔法**：通过“后来的新元素不断去和栈顶历史元素激烈碰撞、一旦打破单调性就立刻弹栈结算”的机制，把时间复杂度**压榨到线性的 $\mathcal{O}(N)$**（因为每个元素最多进栈一次、出栈一次）。


## LeetCode 739. 每日温度 (Daily Temperatures) 题解

### 📋 1. 题目大意
# 739. Daily Temperatures

* **难度**：Medium
* **分类**：Stack / Monotonic Stack

## 题目描述 (Description)

Given an array of integers `temperatures` represents the daily temperatures, return an array `answer` such that `answer[i]` is the number of days you have to wait after the $i^{\text{th}}$ day to get a warmer temperature. If there is no future day for which this is possible, keep `answer[i] == 0` instead.

## 示例演练 (Examples)

### Example 1:
* **Input**: `temperatures = [73, 74, 75, 71, 69, 72, 76, 73]`
* **Output**: `[1, 1, 4, 2, 1, 1, 0, 0]`

### Example 2:
* **Input**: `temperatures = [30, 40, 50, 60]`
* **Output**: `[1, 1, 1, 0]`

### Example 3:
* **Input**: `temperatures = [30, 60, 90]`
* **Output**: `[1, 1, 0]`

## 约束条件 (Constraints)

- $1 \le \text{temperatures.length} \le 10^5$
- $30 \le \text{temperatures}[i] \le 100$

### 🧠 2. 物理沙盘直觉
- **为什么栈里存的是下标（Index）而不是具体温度？**
  因为我们需要计算的是“天数差”（即两个日子在数组中的距离，用当前下标减去过去下标）。
- **单调递减栈的维持逻辑**：
  我们让栈底到栈顶所对应的气温保持**严格单调递减**。当新来一天的温度比栈顶记录的温度高时，说明栈顶那天的“苦日子”熬出头了，它等到了比它更高的气温！

### 💻 3. Python3 完美通关代码 (Solution)

```python
class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        answer = [0] * n
        stack = []  # 专门用来存天数的“索引（下标）”
        
        for i, temp in enumerate(temperatures):
            # 当“新来的温度”比“栈顶记录的那天温度”还要高时，
            # 说明栈顶那天的苦日子熬出头了，结算天数差！
            while stack and temp > temperatures[stack[-1]]:
                prev_day = stack.pop()
                answer[prev_day] = i - prev_day
                
            # 把当前天的索引压入栈中，等待未来被比它高的人“解救”
            stack.append(i)
            
        return answer
```

# 🥞 单调栈（Monotonic Stack）的本质与觉醒形态

咱们刚才厘清了普通 Stack（栈）是**后进先出（LIFO）**的叠盘子逻辑。那么**单调栈（Monotonic Stack）**作为它的“高级觉醒形态”，它的进出规则又是什么样的呢？

咱们直接用物理沙盘直觉把单调栈的规则彻底盘透：

### 1. 单调栈也是栈，它遵循 LIFO 吗？
**是的，百分之百遵循！**
单调栈在底层没有任何特殊的数据结构改造，它依然是一个标准的 Stack（后进先出，LIFO）。你对它执行的依然是标准的 `push()`（压栈）和 `pop()`（弹栈）。

### 2. 那它凭什么叫“单调”？
虽然它的存取规则是后进先出，但我们在往里压元素的时候，多立了一条**“极其严苛的纪律”**：
* 栈内的所有元素（或者对应的数值、下标），必须永远保持严格的单调性（要么从底到顶严格单调递减，要么严格单调递增）。

**当新来的元素打破了这份单调性时，会发生什么？**
* 比如我们要维持一个**单调递减栈**（栈底大，栈顶小）。
* 如果新来了一个“比栈顶还要大”的元素，它就打破了递减的规矩。
* 此时，栈顶的历史元素就会被强行 `pop()` 弹出，进行结算（比如我们刚才在 LeetCode 739 里算天数差）。
* 这种**“遇大则弹栈结算，遇小则乖乖入栈维持单调”**的动态微操，就是单调栈的核心灵魂！

### 3. 单调栈和普通栈的本质区别

| 维度对比 | 普通 Stack（栈） | 单调栈 (Monotonic Stack) |
| :--- | :--- | :--- |
| **核心纪律** | 随心所欲，压什么都行。 | **极其严苛**：新元素入栈前，必须和栈顶碰撞检查，破坏单调性就必须弹栈。 |
| **主要用途** | 括号匹配、表达式求值、控制反转、DFS 路径回溯。 | **降维打击**：专治“寻找数组中每一个元素右边/左边第一个比它大或小的元素”。 |
| **时间复杂度** | 视具体操作而定。 | $\mathcal{O}(N)$ 线性时间（每个元素最多进栈一次、出栈一次）。 |

# ❌ 纠正误区：单调栈绝对不是“自动 Sort”！

单调栈**不会**对进来的所有元素进行整体的 `sort()` 排序。咱们用物理沙盘的视角，看看它和“自动排序”有什么根本的不同：

### 🔍 1. “自动 Sort” vs “单调栈的动态过滤”

* **如果是 `sort()`（排序）**：
  * 把一堆杂乱无章的数字（比如 `[73, 74, 75, 71, 69, 72]`）扔给排序算法，它会把它们从头到尾重新排成一个整齐的序列（如 `[69, 71, 72, 73, 74, 75]`）。
  * 在这个过程中，原本元素之间的先后顺序（时间先后、数组下标关系）全被打乱了。
* **如果是单调栈（Monotonic Stack）**：
  * 它**严格保留**了元素在原数组中的先后顺序（从左到右依次扫描）。
  * 它在维护单调性时，采用的是**“不符合规矩的直接无情弹栈（pop）”**的策略，而不是把新来的元素插入到中间某个位置去排序。

### 🧪 2. 用 LeetCode 739 的例子再看一眼

假设数组是：`[75, 71, 72]`（我们维护一个单调递减栈，栈底到栈顶从大到小）：

1. **处理 `75`**：栈为空，直接压入。栈变成：`[75]`。
2. **处理 `71`**：`71` 比栈顶 `75` 小，符合“递减”规矩，直接压入。栈变成：`[75, 71]`。
3. **处理 `72`**：
   * 如果单调栈是“自动 sort”，它应该把 `72` 夹在 `75` 和 `71` 中间，变成 `[75, 72, 71]`。
   * **但单调栈绝对不这么干！**
   * 单调栈发现新来的 `72` **比栈顶的 `71` 要大**，它直接触发弹栈：**把 `71` 给 `pop()` 弹出并结算**。
   * 弹出 `71` 之后，栈顶变成了 `75`。此时 `72` 再和 `75` 比较，`72` 比 `75` 小，于是把 `72` 压入栈顶。最终栈变成：`[75, 72]`。

### 💡 3. 核心总结对比

| 维度对比 | 整体排序 (`sort()`) | 单调栈 (`Monotonic Stack`) |
| :--- | :--- | :--- |
| **核心目标** | 让全场所有元素整体变有序 | 寻找左边或右边第一个更大/更小的元素 |
| **时间代价** | $\mathcal{O}(N \log N)$ | **$\mathcal{O}(N)$ 线性时间**（每个元素最多进栈一次、出栈一次） |
| **顺序关系** | **会打乱**原本的数组下标/前后顺序 | **严格保留**原数组的先后扫描顺序 |
| **维护手段** | 全局重新排列 | 遇到破坏单调性的元素直接**丢弃/弹出（pop）** |

# 📉 单调递减栈 vs 单调递增栈大盘点

我们刚才讲的 LeetCode 739（每日温度）用的其实是**【单调递减栈】**！为什么它叫单调递减栈呢？因为从**栈底到栈顶**，温度是**从大到小（越来越低）**的（比如栈底是 75，栈顶是 69）。

那么，你问的**“单调递增栈”**究竟是什么样子的？它什么时候用？咱们用同样的排队模型，把它彻底盘透！🔥

## 📉 一、 什么是“单调递增栈”？

* **排队规矩**：
  从队伍的最左边（栈底）到最右边（栈顶），人的身高（或者数值）必须是**【越来越高】**的（严格单调递增）。
  * 比如：栈底是 10cm，中间 20cm，栈顶是 30cm。
* **它专治什么类型的问题？**
  * **单调递减栈**（刚才学过的 LeetCode 739）：用来找**“右边（或左边）第一个比我大的元素”**。
  * **单调递增栈**：正好反过来，用来找**“右边（或左边）第一个比我小的元素”**！

## 🧪 二、 用一个经典例子看“单调递增栈”怎么跑

假设我们有一个数组：`nums = [5, 3, 4, 2, 8]`
我们的目标是：**找出数组中每一个元素右边第一个比它小的元素是谁。**
我们要维护一个**单调递增栈**（栈底到栈顶：从小到大）。

1. **处理 `5`**：
   * 栈空，直接压入。栈变成：`[5]`。
2. **处理 `3`**：
   * 新来的 `3` 比栈顶的 `5` **要小**！
   * 打破了递增的规矩（栈顶本来应该比新来的小，结果栈顶反而大）。
   * **触发弹栈结算**：栈顶的 `5` 遇到克星了，它右边第一个比它小的元素就是 `3`！把 `5` 弹出，记录结果。
   * 弹出后栈空了，`3` 压入。栈变成：`[3]`。
3. **处理 `4`**：
   * 新来的 `4` 比栈顶的 `3` 要大。
   * 符合规矩（栈底到栈顶越来越大：3 < 4）。乖乖压入。栈变成：`[3, 4]`。
4. **处理 `2`**：
   * 新来的 `2` 比栈顶的 `4` 小，触发弹栈（4 的右侧第一个更小是 2）。
   * 接着 `2` 还比栈顶的 `3` 小，再次触发弹栈（3 的右侧第一个更小是 2）。
   * 栈空，`2` 压入。栈变成：`[2]`。
5. **处理 `8`**：
   * `8` 比 `2` 大，合规压入。栈变成：`[2, 8]`。

## 💻 三、 代码长什么样？（对比一下方向）

* **单调递减栈（找右侧更大的 LeetCode 739）**：
  ```python
  # 当新元素大于栈顶时，触发弹栈
  while stack and temp > temperatures[stack[-1]]:
      prev_day = stack.pop()
  ```

* **单调递增栈（找右侧更小的模板）**：

```Python
# 当新元素小于栈顶时，说明破坏了递增规矩，触发弹栈！
while stack and current_val < nums[stack[-1]]:
    idx = stack.pop()
    # 结算：栈顶那个元素的右侧第一个更小值，就是当前元素 current_val
```

# 📈 901. Online Stock Span (股票价格跨度)

* **难度**：Medium
* **分类**：Stack / Monotonic Stack / Stream Processing (数据流处理)

## 📝 一、 题目描述 (Description)

Design an algorithm that collects daily price quotes for some stock and returns the **span** of that stock's price for the current day.

The **span** of the stock's price in one day is the maximum number of consecutive days (starting from today and going backwards) for which the stock price was less than or equal to today's price.

For example, if the price of a stock over the next seven days were `[100, 80, 60, 70, 60, 75, 85]`, then the stock spans would be `[1, 1, 1, 2, 1, 4, 6]`.

Implement the `StockSpanner` class:
- `StockSpanner()` Initializes the object of the class.
- `int next(int price)` Returns the daily span of the given stock's price for today.

## 🧠 二、 物理核心直觉与破局点

* **流式输入（Online Stream）的挑战**：
  这道题和上一题（739 每日温度）不同，它不是一次性给你全量数组，而是每天丢给你一个当天的 `price`，要求你立刻返回跨度。
* **单调栈的魔改艺术（跨度累加流 / Span Inheritance）**：
  1. 我们在单调栈里不仅要存价格，还要打包存一个**连续统治天数（Span）**，即元组 `(price, span)`。
  2. 维持一个**严格单调递减栈**（栈底到栈顶：价格从大到小）。
  3. 当新来的 `price` 大于或等于栈顶价格时，说明栈顶那个历史元素不仅要被压过去，它曾经统治的那些天数（它的 `span`）也必须**全部累加继承**到我们身上！

## 💻 三、 Python3 完美通关代码 (Solution)

```python
class StockSpanner:

    def __init__(self):
        # 栈内存储元组：(price, span)
        self.stack = []

    def next(self, price: int) -> int:
        current_span = 1
        
        # 当栈不为空，且栈顶价格小于等于当前价格时，触发吞并与跨度累加
        while self.stack and self.stack[-1][0] <= price:
            prev_price, prev_span = self.stack.pop()
            current_span += prev_span  # 完美继承前人的统治天数！
            
        # 把合并后的结果压入单调栈
        self.stack.append((price, current_span))
        
        return current_span
```

## 四、 以 `[100, 80, 60, 70, 60, 75, 85]` 为例的 Dry Run 推演

* `next(100)`：栈空，直接压入 `(100, 1)`。返回 `1`。
* `next(80)`：`80 < 100`，不触发循环，压入 `(80, 1)`。返回 `1`。栈：`[(100,1), (80,1)]`
* `next(60)`：`60 < 80`，压入 `(60, 1)`。返回 `1`。栈：`[(100,1), (80,1), (60,1)]`
* `next(70)`：`70 >= 60`！触发弹栈：弹出 `(60, 1)`，`current_span += 1`（变成 2）。接着 `70 < 80` 停止。压入 `(70, 2)`。返回 `2`。
* `next(60)`：`60 < 70`，压入 `(60, 1)`。返回 `1`。
* `next(75)`：`75` 触发连环吞并：吞掉 `(60, 1)`、`(70, 2)`、`(80, 1)`，跨度累加：`1 + 1 + 2 + 1 = 4`。压入 `(75, 4)`。返回 `4`。
* `next(85)`：`85` 吞掉 `(75, 4)` 和 `(100, 1)` 之前的元素（100不满足，停在100），跨度累加：`1 + 4 + 1 = 6`。压入 `(85, 6)`。返回 `6`。


## 📊 五、 复杂度核验 (Complexity Analysis)

| :--- | :---: | :---: | :--- |
