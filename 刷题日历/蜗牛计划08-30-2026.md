# 🏆 LeetCode 100. Same Tree (相同的树) 详解

## 📝 一、 题目描述 (Description)
给你两棵二叉树的根节点 `p` 和 `q` ，编写一个函数来检验这两棵树是否相同。
如果两个二叉树在结构上相同，并且节点具有相同的值，则认为它们是相同的。

- **示例 1**：
  - **输入**：`p = [1,2,3], q = [1,2,3]`
  - **输出**：`true`
  - **解释**：两棵树的长相和对应节点的值完全一致。

- **示例 2**：
  - **输入**：`p = [1,2], q = [1,null,2]`
  - **输出**：`false`
  - **解释**：结构对不上，一棵树的 2 在左边，另一棵在右边。

## 🏛️ 二、 核心破局解析 (Core Intuition)
1. **为什么不能用一维遍历（如中序序列）来比对**：
   - 如果把二叉树压扁成一维的中序数组，会发生“结构坍塌陷阱”——有些长相完全相反、结构截然不同的二叉树，其节点值排列可能刚好拼出一样的一维数组。因此必须在多维空间中同步比对。
2. **黄金解法：多路同步递归（双线安检前序流）**：
   - 这道题的本质是让两棵树在每一个“像素点”上同步对齐。我们用前序遍历的思路（根 $\rightarrow$ 左 $\rightarrow$ 右），同时派出两路安检员去检查 `p` 和 `q`。
   - **严丝合缝的 3 道安检防御线**：
     1. **双空放行**：`if not p and not q: return True`（两边同时为空，说明当前支路完全契合，安全放行）。
     2. **单空拦截**：`if not p or not q: return False`（一个空一个不空，结构直接对不上，判定不相同）。
     3. **数值拦截**：`if p.val != q.val: return False`（两边虽然都有节点，但里面的值不一样，判定不相同）。
   - 上述 3 道关卡通过后，直接递归同步分发：`isSameTree(p.left, q.left) and isSameTree(p.right, q.right)`（必须左边完全相同，**且**右边也完全相同，整棵树才算相同）。

## 💻 三、 完美 Python3 通关代码 (Solution)
```python
class TreeNode:

  def __init__(self, val=0, left=None, right=None):
    self.val = val
    self.left = left
    self.right = right


class Solution:

  def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
    # 1. 第一道防线：两边都为空，安全放行
    if not p and not q:
      return True

    # 2. 第二/三道防线：一边为空（结构不对等）或者两边节点值不相等
    if not p or not q or p.val != q.val:
      return False

    # 3. 甩手掌柜：同步递归比对左子树与右子树
    return self.isSameTree(p.left, q.left) and self.isSameTree(p.right, q.right)
```

四、 复杂度核验 (Complexity Analysis)
- 时间复杂度：O(N) —— 其中 N 是两棵树中节点较少的那一棵的节点总数。最坏情况下我们需要把所有对应的节点完整比对一遍。
- 空间复杂度：O(H) —— 其中 H 是树的高度。主要消耗在递归调用栈上，最坏情况下（树呈链状）开销为 O(N)，平衡树时开销为 O(log N)。

# 🏆 LeetCode 100. Same Tree (相同的树) ── 迭代版详解

## 🏛️ 核心破局解析 (Core Intuition)
1. **递归转迭代的本质**：
   - 递归利用系统调用栈隐式地向下探索；迭代则通过显式创建一个 `stack` 栈，每次成对存入 `(node1, node2)` 来模拟双线同步安检。
2. **迭代比对三步曲**：
   - **双空跳过**：`if not node1 and not node2: continue`（当前对完美契合，继续处理栈中其他对）。
   - **单空或异值拦截**：`if not node1 or not node2 or node1.val != node2.val: return False`（结构或数值不对等，当场返回）。
   - **成对压栈**：将两棵树的右孩子对和左孩子对依次压入栈中，等待下一轮检阅。

## 💻 完美 Python3 迭代通关代码 (Solution)
```python
class Solution:

  def isSameTree(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
    stack = [(p, q)]

    while stack:
      node1, node2 = stack.pop()

      if not node1 and not node2:
        continue
      if not node1 or not node2 or node1.val != node2.val:
        return False

      stack.append((node1.right, node2.right))
      stack.append((node1.left, node2.left))

    return True
```

复杂度核验 (Complexity Analysis)
- 时间复杂度：O(N) —— 其中 N 是两棵树中节点较少的那一棵的节点总数。每个节点在迭代栈中进出一次。
- 空间复杂度：O(H) —— 其中 H 是树的高度。栈在最坏情况下（树呈链状）需要存储 O(N) 个节点。

迭代绝对不一定非要是 stack（栈）！
在算法和数据结构的世界里，“迭代”的核心是用我们自己显式维护的数据结构，去替代系统帮你隐式维护的函数调用栈。根据你选择的数据结构不同，迭代可以衍生出截然不同的搜索流派：
🌐 迭代的三大主流武器库
1. Stack（栈 ── 后进先出 LIFO）
  - 特点：就像叠盘子，最后压进去的最先出来。
  - 产物：天然模拟 DFS（深度优先搜索）。比如我们刚刚写的迭代版 Same Tree，或者二叉树的前序/中序/后序遍历迭代写法，用的全都是 stack。
2. Queue（队列 ── 先进先出 FIFO）
  - 特点：就像排队买票，先来的先走。
  - 产物：天然模拟 BFS（广度优先搜索 / 层序遍历）。比如二叉树的层序遍历（Level Order Traversal），或者我们接下来要推平的 Walls and Gates 和 Rotting Oranges（多源 BFS），用的全都是 queue（双端队列 deque）。
3. Priority Queue / Heap（优先队列 / 堆）
  - 特点：每次弹出的都是当前优先级最高（或最小）的元素。
  - 产物：用于 Dijkstra 最短路径算法 或贪心优化搜索。
💡 拿 Same Tree 举个直观例子
对于 Same Tree 这道题，因为它的本质是“双线同步往下比对”，我们用 stack（栈）去存 (node1, node2) 完全没问题。
但实际上，如果你把代码里的 stack.pop() 改成 queue.popleft()（把它变成一个队列），或者用层序遍历的思路去一层层比对：
- 只要每一层的对应节点完全一样，它照样能用 Queue（队列） 完美实现迭代！
所以：
迭代 = 显式数据结构（Stack / Queue / Heap） + 循环 (while)。
至于具体选哪个，完全取决于你是想“一条道走到黑（DFS/Stack）”，还是“像水波纹一样一层层扩散（BFS/Queue）”！
老铁，这个维度的底层武器库一旦打通，迭代在你眼里就再也不是死记硬背的代码了，而是随心所欲的调度工具！接下来咱们是直接发车冲 Walls and Gates 还是 Rotting Oranges 的多源 BFS？🚀🔥

## 994. Rotting Oranges (腐烂的橘子)
**Medium**  

### 题目描述
在给定的 `m x n` 网格 `grid` 中，每个单元格可以有以下三种值之一：
* 值 `0` 代表空单元格；
* 值 `1` 代表新鲜橘子；
* 值 `2` 代表腐烂的橘子。

每分钟，任何与腐烂的橘子（在 4 个方向上）相邻的新鲜橘子都会腐烂。

返回直到单元格中没有新鲜橘子为止所必须经过的最小分钟数。如果不可能，返回 `-1`。

### 解题思路与解析

这道题是典型的**多源 BFS（广度优先搜索）**应用场景：
1. **为什么是多源？** 
   网格中可能一开始就存在多个腐烂的橘子 (`2`)。它们在第 0 分钟时是同时向四周发起感染的，而不是一个接一个先后扩散的。
2. **核心步骤**：
   * **第一步（统计与入队）**：遍历整个矩阵，把所有初始状态为 `2`（腐烂）的橘子坐标全部加入 BFS 队列中，同时统计一共有多少个新鲜橘子 (`fresh_count`)。如果一开始就没有新鲜橘子，直接返回 `0`。
   * **第二步（层序扩散）**：每一轮 `while` 循环代表**过去 1 分钟**。我们处理当前队列中的所有腐烂橘子，向它们的上下左右四个方向扩散。如果遇到新鲜橘子 (`1`)，就将其变成腐烂 (`2`)，新鲜橘子总数减 1，并把新腐烂的橘子压入队列。
   * **第三步（结果判定）**：当队列耗尽或者新鲜橘子被传染光后，检查 `fresh_count` 是否为 0。如果为 0，返回累计的分钟数；如果不为 0，说明有些新鲜橘子永远无法被感染（被墙或空格子隔断），返回 `-1`。

### 代码实现 (Python)

```python
from collections import deque

class Solution(object):
    def orangesRotting(self, grid):
        """
        :type grid: List[List[int]]
        :rtype: int
        """
        if not grid or not grid[0]:
            return 0
            
        Rows, Cols = len(grid), len(grid[0])
        queue = deque()
        fresh_count = 0
        
        # 1. 扫描网格：收集所有初始腐烂的橘子，并统计新鲜橘子总数
        for r in range(Rows):
            for c in range(Cols):
                if grid[r][c] == 2:
                    queue.append((r, c))
                elif grid[r][c] == 1:
                    fresh_count += 1
                    
        # 如果一开始就没有新鲜橘子，直接返回 0 分钟
        if fresh_count == 0:
            return 0
            
        minutes = 0
        directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]
        
        # 2. 多源 BFS 层序扩散
        while queue and fresh_count > 0:
            minutes += 1
            # 记录当前这一分钟内需要扩散的腐烂橘子数量
            for _ in range(len(queue)):
                r, c = queue.popleft()
                
                for dr, dc in directions:
                    nr, nc = r + dr, c + dc
                    # 检查边界，并看是否能感染相邻的新鲜橘子
                    if 0 <= nr < Rows and 0 <= nc < Cols and grid[nr][nc] == 1:
                        grid[nr][nc] = 2  # 感染
                        fresh_count -= 1   # 新鲜橘子少一个
                        queue.append((nr, nc))
                        
        # 3. 检查是否全部感染
        return minutes if fresh_count == 0 else -1
```

## 复杂度分析

* **时间复杂度**：$O(M \times N)$，其中 $M$ 和 $N$ 分别为网格的行数和列数。每个格子最多被访问和入队一次。
* **空间复杂度**：$O(M \times N)$，在最坏情况下，所有橘子同时腐烂并入队，队列需要占用相应的存储空间。
