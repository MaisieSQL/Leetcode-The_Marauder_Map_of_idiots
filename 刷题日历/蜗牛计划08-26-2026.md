## LeetCode 144. 二叉树的前序遍历 - 详细解析与题解

### 题目描述
给你二叉树的根节点 `root`，返回它节点值的 **前序遍历**（Preorder Traversal）。
* **前序遍历规则**：按照 **根节点 $\rightarrow$ 左子树 $\rightarrow$ 右子树** 的顺序访问节点。

### 方法一：递归法 (Recursion) —— 最直观的官方标准解法

#### 1. 核心思路
前序遍历的定义本身具有天然的递归性：
1. 先访问当前根节点（把值加入结果集）。
2. 递归调用函数遍历左子树。
3. 递归调用函数遍历右子树。
当遇到空节点（`None`）时，递归终止并返回。

#### 2. 代码实现 (Python)
```python
class Solution:
    def preorderTraversal(self, root: TreeNode) -> list[int]:
        res = []
        
        def dfs(node):
            # 终止条件：如果节点为空，直接返回
            if not node:
                return
            
            # 1. 根：访问当前节点
            res.append(node.val)
            # 2. 左：递归遍历左子树
            dfs(node.left)
            # 3. 右：递归遍历右子树
            dfs(node.right)
            
        dfs(root)
        return res
```

### 方法二：迭代法 / 显式栈 (Iteration with Stack) —— 硬核底层模拟

#### 1. 核心思路
递归的本质是操作系统在内存中维护了一个“系统调用栈”。我们可以用一个显式的列表 `stack` 来模拟这个栈：
* 前序遍历的访问顺序是“根 $\rightarrow$ 左 $\rightarrow$ 右”。
* 因为栈是**先进后出 (LIFO)** 的：
  * 如果我们想让**左子树**先被弹出来处理，就必须**先把右子树压入栈，再把左子树压入栈**。
* 每次从栈顶弹出当前节点，记录其值，然后重复上述压栈过程。

#### 2. 代码实现 (Python)
```python
class Solution:
    def preorderTraversal(self, root: TreeNode) -> list[int]:
        if not root:
            return []
            
        res = []
        stack = [root]  # 初始化栈，放入根节点
        
        while stack:
            # 1. 弹出当前栈顶节点（相当于访问“根”）
            node = stack.pop()
            res.append(node.val)
            
            # 2. 先压入右子树（确保左子树先出栈）
            if node.right:
                stack.append(node.right)
                
            # 3. 再压入左子树
            if node.left:
                stack.append(node.left)
                
        return res
```

### 两种方法对比

| 维度 | 方法一：递归法 (Recursion) | 方法二：迭代法 (Iteration with Stack) |
| :--- | :--- | :--- |
| **底层原理** | 依赖系统调用栈 (Call Stack) | 依赖程序员自己维护的显式栈 (`stack` 列表) |
| **代码简洁度** | 极简，逻辑与前序定义完全对齐 | 稍显繁琐，需要处理栈的进出顺序 |
| **空间复杂度** | $O(H)$ （$H$ 为树的高度，最坏链状时为 $O(N)$） | $O(H)$ （同样需要用栈存储路径上的节点） |
| **时间复杂度** | $O(N)$ （每个节点恰好被访问一次） | $O(N)$ （每个节点恰好被压入和弹出一次） |
| **安全性** | 树太深（如链状达 $10^5$ 层）时，可能导致**栈溢出 (Stack Overflow)** | 安全，不受系统递归深度限制 |
| **适用场景** | 面试首选，绝大多数常规情况下的最优解 | 面试官明确要求“不用递归”或树极深时的安全解法 |

用栈的这种迭代法，它既不是纯粹的“一层一层走（广度优先 BFS）”，也不是死板的“一杆子捅到底（纯递归 DFS）”，而是利用栈的 LIFO（后进先出）特性，在“向右拐”和“向左拐”之间做精准的控制。

为了让你看清它每一步到底是怎么跑的，我们用你给的这棵树来进行一次 **Dry Run（手动模拟运行）**！

### 第一步：还原你给的这棵树的结构
根据 LeetCode 数组层序遍历的规则，输入 `[1, 2, 3, 4, 5, null, 8, null, null, 6, 7, 9]` 对应的树形结构是这样的：
* 根节点：`1`
* `1` 的左子树是 `2`，右子树是 `3`
* `2` 的左子树是 `4`，右子树是 `5`
* `3` 的左子树是空 (`null`)，右子树是 `8`
* `4` 的左右都空
* `5` 的左子树是 `6`，右子树是 `7`
* `8` 的左子树是空，右子树是 `9`

### 第二步：Dry Run 开始！
我们初始状态：`res = []`，`stack = [1]`（把根节点 `1` 放进去）。

* **循环 1**：
  * `stack.pop()`：弹出栈顶，拿到节点 **`1`**。
  * `res.append(1)` $\rightarrow$ `res = [1]`
  * 检查右子树和左子树，按代码逻辑先压右、再压左：
    * 压入右子树 `3` $\rightarrow$ `stack = [3]`
    * 压入左子树 `2` $\rightarrow$ `stack = [3, 2]`（注意：`2` 在栈顶！）

* **循环 2**：
  * `stack.pop()`：弹出栈顶（此时是 **`2`**，左子树先出来了！）。
  * `res.append(2)` $\rightarrow$ `res = [1, 2]`
  * 检查 `2` 的子树：
    * 有右子树 `5` $\rightarrow$ 压入 $\rightarrow$ `stack = [3, 5]`
    * 有左子树 `4` $\rightarrow$ 压入 $\rightarrow$ `stack = [3, 5, 4]`（`4` 在栈顶）

* **循环 3**：
  * `stack.pop()`：弹出栈顶 **`4`**。
  * `res.append(4)` $\rightarrow$ `res = [1, 2, 4]`
  * `4` 没有左右子树，栈不变 $\rightarrow$ `stack = [3, 5]`（`5` 在栈顶）

* **循环 4**：
  * `stack.pop()`：弹出栈顶 **`5`**。
  * `res.append(5)` $\rightarrow$ `res = [1, 2, 4, 5]`
  * 检查 `5` 的子树：
    * 压入右子树 `7` $\rightarrow$ `stack = [3, 7]`
    * 压入左子树 `6` $\rightarrow$ `stack = [3, 7, 6]`（`6` 在栈顶）

* **循环 5**：
  * `stack.pop()`：弹出栈顶 **`6`**。
  * `res.append(6)` $\rightarrow$ `res = [1, 2, 4, 5, 6]`
  * `6` 无子树 $\rightarrow$ `stack = [3, 7]`（`7` 在栈顶）

* **循环 6**：
  * `stack.pop()`：弹出栈顶 **`7`**。
  * `res.append(7)` $\rightarrow$ `res = [1, 2, 4, 5, 6, 7]`
  * `7` 无子树 $\rightarrow$ `stack = [3]`（`3` 在栈顶）

  *(看！到这里，左边的一大片枝丫 `1 -> 2 -> (4, 5 -> 6, 7)` 全部被处理完了！)*

* **循环 7**：
  * `stack.pop()`：弹出栈顶 **`3`**。
  * `res.append(3)` $\rightarrow$ `res = [1, 2, 4, 5, 6, 7, 3]`
  * 检查 `3` 的子树：
    * 左子树为空。
    * 右子树 `8` $\rightarrow$ 压入 $\rightarrow$ `stack = [8]`

* **循环 8**：
  * `stack.pop()`：弹出栈顶 **`8`**。
  * `res.append(8)` $\rightarrow$ `res = [1, 2, 4, 5, 6, 7, 3, 8]`
  * 检查 `8` 的子树：
    * 右子树 `9` $\rightarrow$ 压入 $\rightarrow$ `stack = [9]`

* **循环 9**：
  * `stack.pop()`：弹出栈顶 **`9`**。
  * `res.append(9)` $\rightarrow$ `res = [1, 2, 4, 5, 6, 7, 3, 8, 9]`
  * `9` 无子树 $\rightarrow$ `stack = []`

`stack` 空了，循环结束！

### 最终输出：
`[1, 2, 4, 5, 6, 7, 3, 8, 9]` —— **完美吻合！**

### 总结：它到底是“怎么走”的？
通过这个 Dry Run，你会发现它的足迹是这样的：
1. **先死死沿着左边一路向下切入**（`1 -> 2 -> 4`），把左边的根和左孩子全处理了。
2. 当左边到底（比如 `4` 没孩子了），因为栈里还压着刚才路过时顺手塞进去的右边兄弟（比如 `5` 的右边、`3` 节点等），它会**自动回溯到上一个分叉口，去处理那些被暂存的右边分支**。

所以它本质上依然是 **DFS（深度优先搜索）** 的前序遍历轨迹，只是聪明地用一个栈把“还没来得及看的右边亲戚”先记在小本本上，等左边逛完了，回过头再去挨个访问！
