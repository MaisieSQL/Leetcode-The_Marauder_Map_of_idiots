# 703. Kth Largest Element in a Stream

- **LeetCode 链接**: [Kth Largest Element in a Stream](https://leetcode.com/problems/kth-largest-element-in-a-stream/)
- **难度**: Easy
- **核心考点**: 数据流处理 / 堆 (Min-Heap) / Top-K 问题

## 1. 题目直觉与场景还原

> **用一句话解释**：设计一个实时排行榜，每次有新成绩加进来，立刻报出“第 $k$ 名”是谁。

### 场景推导（以 $k = 3$ 为例）
时刻追踪全场第 3 名的成绩：

1. **初始池子**：`[4, 5, 8, 2]`
   - 从大到小排序：`8, 5, 4, 2`
   - 前 3 名是 `[8, 5, 4]`，其中第 3 名是 **4**。
2. **调用 `add(3)`**：新加入一个成绩 3
   - 当前所有成绩：`8, 5, 4, 3, 2`
   - 前 3 名依然是 `[8, 5, 4]`，第 3 名依然返回 **4**。
3. **调用 `add(5)`**：新加入一个成绩 5
   - 当前所有成绩：`8, 5, 5, 4, 3, 2`
   - 前 3 名变成了 `[8, 5, 5]`，第 3 名被刷新为 **5**。
4. **调用 `add(10)`**：新加入一个高分 10
   - 前 3 名变成了 `[10, 8, 5]`，第 3 名依然是 **5**。
5. **调用 `add(9)`**：新加入一个高分 9
   - 前 3 名变成了 `[10, 9, 8]`，第 3 名被刷新为 **8**。

## 2. 为什么暴力解法不行？

- **暴力做法**：每次调用 `add()`，把新数字追加到数组末尾，然后重新整体排序 `sort()`，返回倒数第 $k$ 个数。
- **致命缺陷**：数据流会不断调用 `add()`。假设调用 $M$ 次，每次排序耗时 $O(N \log N)$，总时间复杂度高达 $O(M \cdot N \log N)$，直接引发超时（TLE）。

## 3. 核心破局点：维护大小为 $k$ 的“最小堆”（Min-Heap）

求“第 $k$ 大”，直觉上容易联想到大顶堆，但**最优解法是维护一个容量上限为 $k$ 的最小堆**：

- **逻辑本质**：
  - 我们根本不关心比第 $k$ 名更差的人（第 $k+1$ 名及之后可以直接丢弃）。
  - 我们只维护一个“VIP 俱乐部”，这个俱乐部**永远只保留全场最强的 $k$ 个人**。
- **为什么用最小堆？**
  - 在这 $k$ 个顶尖元素的集合中，堆顶存放的是**该集合中的最小值**。
  - 这个处于门槛位置的最小值，在全局视角下正好就是**全场第 $k$ 大的元素**。

## 4. 算法运转流程

1. **初始化 `__init__`**：
   - 将现有数组转为堆结构，多余的元素弹出，直到堆的大小缩小到 $k$。
2. **调用 `add(val)`**：
   - 将新元素入堆：`heapq.heappush(self.min_heap, val)`。
   - 检查堆容量：若堆大小超过 $k$，弹出堆顶最小值：`heapq.heappop(self.min_heap)`。
   - 此时堆顶 `self.min_heap[0]` 即为当前流中的第 $k$ 大元素。

## 5. 代码实现 (Python3)

```python
import heapq
from typing import List

class KthLargest:

    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.min_heap = nums
        heapq.heapify(self.min_heap)
        
        # 保持堆的容量不超过 k
        while len(self.min_heap) > self.k:
            heapq.heappop(self.min_heap)

    def add(self, val: int) -> int:
        heapq.heappush(self.min_heap, val)
        
        # 超过容量则淘汰最小值
        if len(self.min_heap) > self.k:
            heapq.heappop(self.min_heap)
            
        # 堆顶即为第 k 大元素
        return self.min_heap[0]
```

## 6. 复杂度分析

- **时间复杂度**:
  - **初始化 `__init__`**: $O(N \log k)$ 或建堆 $O(N) + (N - k) \log N$。总耗时可控制在 $O(N \log k)$。
  - **单次 `add` 操作**: 堆的大小恒定 $\le k$，入堆与出堆耗时均为 $O(\log k)$，读取堆顶为 $O(1)$。若调用 $M$ 次 `add`，总耗时为 $O(M \log k)$。
- **空间复杂度**: $O(k)$。堆中仅保留 $k$ 个元素，消耗与数据流总长度无关的固定空间。

### 一、 单次 add 操作为什么是 $O(\log k)$？

因为我们限制了堆的最大容量永远只有 $k$：

* **二叉堆的高度**：一个拥有 $k$ 个元素的完全二叉树（堆），其树的高度是 $\log_2 k$。
* **入堆与出堆机制**：
  * `heappush(val)`：把新元素放在树底，沿路径向上调整（Sift Up），最多走整棵树的高度，即 $\log k$ 步。
  * `heappop()`：把堆顶拿走，将末尾元素移到堆顶并向下调整（Sift Down），同样最多走整棵树的高度，即 $\log k$ 步。
* **读取堆顶**：堆顶就是数组第 0 个元素 `heap[0]`，直接寻址，耗时 $O(1)$。
* **总耗时**：单次 `add` 做了常数次堆操作，所以单次代价是 $O(\log k)$；如果调用了 $M$ 次，总代价就是 $O(M \log k)$。

### 二、 初始化 __init__ 的复杂度是怎么来的？

初始数组有 $N$ 个元素，我们有两种构建方式：

**方式 1：逐个插入（动态维护大小为 $k$ 的堆）**
* 从前往后遍历 $N$ 个数，每来一个数就 push 进堆，一旦大小超过 $k$ 就 pop 掉。
* 堆的大小始终被压制在 $k$ 以内，因此每次插入/弹出的成本都不会超过 $O(\log k)$。
* 一共处理 $N$ 个数，总耗时就是稳稳的 $O(N \log k)$。

**方式 2：先原地建堆，再弹出多余元素（即上面写的第二种推导）**
* **原地建堆 `heapq.heapify(nums)`**：
  Python 底层使用的是 Floyd 建堆算法（自底向下调整），直接把包含 $N$ 个元素的列表在原地调整成堆，这一步耗时是 $O(N)$（而不是很多人直觉上的 $N \log N$）。
* **弹出多余元素**：
  堆里原来有 $N$ 个数，我们要保留前 $k$ 个，就需要连续执行 $(N - k)$ 次 `heappop()`。
  每次 pop 时，堆的大小在从 $N$ 逐渐缩减到 $k$。每次弹出需要走树高 $O(\log N)$。
  所以弹出多余元素消耗的时间是 $(N - k) \log N$。
* **两者相加**：
  $$\text{总耗时} = O(N) + (N - k) \log N$$

### 两种写法的本质对比

* 当 $k \ll N$（比如 $N = 10^5, k = 5$）：
  * 方式 1 只需要 $O(N \log 5)$，非常轻量。
  * 方式 2 要 pop 掉几乎全部元素，花了大量的 $(N - k) \log N$ 时间。
* 两种方式在大量工业库或面试手写中都很常见，但结论是一致的：只要在初始化阶段把堆的规模压到 $k$ 以内，后续所有的 `add` 就能稳定享受 $O(\log k)$ 的低开销。

| 操作类型 | 常见方法 / 函数 (以 Python `heapq` 为例) | 时间复杂度 | 空间复杂度 | 核心机制与说明 |
| :--- | :--- | :--- | :--- | :--- |
| **访问堆顶** | `heap[0]`（查看最值） | $O(1)$ | $O(1)$ | 根节点固定在数组第 0 位，直接寻址 |
| **插入元素** | `heapq.heappush(heap, val)` | $O(\log N)$ | $O(1)$ | 放入数组末尾，向上调整（Sift Up），最多走树高 |
| **删除堆顶** | `heapq.heappop(heap)` | $O(\log N)$ | $O(1)$ | 末尾换到根部并弹出，向下调整（Sift Down） |
| **替换堆顶并弹出** | `heapq.heapreplace(heap, val)` | $O(\log N)$ | $O(1)$ | 先弹堆顶再压新值，只需一次向下调整，比先 pop 再 push 更快 |
| **压入并弹出最值** | `heapq.heappushpop(heap, val)` | $O(\log N)$ | $O(1)$ | 若新值比堆顶小/大直接返回新值，否则替换后向下调整 |

| **查找任意元素** | `val in heap` / 遍历查找 | $O(N)$ | $O(1)$ | 堆仅保证父子偏序关系，兄弟节点间无序，只能线性扫描 |
| **删除任意指定节点** | 定位位置后将其与末尾交换并调整 | $O(N)$ | $O(1)$ | 查找耗时 $O(N)$，找到后位置重调（Sift）耗时 $O(\log N)$ |

### 原地建堆时间复杂度为 $O(n)$ 的数学推导

原地建堆（即自底向上使用 `sift-down` 调整，从最后一个非叶子节点开始依次向下下沉）的时间复杂度是 **$O(n)$** 而非直觉上的 $O(n \log n)$。核心原因在于：**绝大多数节点集中在二叉树的最底层，而这些底层节点所需下沉的最大高度极小。**

#### 1. 直觉与实际的差异

* **直觉误区（$O(n \log n)$）**：
  整棵树有 $n$ 个节点，树高约为 $\log n$，若假设每个节点都下沉 $\log n$ 次，则总时间为 $n \times \log n$。
* **实际情况**：
  只有根节点这单独 1 个节点需要下沉 $\log n$ 层；约占总节点数一半的叶子节点完全不需要下沉（下沉高度为 0）。

#### 2. 节点层级分布与下沉步数

假设二叉树为满二叉树，树高为 $h$（根节点高度为 $h$，叶子节点高度为 $0$），总节点数 $n = 2^{h+1} - 1$：

| 节点所在深度（从根往下） | 该层节点数量 | 该层节点最多下沉步数 |
| :--- | :--- | :--- |
| **第 $0$ 层（根节点）** | $2^0 = 1$ | $h$ |
| **第 $1$ 层** | $2^1 = 2$ | $h - 1$ |
| **第 $i$ 层** | $2^i$ | $h - i$ |
| **第 $h-1$ 层** | $2^{h-1}$ | $1$ |
| **第 $h$ 层（叶子节点）** | $2^h \approx \frac{n}{2}$ | $0$ |

#### 3. 数学推导过程

将所有层节点的最多操作步数累加，可得总操作上限 $S$：

$$S = \sum_{i=0}^{h} 2^i \cdot (h - i)$$

设 $k = h - i$（即节点的高度，从下往上数），求和公式可以重写为：

$$S = \sum_{k=0}^{h} 2^{h-k} \cdot k = 2^h \sum_{k=0}^{h} \frac{k}{2^k}$$

令括号内的求和项为 $T$：

$$T = \sum_{k=0}^{h} \frac{k}{2^k} = \frac{1}{2} + \frac{2}{4} + \frac{3}{8} + \frac{4}{16} + \dots + \frac{h}{2^h}$$

使用**错位相减法**计算差比数列的和：

两边同乘 $\frac{1}{2}$：

$$\frac{1}{2} T = \frac{1}{4} + \frac{2}{8} + \frac{3}{16} + \dots + \frac{h-1}{2^h} + \frac{h}{2^{h+1}}$$

原式 $T$ 减去 $\frac{1}{2}T$：

$$T - \frac{1}{2} T = \frac{1}{2} + \left( \frac{1}{4} + \frac{1}{8} + \frac{1}{16} + \dots + \frac{1}{2^h} \right) - \frac{h}{2^{h+1}}$$

中间的括号为一个公比为 $\frac{1}{2}$ 的等比数列：

$$\frac{1}{2} + \left( \frac{1}{4} + \frac{1}{8} + \dots + \frac{1}{2^h} \right) = 1 - \frac{1}{2^h}$$

代回等式：

$$\frac{1}{2} T = 1 - \frac{1}{2^h} - \frac{h}{2^{h+1}} < 1$$

两边同乘 2：

$$T < 2$$

将 $T < 2$ 代回最初的总操作数 $S$：

$$S = 2^h \cdot T < 2 \cdot 2^h$$

由于总节点数 $n = 2^{h+1} - 1 = 2 \cdot 2^h - 1$，即 $2 \cdot 2^h = n + 1$：

$$S < n + 1$$

因此，总比较与交换步数被限制在 $n$ 的常数倍以内，时间复杂度为：

$$\mathcal{O}(n)$$

#### 4. 核心对比

* **自顶向下建堆（逐个 `push` / `sift-up`）**：
  * 节点多的层（底层）往上爬的高度最长（$O(\log n)$）。
  * 加权累加结果为 **$O(n \log n)$**。
* **自底向上建堆（`heapify` / `sift-down`）**：
  * 节点多的层（底层）往下沉的高度最短（$0 \sim 1$ 步）。
  * 加权累加收敛于 **$O(n)$**。

### 单次 `push` 时间复杂度为 $O(\log n)$ 的原理推导

单次向二叉堆中插入元素（`push`）的时间复杂度为 **$O(\log n)$**。核心原因在于：**为了维护完全二叉树的结构，新元素必须先放在树底，随后沿着唯一通往根节点的路径向上爬升，而树的最大高度严格受制于 $\log_2 n$。**

#### 1. `push` 的操作步骤（Sift-Up / 上浮）

以大顶堆为例，当堆中已有 $n$ 个元素时，插入新元素的过程如下：

1. **追加至末尾**：
   新元素直接写入数组的末尾（即**完全二叉树最底层的最左空位**），以保证堆的结构性不被破坏。
2. **向上比较与交换（Sift-Up）**：
   * 将新元素与其父节点（索引为 $\lfloor \frac{i-1}{2} \rfloor$）进行数值比较；
   * 若新元素大于父节点，则二者交换位置；
   * 重复上述过程，直至新元素小于等于其当前父节点，或已经抵达**堆顶（根节点）**。

#### 2. 数学推导：为什么上限是 $\log n$？

一个包含 $n$ 个节点的**完全二叉树（Complete Binary Tree）**，其高度 $h$（从根节点到最底层叶子节点的路径长度）具有严格的数学上下界：

$$2^h \le n < 2^{h+1}$$

对不等式取以 2 为底的对数：

$$h \le \log_2 n < h + 1 \implies h = \lfloor \log_2 n \rfloor$$

在执行 `sift-up` 时：
* **路径唯一性**：二叉树中除根节点外，**任何一个节点有且仅有唯一的一个父节点**。因此，从任何叶子节点爬升到根节点，只有一条长度至多为 $h$ 的单向路径。
* **最坏情况代价**：如果新插入的值是当前堆中的全局最大值，它必须沿着这条唯一的路径一路交换至根节点，总共执行的比较与交换步数为树的高：

$$\text{最坏步数} = h = \lfloor \log_2 n \rfloor$$

由于每一次与父节点的比较和交换均为 $O(1)$ 操作，因此单次插入操作的最坏时间复杂度为：

$$\mathcal{O}(\log n)$$

#### 3. 核心对比：为什么建堆不是 $n \times \log n$？

| 操作类型 | 起点位置 | 移动方向 | 规模分布 | 最终复杂度 |
| :--- | :--- | :--- | :--- | :--- |
| **单次 `push`** | 树的最底叶子节点 | 向上（`sift-up`） | 单个孤立节点，必须跨越整棵树的高度 | **$O(\log n)$** |
| **连续 $n$ 次 `push` 建堆** | 每个新节点都从底部进 | 向上（`sift-up`） | 约 $50\%$ 的节点需要爬 $\approx \log n$ 步 | **$O(n \log n)$** |
| **原地建堆（`heapify`）** | 从非叶子节点自底向上 | 向下（`sift-down`） | 约 $50\%$ 的底层节点走 $0$ 步，仅 $1$ 个根节点走 $\log n$ 步 | **$O(n)$** |

### 题目分析：LeetCode 752. Open the Lock（打开转盘锁）

这是一道标准的**无权图最短路径问题**，最优解法是 **广度优先搜索（BFS）**，进阶优化为 **双向 BFS（Bidirectional BFS）**。

#### 1. 核心模型抽象

* **状态表示**：每个状态是一个 4 位数字字符串（如 `"0000"`），总共有 $10^4 = 10,000$ 种可能状态。
* **状态转移（边）**：每个拨轮可以向上转（+1）或向下转（-1），4 个拨轮共有 $4 \times 2 = 8$ 个相邻状态。
* **障碍物**：`deadends` 集合中的状态是死锁点，不能访问。
* **目标**：求从起点 `"0000"` 到 `target` 的最少旋转次数（最短步数）。

#### 2. 标准单向 BFS 解法

```python
from collections import deque

class Solution:
    def openLock(self, deadends: list[str], target: str) -> int:
        dead_set = set(deadends)
        if "0000" in dead_set:
            return -1
        if target == "0000":
            return 0
        
        queue = deque([("0000", 0)])
        visited = set(["0000"])
        
        while queue:
            status, step = queue.popleft()
            
            if status == target:
                return step
            
            # 生成 8 个相邻状态
            for i in range(4):
                digit = int(status[i])
                # +1 和 -1（带模 10 循环）
                for diff in (-1, 1):
                    new_digit = (digit + diff) % 10
                    neighbor = status[:i] + str(new_digit) + status[i+1:]
                    
                    if neighbor not in dead_set and neighbor not in visited:
                        visited.add(neighbor)
                        queue.append((neighbor, step + 1))
                        
        return -1
```

### 752. 打开转盘锁 (Open the Lock) - 复杂度分析

设：
* 密码锁位数 $L = 4$
* 每个轮盘数字基数 $A = 10$（数字 0 到 9）
* 死亡数字集合大小为 $D$（即 `len(deadends)`）

---

#### 1. 时间复杂度：$O(A^L \cdot L^2 + D)$

最坏情况下（无解或目标在搜索树最深处），算法需要遍历整个状态空间：

* **哈希集合预处理**：将 `deadends` 转为 `dead_set`，需要处理 $D$ 个长度为 $L$ 的字符串，耗时 **$O(D \cdot L)$**（$L=4$ 时可视为常数项 $O(D)$）。
* **状态总数（节点数 $V$）**：转盘密码所有可能组合共 $A^L = 10^4 = 10,000$ 种。
* **转移总数（边数 $E$）**：每个节点有 $L$ 个轮盘，每个轮盘有 $+1$ 与 $-1$ 两种拨法，共 $2L = 8$ 条出边。
* **字符串拼接开销**：Python 中字符串不可变，`status[:i] + str(new_digit) + status[i+1:]` 的切片拼接耗时为 $O(L)$。遍历一个状态的所有 $2L$ 个邻居总耗时为 $O(2L \cdot L) = O(L^2)$。

> **数值估算**：
> 带入参数：$10^4 \times (2 \times 4) \times 4 \approx 3.2 \times 10^5$ 次操作，在系统评测中通常耗时为几百毫秒，运行极为安全。

#### 2. 空间复杂度：$O(A^L \cdot L + D)$

* **`dead_set`**：存储 $D$ 个长度为 $L$ 的字符串，占用 **$O(D \cdot L)$**。
* **`visited` 集合**：最多存入所有合法密码状态，上限为 $A^L$ 个字符串，占用 **$O(A^L \cdot L)$**。
* **`queue` 队列**：存储 BFS 某一层的边界状态，最大不超过总节点数，也是 **$O(A^L \cdot L)$** 级别。

> **数值估算**：
> 总状态数仅 10,000 个，每个字符串 4 字节，实际内存开销在几 MB 以内。

#### 3. 核心指标对照表

| 维度 | 代数表达式 | 本题固定规模 ($L=4, A=10$) |
| :--- | :--- | :--- |
| **时间复杂度** | $O(A^L \cdot L^2 + D)$ | 约 $3.2 \times 10^5 + D$ 次基本操作 |
| **空间复杂度** | $O(A^L \cdot L + D)$ | 约 $4 \times 10^4$ 字符存储 + $D$ |

### 3. 进阶优化：双向 BFS（Bidirectional BFS）

在图搜索中，如果起点和终点都已知，单向 BFS 的搜索空间随深度呈指数级发散（像一个巨大的圆锥体）。采用双向 BFS 从起点和终点同时向中间扩散，可以大幅剪枝，将搜索空间从 $b^d$ 减少到 $2 \times b^{d/2}$。

```python
class Solution:
    def openLock(self, deadends: list[str], target: str) -> int:
        dead_set = set(deadends)
        if "0000" in dead_set or target in dead_set:
            return -1
        if target == "0000":
            return 0
        
        # 使用哈希集合替代队列，方便交集判断与交换优化
        start_set = {"0000"}
        end_set = {target}
        visited = set(deadends)  # 直接将 deadends 当作已访问
        visited.add("0000")
        
        step = 0
        
        while start_set and end_set:
            # 贪心选择更小的集合进行扩展，保持两端平衡
            if len(start_set) > len(end_set):
                start_set, end_set = end_set, start_set
            
            next_set = set()
            
            for status in start_set:
                for i in range(4):
                    digit = int(status[i])
                    for diff in (-1, 1):
                        neighbor = status[:i] + str((digit + diff) % 10) + status[i+1:]
                        
                        # 两端相遇，找到最短路径
                        if neighbor in end_set:
                            return step + 1
                        
                        if neighbor not in visited:
                            visited.add(neighbor)
                            next_set.add(neighbor)
            
            step += 1
            start_set = next_set
            
        return -1
```
### 752. 打开转盘锁 - 双向广度优先搜索 (Bidirectional BFS) 复杂度分析

设：
* 密码锁位数 $L = 4$
* 每个轮盘数字基数 $A = 10$
* 死亡数字集合大小为 $D$（即 `len(deadends)`）
* 从起点到终点的实际最短步数为 $d$

#### 1. 时间复杂度：理论渐近仍为 $O(A^L \cdot L^2 + D)$，但实际运行次数降为 $O(B^{d/2} \cdot L^2 + D)$

* **理论最坏情况（渐近上界）**：
  * 若目标不可达，或者两端搜索直到铺满整个图才判定失败，访问的节点总数依然可能逼近整个状态空间 $A^L$。
  * 加上每个状态生成 $2L$ 个分支及字符串切片的 $O(L)$ 开销，理论上界仍写作 **$O(A^L \cdot L^2 + D)$**。

* **实际工程表现（双向 BFS 的核心威力）**：
  * 单向 BFS 的搜索空间随深度以指数级膨胀：$O(B^d)$（其中分支因子 $B \le 8$）。
  * 双向 BFS 每次优先扩展较小集合（`len(start_set) > len(end_set)` 交换），两端各扩展约 $d / 2$ 层即发生碰撞相遇：
    $$B^{d/2} + B^{d/2} = 2 \cdot B^{d/2} \ll B^d$$
  * 实际遍历的状态总数呈现**数量级（根号级）的缩减**，在 LeetCode 上的耗时通常会从单向 BFS 的 **几百毫秒** 骤降至 **几十毫秒**。

#### 2. 空间复杂度：$O(A^L \cdot L + D)$

* **`visited` 集合**：初始化存入了所有 `deadends`，并在搜索过程中记录已访问节点，最多存储全部合法状态与死亡状态，占用 **$O(A^L \cdot L + D)$**。
* **`start_set` 与 `end_set`**：保存当前搜索前沿的边界节点。在实际双向推进中，边界层节点总数远小于单向 BFS 在最深层时的队列规模，峰值内存占用更小，但理论渐近上界仍为 **$O(A^L \cdot L)$**。

#### 3. 单向 BFS vs 双向 BFS 对比

| 对比维度 | 单向 BFS (实现一) | 双向 BFS (实现二) |
| :--- | :--- | :--- |
| **理论时间上界** | $O(A^L \cdot L^2 + D)$ | $O(A^L \cdot L^2 + D)$ |
| **实际搜索规模** | 搜索半径为 $d$ 的整球体积 $\propto B^d$ | 两个半径为 $d/2$ 的半球体积 $\propto 2 \cdot B^{d/2}$ |
| **空间复杂度** | $O(A^L \cdot L + D)$ | $O(A^L \cdot L + D)$ |
| **相遇判定机制** | 终点出队或生成时判断 `status == target` | `neighbor in end_set`（集合交集命中） |
| **状态平衡策略** | 无（固定单端向外推） | `len(start_set) > len(end_set)` 动态交换小端优先 |

### 4. 复杂度分析

* **时间复杂度**：$\mathcal{O}(D \cdot A^N + |\text{deadends}|)$
  * 其中 $N=4$ 为拨轮位数，$A=10$ 为每个拨轮的状态数（总节点数 $10^4$）。
  * 每个节点生成 $2N = 8$ 个邻居，字符串切片耗时 $\mathcal{O}(N)$。
  * 最坏情况下遍历全部状态，耗时受常数上限约束（约在毫秒级内完成）。
* **空间复杂度**：$\mathcal{O}(A^N + |\text{deadends}|)$
  * 哈希表与集合存储访问过的状态，最多 $10,000$ 项。

## 为什么双向BFS把 `Queue` 换成了两个 `Set`，但它在数学本质上依然是 100% 的 BFS。**

### 1. 为什么平时 BFS 非要用 `Queue`？

在标准的单向 BFS 里，用队列是为了**维护层级顺序**（先进先出 FIFO）：
* 队列里挤着当前层还没处理完的节点，以及下一层刚生出来的节点；
* 必须靠队列“排队”的机制，保证步数为 1 的节点全部出队后，才开始处理步数为 2 的节点。

### 2. 为什么双向 BFS 可以抛弃 `Queue`，改用 `Set`？

因为在双向 BFS 中，我们是**一整层一整层批量打包处理的**：

* `start_set` 里装的就是当前这一整层（比如距离起点步数为 $k$）的所有节点。
* `next_set` 用来收集下一整层（距离起点步数为 $k+1$）的所有节点。
* 每一轮循环：
  * 把 `start_set` 里的所有节点挨个拿出来，算好它们所有的邻居塞进 `next_set`；
  * `step += 1`；
  * `start_set = next_set`（整层替换）。

因为这一层和下一层已经被硬生生拆分成了两个独立的集合，不再需要一个长队列来维持先后秩序了。

### 3. 改用 `Set` 的致命优势：$O(1)$ 的相交碰撞检测

如果两端都用 `queue1` 和 `queue2`，当从一端搜出一个新节点 `neighbor` 时，你怎么知道它有没有撞上另一端？

* **用 Queue**：你得在 `queue2` 里面找 `if neighbor in queue2`，队列查找是 **$\mathcal{O}(N)$** 的，效率极差。
* **用 Set**：哈希集合的底层是哈希表，`if neighbor in end_set` 的查找耗时是 **$\mathcal{O}(1)$**！

### 4. 灵魂代码解析：那句神奇的“集合交换”

整段代码最精髓的就是这 3 行：

```python
# 贪心选择更小的集合进行扩展，保持两端平衡
if len(start_set) > len(end_set):
    start_set, end_set = end_set, start_set
```

这句代码实际上在做**身份调换**：
* 谁包含的节点少，谁就成为当前的 `start_set`（负责往外走一步的那一端）；
* 谁包含的节点多，谁就静止不动当靶子 `end_set`。

**为什么这样做能快上百倍？**
* 假设当前正向波纹有 1000 个节点，而反向波纹只有 2 个节点：
  * 如果盲目去扩散这 1000 个节点，每个节点生 8 个邻居，你得循环算 **8000 次**；
  * 但只要把它们俩身份对调，变成去扩散那 2 个节点的端点，每个生 8 个邻居，只要算 **16 次**！
* 只要那 16 次算出来的新状态撞进了那 1000 个节点的集合里，路径立马就连通了。

### 总结

`Set` 只是把“流水线式的入队出队”，变成了“整层批量快照”。每一步都在用 $\mathcal{O}(1)$ 检测两圈水波是否相交，并且永远挑小的一侧去扩散。

## 这道题在数学本质上就是一个**“无权图求最短路径（Shortest Path in an Unweighted Graph）”**问题。

题目虽然披了一层“密码锁拨轮”的生活外衣，但只要把生活语言翻译成数据结构语言，整张图就完全浮现出来了：

### 1. 生活语言 $\to$ 图论语言的精准映射

* **图的节点（Vertex / Node）**：
  * 密码锁上的每一个 4 位数状态（如 `"0000"`、`"0001"`、`"1000"`）。
  * 全图总共有 $10 \times 10 \times 10 \times 10 = 10,000$ 个独立的节点。
* **图的边（Edge）**：
  * 旋转一次转盘的操作。
  * 比如 `"0000"` 向上拨一下变成 `"0001"`，或者向下拨一下变成 `"0009"`，就代表节点 `"0000"` 与 `"0001"`、`"0009"` 之间**存在一条双向相连的边**。
  * 每个节点只有 8 条边（4 个轮子 $\times$ 向上/向下 2 种拨法）。
* **边的权重（Weight）**：
  * 每转动一次算作 1 步，所有边的长度都严格等于 $1$（**标准的无权图 / 等权图**）。
* **障碍物（Obstacle）**：
  * `deadends` 就是图里被“炸毁”或者“封路”的死节点，遍历时绝对不能踩进去。
* **目标**：
  * 求从起点节点 `"0000"` 走到终点节点 `target` 的**最少旋转次数**（即图论里的**最短路径长度**）。

### 2. 为什么必须是 BFS，而不是 DFS？

面对图的搜索，通常只有深度优先（DFS）和广度优先（BFS）两种选择：

* **为什么不能用 DFS（深度优先）？**
  * DFS 是一条路走到黑，可能会在图里顺着某条长路径转几十圈才到达终点，必须把整张图的所有路径全部搜完、穷举出所有可能，才能比较出哪条最短。这会导致严重的递归超时或栈溢出。
* **为什么 BFS（广度优先）天生是解药？**
  * BFS 是**像水波一样一层一层向外同心圆扩散**：
    * 第 0 层：起点 `"0000"`（步数 0）
    * 第 1 层：转 1 次能到达的所有节点（共 8 个）
    * 第 2 层：转 2 次能到达的所有节点……
  * **数学性质保证**：因为每条边的代价都是 1，**队列中第一次把 `target` 弹出来的那个瞬间，所经历的层数必然就是全局最短步数**，找到即可直接返回，连多余的边都不用搜。

### 一句话看透

当你看到题目要求：**“最少步数 / 最短距离”** 且 **“每一步的代价都相等（都是 1）”** 时，条件反射就是**把状态抽象成图的节点，直接上 BFS**。

## 在高阶算法和实际工程里，图分为两种：**显式图（Explicit Graph）** 和 **隐式图（Implicit Graph）**。

### 1. 显式图 vs 隐式图

* **显式图（如 Copy Graph）**：
  * **先建好再给你**。内存里已经有 `Node` 对象，所有的边（邻接表/指针）都预先画好了，你拿着指针顺藤摸瓜。
* **隐式图（如 Open the Lock / 华容道 / 迷宫 / 走围棋）**：
  * **内存里根本没有 `Node` 对象，也没有画好的边，但逻辑上它完全符合图的公理定义**。
  * 节点是**状态（State）**，边是**合法操作（Action/Transition）**。
  * 邻居节点不需要存在数组里，而是靠你**现算出来的**！

### 2. 数学上对“图”的严格定义是什么？

在离散数学里，只要一个系统能定义出两样东西，它在数学上就是一个**图 $G = (V, E)$**：

* **顶点集 $V$（Vertices / 节点）**：
  * 只要是系统的一个**确定状态**，就是一个节点。
  * 在锁的题目里，当前屏幕显示什么数字？`"0000"` 是一个状态，`"0239"` 是一个状态。全宇宙一共有 10,000 个可能的状态，这就是 $10,000$ 个顶点。
* **边集 $E$（Edges / 连线）**：
  * 两个状态之间，**如果能通过一步合法操作相互转换，那它们之间就存在一条边**。
  * 你手里拿着 `"0000"`，手指向上拨动第一位，变成了 `"1000"`。
  * 这意味着什么？意味着 `"0000"` 和 `"1000"` 之间**存在一条通路**。

### 3. 用“Copy Graph 的视角”看“Open the Lock”

如果你非要用 `Node` 类来写这道题，它完全可以等价写成下面这样：

```python
# 假设系统在后台预先偷偷帮你建好了这一万个 Node：
node_0000 = Node("0000")
node_1000 = Node("1000")
node_9000 = Node("9000")
...

# 然后把每个节点的 neighbors 连好：
node_0000.neighbors = [node_1000, node_9000, node_0100, node_0900, ...]
```

如果题目先把这一万个对象在内存里建好、连好，然后把 `node_0000` 作为入口传给你：

> “给你一个图的起点 `node_0000`，请问走几步能走到 `node_target`？”

这时候你绝对一眼就认出它是图了，对吧？

**为什么题目不这么给？**  
因为根本没必要浪费内存去建这一万个对象！当你在遍历到 `"0000"` 时，写一个简单的循环做加减法：

```python
# 这段代码，本质上就是在动态生成它的 neighbors！
neighbors = []
for i in range(4):
    neighbors.append(turn_up(status, i))
    neighbors.append(turn_down(status, i))
```

这和去读 `node.neighbors` 没有任何区别，只是邻居由“内存指针”变成了“算术函数”。

### 总结

* **不要被没有 `class Node` 迷惑**。
* **只要一道题在做“状态转移”**（从一个状态通过某些规则变到下一个状态，问最少几步能变到目标状态），它的骨子里就是一张**图**。
* 每一种状态是一个节点，每一次操作就是一条边。求最少步数，就是在图上找最短路径，所以必须用 **BFS**。

## ### 以样例深度解析：水波（BFS）是如何在这道题里一层层渗透的？

* **起点**：`"0000"`
* **障碍物**：`["0201", "0101", "0102", "1212", "2002"]`
* **终点**：`"0202"`
* **输出**：`6`

#### 1. 水波的扩散过程（层级推进）

将起点 `"0000"` 视作水池中心投入的一粒石子，水波以**“旋转步数”**为半径，一圈圈向外荡开：

* **第 0 层（水滴入水，步数 = 0）**
  * 包含状态：`["0000"]`
  * 检查：是否为目标 `"0202"`？不是。
  * 推进：每个轮子向上拨一下、向下拨一下，向外激荡出第 1 圈波纹。

* **第 1 层（水波荡开第 1 圈，步数 = 1）**
  * 包含所有转动 **1 次** 可达的状态（共 8 个）：
    `["1000", "9000", "0100", "0900", "0010", "0090", "0001", "0009"]`
  * 检查：是否包含 `"0202"`？无。
  * 推进：这 8 个状态各自再向外拨动 1 次，激荡出第 2 圈波纹。

* **第 2 层（水波荡开第 2 圈，步数 = 2）**
  * 包含由第 1 层状态衍生出的所有二次转动结果（如 `"0100"` 演化出的 `["0200", "0110", ...]`，`"0001"` 演化出的 `["0002", ...]` 等）。
  * **遇到障碍物（礁石）**：
    * 在这一层扩散时，部分分支转出了 `"0101"`、`"0102"`、`"2002"`。
    * 遇到这些死锁点，水波**直接被挡住，该分支不再向前蔓延**。
  * 检查：剩余水波中是否包含 `"0202"`？依然无。

* **第 3、4、5 层（水波持续向外漫延）**
  * 分别计算步数等于 3、4、5 的所有合法新状态。
  * 在这几圈波纹内，均未触碰到 `"0202"`。

* **第 6 层（水波首次触碰终点，步数 = 6）**
  * 沿某条绕开障碍的路线（例如 `"0000"` $\to$ `"0001"` $\to$ `"0002"` $\to$ `"1002"` $\to$ `"1102"` $\to$ `"1202"` $\to$ `"0202"`）：
  * **队列中首次弹出目标状态 `"0202"`**。
  * 程序立即停止搜索，直接返回当前层数：**`6`**。

#### 2. 为什么“水波扩散”必然锁定“最少步数”？

通过反证法即可明确其数学确定性：

1. **严格按步数半径递增推进**：
   * 算法必定遍历完**第 1 层的 8 个可能**；
   * 随后遍历完**第 2 层的全部可能**；
   * 依此类推逐层向外覆盖。
2. **全局最优解的必然性**：
   * 若 `"0202"` 可以在 **$\le 5$ 步** 内到达，它必定在第 1 至 5 层的扩散中就已经被触碰到。
   * 它直到第 6 层才首次被波纹覆盖，从逻辑上**严格排除了存在 $\le 5$ 步路径的可能性**。

#### 3. 为什么不用 DFS（深度优先）？

* **DFS 的遍历机制**：一条路走到黑。
  * 例如在某分支上一路递增：`"0000"` $\to$ `"1000"` $\to$ `"2000"` $\dots$；
  * 可能在图内弯弯绕绕转了 **50 步** 后碰巧撞上 `"0202"`。
* **致命缺陷**：
  * 此时无法将 `50` 作为答案返回，因为无法判断其他分支是否存在 6 步直达的捷径。
  * 必须将全图所有可能路径完整穷举回溯一遍，才能确定最小值，效率极低。

**结论**：求无权图的“最少步数 / 最短距离”，BFS 的层级推进性质保证了**首次触及目标时的层数即为全局最优解**。

### 双向 BFS（Bidirectional BFS）：双水波相向相撞机制

单向 BFS 是从起点单向荡开一圈水波去追终点；**双向 BFS** 则是**起点与终点同时入水**——一颗扔在起点 `"0000"`，另一颗扔在终点 `"0202"`，两圈水波同时向中间荡开，直到水花相撞。

同样以该组输入为例：
* **起点**：`"0000"`
* **终点**：`"0202"`
* **最短步数**：`6`

#### 1. 双向水波的推进时序

双向 BFS 不需要单向走满 6 步，而是**两头各自推进 3 步**：

* **第 0 步（初始状态）**
  * 正向集合（起点）：`{"0000"}`
  * 反向集合（终点）：`{"0202"}`

* **第 1 步（正向水波荡开第 1 圈，半径 = 1）**
  * 正向扩展 8 个状态：`{"1000", "9000", "0100", "0001", ...}`
  * 检查：正向状态是否出现在反向集合中？无重合。

* **第 2 步（反向水波荡开第 1 圈，半径 = 1）**
  * 反向从 `"0202"` 倒推 1 圈（共 8 个邻居）：`{"1202", "9202", "0302", ...}`
  * 过滤死锁点（如 `"0102"`, `"0201"` 等）。
  * 检查：是否与正向状态集合重合？无重合。

* **第 3 步（正向水波荡开第 2 圈，半径 = 2）**
  * 正向集合继续向外推一层，生成步数为 2 的合法新状态。
  * 检查：依然未触及反向集合。

* **第 4 步（反向水波荡开第 2 圈，半径 = 2）**
  * 反向集合再向外倒推一层，生成步数为 2 的状态集合。
  * 检查：两端仍未相遇。

* **第 5 步（正向水波荡开第 3 圈，半径 = 3，相撞发生）**
  * 正向波纹推到第 3 步，扩散到了某个中间状态 $X$。
  * **命中交集**：该状态 $X$ **已存在于反向波纹的集合中**。
  * **两端接力成功**：正向走了 3 步，反向走了 3 步，总步数：$3 + 3 = \mathbf{6}$。
  * 搜索立即终止并返回结果。

#### 2. 为什么双向 BFS 能快成百上千倍？

图搜索的状态树具有**指数级发散**的特点。设每个节点的分支因子为 $b$（本题中 $b \approx 8$），最短路径深度为 $d = 6$：

* **单向 BFS（单个大圆）**
  * 必须硬搜满 6 层：
    $$\text{搜索规模} \approx b^d = 8^6 \approx 262,144 \text{ 个状态}$$
* **双向 BFS（两个小圆之和）**
  * 两端各搜 3 层即可相遇：
    $$\text{搜索规模} \approx 2 \times b^{d/2} = 8^3 + 8^3 = 512 + 512 = 1,024 \text{ 个状态}$$

$$\frac{262,144}{1,024} \approx 256 \text{ 倍性能提升}$$

* **几何直觉**：单向 BFS 覆盖的是一个半径 $R=6$ 的巨型圆锥体；双向 BFS 覆盖的是两个半径 $r=3$ 的小型对顶圆锥体，二者的截面面积与体积具有量级差距。

#### 3. 核心优化细节：贪心交替扩展

代码中没有固定采用“正向走一步、反向走一步”的机械轮换，而是使用**双向集合大小比较**进行贪心剪枝：

```python
# 永远只扩散节点数较少的那一端集合
if len(start_set) > len(end_set):
    start_set, end_set = end_set, start_set
```

* 哪一侧当前波纹中的候选节点少，就优先扩展哪一侧。
* 该策略确保搜索树始终在最狭窄的截面处进行繁殖，将内存占用与邻居计算量控制在理论下界。

这是一张**无向图（Undirected Graph）**。

判断一张状态图是有向还是无向，核心标准只有一个：**任何一次操作是否完全可逆？**

### 1. 为什么是无向的？

* **操作完全对等且可逆**：
  * 如果你可以把第一位从 `0` **向上拨**变成 `1`（`"0000"` $\to$ `"1000"`）；
  * 那么在 `"1000"` 状态下，你完全可以原路**向下拨**变回 `0`（`"1000"` $\to$ `"0000"`）。
* **循环边界同样可逆**：
  * `0` 向下拨是 `9`（`"0000"` $\to$ `"9000"`）；
  * `9` 向上拨就能直接回到 `0`（`"9000"` $\to$ `"0000"`）。

节点 $A$ 能一步走到节点 $B$，节点 $B$ 就必然能一步走回节点 $A$。二者之间的连线是**双向互通**的，因此数学建模上是一张**无向图**。

### 2. 这个性质为什么对“双向 BFS”至关重要？

正因为它是**无向图**，反向搜索才能写得如此丝滑：

* 从终点 `target` 往回倒着搜时，**状态转移的规则（邻居生成函数）和从起点往前搜完全一模一样**（依然是 4 个位置各自 $+1$ 和 $-1$）。
* 如果是有向图，反向搜索时必须沿着**反向边（Reverse Edges）**倒着走；而无向图的“反向边就是正向边自己”，这也是双向 BFS 能直接复用同一套生成逻辑的前提。

### 什么是“有向图”（Directed Graph / Digraph）？

**有向图**是指图中的边具有**单向性（方向）**。若存在一条从节点 $A$ 指向节点 $B$ 的边（记作 $A \to B$），并不代表可以从 $B$ 原路返回 $A$。

#### 1. 现实生活中的直观映射

* **城市路网中的单行道（One-way Street）**：
  * 可以驾车从路口 $A$ 开到路口 $B$，但从 $B \to A$ 属于逆行，物理/规则上不通。
* **社交网络的关系链**：
  * **无向图模型（如微信好友）**：双方必须互通，添加即为双向连通。
  * **有向图模型（如 Twitter / 微博关注）**：用户 $A$ 关注用户 $B$（$A \to B$），并不代表用户 $B$ 关注了用户 $A$。
* **互联网超链接（PageRank 算法基石）**：
  * 网页 $A$ 页面内嵌入了指向网页 $B$ 的超链接，网页 $B$ 上并不必然存在返回 $A$ 的反向链接。

#### 2. 算法题目中的典型“隐式有向图”

与“转盘锁（拨动操作完全对称可逆）”不同，许多算法场景中的状态转移是**单向不可逆**的：

* **课程安排 / 拓扑排序（如 LeetCode 207. Course Schedule）**：
  * 选修《机器学习》（$B$）的前提是先修完《线性代数》（$A$）。
  * 依赖方向严格为 $A \to B$，这是最经典的**有向无环图（DAG, Directed Acyclic Graph）**。
* **状态倒水问题（Water Jug Problem）**：
  * 将大容量壶中的水倒入小容量壶直至倒满，该状态转移无法通过同一物理动作瞬间逆转，状态迁移带有明确的方向约束。
* **迷宫中的单向传送门 / 滑冰单向坡道**：
  * 从单元格 $A$ 滑落或传送到单元格 $B$，但 $B$ 处不存在反向通往 $A$ 的出口。

#### 3. 代码实现层面的区别（邻接表）

在邻接表（Adjacency List）的代码实现中，两者的区别非常直观：

```python
# 无向图（Undirected）：双向互通，必须两端相互注册
def add_undirected_edge(adj, u, v):
    adj[u].append(v)
    adj[v].append(u)

# 有向图（Directed）：单向箭头，仅注册出边
def add_directed_edge(adj, u, v):
    adj[u].append(v)  # 仅表示 u -> v
```

#### 4. 核心维度对比

| 维度 | 无向图（Undirected Graph） | 有向图（Directed Graph） |
| :--- | :--- | :--- |
| **边的数学表示** | 无序对 $(u, v)$，等价于线段 $A - B$ | 有序对 $\langle u, v \rangle$，表现为单向箭头 $A \to B$ |
| **路径可逆性** | 完全对称、可双向折返 | 单向、不对称、不可沿原边逆行 |
| **节点的度数** | 仅有“度”（Degree）的概念 | 严格区分入度（In-degree）与出度（Out-degree） |
| **转盘锁题目的类比** | 向上拨一下，立即可以向下拨还原 | 若锁盘设计了内部机械棘轮，只允许单向向前拨动，则退化为有向图 |

# 210. 课程表 II (Course Schedule II)

现在你总共有 `numCourses` 门门课需要选，记为 `0` 到 `numCourses - 1`。给你一个数组 `prerequisites` ，其中 `prerequisites[i] = [a_i, b_i]` ，表示在选修课程 `a_i` 前 **必须** 先完成课程 `b_i` 。

* 例如，想要学习课程 `0` ，你需要先完成课程 `1` ，我们用一个匹配来表示：`[0, 1]` 。

返回你为了学完所有课程所安排的学习顺序。可能会有多个正确的顺序，你只要返回 **任意一种** 就可以了。如果不可能完成所有课程，返回 **一个空数组** 。

### 示例 1

* **输入**: `numCourses = 2, prerequisites = [[1,0]]`
* **输出**: `[0,1]`
* **解释**: 总共有 2 门课程。要学习课程 1，你需要先完成课程 0。因此，正确的课程顺序为 `[0,1]` 。

### 示例 2

* **输入**: `numCourses = 4, prerequisites = [[1,0],[2,0],[3,1],[3,2]]`
* **输出**: `[0,2,1,3]` 或 `[0,1,2,3]`
* **解释**: 总共有 4 门课程。要学习课程 3，你应该先完成课程 1 和课程 2。并且课程 1 和课程 2 都应该排在课程 0 之后。
因此，一个可能的课程顺序是 `[0,1,2,3]`。另一个可能的学问顺序是 `[0,2,1,3]`。

### 示例 3

* **输入**: `numCourses = 1, prerequisites = []`
* **输出**: `[0]`

### 提示

* `1 <= numCourses <= 2000`
* `0 <= prerequisites.length <= numCourses * (numCourses - 1)`
* `prerequisites[i].length == 2`
* `0 <= a_i, b_i < numCourses`
* `a_i != b_i`
* 所有 `[a_i, b_i]` **互不相同**


这道题是图论中最经典的**有向无环图（DAG）拓扑排序（Topological Sort）**问题。与刚刚的转盘锁（无向图、状态隐式生成）不同，这是一道**显式建图的有向图**题目。

#### 1. 核心模型抽象

* **图的节点（Vertex）**：课程编号 $0$ 到 $\text{numCourses}-1$。
* **图的有向边（Directed Edge）**：先修依赖关系。
  * 输入给出的 `[a, b]` 表示：想修课程 `a`，必须先修课程 `b`。
  * **建边方向**：$b \to a$（修完 $b$，才能解锁 $a$）。
* **核心数学概念：入度（In-degree）**：
  * 指向节点 $u$ 的边的条数。
  * **生活意义**：修课程 $u$ 之前，还剩几门必修前置课没上完。
  * **入度为 0**：代表没有任何前置依赖，可以立刻选修。
* **目标**：找出一个合法的线性修课顺序（即拓扑序列）。若图中存在**环（Cycle）**，说明存在死锁循环依赖，直接返回空列表 `[]`。

#### 2. Kahn 算法（基于 BFS 的拓扑排序）

Kahn 算法用队列实现，核心思想是**“剥洋葱”**：

1. 统计所有节点的初始入度，并构建有向邻接表。
2. 将所有**入度为 0** 的课程送入队列（这些课没有任何先修门槛）。
3. 当队列不为空时：
   * 弹出一门课程 `cur`，加入修课清单 `order`（表示该课已修完）。
   * 遍历 `cur` 指向的后续课程 `nxt`：将 `nxt` 的入度减 1（表示 `nxt` 的前置要求少了一门）。
   * 若此时 `nxt` 的入度减到了 0，说明它的所有先决条件都已满足，将其送入队列。
4. **环的判定**：最终检查 `len(order) == numCourses`。
   * 若等于，返回 `order`。
   * 若小于，说明图中有**环**，环内的节点入度永远不可能减到 0，导致无法全部入队，返回 `[]`。

```python
from collections import deque

class Solution:
    def findOrder(self, numCourses: int, prerequisites: list[list[int]]) -> list[int]:
        # 1. 统计入度与构建邻接表
        in_degrees = [0] * numCourses
        adj = [[] for _ in range(numCourses)]
        
        for course, pre in prerequisites:
            adj[pre].append(course)  # 有向边: pre -> course
            in_degrees[course] += 1  # course 的入度 +1
            
        # 2. 将所有入度为 0 的节点放入队列
        queue = deque([i for i in range(numCourses) if in_degrees[i] == 0])
        order = []
        
        # 3. BFS 推进（Kahn 算法）
        while queue:
            cur = queue.popleft()
            order.append(cur)
            
            for nxt in adj[cur]:
                in_degrees[nxt] -= 1
                if in_degrees[nxt] == 0:
                    queue.append(nxt)
                    
        # 4. 环检测：修完的课程数是否等于总课程数
        return order if len(order) == numCourses else []
```

#### 3. 复杂度分析

* **时间复杂度**：O(V + E)
  * 其中 V = numCourses 为节点数，E = prerequisites 的长度（先修依赖的边数）。
  * 建图遍历所有边需要 O(E) 时间；BFS 过程中每个节点入队和出队至多各一次，耗时 O(V)；每条有向边被检查并松弛至多一次，耗时 O(E)。
* **空间复杂度**：O(V + E)
  * 邻接表存储所有节点和边，占用 O(V + E) 空间。
  * 入度数组 `in_degrees` 与辅助队列 `queue` 各自占用 O(V) 空间。

# 207. 课程表 (Course Schedule)

你这个学期必须选修 `numCourses` 门课程，记为 `0` 到 `numCourses - 1` 。

在选修某些课程之前需要一些先修课程。先修课程按数组 `prerequisites` 给出，其中 `prerequisites[i] = [a_i, b_i]` ，表示如果要学习课程 `a_i` 则 **必须** 先学习课程 `b_i` 。

* 例如，先修课程对 `[0, 1]` 表示：想要学习课程 `0` ，你需要先完成课程 `1` 。

请你判断是否可能完成所有课程的学习？如果可以，返回 `true` ；否则，返回 `false` 。

### 示例 1

* **输入**：`numCourses = 2, prerequisites = [[1,0]]`
* **输出**：`true`
* **解释**：总共有 2 门课程。学习课程 1 之前，你需要完成课程 0。这是可能的。

### 示例 2

* **输入**：`numCourses = 2, prerequisites = [[1,0],[0,1]]`
* **输出**：`false`
* **解释**：总共有 2 门课程。学习课程 1 之前需要先完成课程 0；并且学习课程 0 之前还必须先完成课程 1。形成闭环，因此不可能完成。

### 提示

* `1 <= numCourses <= 2000`
* `0 <= prerequisites.length <= 5000`
* `prerequisites[i].length == 2`
* `0 <= a_i, b_i < numCourses`
* `prerequisites[i]` 中的所有课程对 **互不相同**

### 题目解析：核心模型转换

1. **图建模**：
   * **节点**：每门课程（$0$ 到 $\text{numCourses}-1$）。
   * **有向边**：对于 `[a, b]`，其含义是先修 $b$ 再修 $a$，因此建立有向边 **$b \to a$**。
2. **问题本质**：
   * 判断一个有向图是否存在**环（Cycle）**。
   * 若图中有环（如 $A \to B \to A$），代表死锁依赖，无法完成修课；若无环（即有向无环图 DAG），则必定存在一条合法的修课路径。

### 解法：Kahn 算法（BFS 拓扑排序）

#### 算法逻辑
1. 维护每个节点的**入度数组** `in_degrees`（即前置课程数量）与**邻接表** `adj`。
2. 将所有初始**入度为 0** 的节点（没有依赖的课）放入队列。
3. 循环出队：
   * 每次弹出一个节点，代表修完一门课，计数器 `visited_count += 1`。
   * 遍历该课程指向的所有后置课程，将其入度减 1。
   * 若后置课程的入度减为 0，将其入队。
4. 遍历结束后，如果 `visited_count == numCourses`，说明无环，返回 `True`；否则存在环，返回 `False`。

#### Python 参考代码

```python
from collections import deque

class Solution:
    def canFinish(self, numCourses: int, prerequisites: list[list[int]]) -> bool:
        # 1. 统计入度与构建邻接表
        in_degrees = [0] * numCourses
        adj = [[] for _ in range(numCourses)]
        
        for course, pre in prerequisites:
            adj[pre].append(course)  # 有向边: pre -> course
            in_degrees[course] += 1  # 后置课程入度 +1
            
        # 2. 将所有入度为 0 的节点加入队列
        queue = deque([i for i in range(numCourses) if in_degrees[i] == 0])
        visited_count = 0
        
        # 3. BFS 拓扑排序
        while queue:
            cur = queue.popleft()
            visited_count += 1
            
            for nxt in adj[cur]:
                in_degrees[nxt] -= 1
                if in_degrees[nxt] == 0:
                    queue.append(nxt)
                    
        # 4. 判断是否所有课程都能修完
        return visited_count == numCourses
```

### 复杂度分析

* **时间复杂度**：O(V + E)
  * V = numCourses，E = len(prerequisites)。
  * 建图遍历所有依赖对耗时 O(E)；队列出入队每个节点至多一次耗时 O(V)；遍历所有邻接边耗时 O(E)。
* **空间复杂度**：O(V + E)
  * 邻接表占用 O(V + E) 空间；入度数组与队列占用 O(V) 空间。
 
## 两道题的算法内核完全一致（都是检测有向图是否有环并进行拓扑排序），核心区别只在于返回值的要求：

| 题目 | LeetCode 207. Course Schedule（课程表 I） | LeetCode 210. Course Schedule II（课程表 II） |
| :--- | :--- | :--- |
| **提问目标** | **判定题**（能不能修完？） | **构造题**（怎么修？给出一个具体顺序） |
| **返回值类型** | `bool` (`True` / `False`) | `list[int]`（具体修课序列，无解返回 `[]`） |
| **数学本质** | 判断图是否为 **DAG**（有向无环图） | 输出该 DAG 的一个 **拓扑排序序列**（Topological Sort） |

### 这道题还可以用三色标记法来解.到底什么是 DFS “三色标记法”（Three-Color Marking）？

**三色标记法**是《算法导论》中用 **DFS 遍历有向图**时最经典的状态标记方法。

它专门用来解决两个核心问题：
1. **精准检测有向图中是否存在“环（Cycle）”**。
2. **在 DFS 递归回溯时，顺手生成“拓扑排序序列”**。

#### 1. 为什么叫“三色”？

在常规的无向图或简单遍历中，通常只用一个布尔值 `visited`（访问过 / 没访问过）。但在**有向图**中，如果只有两种状态，你会无法区分：
* “这个节点是在**当前搜索路径（调用栈）**上，还是在**之前的某条已经搜完的安全分支**上？”

因此，需要定义 **三种状态（三种颜色）**：

| 状态值 | 颜色代表 | 含义与解释 |
| :--- | :--- | :--- |
| `0` | **白色（White）** | **未访问**：算法还没有触碰过这个节点。 |
| `1` | **灰色（Gray）** | **搜索中（当前递归调用栈上）**：该节点正在被访问，且它的后代节点还没递归结束。 |
| `2` | **黑色（Black）** | **已完成**：以该节点为起点的所有子树/后代路径已经全部遍历完毕，且确认无环。 |

#### 2. 核心原理：怎么抓到“环”？

有向图出现环的充分必要条件：**在 DFS 向深处推进的过程中，撞见了当前递归栈里的“祖先节点”**。

* 如果邻居是 **白色（0）**：说明是全新节点，继续正常深入递归。
* 如果邻居是 **黑色（2）**：说明这个邻居之前已经全盘搜过并且是安全的，直接跳过（剪枝），不需要重复走。
* **如果邻居是 灰色（1）**：
  * 意味着当前节点顺着箭头走，居然连回了自己的祖先节点！
  * 这在图论中叫 **回边（Back Edge）**，即**必定存在环（Cycle）**。

#### 3. 为什么拓扑排序需要“逆序”？

这是 DFS 做拓扑排序最精妙的一点：

* 当一个节点变成 **黑色（2）** 时，意味着**所有依赖它的后置课程都已经彻底搜完并处理完了**。
* 换句话说，谁最先变成黑色，谁就属于依赖链条的“最底端（最深处）”。
* 因此，在节点遍历结束、即将出栈被标记为黑色时，将其加入结果列表；**最后把整个列表反转（Reverse），或者每次从头部插入（倒序输出）**，得到的正好就是合法的拓扑排序。

#### 4. 完整代码实现（以 LeetCode 210 为例）

```python
class Solution:
    def findOrder(self, numCourses: int, prerequisites: list[list[int]]) -> list[int]:
        # 1. 构建邻接表: pre -> course
        adj = [[] for _ in range(numCourses)]
        for course, pre in prerequisites:
            adj[pre].append(course)
            
        # 0: 白色(未访问), 1: 灰色(正在当前栈中访问), 2: 黑色(已完成)
        visited = [0] * numCourses
        order = []
        has_cycle = False
        
        def dfs(u: int) -> None:
            nonlocal has_cycle
            if has_cycle:
                return
            
            visited[u] = 1  # 进栈，染成灰色
            
            for v in adj[u]:
                if visited[v] == 0:  # 未访问节点，继续递归
                    dfs(v)
                elif visited[v] == 1:  # 撞见祖先节点(灰色)，发现了环！
                    has_cycle = True
                    return
                # visited[v] == 2 的黑色节点直接跳过
            
            visited[u] = 2   # 所有邻居都处理完了，出栈，染成黑色
            order.append(u)  # 记录完成顺序(后序遍历)
            
        # 对每一个还未访问的节点启动 DFS
        for i in range(numCourses):
            if visited[i] == 0:
                dfs(i)
                if has_cycle:
                    return []
                    
        # 后序遍历出栈的顺序是反的，翻转后即为正确的拓扑序
        return order[::-1]
```

#### 5. Kahn 算法 (BFS) vs 三色标记法 (DFS)

| 对比维度 | Kahn 算法（BFS） | 三色标记法（DFS） |
| :--- | :--- | :--- |
| **思维模型** | **入度视角（剥洋葱）**：从源头（入度=0）往前推 | **回溯视角（深搜）**：从终点后序收集，最后逆序 |
| **空间开销** | 显式队列 `queue` + `in_degrees` 数组 | 系统递归栈（递归深度最多 $V$）+ `visited` 状态数组 |
| **面试推荐度** | **首选**：逻辑直观，不易爆栈，无须逆序操作 | **备选/进阶**：适合展示对图遍历、状态机及调用栈的理解 |

# 198. 打家劫舍 (House Robber)

你是一个专业的小偷，计划偷窃沿街的房屋。每间房内都藏有一定的现金，影响你偷窃的唯一制约因素就是相邻的房屋装有相互连通的防盗系统，**如果两间相邻的房屋在同一晚上被小偷闯入，系统会自动报警**。

给定一个代表每个房屋存放金额的非负整数数组 `nums` ，计算你 **不触动警报装置的情况下** ，一夜之内能够偷窃到的最高金额。

### 示例 1

* **输入**：`nums = [1,2,3,1]`
* **输出**：`4`
* **解释**：偷窃 1 号房屋 (金额 = 1) ，然后偷窃 3 号房屋 (金额 = 3)。偷窃到的最高金额 = 1 + 3 = 4 。

### 示例 2

* **输入**：`nums = [2,7,9,3,1]`
* **输出**：`12`
* **解释**：偷窃 1 号房屋 (金额 = 2), 偷窃 3 号房屋 (金额 = 9)，接着偷窃 5 号房屋 (金额 = 1)。偷窃到的最高金额 = 2 + 9 + 1 = 12 。

### 提示

* `1 <= nums.length <= 100`
* `0 <= nums[i] <= 400`

### 题目解析：单串线性动态规划

#### 1. 状态定义
设 `dp[i]` 表示考虑前 `i` 间房屋（下标 `0` 到 `i`）时能偷到的最高金额。

#### 2. 状态转移方程
对于第 `i` 间房屋，小偷只有两种决策：
* **不偷第 i 间房**：最大收益等于前 `i-1` 间房的最大收益，即 `dp[i-1]`。
* **偷第 i 间房**：因为相邻房不能偷，所以第 `i-1` 间房必定不能偷，最大收益等于前 `i-2` 间房的最大收益加上第 `i` 间房的金额，即 `dp[i-2] + nums[i]`。

因此状态转移方程为：
`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`

#### 3. 空间优化（滚动变量）
观察发现，计算当前状态 `dp[i]` 只需要前两项 `dp[i-1]` 和 `dp[i-2]`。因此不需要开辟长度为 $N$ 的数组，只需两个变量滚动更新，将空间复杂度压至 $O(1)$。

### 动态规划解法详解

#### 1. 状态定义
设 `dp[i]` 表示考虑前 `i` 间房屋（下标 `0` 到 `i`）时，能够盗取的最高金额。

#### 2. 状态转移方程
对于第 `i` 间房屋，小偷面临两种互斥抉择：
* **不偷第 i 间房**：损失第 `i` 间房的现金，但前一间房不受限制。此时的最大收益完全继承自前 `i-1` 间房的最优解，即 `dp[i-1]`。
* **偷第 i 间房**：获得第 `i` 间房的现金 `nums[i]`，但由于防盗系统相邻报警，第 `i-1` 间房绝对不能偷。因此最大收益为前 `i-2` 间房的最优解加上当前房间金额，即 `dp[i-2] + nums[i]`。

综合两种情况取最大值：
$$dp[i] = \max(dp[i-1], dp[i-2] + nums[i])$$

#### 3. 基础初始条件 (Base Cases)
* 只有一间房时（$i = 0$）：显然必偷这间房，`dp[0] = nums[0]`。
* 有两间房时（$i = 1$）：只能二选一，选金额更大的一间，`dp[1] = max(nums[0], nums[1])`。

### 代码实现一：标准 DP 数组（清晰易懂）

```python
class Solution:
    def rob(self, nums: list[int]) -> int:
        if not nums:
            return 0
        if len(nums) == 1:
            return nums[0]
            
        n = len(nums)
        dp = [0] * n
        
        # 基础状态初始化
        dp[0] = nums[0]
        dp[1] = max(nums[0], nums[1])
        
        # 线性状态转移
        for i in range(2, n):
            dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
            
        return dp[-1]
```

* **时间复杂度**：O(N)，单重循环遍历数组一次。
* **空间复杂度**：O(N)，开辟了一个长度为 N 的 DP 数组。

### 代码实现二：空间优化（滚动变量）

在计算 `dp[i]` 时，只依赖前两个历史值：`dp[i-1]` 与 `dp[i-2]`。不需要维护完整数组，只需两个标量变量不断向前滚动覆盖即可。

```python
class Solution:
    def rob(self, nums: list[int]) -> int:
        if not nums:
            return 0
        if len(nums) == 1:
            return nums[0]
            
        # prev2 相当于 dp[i-2], prev1 相当于 dp[i-1]
        prev2 = 0
        prev1 = 0
        
        for x in nums:
            cur = max(prev1, prev2 + x)
            prev2 = prev1
            prev1 = cur
            
        return prev1
```

时间复杂度：O(N)，其中 N 为房屋数量，只需单次遍历数组。
空间复杂度：O(1)，仅使用常数个滚动变量。

**House Robber（打家劫舍）是计算机算法界最经典、最纯粹的入门级动态规划（Dynamic Programming）题目之一**。

它之所以是教科书级的 DP，是因为它完全符合动态规划的两大硬核数学特征：

### 1. 为什么它是 DP？两大核心特征

* **特征一：重叠子问题（Overlapping Subproblems）**
  * 假设你想求前 5 间房能偷的最大金额。
  * 你需要知道前 4 间房的最大金额，以及前 3 间房的最大金额。
  * 而在算前 4 间房的最大金额时，你又需要去算前 3 间房和前 2 间房的最大金额。
  * 这里的“前 3 间房的最佳偷法”被**反复计算了多次**，存在大量的重叠子问题。

* **特征二：最优子结构（Optimal Substructure）**
  * “全局偷得最多”，完全可以由“前面更小规模子房屋偷得最多的状态”组合推导出来。

### 2. 为什么贪心（Greedy）在这题必死无疑？

很多人第一直觉是想用“贪心策略”：
* “我挑金额最大的房偷行不行？”
* “我按奇数偶数偷行不行？（偷所有偶数号房，或者偷所有奇数号房）”

**反例立刻打脸**：
假设金额是 `[2, 1, 1, 2]`
* 如果按奇偶偷：
  * 选下标 0 和 2：`2 + 1 = 3`
  * 选下标 1 和 3：`1 + 2 = 3`
* 但最优解是选两头的 **下标 0 和 3**：`2 + 2 = 4`！中间跳过了两间房（1 和 1）。
* 局部做最贪的选择，得不到全局最优，必须靠 DP 记住所有历史可能。

### 3. 一句话看透它的 DP 决策方程

面对走到眼前的第 `i` 间房，小偷脑子里其实就一念之差的**抉择**：

$$\text{dp}[i] = \max(\underbrace{\text{dp}[i-1]}_{\text{不偷这间，收益跟前一间一样}}, \underbrace{\text{dp}[i-2] + \text{nums}[i]}_{\text{偷这间，前一间必定不能偷，拿这间的钱加更早前的最大收益}})$$

这种**“当前状态由前面几个子状态的最优解转移而来”**的思路，就是标准的线性动态规划。

## 这段代码在算法分类上**是 100% 的动态规划（DP）**，只是它做了**空间压缩（State Compression / 滚动数组）**。

很多人初学时会建立一个刻板印象：“有数组 `dp = [...]` 才是 DP，只有几个变量就不是 DP”。其实动态规划的判断标准从来不是数据结构，而是其**数学状态与转移逻辑**。


### 1. 为什么它本质依然是 DP？

动态规划的核心三要素：

* **状态定义**：`prev1` 代表子问题 `dp[i-1]`，`prev2` 代表子问题 `dp[i-2]`。
* **状态转移方程**：
```python
  cur = max(prev1, prev2 + x)
```

这行代码严格对应数学方程：`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`

* **消除重叠子问题**：它记录了历史最优解，避免了指数级的暴力递归回溯。

### 2. 对比：从“显式 DP”到“滚动 DP”

为了直观看到二者的等价性，看一步一步的推导过程：

* **写法 A（显式 DP 数组，空间 O(N)）**：

```python
  dp = [0] * n
  dp[0] = nums[0]
  dp[1] = max(nums[0], nums[1])
  for i in range(2, n):
      dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
```

在第 `i` 步计算时，计算机只需要读取 `dp[i-1]` 和 `dp[i-2]`。前面的 `dp[i-3]`, `dp[i-4]`... 已经彻底完成历史使命，留在内存里只是占地方。

* **写法 B（你的代码，滚动变量，空间 O(1)）**：

```python
  cur = max(prev1, prev2 + x)  # 计算当前 dp[i]
  prev2 = prev1                # 窗口向右滑动：更新 dp[i-2]
  prev1 = cur                  # 窗口向右滑动：更新 dp[i-1]
```

两者的状态转移路径完全相同，后者只是把数组从“一整张表格”压缩成了“只保留前两格的滑动窗口”。

### 3. 一个极佳的类比：斐波那契数列

* **公式**：`F(n) = F(n-1) + F(n-2)`

* **数组写法（DP）**：

```python
  fib = [0] * (n + 1)
  fib[1] = 1
  for i in range(2, n + 1):
      fib[i] = fib[i - 1] + fib[i - 2]
```

滚动变量写法（仍然是 DP）：

```Python
a, b = 0, 1
for _ in range(2, n + 1):
    a, b = b, a + b
```

没人会因为用 a, b 替代了 fib[] 数组，就认为它不再是动态规划递推。

在面试和系统评测中，这种写法被称为“空间优化后的动态规划”，也是面试官最希望看到的最佳解法。

# 213. 打家劫舍 II (House Robber II)

你是一个专业的小偷，计划偷窃沿街的房屋，每间房内都藏有一定的现金。这个地方所有的房屋都 **围成一圈** ，这意味着第一个房屋和最后一个房屋是紧挨着的。同时，相邻的房屋装有相互连通的防盗系统，**如果两间相邻的房屋在同一晚上被小偷闯入，系统会自动报警** 。

给定一个代表每个房屋存放金额的非负整数数组 `nums` ，计算你 **在不触动警报装置的情况下** ，今晚能够偷窃到的最高金额。

### 示例 1

* **输入**：`nums = [2,3,2]`
* **输出**：`3`
* **解释**：你不能先偷窃 1 号房屋（金额 = 2），然后偷窃 3 号房屋（金额 = 2）, 因为他们是相邻的。

### 示例 2

* **输入**：`nums = [1,2,3,1]`
* **输出**：`4`
* **解释**：你可以先偷窃 1 号房屋（金额 = 1），然后偷窃 3 号房屋（金额 = 3）。偷窃到的最高金额 = 1 + 3 = 4 。

### 示例 3

* **输入**：`nums = [1,2,3]`
* **输出**：`3`

### 提示

* `1 <= nums.length <= 100`
* `0 <= nums[i] <= 1000`

### 题目解析：环形拆解为两个线性子问题

#### 1. 核心矛盾：首尾相连
与第 198 题相比，唯一的改变是第一间房 `nums[0]` 和最后一间房 `nums[n-1]` 变成了相邻关系。这意味着：**第一间房和最后一间房绝对不能同时被偷**。

#### 2. 分类讨论（破环成链）
既然首尾互斥，整个问题可以严密地划分为两种互斥情况：
1. **不偷最后一间房 `nums[n-1]`**：候选房屋范围为 `nums[0 : n-1]`（即第一间到倒数第二间）。
2. **不偷第一间房 `nums[0]`**：候选房屋范围为 `nums[1 : n]`（即第二间到最后一间）。

在这两段子区间内，房屋结构**退化成了完全平行的单向直线**，不再存在环的约束。因此，直接对这两个区间分别调用第 198 题的线性 DP 函数，取二者的最大值即可：
`ans = max(rob_linear(nums[0 : n-1]), rob_linear(nums[1 : n]))`

#### 3. Python 参考代码

```python
class Solution:
    def rob(self, nums: list[int]) -> int:
        n = len(nums)
        if n == 1:
            return nums[0]
            
        # 封装 198 题的标准线性打家劫舍函数 (空间 O(1))
        def rob_linear(houses: list[int]) -> int:
            prev2, prev1 = 0, 0
            for x in houses:
                cur = max(prev1, prev2 + x)
                prev2 = prev1
                prev1 = cur
            return prev1
            
        # 拆分为两个单向线性子问题取极大值
        return max(rob_linear(nums[:-1]), rob_linear(nums[1:]))
```

时间复杂度：O(N)，执行两次线性扫描，总耗时为 O(N)。
空间复杂度：O(1)，切片或指针传递仅消耗常数级额外空间。

| 对比维度 | LeetCode 198. House Robber (I) | LeetCode 213. House Robber II |
| :--- | :--- | :--- |
