# LeetCode 997. 找到小镇的法官（Find the Town Judge）题目解析

「找到小镇的法官」（Find the Town Judge）是 LeetCode 第 997 题，是一道经典的图论与数组统计问题。

## 1. 题目描述

在一个小镇里，有 `n` 个人，被标记为从 `1` 到 `n`。传言称，这些人中有一个是小镇上的秘密法官。

如果小镇的法官真的存在，那么：
1. 小镇的法官**不相信任何人**。
2. 每个人（除了法官外）都**信任**小镇的法官。
3. 只有一个人同时满足属性 1 和属性 2。

给你一个数组 `trust`，其中 `trust[i] = [a_i, b_i]` 表示标记为 `a_i` 的人信任标记为 `b_i` 的人。

如果小镇法官存在并可以确定其身份，请返回法官的标记；否则，返回 `-1`。

## 2. 核心思路

可以将这 `n` 个人看作图中的 `n` 个节点，`trust` 数组中的每个关系 `[a, b]` 看作一条从 `a` 指向 `b` 的有向边。

根据法官的定义，法官需要满足两个核心条件：
* **不相信任何人**：法官的**出度**（Out-degree）必须为 `0`（即没有以他为起点的边）。
* **被所有人信任（除了他自己）**：法官的**入度**（In-degree）必须为 `n - 1`（即除了他自己之外的所有人都指向他）。

我们可以用一个长度为 `n + 1` 的数组来统计每个人的**净得分**（即**入度减去出度**，`in_degree - out_degree`）：
* 当一个人 `u` 信任别人 `v` 时，`u` 的出度加 1（相当于净得分减 1）。
* 当一个人 `v` 被别人信任时，`v` 的入度加 1（相当于净得分加 1）。

如果小镇中存在符合条件的法官，那么这个人的净得分必然刚好等于 `n - 1`。

## 3. 代码实现 (Python)

```python
class Solution:
    def findJudge(self, n: int, trust: List[List[int]]) -> int:
        # 统计每个人的 (入度 - 出度)
        # 下标 0 不使用，从 1 到 n
        scores = [0] * (n + 1)
        
        for u, v in trust:
            scores[u] -= 1  # u 信任 v，u 的出度+1（得分减1）
            scores[v] += 1  # v 被 u 信任，v 的入度+1（得分加1）
            
        for i in range(1, n + 1):
            if scores[i] == n - 1:
                return i
                
        return -1
```

## 4. 复杂度分析

* **时间复杂度**：$O(E + N)$，其中 $E$ 是 `trust` 数组的长度，`N` 是人数。我们需要遍历一次 `trust` 数组统计度数，再遍历一次长度为 `N` 的数组寻找法官。
* **空间复杂度**：$O(N)$，用于存储大小为 `n + 1` 的度数统计数组 `scores`。

# LeetCode 152. 乘积最大子数组（Maximum Product Subarray）题目解析

「乘积最大子数组」（Maximum Product Subarray）是 LeetCode 第 152 题，是一道经典的动态规划问题。

## 1. 题目描述

给你一个整数数组 `nums`，请你找出数组中乘积最大的非空连续子数组（该子数组中至少包含一个数字），并返回该子数组所对应的乘积。

测试用例的答案是一个 32-位 整数。

## 2. 核心思路

这道题与经典的“最大子数组和”（Kadane 算法）类似，但由于**负负得正**的性质，一个很小的负数乘以一个负数可能会变成一个很大的正数。

因此，在遍历数组时，仅仅记录当前的最大值是不够的，我们还需要同时记录当前的**最小值**。
对于每个元素 `nums[i]`，它有三种可能成为最大/最小乘积的选择：
1. 当前元素本身 `nums[i]`（即从当前元素重新开始算一个子数组）。
2. 当前元素与前一个位置的**最大乘积**相乘 (`prev_max * nums[i]`)。
3. 当前元素与前一个位置的**最小乘积**相乘 (`prev_min * nums[i]`) —— 主要用于处理 `nums[i]` 为负数的情况。

状态转移方程为：
* `max_prod = max(nums[i], prev_max * nums[i], prev_min * nums[i])`
* `min_prod = min(nums[i], prev_max * nums[i], prev_min * nums[i])`

## 3. 代码实现 (Python)

```python
class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        if not nums:
            return 0
            
        max_so_far = nums[0]
        min_so_far = nums[0]
        result = max_so_far
        
        for i in range(1, len(nums)):
            curr = nums[i]
            # 暂存前一个 max_so_far，因为更新 min_so_far 时会用到原先的 max_so_far
            temp_max = max_so_far
            
            max_so_far = max(curr, temp_max * curr, min_so_far * curr)
            min_so_far = min(curr, temp_max * curr, min_so_far * curr)
            
            result = max(result, max_so_far)
            
        return result
```

## 4. 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是数组 `nums` 的长度。我们只需要对数组进行一次线性遍历。
* **空间复杂度**：$O(1)$，只需要常数级别的额外空间来存储状态变量。

# LeetCode 139. 单词拆分（Word Break）题目解析

「单词拆分」（Word Break）是 LeetCode 第 139 题，是一道经典的动态规划（或广度优先搜索）问题。

## 1. 题目描述

给你一个字符串 `s` 和一个字符串列表 `wordDict` 作为字典。如果可以利用字典中出现的单词拼接出 `s` 则返回 `true`。

注意：不要求字典中出现的单词全部都使用，并且字典中的单词可以重复使用。

## 2. 核心思路

我们可以使用**动态规划**来解决这道题。

* **状态定义**：设 `dp[i]` 表示字符串 `s` 的前 `i` 个字符（即子串 `s[0...i-1]`）是否可以被字典中的单词完美拼接。
* **状态初始化**：`dp[0] = true`，表示空串可以被拼出。其余的 `dp` 值初始化为 `false`。
* **状态转移**：
  * 对于每个长度 `i`（从 `1` 到 `n`）：
  * 遍历每一个可能的分割点 `j`（从 `0` 到 `i-1`）：
  * 如果 `dp[j]` 为 `true`，且子串 `s[j...i-1]` 存在于 `wordDict` 中，说明前 `i` 个字符也可以被拼出，令 `dp[i] = true`，并跳出内层循环。

## 3. 代码实现 (Python)

```python
class Solution:
    def wordBreak(self, s: str, wordDict: List[str]) -> bool:
        word_set = set(wordDict)
        n = len(s)
        # dp[i] 表示 s 的前 i 个字符是否可以被拆分成字典中的单词
        dp = [False] * (n + 1)
        dp[0] = True
        
        for i in range(1, n + 1):
            for j in range(i):
                if dp[j] and s[j:i] in word_set:
                    dp[i] = True
                    break
                    
        return dp[n]
```

## 4. 复杂度分析

* **时间复杂度**：$O(N^2 + M \cdot K)$，其中 $N$ 是字符串 `s` 的长度，外层循环执行 $N$ 次，内层循环最多执行 $N$ 次，每次切片和哈希表查找耗时与单词长度相关；$M$ 是字典单词数，$K$ 是单词平均长度（用于构建哈希集合）。
* **空间复杂度**：$O(N + M \cdot K)$，主要用于存储 `dp` 数组以及将 `wordDict` 转换为哈希集合所消耗的空间。

# LeetCode 1406. 石子游戏 III（Stone Game III）题目解析

「石子游戏 III」（Stone Game III）是 LeetCode 第 1406 题，是一道经典的博弈论与动态规划问题。

## 1. 题目描述

Alice 和 Bob 继续他们的石子游戏。几堆石子排成一行，每堆石子都对应一个得分，由数组 `stoneValue` 给出。

Alice 和 Bob 轮流取石子，Alice 总是先开始。在每个玩家的回合中，该玩家可以拿走剩下石子中的前 `1`、`2` 或 `3` 堆石子。比赛一直持续到所有石头都被拿走。

每个玩家的最终得分为他所拿到的每堆石子的对应得分之和。比赛的目标是决出最高分，得分最高的选手将会赢得比赛，比赛也可能会出现平局。

假设 Alice 和 Bob 都采取**最优策略**。如果 Alice 赢了就返回 `"Alice"`，Bob 赢了就返回 `"Bob"`，分数相同返回 `"Tie"`。

## 2. 核心思路

这是一道典型的极小化极大（Minimax）博弈问题，可以通过**动态规划（从后向前推导）**来解决。

* **状态定义**：设 `dp[i]` 表示从第 `i` 堆石子开始到最后，当前玩家能够获取的**“自己得分减去对手得分”的最大净胜分**（博弈差值）。
* **状态转移**：
  对于当前的第 `i` 堆，玩家可以自主选择拿走 `1`、`2` 或 `3` 堆：
  * 如果拿 `1` 堆（即拿走 `stoneValue[i]`），剩下的总分净胜分为 `dp[i+1]`，那么当前玩家的选择得分为：`stoneValue[i] - dp[i+1]`
  * 如果拿 `2` 堆（即拿走 `stoneValue[i] + stoneValue[i+1]`），剩下的总分净胜分为 `dp[i+2]`，当前玩家的选择得分为：`(stoneValue[i] + stoneValue[i+1]) - dp[i+2]`
  * 如果拿 `3` 堆（即拿走 `stoneValue[i] + stoneValue[i+1] + stoneValue[i+2]`），剩下的总分净胜分为 `dp[i+3]`，当前玩家的选择得分为：`(stoneValue[i] + stoneValue[i+1] + stoneValue[i+2]) - dp[i+3]`

  当前玩家会采取最优策略，因此 `dp[i]` 取上述所有可选方案的最大值：
  $$\text{dp}[i] = \max_{1 \le k \le 3} \left( \sum_{j=i}^{i+k-1} \text{stoneValue}[j] - \text{dp}[i+k] \right)$$

* **边界条件**：
  从数组末尾向前计算。当 `i` 超出数组大小时，`dp` 值为 `0`。
  最终只需比较 `dp[0]` 的值：
  * 若 `dp[0] > 0`，说明 Alice 赢，返回 `"Alice"`；
  * 若 `dp[0] < 0`，说明 Bob 赢，返回 `"Bob"`；
  * 若 `dp[0] == 0`，说明平局，返回 `"Tie"`。

## 3. 代码实现 (Python)

```python
class Solution:
    def stoneGameIII(self, stoneValue: List[int]) -> str:
        n = len(stoneValue)
        # dp[i] 表示从第 i 堆开始，当前玩家能获得的领先对手的最大分数
        # 为了处理边界，多开辟几个空间
        dp = [0] * (n + 2)
        
        # 从后向前倒推
        for i in range(n - 1, -1, -1):
            # 初始化为一个极小值
            max_val = float('-inf')
            current_sum = 0
            
            # 每次可以取 1, 2, 3 堆
            for k in range(1, 4):
                if i + k - 1 < n:
                    current_sum += stoneValue[i + k - 1]
                    max_val = max(max_val, current_sum - dp[i + k])
                else:
                    break
            dp[i] = max_val
            
        if dp[0] > 0:
            return "Alice"
        elif dp[0] < 0:
            return "Bob"
        else:
            return "Tie"
```

## 4. 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是数组 `stoneValue` 的长度。我们只需要从后向前进行一次线性扫描，内层循环最多执行常数次（3次）。
* **空间复杂度**：$O(N)$，用于存储大小为 $N + 2$ 的动态规划数组 `dp`（空间也可以通过只保留最后几个状态优化至 $O(1)$）。

# LeetCode 1406. 石子游戏 III（Stone Game III）DFS 解法解析

「石子游戏 III」（Stone Game III）可以通过 **DFS（深度优先搜索）+ 记忆化（Memoization）** 的自顶向下（Top-Down）动态规划来高效解决。

## 1. 核心思路

* **状态定义**：设 `dfs(i)` 表示从第 `i` 堆石子开始到最后，当前玩家能够获取的**“自己得分减去对手得分”的最大净胜分**。
* **状态转移**：
  在每个状态 `i` 下，当前玩家可以选择拿走 `1`、`2` 或 `3` 堆石子：
  * 如果拿 `k` 堆（$k \in \{1, 2, 3\}$），当前玩家获得的即时石子和为 $\sum_{j=i}^{i+k-1} \text{stoneValue}[j]$。
  * 留给对手的净胜分是 `dfs(i + k)`。
  * 因此，当前玩家的净胜分为：`current_sum - dfs(i + k)`。
  * 玩家会采取最优策略，取所有可选方案的最大值：
    $$\text{dfs}(i) = \max_{1 \le k \le 3, \, i+k-1 < n} \left( \sum_{j=i}^{i+k-1} \text{stoneValue}[j] - \text{dfs}(i + k) \right)$$
* **递归终止条件**：当 `i >= n` 时，没有剩余石子，返回 `0`。

## 2. 代码实现 (Python)

```python
from functools import lru_cache
from typing import List

class Solution:
    def stoneGameIII(self, stoneValue: List[int]) -> str:
        n = len(stoneValue)
        
        @lru_cache(None)
        def dfs(i: int) -> int:
            if i >= n:
                return 0
                
            max_val = float('-inf')
            current_sum = 0
            
            for k in range(1, 4):
                if i + k - 1 < n:
                    current_sum += stoneValue[i + k - 1]
                    max_val = max(max_val, current_sum - dfs(i + k))
                else:
                    break
                    
            return max_val
            
        diff = dfs(0)
        if diff > 0:
            return "Alice"
        elif diff < 0:
            return "Bob"
        else:
            return "Tie"
```

## 3. 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是数组 `stoneValue` 的长度。通过 `@lru_cache` 记忆化，每个状态（每个索引 `i`）只会被计算一次，内层循环固定执行 3 次。
* **空间复杂度**：$O(N)$，递归调用栈的深度以及记忆化缓存最多占用 $N$ 级别的空间。
