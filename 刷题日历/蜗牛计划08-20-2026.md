# 35. Search Insert Position (搜索插入位置)
Easy

## 📝 Description
Given a sorted array of distinct integers and a target value, return the index if the target is found. If not, return the index where it would be if it were inserted in order.

You must write an algorithm with $O(\log n)$ runtime complexity.

## 💡 Example 1:
* **Input:** `nums = [1,3,5,6]`, `target = 5`
* **Output:** `2`

## 💡 Example 2:
* **Input:** `nums = [1,3,5,6]`, `target = 2`
* **Output:** `1`

```python
class Solution(object):
    def searchInsert(self, nums, target):
        """
        :type nums: List[int]
        :type target: int
        :rtype: int
        """
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = left + (right - left) // 2
            
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1      # 目标在右边，左指针右移
            else:
                right = mid - 1     # 目标在左边，右指针左移
                
        # 💡 为什么最后返回 left？
        return left
```

## 🔍 深度解析：为什么最后必须 `return left`？

这道题是二分查找最经典的“边界查找”变体。很多人疑惑为什么找不到时要返回 `left`，其实它是二分查找的一个物理必然结果：

### 1. 二分结束时的交错状态
当 `while left <= right:` 循环正常退出时，意味着 `left` 已经**大于** `right` 了（即 `left = right + 1`）。此时，两个指针形成了一种“大军合围”后的交叉状态。

### 2. `left` 停下的物理位置
* 在整个夹逼过程中，如果没找到 `target`，`right` 会一直往左收缩，`left` 会一直往右挺进。
* 当循环结束的那一瞬间，**`left` 刚好精准停在了“第一个大于 target 的元素”的位置上**。
* 如果 `target` 比数组里所有数都大，`left` 会一路向右跨过所有格子，最终停在 `len(nums)`（即数组的最末尾）。

### 3. 完美契合插入定义
这个刚好比 `target` 大的位置，或者说大军合围交错后的分界点，就是 `target` 按顺序理应插入的正确下标。所以最后无脑 `return left`，就能优雅通关。

### 📊 复杂度核验 (Complexity Analysis)
时间复杂度：O(log n)。二分查找每次将搜索空间对半砍，效率呈指数级上升。
空间复杂度：O(1)。只用了常数个指针变量（left, right, mid），没有占用额外的动态内存。

# LeetCode 355. Design Twitter (设计推特)

Medium Topics Companies

## 📝 1. 题目描述 (Description)
设计一个简化版的推特(Twitter)，可以让用户实现发送推文、关注/取消关注其他用户、以及获取自己及关注的人最近 10 条推文的 Feed 流（News Feed）。

实现 `Twitter` 类：
* `Twitter()` 初始化简易推特对象。
* `void postTweet(int userId, int tweetId)` 使用给定的 `userId` 和 `tweetId` 创建一条新推文。每次调用此函数都会使用一个唯一的 `tweetId`。
* `List<Integer> getNewsFeed(int userId)` 检索当前用户新闻 Feed 流中最近的 10 条推文 ID。新闻 Feed 流中的每一项都必须是由用户关注的人或者是用户自己发布的推文。推文必须 **按照时间倒序排序**（从最近到最旧）。
* `void follow(int followerId, int followeeId)` ID 为 `followerId` 的用户开始关注 ID 为 `followeeId` 的用户。
* `void unfollow(int followerId, int followeeId)` ID 为 `followerId` 的用户开始取消关注 ID 为 `followeeId` 的用户。

## 💡 2. 核心设计与物理直觉 (Core Design & Intuition)

这是一道极其经典的 **面向对象设计 (OOD) + 哈希表 + 堆 (Min-Heap / 优先队列)** 的系统设计题。核心难点在于 `getNewsFeed`：
1. **全局时间戳 (Timestamp)**：
   - 推文必须按时间倒序排列。我们需要一个全局自增的计数器 `self.time`，每次发推文时把当前时间戳打在推文上，保证时序严格一致。
2. **关系网维护 (Following List)**：
   - 用一个哈希表 `self.following = collections.defaultdict(set)` 来记录每个用户关注了哪些人。
   - **注意点**：用户默认是“关注自己的”（`userId` 必须在自己的关注列表里），这样获取 Feed 流时才能顺便把自己的推文捞出来。
3. **Feed 流聚合与多路归并 (K-Way Merge via Min-Heap)**：
   - 获取某个用户及其所有关注者的最近推文时，如果把所有人的推文无脑拿出来排序，效率会很低。
   - 最佳实践是：利用 **小顶堆 (Min-Heap)** 维护最多 10 个最新的推文，或者将多人的推文链表进行多路归并，高效选出时间最近的 10 条推文！

## 💻 3. Python3 完美通关代码 (Solution)

```python
import collections
import heapq

class Twitter(object):

    def __init__(self):
        # 全局时间戳，每发一条推文自增一次
        self.time = 0
        # 映射表：userId -> list of [time, tweetId]，存储每个用户发的推文
        self.tweets = collections.defaultdict(list)
        # 关系网：userId -> set of followeeId，存储每个用户关注的人
        self.following = collections.defaultdict(set)

    def postTweet(self, userId, tweetId):
        """:type userId: int
        :type tweetId: int
        :rtype: None
        """
        self.tweets[userId].append((self.time, tweetId))
        self.time += 1

    def getNewsFeed(self, userId):
        """:type userId: int
        :rtype: List[int]
        """
        res = []
        # 小顶堆，用来维护按时间最新的推文（堆顶存放最旧的，方便控制大小在 10 以内）
        min_heap = []
        
        # 用户自己也算自己的“关注对象”，必须把自己的 ID 加进去一起聚合
        self.following[userId].add(userId)
        
        # 遍历自己以及所有关注的人
        for followeeId in self.following[userId]:
            if followeeId in self.tweets:
                # 拿到该用户发的所有推文
                user_tweets = self.tweets[followeeId]
                # 从该用户最近的推文开始往前看
                for t, tweetId in reversed(user_tweets):
                    heapq.heappush(min_heap, (t, tweetId))
                    # 如果堆的大小超过了 10，把时间最旧的（堆顶）弹出，保持堆大小最多为 10
                    if len(min_heap) > 10:
                        heapq.heappop(min_heap)
                        
        # 弹出堆中所有元素，由于是小顶堆，我们需要按时间从大到小（倒序）排列结果
        while min_heap:
            t, tweetId = heapq.heappop(min_heap)
            res.append(tweetId)
            
        # 因为是从小到大弹出的，最后需要反转，让最近的推文排在最前面
        return res[::-1]

    def follow(self, followerId, followeeId):
        """:type followerId: int
        :type followeeId: int
        :rtype: None
        """
        self.following[followerId].add(followeeId)

    def unfollow(self, followerId, followeeId):
        """:type followerId: int
        :type followeeId: int
        :rtype: None
        """
        # 自己不能取消关注自己
        if followerId != followeeId and followeeId in self.following[followerId]:
            self.following[followerId].remove(followeeId)
```

### 复杂度核验 (Complexity Analysis)

#### 时间复杂度
* **postTweet**: $O(1)$，直接追加到列表中。
* **getNewsFeed**: $O(K \log U)$，其中 $U$ 是用户关注的人数，每次合并推文从 $U$ 个列表中取最值，$K$ 是要获取的条数（通常为 10）。
* **follow/unfollow**: $O(1)$，哈希表操作。

#### 空间复杂度
* **总体**: $O(T + U^2)$
* **说明**: 其中 $T$ 为推文总数，$U$ 为用户总数。主要用于存储所有人的推文历史和关注关系表。

### 空间复杂度分析：O(T + U^2)

空间复杂度的构成主要分为两部分：**推文存储**与**关注关系存储**。

#### 1. 推文存储空间：$O(T)$
* **含义**：$T$ 是系统内所有用户发布的推文总数。
* **原因**：无论用户如何关注或取关，系统都需要持久化保存每一条已发布的推文。每一条推文（包括 `tweetId` 和时间戳）都必须存储在内存中，因此这部分空间与推文总数呈线性关系。

#### 2. 关注关系存储空间：$O(U^2)$
* **含义**：$U$ 是系统中的用户总数。
* **原因**：这是基于“最坏情况”的假设：
    * 每一个用户都可以关注其他所有用户。
    * 如果系统中共有 $U$ 个用户，每个用户维护一个 `HashSet`（或类似结构）来记录他所关注的人。
    * 在极端情况下（例如社交网络是完全图），每个用户都关注了除了自己以外的 $U-1$ 个人。
    * 因此，总的关注关系边数为 $U \times (U - 1)$，即空间复杂度为 $O(U^2)$。

**总结**：
总空间复杂度 $O(T + U^2)$ 意味着系统不仅要为**海量推文内容**（$T$）付费，还要为**稠密的社交网络关系**（$U^2$）付费。在实际生产环境中，由于关注关系通常是稀疏的（远小于 $U^2$），实际的空间开销往往会更小。
