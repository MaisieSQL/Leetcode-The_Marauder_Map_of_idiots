## 🔍 第二步：全解法发散（从笨到精）

面对这道题，我们能想到以下三种解法：

### 1. 解法流派一：暴力穷举流 (Linear Search)
* **物理直觉**：不管三七二十一，用 `for` 循环从头到尾一个一个数去比对，直到找到 `target`。
* **复杂度**：时间复杂度 $\mathcal{O}(N)$，空间复杂度 $\mathcal{O}(1)$。
* **缺点**：根本没有利用题目给的“有序”这一大前提，在大数据量下效率极低。

### 2. 解法流派二：哈希表空间换时间流 (Hash Map)
* **物理直觉**：既然要频繁查找，我一开始用一个哈希集合把所有数字存起来，以后每次查 `target` 只要 $\mathcal{O}(1)$。
* **复杂度**：时间复杂度预处理 $\mathcal{O}(N)$、查询 $\mathcal{O}(1)$，但空间复杂度直接飙升到 $\mathcal{O}(N)$。
* **缺点**：杀鸡用牛刀，多开辟了不必要的内存空间。

### 3. 解法流派三：秩序与单调性利用流 ── 标准二分查找 (Binary Search)
* **物理直觉**：既然数组已经从小到大排好序了，每次取中间的数比大小：如果比目标大，说明目标在左边，直接把右半边全部抛弃（对半砍）！
* **复杂度**：时间复杂度 $\mathcal{O}(\log N)$，空间复杂度 $\mathcal{O}(1)$。
* **优点**：时间和空间全部压榨到极致，工业界的绝对最优解。

## 🎯 第四部分：最优解路径确认与慢动作拆解

既然通过罗盘锁定了二分查找，在写代码时，最容易翻车的是什么？——**边界条件（`left <= right` 还是 `left < right`？ `right = mid - 1` 还是 `right = mid`？）**。

我们用经典的**【左闭右闭区间 `[left, right]`】**模板来完美收网：
1. **初始化**：`left = 0`, `right = len(nums) - 1`（区间两端都包住）。
2. **循环条件**：`while left <= right`（只要区间里还有格子，就继续找）。
3. **中间指针计算**：`mid = left + (right - left) // 2`（防止数字太大相加溢出）。
4. **收缩指针**：
   * 如果 `nums[mid] == target`，直接返回 `mid`。
   * 如果 `nums[mid] < target`，说明目标在右边，`left = mid + 1`。
   * 如果 `nums[mid] > target`，说明目标在左边，`right = mid - 1`。

## 💻 第五部分：Python3 完美通关代码 (Solution)

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = left + (right - left) // 2
            
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
                
        return -1
```

### 📊 第六部分：复杂度核验 (Complexity Analysis)

* **时间复杂度**：$\mathcal{O}(\log N)$。每次循环把搜索区间对半砍，效率呈指数级上升。
* **空间复杂度**：$\mathcal{O}(1)$。只用了常数个指针变量（`left`, `right`, `mid`），没有占用额外的动态内存。

二分查找在工业界和面试中，最主流的写法其实有两大宗派：
* **第一派：左闭右闭区间 `[left, right]`**
* **第二派：左闭右开区间 `[left, right)`**

咱们今天把这两大流派的代码实现、物理直觉、边界对齐逻辑以及它们的优劣对比，用最透彻的大白话一次性彻底盘个底朝天！


## 🛡️ 流派一：左闭右闭区间 `[left, right]` ── “稳健严谨流”

### 1. 物理直觉与核心定义
* **定义**：`left` 和 `right` 都指向数组中真实存在的、合法的有效格子。
* **初始化**：`left = 0`, `right = len(nums) - 1`（两端全部包住）。
* **循环条件**：`while left <= right`
  * *为什么可以用 `<=`？* 因为当 `left == right` 时，区间 `[left, right]` 里其实还剩最后一个数字没有被检测过（比如 `[3, 3]` 代表数组下标 3 那个格子）。如果写成 `<`，这个最后的格子就会被漏掉！
* **边界收缩逻辑**：
  * 如果 `nums[mid] < target`，说明目标在 `mid` 的右边。因为 `mid` 已经被确认不是目标了，所以左边界要跨过 `mid`，即：`left = mid + 1`。
  * 如果 `nums[mid] > target`，说明目标在 `mid` 的左边，右边界收缩：`right = mid - 1`。

### 2. 代码实现

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = left + (right - left) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid - 1
                
        return -1
```

### 🚀 流派二：左闭右开区间 `[left, right)` —— “激进前卫流”

#### 1. 物理直觉与核心定义

* **定义**：`left` 指向合法的格子，而 `right` 指向一个“永远取不到的越界虚拟边界”（即区间包含 `left`，但不包含 `right`）。
* **初始化**：`left = 0`, `right = len(nums)`（注意：`right` 是数组长度，直接指向尾部的下一个空气位）。
* **循环条件**：`while left < right`
  * **为什么只能用 `<`？** 因为当 `left == right` 时（比如 `[2, 2)`），左闭右开区间里已经没有任何合法的格子了（左边闭合、右边开区间等于什么都没夹住），此时循环必须立刻终止。如果你写了 `<=`，会导致死循环或者数组越界！
* **边界收缩逻辑**：
  * 如果 `nums[mid] < target`，左边界更新：`left = mid + 1`。
  * 如果 `nums[mid] > target`，因为右边界本来就是开区间（取不到），所以可以直接把 `right` 赋值为 `mid`，即：`right = mid`。
 

```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums)
        
        while left < right:
            mid = left + (right - left) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                left = mid + 1
            else:
                right = mid  # 注意这里没有 -1
                
        return -1
```

⚔️ 两大流派横向深度对比矩阵

| 维度对比 | 左闭右闭流 `[left, right]` | 左闭右开流 `[left, right)` |
| :--- | :--- | :--- |
| **区间初始化** | `right = len(nums) - 1`（指向最后一个元素） | `right = len(nums)`（指向长度，即越界位） |
| **循环条件** | `while left <= right`（包含等于号） | `while left < right`（不含等于号） |
| **当 `nums[mid] > target` 时** | `right = mid - 1` | `right = mid` |
| **思维负担** | 极低。符合人类直觉（两边都是真实的边界） | 略高。需要时刻记住 `right` 指向的是空气 |
| **适用场景** | 绝大多数基础二分查找、寻找单一精确值 | 查找左边界 / 右边界的变体题（如 LeetCode 34） |

## LeetCode 105. 从前序与中序遍历序列构造二叉树 (Construct Binary Tree from Preorder and Inorder Traversal)

### 题目细节

* **难度**：中等
* **题目描述**：
  给定两个整数数组 `preorder` 和 `inorder`，其中 `preorder` 是二叉树的**前序遍历**，`inorder` 是同一棵树的**中序遍历**，请构造二叉树并返回其根节点。

* **提示**：
  * `1 <= preorder.length <= 3000`
  * `inorder.length == preorder.length`
  * `preorder` 和 `inorder` 均 **无重复元素**

### 核心解题思路（分治法）

要理解这道题，首先要掌握二叉树遍历的性质：
1. **前序遍历 (Preorder)**：顺序为 `[ 根节点 | 左子树的前序 | 右子树的前序 ]`。
   * **关键点**：`preorder[0]` 永远是当前树（或子树）的**根节点**。
2. **中序遍历 (Inorder)**：顺序为 `[ 左子树的中序 | 根节点 | 右子树的中序 ]`。
   * **关键点**：通过在中序遍历中找到根节点的位置，可以将数组划分为“左子树”和“右子树”两部分。

#### 递归分治的四个步骤：
1. **获取根节点**：从 `preorder` 取出首元素作为 `root`。
2. **定位根节点**：在 `inorder` 中找到该 `root` 的索引 `mid_idx`。
3. **划分区间**：
   * 左子树的节点数量为 `mid_idx`。
   * 在 `preorder` 中切分出左、右子树的前序序列。
   * 在 `inorder` 中切分出左、右子树的中序序列。
4. **递归构建**：递归地对左右子树执行上述过程，并连接到 `root` 上。

### 答案代码 (Python)

为了优化性能，我们将 `inorder` 的元素和索引存入哈希表，实现 $O(1)$ 的查找。

```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def buildTree(self, preorder: list[int], inorder: list[int]) -> TreeNode:
        # 使用哈希表优化查找索引的速度 (O(N) -> O(1))
        inorder_map = {val: i for i, val in enumerate(inorder)}
        
        def helper(pre_left, pre_right, in_left, in_right):
            if pre_left > pre_right:
                return None
            
            # 前序遍历的第一个节点即为根节点
            root_val = preorder[pre_left]
            root = TreeNode(root_val)
            
            # 在中序遍历中定位根节点位置
            mid_idx = inorder_map[root_val]
            
            # 计算左子树的大小
            left_size = mid_idx - in_left
            
            # 递归构建左子树
            root.left = helper(pre_left + 1, pre_left + left_size, in_left, mid_idx - 1)
            # 递归构建右子树
            root.right = helper(pre_left + left_size + 1, pre_right, mid_idx + 1, in_right)
            
            return root
        
        return helper(0, len(preorder) - 1, 0, len(inorder) - 1)
```

### 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是节点个数。每个节点被访问一次，且哈希表查找索引的操作为 $O(1)$。
* **空间复杂度**：$O(N)$。需要 $O(N)$ 的空间存储哈希表，且递归调用栈在最坏情况下（树退化为链表）为 $O(N)$。

* **难度**：中等
* **题目描述**：
  给你一个无重复元素的整数数组 `candidates` 和一个目标整数 `target`，找出 `candidates` 中可以使数字和为目标数 `target` 的所有不同组合，并以列表形式返回。你可以按**任意顺序**返回这些组合。
  `candidates` 中的同一个数字可以**无限制重复被选取**。如果其中一个数字的被选取次数不同，则两个组合是不同的。

简单来说，**LeetCode 39. 组合总和** 这道题就是在玩一个**“凑钱”**或者**“拼积木”**的游戏：

1. **给你一堆不同面值的硬币**（比如候选数组 `candidates = [2, 3, 6, 7]`）。
2. **给你一个目标总金额**（比如 `target = 7`）。
3. **规则是**：每种面值的硬币你可以**无限次使用**，问你有多少种不同的组合方式，能把这些硬币加起来**刚好等于**这个目标金额？

### 举个直观的例子：
假设你要去买 7 块钱的东西，手里有面值为 `2元`、`3元`、`6元`、`7元` 的硬币，而且每种硬币要多少有多少。
怎么凑出 7 块钱呢？
* 方案 A：拿三个 2 块的，再拿一个 1 块的？不行，没有 1 块的硬币。
* 方案 B：拿两个 2 块的，再拿一个 3 块的（`2 + 2 + 3 = 7`），刚好等于 7！
* 方案 C：直接拿一个 7 块的（`7 = 7`），也刚好等于 7！

所以这道题的终极目的，就是要把所有能刚好凑出目标金额 `7` 的**组合方案全部找出来**，最后把它们打包成一个大列表返回：`[[2, 2, 3], [7]]`。

* **Example 1**:
  * **Input**: `candidates = [2, 3, 6, 7]`, `target = 7`
  * **Output**: `[[2, 2, 3], [7]]`
  * **Explanation**:
    * `2` and `3` are candidates, and `2 + 2 + 3 = 7`. Note that `2` can be used multiple times.
    * `7` is a candidate, and `7 = 7`.
    * These are the only two combinations.

* **Example 2**:
  * **Input**: `candidates = [2, 3, 5]`, `target = 8`
  * **Output**: `[[2, 2, 2, 2], [2, 3, 3], [3, 5]]`

* **Example 3**:
  * **Input**: `candidates = [2]`, `target = 1`
  * **Output**: `[]`

* **提示**：
  * `1 <= candidates.length <= 30`
  * `2 <= candidates[i] <= 40`
  * `candidates` 的所有元素互不相同
  * `1 <= target <= 40`

### 核心解题思路（回溯算法 / DFS）

因为这道题要求找出**所有**可能组合，所以需要用**回溯法**去穷举每一种可能性。

1. **决策树模型**：
   * 每一个节点代表选择了一个数字。
   * 因为数字可以重复使用，所以每次往下递归时，**还可以选当前的这个数字**（传入当前的索引 `i`），也可以选后面的数字。
2. **三个核心要素**：
   * **路径（Path）**：当前已经选了哪些数字（例如 `[2, 2]`）。
   * **目标余数（Remainder）**：随着不断选择数字，`target` 越来越小。当它减到 `0` 时，说明找到了一组有效组合。
   * **剪枝（Pruning）**：如果在递归过程中，`target` 减成了负数，说明当前这条路走不通了，直接 **`return`（回溯）**。

### 答案代码 (Python)

```python
class Solution:
    def combinationSum(self, candidates: list[int], target: int) -> list[list[int]]:
        result = []
        
        def backtrack(start_idx: int, current_path: list[int], remain_target: int):
            # 1. 递归终止条件：余数刚好为 0，说明凑出了一组解
            if remain_target == 0:
                result.append(list(current_path))  # 注意要做一次拷贝
                return
            
            # 如果余数小于 0，说明超了，直接剪枝返回
            if remain_target < 0:
                return
            
            # 2. 遍历候选数组
            for i in range(start_idx, len(candidates)):
                num = candidates[i]
                
                # 做选择：把当前数字加入路径
                current_path.append(num)
                
                # 递归：因为数字可以重复选，下一次依然从当前索引 i 开始
                backtrack(i, current_path, remain_target - num)
                
                # 撤销选择（回溯）：把刚加的数字弹出来，尝试下一个分支
                current_path.pop()
        
        # 从索引 0 开始回溯
        backtrack(0, [], target)
        return result
```

### 关键点解析：为什么是 `backtrack(i, ...)` 而不是 `i + 1`？

* 如果是**不能重复选**的题目，每次往下递归时传的是 `i + 1`，表示用过的不能再用。
* 但在这道题里，**同一个数字可以无限次使用**，所以当你选了 `candidates[i]` 之后，下一次你依然有资格继续选它。因此递归时传的是 **`i`**。

### 复杂度分析

* **时间复杂度**：O(S)，其中 S 为所有可行解的长度之和。在最坏情况下（例如 target 很大且候选数字很小），回溯算法会遍历大量的决策分支，时间复杂度呈指数级增长。
* **空间复杂度**：`O(target / min_val)`，主要取决于递归调用栈的深度以及存储临时路径 `current_path` 所需的空间。在最坏情况下，递归树的最大深度为 target 除以候选数组中的最小元素。

## 对于 **LeetCode 39. 组合总和** 这类求“所有可能组合”的问题，核心解法基本上绕不开**穷举与搜索**。

主要可以从以下几个维度来看它的解法和演进：

### 1. 标准解法：回溯算法 / DFS（深度优先搜索）—— 最标准、最常用
这是解决这类组合、子集、排列问题最正统、最高效的解法。
* **核心思想**：通过画出一棵“决策树”，系统性地尝试每一种可能的数字组合。在递归的过程中不断减去当前选的数字（更新目标余数），如果余数刚好为 0 就收录结果，如果小于 0 就剪枝返回。
* **特点**：代码结构清晰，利用“回溯（撤销选择）”机制在同一条递归路径上反复利用状态，是面试中最标准的解法。

### 2. 动态规划（DP）—— 理论上可行，但通常不推荐
因为这道题问的是“**所有具体的组合方案**”，而不是“有多少种组合方案（计数问题）”：
* 如果是问“有多少种凑法”（类似 LeetCode 518 零钱兑换 II），完全可以用动态规划来做。
* 但如果是要求**把所有具体的组合列表打印出来**，动态规划在重构路径时会变得非常繁琐且占用巨大内存。因此，面对这种需要列出具体方案的题目，大家默认都是用**回溯算法**，而不是动规。

### 总结
在实际刷题和面试中，针对 LeetCode 39 只需要掌握并熟练手写 **回溯算法（Backtracking）** 即可。它既能优雅地处理“数字可重复使用”的特点，又能完美地把所有合法组合收集起来。
