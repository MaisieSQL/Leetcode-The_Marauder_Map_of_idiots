## LeetCode 144. 二叉树的前序遍历 - 详细解析与题解

### 题目描述
给你二叉树的根节点 `root`，返回它节点值的 **前序遍历**（Preorder Traversal）。
* **前序遍历规则**：按照 **根节点 $\rightarrow$ 左子树 $\rightarrow$ 右子树** 的顺序访问节点。

### 方法一：递归法 (Recursion) —— 最直观的官方标准解法

#### 1. 核心思路
前序遍历的定义本身具有天然的递归性：
1. 先访问当前根节点（把值加入结果集）。
2. 递归调用函数遍历左子树。
3. 递归调用函数遍历右子树。
当遇到空节点（`None`）时，递归终止并返回。

#### 2. 代码实现 (Python)
```python
class Solution:
    def preorderTraversal(self, root: TreeNode) -> list[int]:
        res = []
        
        def dfs(node):
            # 终止条件：如果节点为空，直接返回
            if not node:
                return
            
            # 1. 根：访问当前节点
            res.append(node.val)
            # 2. 左：递归遍历左子树
            dfs(node.left)
            # 3. 右：递归遍历右子树
            dfs(node.right)
            
        dfs(root)
        return res
```

### 方法二：迭代法 / 显式栈 (Iteration with Stack) —— 硬核底层模拟

#### 1. 核心思路
递归的本质是操作系统在内存中维护了一个“系统调用栈”。我们可以用一个显式的列表 `stack` 来模拟这个栈：
* 前序遍历的访问顺序是“根 $\rightarrow$ 左 $\rightarrow$ 右”。
* 因为栈是**先进后出 (LIFO)** 的：
  * 如果我们想让**左子树**先被弹出来处理，就必须**先把右子树压入栈，再把左子树压入栈**。
* 每次从栈顶弹出当前节点，记录其值，然后重复上述压栈过程。

#### 2. 代码实现 (Python)
```python
class Solution:
    def preorderTraversal(self, root: TreeNode) -> list[int]:
        if not root:
            return []
            
        res = []
        stack = [root]  # 初始化栈，放入根节点
        
        while stack:
            # 1. 弹出当前栈顶节点（相当于访问“根”）
            node = stack.pop()
            res.append(node.val)
            
            # 2. 先压入右子树（确保左子树先出栈）
            if node.right:
                stack.append(node.right)
                
            # 3. 再压入左子树
            if node.left:
                stack.append(node.left)
                
        return res
```

### 两种方法对比

| 维度 | 方法一：递归法 (Recursion) | 方法二：迭代法 (Iteration with Stack) |
| :--- | :--- | :--- |
| **底层原理** | 依赖系统调用栈 (Call Stack) | 依赖程序员自己维护的显式栈 (`stack` 列表) |
| **代码简洁度** | 极简，逻辑与前序定义完全对齐 | 稍显繁琐，需要处理栈的进出顺序 |
| **空间复杂度** | $O(H)$ （$H$ 为树的高度，最坏链状时为 $O(N)$） | $O(H)$ （同样需要用栈存储路径上的节点） |
| **时间复杂度** | $O(N)$ （每个节点恰好被访问一次） | $O(N)$ （每个节点恰好被压入和弹出一次） |
| **安全性** | 树太深（如链状达 $10^5$ 层）时，可能导致**栈溢出 (Stack Overflow)** | 安全，不受系统递归深度限制 |
| **适用场景** | 面试首选，绝大多数常规情况下的最优解 | 面试官明确要求“不用递归”或树极深时的安全解法 |

用栈的这种迭代法，它既不是纯粹的“一层一层走（广度优先 BFS）”，也不是死板的“一杆子捅到底（纯递归 DFS）”，而是利用栈的 LIFO（后进先出）特性，在“向右拐”和“向左拐”之间做精准的控制。

为了让你看清它每一步到底是怎么跑的，我们用你给的这棵树来进行一次 **Dry Run（手动模拟运行）**！

### 总结：它到底是“怎么走”的？
通过这个 Dry Run，你会发现它的足迹是这样的：
1. **先死死沿着左边一路向下切入**（`1 -> 2 -> 4`），把左边的根和左孩子全处理了。
2. 当左边到底（比如 `4` 没孩子了），因为栈里还压着刚才路过时顺手塞进去的右边兄弟（比如 `5` 的右边、`3` 节点等），它会**自动回溯到上一个分叉口，去处理那些被暂存的右边分支**。

所以它本质上依然是 **DFS（深度优先搜索）** 的前序遍历轨迹，只是聪明地用一个栈把“还没来得及看的右边亲戚”先记在小本本上，等左边逛完了，回过头再去挨个访问！

## LeetCode 94. 二叉树的中序遍历 - 详细解析与题解

### 题目描述
给你二叉树的根节点 `root`，返回它节点值的 **中序遍历**（Inorder Traversal）。
* **中序遍历规则**：按照 **左子树 $\rightarrow$ 根节点 $\rightarrow$ 右子树** 的顺序访问节点。

### 方法一：递归法 (Recursion) —— 最直观的标准解法

#### 1. 核心思路
中序遍历的定义同样具有天然的递归性：
1. 先递归遍历左子树。
2. 访问当前根节点（把值加入结果集）。
3. 最后递归遍历右子树。
当遇到空节点（`None`）时，递归终止并返回。

#### 2. 代码实现 (Python)
```python
class Solution:
    def inorderTraversal(self, root: TreeNode) -> list[int]:
        res = []
        
        def dfs(node):
            if not node:
                return
            # 1. 左：先递归遍历左子树
            dfs(node.left)
            # 2. 根：访问当前节点
            res.append(node.val)
            # 3. 右：最后递归遍历右子树
            dfs(node.right)
            
        dfs(root)
        return res
```

### 方法二：迭代法 / 显式栈 (Iteration with Stack) —— 模拟指针一路向左

#### 1. 核心思路
中序遍历用迭代法写时，思路和前序遍历不太一样：

* 因为中序要求“先一直往左走，直到没有左孩子，然后才访问当前节点，最后转向右子树”。
* 我们需要用一个指针 `curr` 配合显式 `stack`：
  * **一路向左**：把沿途经过的所有左节点连续不断地压入栈中，直到 `curr` 变为 `None`。
  * **弹出访问**：从栈顶弹出一个节点（此时它代表当前子树的最左/最底部的未访问节点），将其加入结果集。
  * **转向右子树**：将指针指向这个弹出节点的右子树，重复上述过程。

#### 2. 代码实现 (Python)
```python
class Solution:
    def inorderTraversal(self, root: TreeNode) -> list[int]:
        res = []
        stack = []
        curr = root
        
        while curr or stack:
            # 1. 一路向左，把所有左子树节点压入栈
            while curr:
                stack.append(curr)
                curr = curr.left
                
            # 2. 当前左边到底了，弹出栈顶节点并访问
            curr = stack.pop()
            res.append(curr.val)
            
            # 3. 开始转向处理右子树
            curr = curr.right
            
        return res
```

### 两种方法对比

| 维度 | 方法一：递归法 (Recursion) | 方法二：迭代法 (Iteration with Stack) |
| :--- | :--- | :--- |
| **底层原理** | 依赖系统调用栈 (Call Stack) | 依赖程序员自己维护的显式栈 (`stack`) 与 `curr` 指针 |
| **代码简洁度** | 极简，逻辑与中序定义完全对齐 | 需要用 `while` 嵌套配合指针一路向左 |
| **空间复杂度** | $O(H)$ （$H$ 为树的高度） | $O(H)$ （栈中最多存储一条路径上的节点） |
| **时间复杂度** | $O(N)$ （每个节点恰好被访问一次） | $O(N)$ （每个节点恰好被入栈和出栈一次） |
| **安全性** | 树极深时可能导致系统栈溢出 | 安全，不受系统递归深度限制 |
| **适用场景** | 面试首选，清晰易读 | 面试官要求非递归实现时的标准写法 |

  * `curr = curr.right`：`9` 的右子树为空 $\rightarrow$ `curr = None`。

此时 `curr` 为 `None`，`stack` 为空，主循环结束！

### 最终输出结果：
`[4, 2, 6, 5, 7, 1, 3, 8, 9]` —— **完美吻合你给的 Output！**

通过这个 Dry Run 你可以发现，中序遍历的迭代法精髓就在于：**“用内层 `while` 像切菜一样把一整条左边界全撸进栈里，弹出一个处理一个，然后把视线移到它的右边去”**。

## LeetCode 145. Binary Tree Postorder Traversal (二叉树的后序遍历) - 详细解析与题解

### 题目描述
给你二叉树的根节点 `root`，返回它节点值的 **后序遍历**（Postorder Traversal）。
* **后序遍历规则**：按照 **左子树 $\rightarrow$ 右子树 $\rightarrow$ 根节点** 的顺序访问节点。

### 方法一：递归法 (Recursion) —— 最直观的标准解法

#### 1. 核心思路
后序遍历的定义具有天然的递归性：
1. 先递归遍历左子树。
2. 再递归遍历右子树。
3. 最后访问当前根节点（把值加入结果集）。
当遇到空节点（`None`）时，递归终止并返回。

#### 2. 代码实现 (Python)
```python
class Solution:
    def postorderTraversal(self, root: TreeNode) -> list[int]:
        res = []
        
        def dfs(node):
            if not node:
                return
            # 1. 左：先递归遍历左子树
            dfs(node.left)
            # 2. 右：再递归遍历右子树
            dfs(node.right)
            # 3. 根：最后访问当前节点
            res.append(node.val)
            
        dfs(root)
        return res
```

### 方法二：迭代法 / 巧妙的反向思维 (Iteration with Reversed Preorder)

#### 1. 核心思路
后序遍历是“左 $\rightarrow$ 右 $\rightarrow$ 根”。如果直接用迭代写会比较麻烦（因为需要判断右子树是否被访问过）。
但有一个极其巧妙的降维打击写法：
* 我们知道**前序遍历**的顺序是：**根 $\rightarrow$ 左 $\rightarrow$ 右**。
* 如果我们稍微调整一下前序遍历的压栈顺序，改成：先压入左子树，再压入右子树，那么遍历出来的访问顺序就会变成：**根 $\rightarrow$ 右 $\rightarrow$ 左**。
* 把这个“根 $\rightarrow$ 右 $\rightarrow$ 左”的结果进行**整体反转（Reverse）**，不就刚好变成了**“左 $\rightarrow$ 右 $\rightarrow$ 根”**的后序遍历了吗？！

#### 2. 代码实现 (Python)
```python
class Solution:
    def postorderTraversal(self, root: TreeNode) -> list[int]:
        if not root:
            return []
            
        res = []
        stack = [root]
        
        while stack:
            node = stack.pop()
            res.append(node.val)  # 顺序：根 -> 右 -> 左
            
            # 注意这里：先压入左子树，后压入右子树
            # 这样弹出时就会先弹出右子树，再弹出左子树
            if node.left:
                stack.append(node.left)
            if node.right:
                stack.append(node.right)
                
        # 最后把结果整体反转，变成：左 -> 右 -> 根
        return res[::-1]
```

### 两种方法对比

| 维度 | 方法一：递归法 (Recursion) | 方法二：迭代法 (反转前序法 / Reversed Preorder) |
| :--- | :--- | :--- |
| **底层原理** | 依赖系统调用栈 (Call Stack) | 巧妙利用“前序变体 + 结果反转” ($Root \rightarrow Right \rightarrow Left \implies Left \rightarrow Right \rightarrow Root$) |
| **代码简洁度** | 极简，逻辑与后序定义完全对齐 | 极其简短巧妙，只需要在前序模板上改两行并 `[::-1]` |
| **空间复杂度** | $O(H)$ （$H$ 为树的高度） | $O(N)$ （需要额外的结果列表存储并反转，但树的节点存储空间相同） |
| **时间复杂度** | $O(N)$ （每个节点访问一次） | $O(N)$ （遍历一遍加上最后 $O(N)$ 的反转） |
| **安全性** | 树极深时可能导致系统栈溢出 | 安全，不受系统递归深度限制 |
| **适用场景** | 面试常规首选 | 面试官要求非递归写后序时最偷巧、最不容易写错的解法 |

## LeetCode 102. Binary Tree Level Order Traversal (二叉树的层序遍历) - 详细解析与题解

### 题目描述
给你二叉树的根节点 `root`，返回其节点值的 **层序遍历**（即逐层地，从左到右访问所有节点）。

### 解法：广度优先搜索 / 使用队列 (BFS with Queue)

#### 1. 核心思路
层序遍历要求我们“一层一层、从左到右”横着走。这和前面几题使用的 DFS（深度优先搜索/栈）不同，它必须使用 **BFS（广度优先搜索）**。
* **数据结构**：我们需要借助一个 **队列（Queue）**。在 Python 中，通常使用 `collections.deque` 来实现高效的头部出队。
* **核心步骤**：
  1. 把根节点放入队列中。
  2. 当队列不为空时，记录当前队列的长度 `n`（这个 `n` 就是**当前这一层的节点总数**）。
  3. 循环 `n` 次，依次从队列左侧弹出节点，把它们的值放入当前层的临时列表里，并把这些节点的左右子节点依次从右侧压入队列。
  4. 当前层遍历完后，把临时列表加入到最终结果集中。

#### 2. 代码实现 (Python)
```python
from collections import deque

class Solution:
    def levelOrder(self, root: TreeNode) -> list[list[int]]:
        if not root:
            return []
            
        res = []
        queue = deque([root])  # 初始化队列，放入根节点
        
        while queue:
            level_size = len(queue)  # 当前层的节点数量
            current_level = []
            
            for _ in range(level_size):
                node = queue.popleft()  # 弹出当前层的节点
                current_level.append(node.val)
                
                # 把子节点按“从左到右”的顺序加入队列
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
                    
            res.append(current_level)  # 把当前层的结果存入总结果集
            
        return res
```

### 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是树中节点的总数。每个节点恰好被入队和出队一次。
* **空间复杂度**：$O(N)$，队列中最多时需要存储树的一整层节点（在完全二叉树的最后一层，节点数约为 $N/2$）。

没问题！我们用 LeetCode 102 经典的示例输入：`root = [3, 9, 20, null, null, 15, 7]` 来进行一次清晰的 **Dry Run（手动模拟运行）**。

### 第一步：还原这棵树的结构
根据层序遍历规则，输入的数组对应的二叉树结构如下：
* 根节点：`3`
* `3` 的左子树是 `9`，右子树是 `20`
* `9` 的左右子树都为空 (`null`)
* `20` 的左子树是 `15`，右子树是 `7`

**初始状态**：
* `res = []`
* `queue = deque([3])` （队列里放着根节点 `3`）

### 第二步：Dry Run 开始！

#### 轮次 1：处理第 0 层（根节点层）
1. **获取当前层大小**：`level_size = len(queue) = 1`。
2. **初始化当前层列表**：`current_level = []`。
3. **循环 1 次**（处理当前层的 1 个节点）：
   * 从队列左侧弹出节点：`node = queue.popleft()` $\rightarrow$ 拿到 `3`。
   * 把值加入当前层：`current_level.append(3)` $\rightarrow$ `current_level = [3]`。
   * 检查 `3` 的左右子树，依次加入队列：
     * 有左子树 `9` $\rightarrow$ `queue.append(9)`
     * 有右子树 `20` $\rightarrow$ `queue.append(20)`
     * *(此时队列变为：`deque([9, 20])`)*
4. **存入结果集**：`res.append([3])` $\rightarrow$ `res = [[3]]`。

#### 轮次 2：处理第 1 层
1. **获取当前层大小**：`level_size = len(queue) = 2`（对应节点 `9` 和 `20`）。
2. **初始化当前层列表**：`current_level = []`。
3. **循环 2 次**：
   * **第一次循环**：
     * 弹出节点：`node = queue.popleft()` $\rightarrow$ 拿到 `9`。
     * `current_level.append(9)` $\rightarrow$ `current_level = [9]`。
     * 检查 `9` 的左右子树：皆为空，队列不发生变化。
     * *(此时队列变为：`deque([20])`)*
   * **第二次循环**：
     * 弹出节点：`node = queue.popleft()` $\rightarrow$ 拿到 `20`。
     * `current_level.append(20)` $\rightarrow$ `current_level = [9, 20]`。
     * 检查 `20` 的左右子树，依次加入队列：
       * 左子树 `15` $\rightarrow$ `queue.append(15)`
       * 右子树 `7` $\rightarrow$ `queue.append(7)`
       * *(此时队列变为：`deque([15, 7])`)*
4. **存入结果集**：`res.append([9, 20])` $\rightarrow$ `res = [[3], [9, 20]]`。

#### 轮次 3：处理第 2 层
1. **获取当前层大小**：`level_size = len(queue) = 2`（对应节点 `15` 和 `7`）。
2. **初始化当前层列表**：`current_level = []`。
3. **循环 2 次**：
   * **第一次循环**：
     * 弹出节点：`node = queue.popleft()` $\rightarrow$ 拿到 `15`。
     * `current_level.append(15)` $\rightarrow$ `current_level = [15]`。
     * `15` 无子树。
     * *(此时队列变为：`deque([7])`)*
   * **第二次循环**：
     * 弹出节点：`node = queue.popleft()` $\rightarrow$ `node = 7`。
     * `current_level.append(7)` $\rightarrow$ `current_level = [15, 7]`。
     * `7` 无子树。
     * *(此时队列变为：`deque([])` 空了！)*
4. **存入结果集**：`res.append([15, 7])` $\rightarrow$ `res = [[3], [9, 20], [15, 7]]`。

### 循环结束
此时 `queue` 变为空 `deque([])`，`while` 循环终止。

**最终输出**：`[[3], [9, 20], [15, 7]]` —— **完美吻合！**

通过这个过程可以发现，队列（Queue）加 `level_size` 的控制，能够极其精准地把每一层的节点“打包”在一起，这就是 BFS 层序遍历的灵魂所在！

## LeetCode 22. Generate Parentheses (括号生成) - 详细解析与题解

Given `n` pairs of parentheses, write a function to generate all combinations of well-formed parentheses.

### Example 1:
* **Input:** `n = 3`
* **Output:** `["((()))","(()())","(())()","()(())","()()()"]`

### Example 2:
* **Input:** `n = 1`
* **Output:** `["()"]`

### Constraints:
* `1 <= n <= 8`

### 题目描述
数字 `n` 代表生成括号的对数，请你设计一个函数，用于能够生成所有可能的并且 **有效** 的括号组合。

之前刷组合（Combination）、子集（Subsets）或者排列（Permutations）类题目时，回溯的模板通常是：从一个给定的集合/列表中去“挑数字”或“做选择”（比如从 `[1, 2, 3]` 里挑数凑成目标和）。

但到了 LeetCode 22（括号生成）这里，回溯的对象变了：
* **输入变了**：它没有给你一个现成的列表，输入的只有一个数字 `n`。
* **本质区别**：
  * **以前的组合题**：是从“已知数组”里按索引往后选（像是在做**减法**或遍历）。
  * **这里的括号生成**：是在“凭空构建”一个字符串，每一步的选择不是从数组里拿元素，而是**在“能不能加左括号”和“能不能加右括号”之间做决策**。

虽然外在表现形式不同，但它们的**底层骨架（回溯三部曲）**是完全一模一样的：
* **路径（Path）**：就是参数里的 `current`（当前拼出来的字符串）。
* **选择列表（Choices）**：每一步其实只有两个选项——加 `(` 还是加 `)`。
* **剪枝条件（Constraints）**：不合法的直接抛弃（比如右括号比左括号多时），满足条件就收集（长度达到 $2n$）。

这种把“生成过程”抽象成决策树的回溯，在刷题进阶阶段非常常见！你还记得之前做组合题时，那种“画出递归树、走到头就收集”的感觉吗？括号这道题的递归树其实长得像一棵满二叉树，只是被剪枝剪得瘦了很多。

### 解法：回溯法 / 深度优先搜索 (Backtracking with DFS)

#### 1. 核心思路
这道题要求我们生成所有合法的括号组合。通过**回溯 + 剪枝**，我们可以在构造的过程中就保证每一步都是合法的。只需要维护两个变量：
1. `open_count`：记录当前已经使用了多少个左括号 `(`。
2. `close_count`：记录当前已经使用了多少个右括号 `)`。

**剪枝规则（核心约束）**：
* **条件 1**：只要 `open_count < n`，我们就可以无脑添加一个左括号 `(`。
* **条件 2**：只有当 `close_count < open_count` 时，我们才能添加右括号 `)`（因为必须保证前面的右括号数量没有超过左括号，否则就会变成非法的，如 `)(`）。
* **终止条件**：当 `open_count == n` 且 `close_count == n` 时，说明长度达到了 $2n$，此时收集结果。

#### 2. 代码实现 (Python)

```python
class Solution:
    def generateParenthesis(self, n: int) -> list[str]:
        res = []
        
        def backtrack(current: str, open_count: int, close_count: int):
            # 终止条件：当左右括号都用了 n 个，说明拼好了一个完整合法的组合
            if len(current) == 2 * n:
                res.append(current)
                return
                
            # 1. 如果左括号还没用完，可以继续加左括号
            if open_count < n:
                backtrack(current + '(', open_count + 1, close_count)
                
            # 2. 如果右括号的数量少于左括号，可以加右括号（保证合法性）
            if close_count < open_count:
                backtrack(current + ')', open_count, close_count + 1)
                
        backtrack("", 0, 0)
        return res
```

这是一个非常经典的灵魂拷问！很多刚接触这道题的同学都会有这个疑问：“为什么判断右括号时，限制条件是 `close_count < open_count`，而不是像左括号那样限制 `close_count < n` 呢？”

如果我们写成 `if close_count < n` 会发生什么？让我们通过反例来看一下：

### 如果写成 `if close_count < n`，会产生什么后果？
假设 `n = 3`（最多各用 3 个左右括号）：
* 刚开始时，`open_count = 0`, `close_count = 0`。
* 如果我们允许 `close_count < n`，那么在第一步（甚至还没有左括号的时候），条件 `0 < 3` 成立，代码就会直接允许你加一个右括号 `)`。
* 这样拼出来的第一个字符就是：`")"`。
* **结果**：`")"` 开头的括号串无论后面怎么补，都是**绝对无效**的（因为右括号跑到了左括号前面）。

### 为什么必须是 `close_count < open_count`？
右括号的添加必须满足一个极其严格的物理规律：“先借才能还，有借才有还”。
* **左括号 `(`**：可以随时随地加，只要总数没超过 `n`（即 `open_count < n`），因为左括号永远不会导致结构非法。
* **右括号 `)`**：它的存在是为了“闭合”前面的某个左括号。如果前面连一个左括号都没有（或者左括号全被用光了、已经被别的右括号闭合了），你就凭空加右括号，括号序列立刻就失效了。

因此，**当前已经用掉的右括号数量 (`close_count`) 绝对不能超过或者等于左括号数量 (`open_count`)**。只有当 `close_count < open_count` 时，说明当前还有“未被闭合的左括号”，此时我们加入右括号才是安全、合法的。

### 用代码的视角来看：
* `open_count < n` 限制的是：**总量不能超标**（最多只能有 `n` 个左括号）。
* `close_count < open_count` 限制的是：**顺序和配对不能出错**（右括号的步伐绝对不能跑在左括号前面）。

这就是为什么加右括号时必须拿它和当前的 `open_count` 做对比！

### 复杂度分析

* **时间复杂度**：O(4^n / √n)，生成的合法括号组合数量正好对应第 $n$ 个卡塔兰数（Catalan Number）。
* **空间复杂度**：$O(n)$，递归调用栈的深度最大为 $2n$，临时字符串存储也与 $n$ 成正比。

## 时间复杂度怎么算的?

我们抛开那些吓人的微积分符号，用最清晰、最直观的高中数学（排列组合）来一步步推导为什么括号的合法数量是卡塔兰数，以及怎么得出那个 $4^n$ 的结果。

### 第一步：把括号变成“在网格里走路”
想象你面前有一个 $n \times n$ 的方格网格（比如 $n=3$ 就是一个 $3 \times 3$ 的方格表）。
* **向右走一步** ($\rightarrow$)：代表生成一个左括号 `(`。
* **向上走一步** ($\uparrow$)：代表生成一个右括号 `)`。

要想生成一个长度为 $2n$ 的括号序列，你必须从网格的**左下角 $(0,0)$** 走到**右上角 $(n,n)$**。总共需要向右走 $n$ 步，向上走 $n$ 步，总步数是 $2n$ 步。

1. **如果没有任何限制（随便走）**：
   总共有 $2n$ 步，你只需要在其中选 $n$ 步向右（剩下的自动向上），这不就是经典的排列组合吗？
   $$\text{总路线数} = \binom{2n}{n}$$

2. **加上核心限制（不能穿过对角线）**：
   回到我们前面学的剪枝规则：右括号的数量绝不能超过左括号。
   翻译成网格走路的规则就是：**这条路线绝对不能越过网格正中间的“对角线”（即 $y = x$ 这条线）的上方**。一旦你往上走超出了对角线，就代表右括号比左括号多了，这就是“非法路径”。

### 第二步：用“反射原理”数出非法路径有多少条
数学家安德烈（André）想出一个极其聪明的办法来数“非法路径”：
1. 任何一条**非法**的路线，必然在某个时刻第一次穿过了对角线上方的那条警戒线（即 $y = x + 1$ 这条线）。
2. 从它**第一次碰到警戒线之后的那段路程**开始，把后面所有的“向右走”全部改成“向上走”，“向上走”全部改成“向右走”（也就是关于警戒线做个对称的“反射”）。
3. 奇迹发生了：经过这样一折腾，所有原本会走到右上角 $(n,n)$ 的非法路线，终点全部都被“反射”到了一个新的坐标：$(n-1, n+1)$！

这意味着什么？
* 所有非法路线的总数，正好等于从起点 $(0,0)$ 走到终点 $(n-1, n+1)$ 的所有路线总数。
* 总共要向右走 $n-1$ 步，向上走 $n+1$ 步，总步数是 $(n-1) + (n+1) = 2n$ 步。
* 所以：
  $$\text{非法路线数} = \binom{2n}{n-1}$$

### 第三步：相减得到合法数量（卡塔兰数公式）
合法的路线数 = **总路线数** - **非法路线数**

$$C_n = \binom{2n}{n} - \binom{2n}{n-1}$$

我们把这个组合数展开化简一下：
$$C_n = \frac{(2n)!}{n! \, n!} - \frac{(2n)!}{(n-1)! \, (n+1)!}$$

提取公因式 $\frac{(2n)!}{(n-1)! \, n!}$：
$$C_n = \frac{(2n)!}{(n-1)! \, n!} \left( \frac{1}{n} - \frac{1}{n+1} \right)$$
$$C_n = \frac{(2n)!}{(n-1)! \, n!} \left( \frac{1}{n(n+1)} \right)$$

把分母整理一下，就得到了大名鼎鼎的卡塔兰数闭环公式：
$$C_n = \frac{1}{n+1} \binom{2n}{n} = \frac{(2n)!}{(n+1)! \, n!}$$

### 第四步：为什么最后会变成 $4^n$ 级别？
现在我们知道合法解的总数是 $C_n = \frac{1}{n+1} \binom{2n}{n}$ 了。那当 $n$ 变得很大时，这个式子到底有多大呢？

这里我们要用到阶乘的一个著名估算工具——**斯特林公式 (Stirling's approximation)**：
$$n! \approx \sqrt{2\pi n} \left(\frac{n}{e}\right)^n$$

把它代入到我们的阶乘组合数里：
* 分子的 $(2n)! \approx \sqrt{4\pi n} \left(\frac{2n}{e}\right)^{2n} = \sqrt{4\pi n} \frac{2^{2n} n^{2n}}{e^{2n}} = \sqrt{4\pi n} \frac{4^n n^{2n}}{e^{2n}}$
* 分母的 $(n!)^2 \approx \left(\sqrt{2\pi n} \frac{n^n}{e^n}\right)^2 = 2\pi n \frac{n^{2n}}{e^{2n}}$

上下相除：
* $\frac{n^{2n}}{e^{2n}}$ 直接约掉！
* $4^n$ 顽强地留了下来。
* 剩余的根号和常数项化简后，在分母上产生了一个 $\sqrt{n}$。

最终，整体的数量级就锁定了：
$$\text{总数量} \approx \frac{4^n}{\sqrt{\pi} \cdot n^{3/2}}$$

因为我们在算时间复杂度时，常数和多项式次幂（比如 $n^{3/2}$）相对于指数级的 $4^n$ 来说增长太慢了，可以忽略不计；但由于递归树生成这些合法答案需要付出的总代价中，包含了解的规模，所以我们最终把时间复杂度精简地写成：
$$O\left(\frac{4^n}{\sqrt{n}}\right)$$

这就是从网格走路 $\rightarrow$ 反射原理 $\rightarrow$ 组合数相减 $\rightarrow$ 斯特林公式估算的完整推导闭环！
