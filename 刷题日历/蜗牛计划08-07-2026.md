# LeetCode 680. 验证回文串 II (Valid Palindrome II) ── 完整解析与通关源码

## 一、 题目大意与核心直觉

给你一个字符串 `s`，最多可以**删除其中的一个字符**。请你判断它是否能成为回文字符串。如果能，返回 `true`；否则，返回 `false`。

* **普通回文串回顾**：通常我们用相向双指针（`left` 和 `right`）分别从字符串的两端向中间靠拢，要求对应位置的字符必须完全一致。
* **本题的容错机制**：这道题破天荒地允许你**犯错一次（即跳过/删掉一个字符）**。这意味着当双指针在中间撞见不相等的字符时，我们不能直接判错，而是拥有一次“分叉尝试”的机会。

## 二、 核心解题思路：相向双指针 + 容错分叉

1. 初始化双指针：`left = 0`，`right = len(s) - 1`。
2. 循环向中间逼近：
   * 如果 `s[left] == s[right]`，万事大吉，两指针同时向中间收缩（`left += 1, right -= 1`）。
   * **一旦遇到 `s[left] != s[right]`（发生冲突）**：
     * 说明必须通过删除一个字符来化解矛盾。此时有两种可能：
       1. **删掉左边字符**：检查子串 `s[left+1 ... right]` 是否为严格回文串。
       2. **删掉右边字符**：检查子串 `s[left ... right-1]` 是否为严格回文串。
     * 只要这两种选择中**有任意一种能够顺利通过**，就说明原字符串通过删除一个字符可以变回文，直接返回 `true`；如果两条路都走不通，则返回 `false`。

## 三、 Python3 完美通关代码 (Solution)

```python
class Solution:
    def validPalindrome(self, s: str) -> bool:
        def checkPalindrome(i: int, j: int) -> bool:
            # 内部辅助函数：检查子串 s[i...j] 是否为严格回文串
            while i < j:
                if s[i] != s[j]:
                    return False
                i += 1
                j -= 1
            return True

        left, right = 0, len(s) - 1
        while left < right:
            if s[left] == s[right]:
                left += 1
                right -= 1
            else:
                # 遇到冲突，分叉尝试：跳过左边字符 OR 跳过右边字符
                return checkPalindrome(left + 1, right) or checkPalindrome(left, right - 1)
                
        return True
```

### 四、 复杂度核验 (Complexity Analysis)

* **时间复杂度**：O(N)
  * 主循环中的双指针最多遍历字符串一遍。
  * 如果发生冲突，内部的辅助函数 `checkPalindrome` 会对剩余子串进行一次扫描。由于题目只允许删一个字符，内部扫描顶多执行一次。总体时间复杂度依然保持线性的 O(N)。
* **空间复杂度**：O(1)
  * 整个算法只使用了常数个指针变量（`left`、`right`），没有借助额外的存储空间。

### 🚀 LeetCode 424. 替换后的最长重复字符专题通关卡片

#### 一、 题目大意与核心难点
* **题目要求**：给你一个仅由大写英文字母组成的字符串 `s` 和一个整数 `k`。你可以选择字符串中的任一字符，并将其更改为任何其他大写英文字符。该操作最多可执行 `k` 次。请你找出执行上述操作后，含有相同字母的最长子字符串的长度。
* **面试痛点**：我们不仅能换字符，还能换成任意字符，如果去穷举到底是把哪个字符换成哪个字符，状态空间会直接爆炸。必须通过一个全局视角来对其进行物理降维。

#### 二、 核心物理直觉：滑动窗口与“名额超支”
对于窗口内的任意一段子串（长度为 `length`）：

1. **核心恒等式**：
   * 窗口总长度 = `length = right - left + 1`
   * 窗口内出现次数最多的那个字符的频次 = `max_count`
   * 那么，为了让整个窗口变成由同一个字符填满的纯净连续串，我们需要替换掉的“异己字符”数量就是：
     $$\text{需要替换的字符数} = \text{窗口总长度} - \text{最高频字符次数} = (right - left + 1) - max\_count$$

2. **滑动窗口的核心卡点规则**：
   * **合法扩充**：如果 `需要替换的字符数 <= k`，说明我们手头的修改名额（$k$）足够用！当前窗口是合法的，我们可以放心大胆地把右指针向右扩（`right += 1`），去寻找更长的可能。
   * **违规收缩**：如果 `需要替换的字符数 > k`，说明名额超支了！当前窗口不合法。此时左指针必须向右收缩（`left += 1`），吐出前面的元素，直到窗口重新恢复合法。

#### 三、 Python3 高效通关代码 (Solution)

```python
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count = {}  # 用哈希表记录当前窗口内每个字符的出现频次
        left = 0
        max_freq = 0  # 记录窗口内出现次数最多的那个字符的频次
        max_len = 0   # 记录满足条件的最长子串长度
        
        for right in range(len(s)):
            # 1. 扩充窗口，把当前字符纳入统计
            char = s[right]
            count[char] = count.get(char, 0) + 1
            
            # 2. 动态维护历史最大频次（妙处：即使 left 收缩导致 max_freq 局部变小，也不影响我们寻找全局更长的解）
            max_freq = max(max_freq, count[char])
            
            # 3. 检查当前窗口是否超支：(当前窗口长度 - 最高频字符数 > k)
            current_window_length = right - left + 1
            if current_window_length - max_freq > k:
                # 超支了！左边界向右收缩
                count[s[left]] -= 1
                left += 1
                
            # 4. 更新全局最长长度（此时窗口一定合法）
            max_len = max(max_len, right - left + 1)
            
        return max_len
```

### 四、 架构师级复杂度核验 (Complexity Analysis)

* **时间复杂度**：O(N)
  * 左右指针（`left` 和 `right`）各自最多完整遍历字符串一遍。虽然有哈希表的操作，但字母种类被大写英文字母死死卡在 26 个常数以内，因此整体是绝对的线性时间复杂度。
* **空间复杂度**：O(1)
  * 哈希表 `count` 最多同时存储 26 个大写字母的频次，属于常数级别的额外空间开销。

# LeetCode 153. 寻找旋转排序数组中的最小值 (Find Minimum in Rotated Sorted Array) ── 完整解析与通关源码

## 一、 题目大意与核心直觉

假设按照升序排序的数组在预先未知的某个点上进行了旋转（例如，数组 `[0,1,2,4,5,6,7]` 可能变为 `[4,5,6,7,0,1,2]`）。
请你找出并返回数组中的**最小元素**。
你必须设计一个时间复杂度为 $\mathcal{O}(\log n)$ 的算法解决此问题。

* **物理直觉**：
  * 如果数组没有旋转（或者旋转了 $n$ 次），那么最左边的元素（`nums[0]`）就是最小值。
  * 但如果发生了旋转，数组会被从中间断开，分成**左右两个递增的区间**，并且左边区间的任意元素都大于右边区间的任意元素。
  * 最小值恰好就藏在**“断崖（旋转点）”**的右侧。我们的目标就是利用二分查找，像雷达一样精准锁定这个断崖。

## 二、 核心解题思路：变形二分查找

1. 初始化双指针：`left = 0`，`right = len(nums) - 1`。
2. 循环二分判定（`while left < right`）：
   * 每次计算中点 `mid = left + (right - left) // 2`。
   * **核心比对逻辑**：拿 `nums[mid]` 和右边界 `nums[right]` 进行对比：
     1. 如果 `nums[mid] > nums[right]`：说明 `mid` 处在左边较高的高升区间，而真正的最小值（断崖点）在 `mid` 的**右侧**。因此，令 `left = mid + 1`。
     2. 如果 `nums[mid] < nums[right]`：说明 `mid` 处在右边较低的平缓区间，`mid` 本身或者它的左边可能是最小值。因此，令 `right = mid`（不能是 `mid - 1`，因为 `mid` 有可能是我们要找的最小值）。
3. 当 `left == right` 时，循环结束，此时的 `left`（或 `right`）所指向的元素就是全场的最小值！

## 三、 Python3 完美通关代码 (Solution)

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1
        
        while left < right:
            mid = left + (right - left) // 2
            
            # 如果中点值大于右边界值，说明最小值在 mid 的右边
            if nums[mid] > nums[right]:
                left = mid + 1
            # 否则，最小值在 mid 的左边或者就是 mid 本身
            else:
                right = mid
                
        # 当 left == right 时，即为最小值所在的位置
        return nums[left]
```

### 四、 复杂度核验 (Complexity Analysis)

* **时间复杂度**：O(log N)
  * 每次循环都将搜索空间对半砍（折半搜索），标准的二分查找时间复杂度，面对 $10^5$ 级别的数据规模可以瞬间秒杀。
* **空间复杂度**：O(1)
  * 整个算法只使用了常数个指针变量（`left`、`right`、`mid`），没有开辟任何额外的辅助空间，做到了极致的空间优化。

# LeetCode 410. 分割数组的最大值 (Split Array Largest Sum) ── 完整解析与通关源码

## 一、 题目大意与核心直觉

给你一个非负整数数组 `nums` 和一个整数 `k`，你需要将这个数组分成 `k` 个非空的连续子数组。
设计一个算法，使得这 `k` 个子数组各自和的最大值**最小**。返回这个最小的最大值。

* **物理直觉**：
  * 这道题表面上看起来可以用动态规划（DP）来求解，但由于数据范围和时间限制，DP 的时间复杂度往往较高。
  * **降维打击秘籍：【二分答案 (Binary Search on Answer)】**。
  * 让我们转换视角：答案（即“子数组各自和的最大值”）一定在一个明确的闭区间 `[left, right]` 之内：
    * **最小值 `left`**：数组中最大的那个单个数（因为任何子数组的长度至少为 1，和不可能小于原数组中的最大元素）。
    * **最大值 `right`**：整个数组所有元素的总和（当 `k = 1` 时，整个数组合为一组）。
  * 既然答案在这个范围内单调，我们就可以用二分查找不断猜测一个“最大和阈值（mid）”，然后用**贪心策略**去检验：在这个阈值限制下，原数组最少需要被切成多少个子数组？
    * 如果切出来的组数 **`<= k`**，说明当前的 `mid` 设得太大了或者刚刚好，我们可以尝试往左边收缩找更小的合法解 (`right = mid`)。
    * 如果切出来的组数 **`> k`**，说明当前的 `mid` 太小了，容纳不下，必须放大阈值 (`left = mid + 1`)。

## 二、 核心解题思路：二分答案 + 贪心判定

1. **确定二分边界**：
   * `left = max(nums)` （单个元素的最大值）
   * `right = sum(nums)` （整个数组的总和）
2. **编写贪心验证函数 `countSubarrays(limit)`**：
   * 设定当前每个子数组的最大和上限为 `limit`。
   * 从左到右扫描数组，用一个累加器 `current_sum` 尝试把尽可能多的数塞进当前子数组里。
   * 一旦累加和加上下一个数超过了 `limit`，就必须切一刀（开启新的一组），并将计数器 `count` 加 1。
   * 遍历结束后，返回总共需要的组数是否小于等于 `k`。
3. **二分收敛**：
   * 当 `left == right` 时，二分结束，此时的 `left` 就是全场最优解。

## 三、 Python3 完美通关代码 (Solution)

```python
class Solution:
    def splitArray(self, nums: List[int], k: int) -> int:
        # 1. 确定二分查找的上下界
        left = max(nums)
        right = sum(nums)
        
        # 2. 贪心判定函数：检验在最大和不超过 limit 的情况下，nums 最少需要被切成几段
        def countSubarrays(limit: int) -> int:
            count = 1
            current_sum = 0
            for num in nums:
                if current_sum + num > limit:
                    count += 1
                    current_sum = num
                else:
                    current_sum += num
            return count

        # 3. 标准二分答案框架
        while left < right:
            mid = left + (right - left) // 2
            
            if countSubarrays(mid) <= k:
                # 切出来的段数 <= k，说明 limit 设得可行，尝试向左寻找更小的最大值
                right = mid
            else:
                # 切出来的段数 > k，说明 limit 太小了，无法满足条件，必须向右增大 limit
                left = mid + 1
                
        return left
```

## 四、 复杂度核验 (Complexity Analysis)

- 时间复杂度：O(N log Sum)
  - 其中 N 是数组的长度，Sum 是数组所有元素的总和。
  - 二分查找的区间大小为 `Sum - max(nums)`，二分搜索的次数是 `O(log Sum)` 级别的。每次二分内部需要用 `O(N)` 的线性贪心扫描去判定。总体效率极高，可以完美秒杀大规模数据。
- 空间复杂度：O(1)
  - 整个算法只使用了常数个辅助指针和变量（left、right、mid、count、current_sum），没有开辟任何额外的辅助空间，做到了空间优化的极致。
