# 1046. 最后一块石头的重量 (Last Stone Weight)

有一堆石头，每块石头的重量都是正整数。

每一回合，从中选出两块 **最重的** 石头，然后将它们一起粉碎。假设石头的重量分别为 `x` 和 `y`，且 `x <= y`。那么粉碎的可能结果如下：
* 如果 `x == y`，那么两块石头都会被完全粉碎；
* 如果 `x != y`，那么重量为 `x` 的石头将会完全粉碎，而重量为 `y` 的石头新重量为 `y - x`。

最后，最多只会剩下一块石头。返回此石头的重量。如果没有石头剩下，就返回 `0`。

### 一、 核心解题思路：大顶堆（Max-Heap）模拟

#### 1. 为什么选堆（Priority Queue）？
* **操作模式**：频繁地寻找**当前最大值** $\to$ 移除两个最大值 $\to$ 可能插入一个新值 $\to$ 再次寻找最大值。
* **数据流特性**：数据是动态收缩与插入的。全排序（$O(N \log N)$）在动态插入新元素时会退化为 $O(N^2)$，而堆能以 $O(\log N)$ 的极高效率完成插入与极值提取。

#### 2. Python 语言细节：负数模拟大顶堆
Python 内置的 `heapq` 仅支持小顶堆。为了将其当作大顶堆使用，我们将所有元素**取负数（Negation Trick）**存入堆中：
* 数值最大的元素取负后变成最小，自然浮在小顶堆的堆顶。
* 弹出时再取一次负号，即可还原原数值。

#### 3. 算法步骤
1. **建堆**：将输入数组全部取负，调用 `heapq.heapify()` 在 $O(N)$ 线性时间内原地建堆。
2. **循环粉碎**：只要堆内石头数量 $\ge 2$：
   * 弹出第一重石头 `first = -heapq.heappop(max_heap)`
   * 弹出第二重石头 `second = -heapq.heappop(max_heap)`
   * 若 `first != second`，将差值 `first - second` 取负推入堆中：`heapq.heappush(max_heap, -(first - second))`。
   * 若 `first == second`，两块石头抵消，无需推入任何新值。
3. **收尾返回**：
   * 若堆非空，返回堆顶元素的绝对值 `-max_heap[0]`。
   * 若堆为空，返回 `0`。

### 二、 Python 参考实现

```python
import heapq

class Solution:
    def lastStoneWeight(self, stones: list[int]) -> int:
        # 1. 全部取负，原地构建大顶堆 (O(N) 时间)
        max_heap = [-x for x in stones]
        heapq.heapify(max_heap)
        
        # 2. 模拟两两粉碎过程
        while len(max_heap) > 1:
            first = -heapq.heappop(max_heap)   # 当前最大
            second = -heapq.heappop(max_heap)  # 当前次大
            
            if first != second:
                # 产生新石头，取负后入堆
                heapq.heappush(max_heap, -(first - second))
                
        # 3. 边界判定：若有剩余返回剩余值，否则返回 0
        return -max_heap[0] if max_heap else 0
```

### 三、 复杂度分析

* **时间复杂度**：$O(N \log N)$
  * **建堆阶段**：`heapq.heapify` 耗时 $O(N)$。
  * **粉碎阶段**：每次粉碎至少消耗掉 1 块石头（若碰撞完全抵消则消耗 2 块，产生差值则消耗 2 块加入 1 块，净减少 1 块）。最多进行 $N - 1$ 次循环。
  * 每次循环包含至多 2 次 `heappop` 和 1 次 `heappush`，单次堆操作耗时 $O(\log K)$（$K \le N$）。
  * 总时间复杂度为 $O(N) + O(N \log N) = O(N \log N)$。
* **空间复杂度**：$O(N)$
  * Python 的列表推导式 `[-x for x in stones]` 分配了大小为 $N$ 的新列表用于维护堆。

### 四、 衍生与进阶思考

* **为什么不每次重排数组？**
  * 若使用数组，每粉碎一次产生新元素后调用 `sort()`，单轮排序需 $O(N \log N)$，循环 $N$ 轮总时间为 $O(N^2 \log N)$；即便用二分插入（`bisect.insort`），数组元素的内存平移也是 $O(N)$，总时间退化为 $O(N^2)$。
* **堆在此类问题中的识别特征**：
  * 凡是题目出现“反复取最值”、“动态数据流”、“Top K”、“贪心策略下只关心极值”等描述时，优先考虑堆。

核心原因只有一句话：**这道题要求在“动态变化”的数据集中，极其频繁地获取并更新“全局最大值”。**

### 1. 题目操作的本质：动态维护 Top 2

题目的规则是：
1. 挑出当前**最重（最大）**的两块石头 $x$ 和 $y$（假设 $x \le y$）。
2. 粉碎它们：如果 $x \neq y$，产生一块新石头 $y - x$，**扔回原数据集**。
3. 重复此过程，直到剩下 1 块或 0 块石头。

注意这个动作模式：**取最值 $\to$ 算新值 $\to$ 插入新值 $\to$ 再次取最值**。  
数据集合每一步都在变化，这不是静态排序，而是**动态流式维护**。

### 2. 为什么不用普通数组或排序？

| 数据结构 / 方案 | 取两个最大值 | 插入差值新元素 | 单轮总耗时 | 最终总时间复杂度 ($N$ 轮) |
| :--- | :--- | :--- | :--- | :--- |
| **每次重新排序 (Sort)** | $O(1)$（直接取末尾） | $O(1)$（直接追加） | $O(N \log N)$（下一轮需重排） | $O(N^2 \log N)$（极慢） |
| **线性扫描 (Linear Scan)** | $O(N)$（遍历找前两名） | $O(1)$（直接插入） | $O(N)$ | $O(N^2)$（冗余计算多） |
| **有序数组 + 二分插入 (Bisect)** | $O(1)$（弹末尾） | $O(N)$（二分查位置 $O(\log N)$，但数组平移耗时 $O(N)$） | $O(N)$ | $O(N^2)$ |
| **大顶堆 (Max-Heap)** | **$O(\log N)$**（弹出堆顶） | **$O(\log N)$**（推入堆） | **$O(\log N)$** | **$O(N \log N)$**（最优解） |

### 3. 大顶堆的天然适配性

堆（Priority Queue）解决的经典痛点就是：**只关心极值，不关心全局全排序**。
* 我们根本不需要知道第 5 重、第 6 重的石头顺序是什么。
* 排序做了大量多余的“完全有序化”操作，白白浪费了计算资源。
* **大顶堆（Max-Heap）** 保证堆顶永远是当前最大元素，每次 `heappop` 拿走最大值仅耗时 $O(\log N)$，新差值 `heappush` 沉降平衡也是 $O(\log N)$，刚好精准嵌合题目对效率的要求。

### 4. Python 的特殊实现细节

Python 标准库 `heapq` 默认只支持**小顶堆（Min-Heap）**。为了模拟大顶堆，最经典的做法是**取负数（Negation Trick）**：
* 存入堆时全部取反：$8 \to -8$。
* 此时实际最大的 $8$ 变成了最小的 $-8$，顺理成章地浮在小顶堆的堆顶。
* 弹出时再加负号还原：$-(-8) = 8$。

# 684. 冗余连接 (Redundant Connection)

树可以看成是一个连通且 **无环** 的 **无向** 图。

给定往一棵有 $n$ 个节点（节点值 `1` 到 `n`）的树中添加一条边后的图。添加的边的两个顶点包含在 `1` 到 `n` 中，且没有任何重边。返回一条可以删去的边，使得结果图是一个有着 $n$ 个节点的树。如果有多个答案，则返回二维数组 `edges` 中最后出现的边。

### 一、 核心解题思路：并查集 (Disjoint Set Union, DSU)

#### 1. 题目的数学本质：树与环
* 一棵包含 $n$ 个节点的树，恰好有 **$n - 1$ 条边**，且满足**连通**与**无环**。
* 题目给出了 $n$ 条边，意味着其中**恰好有一条冗余边导致了图中出现环**。
* 我们需要找到那条“造成闭环”的边。若存在多条候选，按题目要求返回在输入中**最后出现**的那一条。

#### 2. 为什么选并查集？
并查集是专门用来处理**动态连通性（Dynamic Connectivity）**与**无向图判环**的高效数据结构：
* 遍历每条边 `[u, v]`：
  * 先查询 `u` 和 `v` 的根节点（Root）：`root_u = find(u)`, `root_v = find(v)`。
  * **若 `root_u == root_v`**：说明在连这条边之前，`u` 和 `v` 已经在同一个连通块内（它们之间已经存在一条通路）。此时再连上 `[u, v]`，**必定闭环**！这条边就是导致成环的冗余边。
  * **若 `root_u != root_v`**：说明它们还未连通，执行合并 `union(u, v)`，把它们归入同一个集合。
* 因为我们是**按输入顺序**依次处理边的，第一条让已连通节点再次相连的边，即为满足题目条件的答案。

#### 3. 关键实现优化：路径压缩 (Path Compression)
在 `find` 操作中，直接将沿途节点的父指针指向最终的根节点：
```python
def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])  # 路径压缩：扁平化树高
    return parent[x]
```

单次操作的均摊时间复杂度降至反阿克曼函数 $\alpha(N)$，实际运行中等价于常数级别 $O(1)$。


### 二、 Python 参考实现

```python
class Solution:
    def findRedundantConnection(self, edges: list[list[int]]) -> list[int]:
        n = len(edges)
        # 节点编号从 1 到 n，开辟大小为 n + 1 的数组，初始每个节点的根是自己
        parent = list(range(n + 1))
        
        # 路径压缩的 find 函数
        def find(x: int) -> int:
            if parent[x] != x:
                parent[x] = find(parent[x])
            return parent[x]
        
        # 合并操作：返回是否合并成功（若已经连通则返回 False）
        def union(x: int, y: int) -> bool:
            root_x = find(x)
            root_y = find(y)
            if root_x == root_y:
                return False  # 已连通，再次相连会成环
            parent[root_x] = root_y
            return True
        
        for u, v in edges:
            # 如果 u 和 v 已经在同一个集合中，当前边即为导致闭环的冗余边
            if not union(u, v):
                return [u, v]
                
        return []
```

### 三、 复杂度分析

* **时间复杂度**：$O(N \cdot \alpha(N)) \approx O(N)$
  * 总共有 $N$ 条边，每条边进行至多两次 `find` 和一次 `union` 操作。
  * 采用路径压缩后，单次操作均摊时间复杂度为反阿克曼函数 $\alpha(N)$（对于实际输入规模，$\alpha(N) \le 4$）。
  * 总体时间极其接近线性时间 $O(N)$。

* **空间复杂度**：$O(N)$
  * `parent` 数组存储 $N + 1$ 个节点的父指针映射，递归调用栈深度在路径压缩扁平化后极浅，辅助空间为 $O(N)$。


### 四、 衍生与横向对比

| 判环场景 | 适用算法 | 核心机制 |
| :--- | :--- | :--- |
| **无向图判环 / 连通块合并** | **并查集 (DSU)** | 查询两端点根节点是否一致，一致即成环 |
| **有向图判环 / 拓扑依赖** | **Kahn 算法 (BFS 入度) 或 DFS 三色标记** | Kahn 统计入度消解；DFS 依赖搜索路径上的“灰色回边” |
| **带权无向图最小生成树** | **Kruskal 算法** | 贪心边权排序 + 并查集判环去重 |
