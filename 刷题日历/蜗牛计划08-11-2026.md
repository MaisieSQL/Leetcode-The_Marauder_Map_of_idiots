# 1095. 山脉数组中查找目标值 - 题目解析与答案

## 一、 题目描述

给定一个山脉数组 `mountainArr`，返回最小的 `index` 使得 `mountainArr.get(index) == target`。如果不存在这样的 `index`，返回 `-1`。

**什么是山脉数组？**
* 数组长度 $\ge 3$。
* 在算法中，索引 $i$ 满足 $0 < i < \text{length} - 1$ 的限制条件。
  * $arr[0] < arr[1] < \dots < arr[i]$
  * $arr[i] > arr[i + 1] > \dots > arr[\text{length} - 1]$

**限制条件：**
* 你无法直接访问山脉数组，只能通过 `MountainArray` 接口：
  * `MountainArray.get(k)`：返回数组中下标为 $k$ 的元素。
  * `MountainArray.length()`：返回数组的长度。
* 调用 `MountainArray.get` 超过 $100$ 次的提交会被判定为错误答案。

## 二、 解题思路

由于题目限制了 `get` 的调用次数不能超过 $100$ 次，且数组具有单调性（先升后降），我们可以很自然地联想到 **二分查找**。

整个解题过程可以分为以下 **三个步骤**：
1. **寻找峰顶元素**：利用二分查找找到山脉数组的最高点（峰顶）索引 $peakIndex$。
2. **在左侧升序数组中查找**：在 $[0, peakIndex]$ 区间内进行升序二分查找。如果找到 `target`，直接返回对应的索引。
3. **在右侧降序数组中查找**：如果在左侧没有找到，则在 $[peakIndex + 1, \text{length} - 1]$ 区间内进行降序二分查找。如果找到，返回索引；若仍未找到，返回 `-1`。

## 三、 Python 代码实现

```python
# """
# This is MountainArray's API interface.
# You should not implement it, or speculate about its implementation
# """
#class MountainArray(object):
#    def get(self, index):
#        """
#        :type index: int
#        :rtype int
#        """
#
#    def length(self):
#        """
#        :rtype int
# """
class Solution:
    def findInMountainArray(self, target: int, mountainArr: 'MountainArray') -> int:
        n = mountainArr.length()
        
        # 步骤 1：使用二分查找找到峰顶元素的索引
        left, right = 0, n - 1
        while left < right:
            mid = (left + right) // 2
            if mountainArr.get(mid) < mountainArr.get(mid + 1):
                left = mid + 1
            else:
                right = mid
        peak = left
        
        # 步骤 2：在左半部分（升序）进行二分查找
        left, right = 0, peak
        while left <= right:
            mid = (left + right) // 2
            val = mountainArr.get(mid)
            if val == target:
                return mid
            elif val < target:
                left = mid + 1
            else:
                right = mid - 1
                
        # 步骤 3：在右半部分（降序）进行二分查找
        left, right = peak + 1, n - 1
        while left <= right:
            mid = (left + right) // 2
            val = mountainArr.get(mid)
            if val == target:
                return mid
            elif val < target:
                right = mid - 1  # 降序数组中，值变小说明目标在左边（索引更小的方向）
            else:
                left = mid + 1   # 值变大说明目标在右边（索引更大的方向）
                
        return -1
```

## 四、 复杂度分析

* **时间复杂度**：$O(\log N)$。其中 $N$ 是数组的长度。寻找峰顶需要 $O(\log N)$，左右两部分二分查找最多各需要 $O(\log N)$，总共的接口调用次数远小于 $100$ 次（在 $N \le 10^4$ 的情况下，调用次数通常在 $30$ 次左右），完全满足题目限制。
* **空间复杂度**：$O(1)$。只需要常数级别的额外空间来存储指针变量。

### 💡 思路一：暴力平推流（Linear Scan / 顺藤摸瓜）
* **怎么想的**：既然管理员说山有那么多格子，那我不动脑子，直接从头（第 0 个）开始，一个一个格子问管理员：“是你吗？不是。那下一个是你吗？”一直摸到头。
* **致命痛点**：
  * **时间复杂度**：$\mathcal{O}(N)$。如果山长 10 万个格子，你最多得问 10 万次。
  * **超次数嫌疑**：管理员有严格的查询限制（不能超过 100 次）。这种暴力平推流在面对 LeetCode 的大规模测试用例时，直接就会被评测机无情地按死在超时（Time Limit Exceeded）的沙滩上。

### 🚀 思路二：三段式二分查找（The Standard Optimal Approach ➔ 正统最优解）
* **怎么想的**：也就是咱们刚刚盘明白的那个逻辑——分而治之。
  * **第 1 次二分**：用二分法找出山顶在哪。
  * **第 2 次二分**：在左边那段“上坡路”（升序区间）里用二分找目标值。
  * **第 3 次二分**：如果在左边没找到，转到右边那段“下坡路”（降序区间）里用二分找。
* **为什么它是工业级最优**：
  * **时间复杂度**：$\mathcal{O}(\log N)$。因为每一次二分都是“对半砍”，哪怕数组长度有 10 亿，总共也只需要问十几次到几十次，绝对不会超过 100 次的上限！
  * **空间复杂度**：$\mathcal{O}(1)$。只用了几个指针变量，没有额外开辟任何大数组。

# 你可能纳闷：“怎么在第一步找山顶时，用的是 left < right（没有等于号），而到了第二步和第三步在左右两边找宝藏时，突然又变成 left <= right（带等于号）了呢？”

咱们别被代码吓住，用大白话和最直观的物理逻辑把它们彻底理清：

🏔️ 第一步：找山顶为什么用 left < right？
我们的目标：我们要通过二分“缩小包围圈”，最后把唯一的那个最高峰死死夹在中间，直到 left 和 right 撞到同一个格子上（即 left == right），循环就结束，这唯一的落脚点就是山顶。

为什么不用等于号：因为如果写了 left <= right，当 left 和 right 相遇时，里面还会再算一次 mid，这在寻找“单峰边界”时容易导致死循环或者指针越界。所以找山顶的经典模板就是 while left < right:，最后靠 left 或 right 停在顶峰收工。

🔍 第二、三步：在左边/右边找宝藏为什么又用 left <= right？
我们的目标：这时候我们的任务变了！我们不是找边界，而是要在一段明确的区间里（比如左边上坡路 [0, peak]）挨个排查每一个格子，看看里面究竟有没有藏着我们要找的 target。

为什么必须带等于号 (left <= right)：

想象一下，如果数组里只有 1 个格子（比如 left = 0, right = 0），如果你的循环条件写的是 left < right，因为 0 < 0 不成立，这个唯一的格子连看一眼的机会都没有，直接就被循环漏掉了！

如果 target 刚好就藏在这个唯一的格子里，程序就会直接漏看并返回 -1。

所以，只要是“在一个确定的区间里精确查找某个具体数值（Target Search）”，就必须用带等于号的标准闭区间二分模板 while left <= right:，确保每一个格子（包括 left == right 时那最后一个重合的格子）都被检查到。

💡 一句话总结两者的本质区别：
找山顶：是“区间收缩法”（寻找一个边界极值），不需要检查最后一个重合点是否满足条件，用 left < right。

找宝藏：是“精确命中法”（在已知区间内捞具体数字），必须把每一个角落（包括单元素区间）都搜干净，用 left <= right。

既然找山顶时循环条件是 `left < right`（没有等于号），那如果 `left` 和 `right` 相遇了（也就是等于了），为什么循环就直接停了？如果它俩相等时刚好卡在山顶，不等它俩相等怎么行？

咱们用最纯粹的物理直觉，把为什么“不能写等于号、写了会发生什么”彻底看透：

### 🏔️ 核心物理真相：`left` 和 `right` 从来不是“去寻找山顶”，而是“把山顶夹在中间”！

在写第一步二分时，我们的逻辑是：
```python
left, right = 0, n - 1
while left < right:
    mid = (left + right) // 2
    if mountainArr.get(mid) < mountainArr.get(mid + 1):
        left = mid + 1  # 还在上坡，山顶在右边
    else:
        right = mid     # 在下坡，山顶在左边或就是当前位置

```

请注意看这里指针的流向：

* 当触发 `left = mid + 1` 时，`left` 主动放弃了当前位置，往右跨了一步。
* 当触发 `right = mid` 时，`right` 收缩到了 `mid`。

这意味着什么？
👉 **山顶永远被死死地夹在当前的 `left` 和 `right` 这两个边界之间！**


### ⚠️ 如果你脑子一热，写成了 `while left <= right:` 会发生什么灾难？

假设当某一次循环时，`left` 和 `right` 终于靠拢了，它们刚好同时指向了真正的山顶（即 `left == right == peak`）。

如果你用了带等于号的 `while left <= right:`，程序会怎么执行：

1. 它会算出 `mid = (left + right) // 2`，此时 `mid` 依然指向山顶。
2. 接下来，它会去查 `mountainArr.get(mid)` 和 `mountainArr.get(mid + 1)`。
3. **致命的问题来了**：`mid` 已经是山顶了，那 `mid + 1` 就在山顶的右边（下坡路）！
4. 所以，山顶的值一定会比右边的值大（`get(mid) > get(mid + 1)`）。
5. 按照我们的 `else` 逻辑，它会执行：`right = mid`。
6. **无限死循环爆发**：此时 `left` 没动（依然在山顶），`right` 被赋值成了 `mid`（也就是山顶）。下一轮循环开始，`left` 和 `right` 还是相等，继续算 `mid`，继续执行 `right = mid`……代码直接卡死在原地，CPU 烧毁！

### 💡 总结一句话：为什么找山顶不能用等于号？

* 因为在找山顶时，我们的 `right = mid` 把包含山顶的可能落脚点死死保留了。
* 当 `left` 和 `right` 终于在某个点撞在一起（`left == right`）时，这个点就是山顶，不需要再进行任何多余的探测了。
* 如果你写了 `left <= right`，当它们在山顶相遇时，代码还要硬着头皮再往下算一次 `mid + 1`（去跟下坡比），从而引发灾难性的死循环。

所以，找山顶的 `while left < right:` 就像是两个围捕的警察，当他俩在顶峰面对面撞个正着时，目标就已经落网，直接收网即可！

# LeetCode 26. Remove Duplicates from Sorted Array (删除有序数组中的重复项)

## 📝 1. 题目描述 (Description)
给你一个非严格递增排列的数组 `nums`，请你**原地**删除重复出现的元素，使每个元素只出现一次，返回删除后数组的新长度。元素的相对顺序应该保持一致。然后返回 `nums` 中唯一元素的个数。

## 💡 2. 核心直觉与解题范式 (Core Intuition)
这道题是经典的**双指针流（快慢指针 / Slow-Fast Pointers）**：
1. **慢指针 `slow`**：负责圈定“无重复合法序列”的右边界。
2. **快指针 `fast`**：负责像侦察兵一样从头到尾扫荡整个数组。
3. **物理动作**：
   - 如果 `nums[fast] != nums[slow]`，说明发现了一个全新的不同数字！
   - 此时我们先把 `slow` 往前挪一步（`slow += 1`），然后把 `nums[fast]` 赋给新的 `slow` 位置（`nums[slow] = nums[fast]`）。
   - 遍历结束后，合法无重复元素的总长度就是 `slow + 1`。

## 💻 3. Python3 完美通关代码 (Solution)

```python
class Solution(object):
    def removeDuplicates(self, nums):
        """:type nums: List[int]

        :rtype: int
        """
        if not nums:
            return 0

        slow = 0
        for fast in range(1, len(nums)):
            if nums[fast] != nums[slow]:
                slow += 1
                nums[slow] = nums[fast]

        return slow + 1
```

## ⏱️ 4. 复杂度分析 (Complexity Analysis)

- **时间复杂度**：$\mathcal{O}(N)$
  - 快指针 `fast` 对整个数组进行了一次线性扫描，每个元素仅被访问一次。
- **空间复杂度**：$\mathcal{O}(1)$
  - 纯原地修改数组，没有额外开辟任何辅助的数据结构或存储空间。
