# 70. Climbing Stairs (爬楼梯)

- **难度**：Easy
- **标签**：动态规划、记忆化搜索、数学（斐波那契数列）
- **LeetCode 链接**：[LeetCode 70. Climbing Stairs](https://leetcode.com/problems/climbing-stairs/)

### 一、 题目描述

假设你正在爬楼梯。需要 `n` 阶你才能到达楼顶。

每次你可以爬 `1` 或 `2` 个台阶。你有多少种不同的方法可以爬到楼顶？

**示例 1：**
* **输入**：`n = 2`
* **输出**：`2`
* **解释**：有两种方法可以爬到楼顶：
  1. 1 阶 + 1 阶
  2. 2 阶

**示例 2：**
* **输入**：`n = 3`
* **输出**：`3`
* **解释**：有三种方法可以爬到楼顶：
  1. 1 阶 + 1 阶 + 1 阶
  2. 1 阶 + 2 阶
  3. 2 阶 + 1 阶

**提示：**
* `1 <= n <= 45`

### 二、 核心解题切入点

**“到达当前台阶的最后一步，只能是从哪里跨过来的？”**

要到达第 $i$ 阶楼梯，因为每次只能走 1 阶或 2 阶，所以**最后一步只有两种可能**：
1. 从第 $i - 1$ 阶跨 **1** 阶上来；
2. 从第 $i - 2$ 阶跨 **2** 阶上来。

根据加法原理，到达第 $i$ 阶的所有走法总数，等于到达第 $i - 1$ 阶的方法数加上到达第 $i - 2$ 阶的方法数。

这正是标准的 **斐波那契数列（Fibonacci Sequence）** 递推模型。

### 三、 动态规划四步走

1. **状态定义**：
   * 定义 `dp[i]` 表示爬到第 $i$ 阶楼梯的不同方法总数。
2. **状态转移方程**：
   * $dp[i] = dp[i - 1] + dp[i - 2]$ （$i \ge 3$）
3. **初始边界条件**：
   * `dp[1] = 1`（爬到第 1 阶只有 1 种方法：走 1 步）
   * `dp[2] = 2`（爬到第 2 阶有 2 种方法：`1+1` 或直接 `2`）
4. **空间优化（滚动变量）**：
   * 计算 `dp[i]` 时，只需要用到它前两个位置的值 `dp[i-1]` 和 `dp[i-2]`。
   * 完全没必要开一个大小为 $n$ 的数组，用两个变量 `prev1` 和 `prev2` 滚动向前推进即可，将空间复杂度从 $O(n)$ 压缩到 $O(1)$。

### 四、 Python 3 最优解实现

#### 解法一：滚动变量空间优化版（面试推荐）

```python
class Solution:

  def climbStairs(self, n: int) -> int:
    # 边界情况快速返回
    if n <= 2:
      return n

    # prev2 代表 dp[i-2]，初始为 dp[1] = 1
    # prev1 代表 dp[i-1]，初始为 dp[2] = 2
    prev2, prev1 = 1, 2

    # 从第 3 阶开始逐步推导到第 n 阶
    for _ in range(3, n + 1):
      curr = prev1 + prev2
      # 变量滚动向前
      prev2 = prev1
      prev1 = curr

    return prev1
```

#### 解法二：标准数组 DP 版（直观便于理解）

```python
class Solution:

  def climbStairs(self, n: int) -> int:
    if n <= 2:
      return n

    dp = [0] * (n + 1)
    dp[1] = 1
    dp[2] = 2

    for i in range(3, n + 1):
      dp[i] = dp[i - 1] + dp[i - 2]

    return dp[n]
```

五、 复杂度分析时间复杂度：$O(n)$。从 $3$ 遍历到 $n$，执行 $n - 2$ 次常数级加法与变量赋值。空间复杂度：滚动变量版：$O(1)$，仅维护 prev1, prev2, curr 三个常量级整数变量。数组 DP 版：$O(n)$，需要维护一个长度为 $n + 1$ 的一维状态数组。

## 这段代码本质上依然是动态规划（DP），而不是算法分类里的“双指针（Two Pointers）”。

产生这种直觉非常自然，因为表面上看确实有两个变量 `prev1` 和 `prev2` 在交替后移，长得很像指针移动。但从算法设计的底层机制来看，两者有根本的区别：

### 一、 为什么它是“动态规划”？

判断一个算法是不是动态规划，核心看两点：
1. **重叠子问题**：要算 $n$ 阶的方法数，依赖 $n-1$ 和 $n-2$ 的答案；而算 $n-1$ 阶又依赖 $n-2$ 和 $n-3$。子问题是高度重叠的。
2. **状态转移**：`curr = prev1 + prev2` 完完全全就是状态转移方程：
   $$dp[i] = dp[i-1] + dp[i-2]$$

这里的 `prev1` 和 `prev2` 存的是“状态计算结果”（子问题的解），而不是内存位置。

之所以没开 `dp = [0] * (n + 1)` 的数组，是因为每次算第 $i$ 步时，历史数据里只有前两步有用，更早的子问题答案再也用不上了。

这种技巧在体系中叫 **“状态压缩”** 或 **“滚动变量优化（Rolling Array）”**，它只是省内存的技巧，没有改变“自底向上递推转移”的 DP 本质。

### 二、 什么是真正的“双指针（Two Pointers）”？

算法中的双指针通常分为两类：
* **相向双指针**：比如二分查找、两数之和（有序数组）、验证回文字符串，左右指针从两端往中间夹逼：`left += 1`, `right -= 1`。
* **同向双指针（滑动窗口 / 快慢指针）**：比如无重复字符的最长子串、链表找环，指针维护的是一个区间窗口或者遍历步长。

双指针的核心在于：**指针指向的是“已有数据结构（数组/链表/字符串）中的特定下标或节点”**，操作的是数据元素的位置移动，用来减少搜索空间；而本题的变量存的是递推计算出的数值。

### 三、 对比小结

| 维度 | 动态规划（滚动变量版） | 双指针（Two Pointers） |
| :--- | :--- | :--- |
| **变量存的是什么** | **子问题的答案**（例如爬到某阶的方法总数） | **数据结构中的索引/位置**（如 `nums[left]`） |
| **推进的核心逻辑** | **状态转移**：通过已知状态相加/取最优，算出新状态 | **搜索剪枝**：根据当前大小关系移动下标，调整考察区间 |
| **典型代表** | 爬楼梯、打家劫舍、斐波那契 | 两数之和 II、三数之和、接雨水、滑动窗口 |

如果单从代码的执行动作来看，两个变量一前一后、步调一致地往前挪（`prev2 = prev1`, `prev1 = curr`），视觉上和“同向双指针”简直长得一模一样！

但计算机科学里区分“双指针”和“DP 滚动变量”，关键不在于长得像不像，而在于这两个变量究竟在充当什么角色：

#### 1. 指针必须“有所指”（它存的是地址/下标）
真正的指针（Pointers）就像你的手指，它指着现成的某样东西：
* **快慢指针**：`slow = 0, fast = 0`，它们存的是数组的下标。你用 `nums[slow]` 和 `nums[fast]` 去查原本就存在数组里的数据。
* 指针本身不代表结果，它只是用来定位元素的。

#### 2. 爬楼梯里的变量是“数值容器”（它存的是状态结果）
在爬楼梯里：
* `prev1` 和 `prev2` 存的根本不是“第几阶”（不是下标 $i$ 或 $i-1$）。
* 它们肚子里装的是实打实的计算结果（比如数字 8、数字 13）。
* `curr = prev1 + prev2` 是在做数学状态的合成（$8 + 13 = 21$）。
* 随后的 `prev2 = prev1; prev1 = curr`，本质上是在做数据缓存淘汰（FIFO 队列更新），意思是：“前前一步的缓存不要了，腾出空间存最新算出来的这个值”。

### 拿个现实场景打比方

* **双指针**：像是两个人手里拿着放大镜，在一条已经印好文字的长纸条（现有数组）上从左往右走，一边走一边看纸条上的字。
* **爬楼梯的滚动变量**：长纸条本身是空白的。两个人手里拿着小黑板，一个人写着上一步的结果，另一个人写着前一步的结果，加出新数后把旧数擦掉。这叫流水线状态计算。

正因为算法题库是按“解题心智模型（Mental Model）”来分类的，这道题的思考起点是数学递推（子问题分解），所以它永远被归在 Dynamic Programming（状态压缩）；而不会出现在需要指针扫描的 Two Pointers 题单里。

不过能注意到它们在代码形态上的这种同构性，说明你对代码的底层执行细节看得非常细致！

# 787. Cheapest Flights Within K Stops (K 站中转内最便宜的航班)

- **难度**：Medium
- **标签**：图论、动态规划、广度优先搜索 (BFS)、Bellman-Ford、Dijkstra 变种
- **LeetCode 链接**：[LeetCode 787. Cheapest Flights Within K Stops](https://leetcode.com/problems/cheapest-flights-within-k-stops/)

### 一、 题目描述

有 `n` 个城市通过一些航班连接。给你一个数组 `flights` ，其中 `flights[i] = [fromi, toi, pricei]` 表示该航班都从城市 `fromi` 开始，以价格 `pricei` 抵达 `toi`。

现在给你所有的城市和航班，以及出发城市 `src` 和目的地 `dst`，你的任务是找到出一条最多经过 `k` 站中转的路线，使得从 `src` 到 `dst` 的 **价格最低**。如果不存在这样的路线，则输出 `-1`。

**关键约束转换**：
* **“最多经过 $k$ 站中转”** = **“最多只能乘坐 $k + 1$ 次航班（即路径最多包含 $k + 1$ 条边）”**。

### 二、 核心解题切入点：为什么这里标准 Dijkstra 会翻车？

**经典 Dijkstra 是无步数限制的贪心**：
* 如果一条路花费极低，但中转了 10 次（超出了 $k$ 的限制），Dijkstra 会优先探索它，甚至可能因为提前标记该点“已访问”而直接堵死了后续虽然费用稍贵、但步数在 $k$ 以内的合法路径。

**解法演进：转为 Bellman-Ford / 步数受限 DP**：
* 还记得 Bellman-Ford 的定义吗？**“松弛 1 轮 = 计算最多经过 1 条边的最短路；松弛 $m$ 轮 = 计算最多经过 $m$ 条边的最短路”**。
* 本题要求最多经过 $k + 1$ 条边，**这简直是量身定做——直接把所有边严格松弛 $k + 1$ 轮！**

### 三、 避坑核心：为什么要开一个 `temp_dist` 副本？

如果不做副本，在同一轮松弛中，前一条边刚把节点 $u$ 更新为较小值，紧接着遍历以 $u$ 为起点的后一条边时，就会拿这个**刚刚更新过的值继续往前冲**。
* 结果：原本一轮循环只能向前推进 1 步，却因为“串联更新”，在单轮内一次性跨越了 2 步甚至更多步，直接破坏了 $k$ 站中转的严格限制。
* **解法**：每一轮松弛前先复制一份当前阶段的距离数组 `temp = dist.copy()`，只用**上一轮的旧距离**来更新新距离。

### 四、 Python 3 最优解实现

#### 解法一：Bellman-Ford（推荐，最贴合步数限制本质）

```python
class Solution:

  def findCheapestPrice(
      self, n: int, flights: list[list[int]], src: int, dst: int, k: int
  ) -> int:
    # dist[i] 表示从 src 到城市 i 的最低花费
    dist = [float("inf")] * n
    dist[src] = 0

    # 最多经过 k 站中转 = 最多经过 k + 1 次飞行（松弛 k + 1 轮）
    for _ in range(k + 1):
      temp = dist.copy()  # 必须使用上一轮的状态副本，防止当轮串联偷跑步数
      updated = False

      for u, v, price in flights:
        if dist[u] != float("inf") and dist[u] + price < temp[v]:
          temp[v] = dist[u] + price
          updated = True

      dist = temp

      # 提前剪枝：如果某一轮没有任何更新，说明已收敛
      if not updated:
        break

    return dist[dst] if dist[dst] != float("inf") else -1
```

#### 解法二：BFS 队列按层遍历（直观的层级探索）

按步数一层一层往外扩，每一层代表多坐一次飞机：

```python
from collections import defaultdict, deque


class Solution:

  def findCheapestPrice(
      self, n: int, flights: list[list[int]], src: int, dst: int, k: int
  ) -> int:
    graph = defaultdict(list)
    for u, v, price in flights:
      graph[u].append((v, price))

    dist = [float("inf")] * n
    dist[src] = 0

    # 队列元素：(当前城市, 当前累计花费)
    queue = deque([(src, 0)])
    stops = 0

    while queue and stops <= k:
      size = len(queue)
      for _ in range(size):
        curr, cost = queue.popleft()

        for neighbor, price in graph[curr]:
          new_cost = cost + price
          # 剪枝：只有当发现到达该邻居更便宜的花费时才入队
          if new_cost < dist[neighbor]:
            dist[neighbor] = new_cost
            queue.append((neighbor, new_cost))

      stops += 1

    return dist[dst] if dist[dst] != float("inf") else -1
```

### 五、 复杂度分析（以 Bellman-Ford 为例）

* **时间复杂度**：$O((k + 1) \times E)$，其中 $E$ 是航班数量（即边数）。
  * 外层循环严格执行 $k + 1$ 次，内层遍历全图所有的边 $E$，执行基本的比大小与加法。
* **空间复杂度**：$O(V)$，其中 $V = n$ 是城市数量。
  * 仅需维护大小为 $n$ 的 `dist` 与 `temp` 数组。

# 到底什么叫“松弛”（Relaxation）？

“松弛”这个词听起来玄乎，其实是当年运筹学从**物理弹性系统**借过来的比喻：
> 把一根原本绷得很紧的橡皮筋，换成一条更短、更松快、阻力更小的近道，让张力“松弛”下来。

### 一、 翻译成人话

用大白话说，**松弛就是：看看能不能抄近道。**

假设你想从 **起点 $S$** 去 **目的地 $V$**：
* 目前你手头已知的一条路线，花费是 **10 块钱**（$dist[V] = 10$）。
* 这时你发现了一个中间朋友 **$U$**：
  * 从起点去 $U$ 只要 **3 块钱**（$dist[U] = 3$）；
  * 而且从 $U$ 坐车直达 $V$ 只要 **4 块钱**（边权 $weight(U, V) = 4$）。
* 你算了一笔账：如果先去 $U$，再从 $U$ 去 $V$，总共才 $3 + 4 = 7$ 块钱。
* **$7 < 10$！抄近道成功！**
* 于是你把去 $V$ 的预算从 10 块改成了 7 块。

**这个“发现绕道 $U$ 更便宜，并把 $dist[V]$ 改小”的动作，在图论里就叫作对边 $(U, V)$ 完成了一次“松弛”。**

### 二、 对应到代码只有这一行

所有的最短路算法（Dijkstra、Bellman-Ford、SPFA、Floyd），无论外层套了堆、队列还是循环，**内核全是在反复执行下面这句判断**：

```python
# 如果从起点先到 u，再从 u 跨到 v 的花费，比目前记录的到 v 的总花费还要小
if dist[u] + weight(u, v) < dist[v]:
  dist[v] = dist[u] + weight(u, v)  # 抄近道成功，更新更优值（这就是“松弛”）
```

* **成功松弛**：找到了一条更短的路线，数值被改小了。
* **无法松弛**：绕道过去反而更远（$dist[u] + weight \ge dist[v]$），维持原方案不变。

### 三、 结合“串联更新”看为什么需要副本

回到 787 题（限制最多坐 $k+1$ 次飞机）：

假设地图是单向直线：`A -> B -> C`，每段花费 10 块。
* **初始状态**：`dist[A] = 0`, `dist[B] = inf`, `dist[C] = inf`。
* **约束**：第 1 轮只允许坐 **1** 次飞机。

#### 1. 如果不用副本（原地修改同一个数组）：
1. 先遍历边 `A -> B`：发现 $0 + 10 < \infty$，松弛成功，`dist[B]` 变成 10。（合法：飞了 1 次）
2. 紧接着遍历边 `B -> C`：你拿刚才**刚刚算出来的** `dist[B] = 10` 去算 $10 + 10 = 20$，发现 $20 < \infty$，于是把 `dist[C]` 也变成了 20！

> **致命问题**：你在单轮循环内顺水推舟完成了两次松弛——**实际上连续坐了两次飞机（A 飞到 B，B 又飞到了 C）**，直接击穿了步数限制。

#### 2. 如果使用副本 `temp = dist.copy()`：
* 遍历 `B -> C` 时，读取的是上一轮冻结的旧值 `dist[B]`（当时还是 $\infty$）。
* $\infty + 10 < \infty$ 不成立，无法松弛！
* **结果**：第 1 轮结束后只有 $B$ 被更新；$C$ 必须老老实实等到第 2 轮（消耗第二张机票）才能被松弛。

如果题目允许你坐第 2 次飞机（比如 $k = 1$），那当然要坐！必须坐！

但关键在于：**如果这道题规定你“只能坐 1 次飞机”（$k = 0$）呢？**

### 问题出在：“你手里的票够不够坐第 2 次？”

我们之所以要写算法，是为了处理任意给定的 $k$：

* **场景 A：如果用户给你的输入是 $k = 1$（最多中转 1 次，也就是最多坐 2 次飞机）**
  * 你当然要从 B 飞到 C。
  * 但合法的过程是：
    * **第 1 轮外层循环**：坐第 1 次飞机，飞到 B。
    * **第 2 轮外层循环**：坐第 2 次飞机，从 B 飞到 C。
    * 每一轮严格代表一张机票，两张机票用完，合法到达 C。

* **场景 B：如果用户给你的输入是 $k = 0$（0 次中转，也就是最多只准坐 1 次飞机）**
  * 规则只准你坐 **1 次** 飞机！
  * 这时候你还想“立刻又坐第 2 次飞机从 B 飞到 C”吗？
  * **绝对不行！因为你没有第 2 张机票！**
  * 从 A 没有直达 C 的航班，只准飞 1 次的话，你根本去不了 C，程序必须老老实实输出 `-1`。

### 为什么说不用副本是 Bug？

如果你**不用副本**，你的代码就完全分不清场景 A 和场景 B 了：

* 哪怕输入是 **$k = 0$（只能飞 1 次）**，外层循环虽然只转了 1 圈，但因为两条边串联在了一起，代码在这一圈里就把 `A->B` 和 `B->C` **全给你坐完了**，直接把去 C 的答案算成了 20！
* 你的程序在只准买 1 张票的情况下，偷偷溜上了第 2 趟飞机。
* 提交到 LeetCode，遇到 $k=0$ 的测试用例立刻就会判你 **Wrong Answer**。

### 加了 `temp` 副本之后：

* **$k = 0$ 时**：第 1 轮只能飞到 B，飞不到 C，外层结束，输出 `-1`（正确）。
* **$k = 1$ 时**：第 1 轮飞到 B；第 2 轮启动时，拿到第 2 张机票，才正式从 B 飞到 C，输出 `20`（正确）。

这下明白为什么必须拦住它，不让它在同一轮里“立刻又坐”了吗？因为下一程必须由**下一轮循环（下一张机票）**来批准！

# 图论核心算法全景脑图与解法选型

图论算法看着千奇百怪，但刷题和面试考察的场景**95% 都可以严格归为以下六大模型**。拿到一道图论题，直接根据**题目问什么**和**边的特征**对号入座即可。

### 一、 核心分类与算法选型总表

| 核心问题分类 | 适用场景与边权特征 | 经典标准算法 | 核心数据结构 / 思想 | 高频代表题 (LeetCode) |
| :--- | :--- | :--- | :--- | :--- |
| **1. 无权图最短路 / 层序遍历** | 边权全为 1（或步数最少） | **BFS (广度优先搜索)** | 队列 (`Queue`) | 127, 752, 1091 |
| **2. 非负权图单源最短路** | 边权非负，求起点到各点代价 | **Dijkstra** | 小顶堆 (`heapq`) + 贪心 | 743, 1631, 787(改) |
| **3. 含负权 / 步数受限最短路** | 含负权边、负权环检测、限步走 | **Bellman-Ford / SPFA** | 数组松弛 / 队列启发式 | 787, 886 |
| **4. 全源最短路** | 任意两点间距离，节点数极小 ($N \le 200$) | **Floyd-Warshall** | 三重循环 + 动态规划 | 1334, 1462 |
| **5. 最小生成树 (MST)** | 无向连通图，用最小总代价连通所有点 | **Kruskal / Prim** | 并查集 (加边) / 小顶堆 (加点) | 1584, 1135 |
| **6. 依赖关系 / 拓扑排序** | 有向无环图 (DAG)，确定先后先后次序 | **Kahn 算法 (入度 BFS) / DFS** | 入度数组 + 队列 | 207, 210, 802 |
| **7. 连通性 / 动态集合合并** | 静态/动态判断两点是否相通，求孤岛数量 | **并查集 (Union-Find) / DFS** | 路径压缩 + 按秩合并 | 200, 547, 684, 2709 |
| **8. 二分图判定 / 染色** | 节点分两组，同组内不能有边 | **双色染色法 (BFS / DFS)** | 访问标记数组 (0/1/-1) | 785, 886 |

### 二、 六大核心解法机制拆解

#### 1. 最短路径族 (Shortest Path)

* **BFS (Breadth-First Search)**
  * **机制**：从起点开始像水波一样一层一层向外扩。
  * **铁律**：**仅适用于所有边权重完全相同（或每走一步代价都为 1）的场景**。第一次访问到某个节点时，所经过的步数必然就是最优解。
* **Dijkstra 算法**
  * **机制**：贪心策略。每次从未确定最短路的节点中，选出当前距离起点最近的一个进行“定版”，并用它更新其邻居。
  * **铁律**：**边权绝不能为负数**。必须使用小顶堆优化，将时间复杂度压到 $O(E \log V)$。
* **Bellman-Ford / SPFA**
  * **机制**：动态规划松弛思想。对所有边进行 $V - 1$ 轮全量更新；若第 $V$ 轮还能缩小，说明有负权环。
  * **特征**：天生适合解决“最多经过 $K$ 站中转”这类有**步数上限约束**的最短路径。
* **Floyd-Warshall 算法**
  * **机制**：三层循环 $O(V^3)$。核心状态转移：`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`。
  * **特征**：求任意两点间的距离，代码仅有 5 行，极其暴力，只能应付数据规模 $N \le 200$ 的题目。

#### 2. 最小生成树族 (Minimum Spanning Tree - MST)

目标：在一个包含 $V$ 个节点的带权无向连通图中，挑出 $V - 1$ 条边将所有点连起来，且**总边权之和最小**。

* **Kruskal 算法（加边法）**
  * **步骤**：
    1. 把图里所有边按权值从小到大排序。
    2. 依次取出最小的边，用**并查集**检查两端点是否已经在同一连通分量里。
    3. 如果不在同一个集合，就合并（采纳这条边）；如果在，就丢弃（防止成环）。
  * **适用场景**：**稀疏图**（边比较少的情况）。
* **Prim 算法（加点法）**
  * **步骤**：
    1. 随意挑一个起点放进集合。
    2. 维护一个小顶堆，存放所有“一头在集合内、一头在集合外”的切分边。
    3. 每次贪心取出最小的边，把对面的新点拉进集合，直到所有点都加进来。
  * **适用场景**：**稠密图**（点少边多，比如完全图 1584 题）。

#### 3. 拓扑排序 (Topological Sort)

目标：排课程表、任务调度、构建依赖检测。

* **Kahn 算法 (入度 BFS 法，面试最推荐)**：
  1. 统计每个节点的**入度（in-degree）**（有多少前置依赖）。
  2. 把所有入度为 0 的节点塞进队列（没有前置要求，可以直接做）。
  3. 队列弹出节点加入答案，并把它的所有后继节点的入度减 1。
  4. 如果某个后继节点入度减到了 0，立刻进队。
  * **环检测**：如果最后输出的节点数量小于总节点数 $V$，说明存在环，无法拓扑排序。

#### 4. 并查集 (Disjoint Set Union - DSU / Union-Find)

目标：高效处理“动态连通性”，判断两个元素是否属于同一组，或者合并两个组。

* **三个固定组件**：
  * `find(x)`：找根节点（**必须带路径压缩**，使树高扁平化）。
  * `union(x, y)`：把两个集合合二为一（可选按秩合并）。
  * `connected(x, y)`：判断 `find(x) == find(y)`。
* **时间复杂度**：带路径压缩后，单次操作几乎是常数级 $O(\alpha(N))$。
* **适用场景**：网络连接冗余、朋友圈分组、网格连通块、质数因数间接连通（2709 题）。

### 三、 算法秒判决策树

```text
拿到图论题
  │
  ├─ 问连通性 / 是否在一个集合？ ──> 并查集 (Union-Find)
  │
  ├─ 问先后顺序 / 选课顺序 / 依赖解环？ ──> 拓扑排序 (Kahn BFS)
  │
  ├─ 问连通所有点的最小代价？ ──> 最小生成树 (Kruskal 或 Prim)
  │
  └─ 问最短路径 / 最小开销？
       │
       ├─ 边权全为 1 ──> 普通 BFS
       ├─ 边权为非负数 ──> 小顶堆 Dijkstra
       ├─ 边权含负数 / 限制最多走 K 步 ──> Bellman-Ford / SPFA
       └─ 求所有点两两之间最短路 (N 极小) ──> Floyd-Warshall
```

# Bellman-Ford 算法体系与通用解题框架

Bellman-Ford 的本质是**动态规划（DP）**，只是它被包装成了图论算法。它的核心直觉是：**“通过多轮全局暴力扫描，逐步把最短路径信息像多米诺骨牌一样扩散到整张图。”**

### 一、 核心解题思路（两条铁律）

#### 1. 步数与松弛轮数的严格等价性
在一个包含 $V$ 个节点的图中，任意两点之间的**简单最短路径（不含环），最多只能包含 $V - 1$ 条边**。
* **松弛 1 轮**：计算出所有“最多经过 1 条边”的最短路；
* **松弛 2 轮**：计算出所有“最多经过 2 条边”的最短路；
* ……
* **松弛 $V - 1$ 轮**：全图所有节点的最短路**必然已经全部确定**。

#### 2. 负权环检测原理
如果图里没有负权环，$V - 1$ 轮后所有距离必然完全收敛。
如果强行跑第 $V$ 轮松弛，发现**居然还能把某个节点的距离改得更小**，说明图里一定存在**负权环**（绕着它转圈能无限刷低成本）。

### 二、 标准场景分类与模板框架

Bellman-Ford 在面试和刷题中只有两种考法：**标准全量最短路（含负权/判负环）** 和 **限制最多走 $K$ 步最短路**。

#### 场景 A：标准全图单源最短路（可检测负权环）
* **循环轮数**：严格执行 $V - 1$ 轮。
* **是否需要备份副本**：**不需要**。因为没有步数限制，就算一轮内发生“串联提前更新”，也只是让收敛变快，完全不影响最终答案。

```python
def bellman_ford(n: int, edges: list[list[int]], src: int):
  """n: 节点总数 (0 到 n-1)

  edges: 每条边 [u, v, weight]
  src: 起点
  """
  dist = [float("inf")] * n
  dist[src] = 0

  # 1. 最多松弛 n - 1 轮
  for _ in range(n - 1):
    updated = False
    for u, v, w in edges:
      if dist[u] != float("inf") and dist[u] + w < dist[v]:
        dist[v] = dist[u] + w
        updated = True
    # 提前收敛剪枝
    if not updated:
      break

  # 2. 第 n 轮检测是否存在负权环
  for u, v, w in edges:
    if dist[u] != float("inf") and dist[u] + w < dist[v]:
      raise ValueError("图中存在负权环，无法定义最短路！")

  return dist
```

#### 场景 B：限制最多经过 $K$ 步的最短路（如 LC 787）

* **循环轮数**：严格执行限制的步数轮（比如最多走 $K+1$ 条边，就循环 $K+1$ 次）。
* **是否需要备份副本**：**必须备份 (`temp = dist.copy()`)**。防止单轮内串联偷跑步数。

```python
def bellman_ford_k_steps(
    n: int, edges: list[list[int]], src: int, dst: int, max_edges: int
) -> int:
  dist = [float("inf")] * n
  dist[src] = 0

  # 限制最多走 max_edges 步，就严格跑 max_edges 轮
  for _ in range(max_edges):
    temp = dist.copy()  # 必须锁定上一轮快照，杜绝串联
    updated = False

    for u, v, w in edges:
      if dist[u] != float("inf") and dist[u] + w < temp[v]:
        temp[v] = dist[u] + w
        updated = True

    dist = temp
    if not updated:  # 提前收敛
      break

  return dist[dst] if dist[dst] != float("inf") else -1
```

### 三、 算法决策：什么时候选 Bellman-Ford？

| 对比维度 | Dijkstra | Bellman-Ford | SPFA (队列优化版 Bellman) |
| :--- | :--- | :--- | :--- |
| **边权是否能为负** | 绝不能为负 | **可以为负** | **可以为负** |
| **能否限制走 $K$ 步** | 很难（需要魔改状态） | **天生支持（改循环轮数即可）** | 较难控制严格层级 |
| **能否检测负权环** | 不能 | **能（跑第 $V$ 轮即可）** | 能（记录节点入队次数） |
| **时间复杂度** | $O(E \log V)$（极快） | $O(V \times E)$（较慢） | 平均 $O(E)$，最差退化到 $O(V \times E)$ |
| **实现难度** | 中等（需维护小顶堆） | **极简单（两层平铺循环）** | 中等（需维护队列） |

**终极判断直觉**：
* 看到**非负权单源最短路** $\rightarrow$ 无脑上 **Dijkstra**。
* 看到**“最多中转 $K$ 次 / 步数受限”** 或 **“边权有负数”** $\rightarrow$ 必须掏出 **Bellman-Ford**。
