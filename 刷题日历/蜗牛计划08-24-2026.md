# LeetCode 226. 翻转二叉树 (Invert Binary Tree)

## 题目描述
给你一棵二叉树的根节点 `root`，请你翻转这棵二叉树，并返回其根节点的指针。
翻转二叉树的定义是：对于树中的每一个节点，交换它的左子树和右子树。

## 解析与思路
翻转二叉树是一道非常经典的递归（DFS）题目。你可以用“分治”的思维来理解它：
* **边界条件（终止条件）**：如果当前节点 `root` 是空（`None`），说明已经走到了叶子节点的下方，直接返回 `None`。
* **递归处理子树**：
  * 递归调用函数去翻转左子树：`left = self.invertTree(root.left)`
  * 递归调用函数去翻转右子树：`right = self.invertTree(root.right)`
* **交换**：把当前节点的左指针指向刚才翻转好的右子树（`root.left = right`），把右指针指向翻转好的左子树（`root.right = left`）。
* **返回**：最后返回当前节点 `root`。

整棵树的每一个节点都会重复这个“交换左右孩子”的过程，当递归一层层退回根节点时，整棵树就已经被完美翻转了。

## 代码实现 (Python)

```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

class Solution:
    def invertTree(self, root: TreeNode | None) -> TreeNode | None:
        # 1. 递归的终止条件：如果节点为空，直接返回
        if not root:
            return None
        
        # 2. 递归翻转左子树和右子树
        root.left, root.right = self.invertTree(root.right), self.invertTree(root.left)
        
        # 3. 返回翻转后的根节点
        return root
```

### 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是二叉树中的节点总数。每一个节点都会被访问并交换一次。
* **空间复杂度**：$O(H)$，其中 $H$ 是树的高度。空间主要消耗在递归调用的栈空间上。在最坏情况下（比如链状树），空间复杂度为 $O(N)$；在平衡二叉树下，空间复杂度为 $O(\log N)$。

# 算法复杂度与二叉树高度详解

## 1. 时间与空间复杂度概览

### 1. 时间复杂度：$O(N)$
其中 $N$ 是二叉树中的节点总数。
无论你怎么写，整棵树的每一个节点都必须要被访问且“翻转”一次。没有一个节点可以逃过，所以时间开销与节点总数 $N$ 成正比，即 **$O(N)$**。

### 2. 空间复杂度：$O(H)$ （最坏 $O(N)$，平均 $\log N$）
这里的空间消耗不在于你写了几行代码，而在于递归调用的系统栈（Call Stack）。
当你在进行递归时，系统需要用栈来记住每一层函数执行到哪了。
树的高度是 $H$：
* 如果是一棵完全二叉树（平衡的），树的高度 $H = \log N$，空间复杂度就是 **$O(\log N)$**。
* 如果这棵树退化成了一条链表（比如所有节点只有左孩子），树的高度 $H = N$，系统栈就要压入 $N$ 层，空间复杂度就是 **$O(N)$**。

所以，看算法的空间复杂度，永远看的是递归调用的深度或者你显式开辟的辅助数据结构（如 Queue/Stack）的大小，跟代码行数或临时变量的多少没有直接关系！

## 2. 为什么一棵“长得均匀”的平衡二叉树，它的高度 $H$ 就是 $\log_2 N$？

你可以把二叉树想象成一个分层的小金字塔：

### 1. 从上往下看：每一层的节点数翻倍
假设这是一棵完美的满二叉树（每一层都塞得满满当当）：
* 第 0 层（根节点）：有 $2^0 = 1$ 个节点
* 第 1 层：有 $2^1 = 2$ 个节点
* 第 2 层：有 $2^2 = 4$ 个节点
* 第 3 层：有 $2^3 = 8$ 个节点
* ……
* 第 $H$ 层：有 $2^H$ 个节点

### 2. 把所有层的节点加起来
如果一共有 $H$ 层（从第 0 层到第 $H-1$ 层，总高度为 $H$），那么整棵树的节点总数 $N$ 大致就是最后一层的节点数（或者说等比数列求和）：
$$N \approx 2^H$$

### 3. 反过来推高度 $H$
既然 $N = 2^H$，那我们要反求高度 $H$，自然就成了对数运算：
$$H = \log_2 N$$

这就是 $\log N$ 的由来：因为每一层节点数都是呈指数级（2 的倍数）增长的，所以反过来，树的高度就是指数的反函数——对数。

### 打个比方感受一下：
* 如果这棵树只有 $N = 7$ 个节点（一个根节点，底下挂了 2 层）：
  * 它的高度 $H = 3$。
  * 而 $\log_2 7 \approx 2.8$（向上取整就是 3）。
* 如果节点数翻倍到 $N = 1023$：
  * 你以为树会变得非常高、要往下走 1023 步吗？
  * 并没有！因为是指数级增长，它的高度 $H = \log_2 1023 = 10$。
  * 也就是说，哪怕节点从 7 个暴增到 1000 多个，树的高度仅仅从 3 变到了 10。这就是对数（$\log N$）恐怖的“增长压制”能力。

所以，只有当这棵树不幸退化成一根“直上直下的棍子”（链表）时，高度 $H$ 才会被打回原形，变成 $N$。而在正常平衡的情况下，它永远是温柔的 $\log N$。

## 3. 为什么空间复杂度是树的高度？

简单一句话来回答：**因为计算机在执行递归（Recursive）时，需要在系统的“调用栈（Call Stack）”里为每一层递归开辟一块内存空间，用来记录返回地址和局部变量。**

我们用一个具体的场景来拆解，为什么空间大小正好等于树的高度 $H$：

### 用“逛楼梯”的视角来理解递归
假设有一棵高度为 3 的平衡二叉树，根节点在 1 楼，叶子节点在 3 楼。
计算机在执行它时，发生的事情是这样的：

* **第 1 步**：你在 1 楼（根节点），调用了 `invertTree(root)`。此时系统在内存的栈里压入第 1 个记录（栈深 = 1）。
* **第 2 步**：没到底呢，你在代码里又调用了 `invertTree(root.left)`，来到了 2 楼。系统在栈里再压入第 2 个记录（栈深 = 2）。
* **第 3 步**：还没到底，继续调用左边，来到了 3 楼（叶子节点）。系统再压入第 3 个记录（栈深 = 3）。
* **第 4 步**：到了 3 楼的叶子节点，触发了终止条件 `if not root: return None`。这时候，最深处的这一层开始“弹出”栈内存，把结果返回给 2 楼。
* 接着，2 楼拿到左边的结果，开始去处理它的右边……

### 关键点来了：为什么最大空间是 $H$ 而不是 $N$？

* 栈内存不是无限累加的，它是“用完就释放”的。
* 当你从 1 楼走到 3 楼最深处时，系统栈最多同时存在 **3 个**栈帧（也就是树的高度 $H = 3$）。
* 当最左边这条路走完、开始往回退（Backtrack）时，那些已经执行完的楼层就会从栈里被**清空（Pop 掉）**，腾出空间给右边的分支复用。
* 因此，在任意一个瞬间，系统栈里同时存在的函数调用记录，不会超过树的最深高度 $H$。

这就是为什么空间复杂度看的是树的高度 $H$，而不是整棵树有多少个节点 $N$。因为计算机不需要把 $N$ 个节点全部同时塞在内存里，它只需要一条路“走到底”的深度内存！

## **Call Stack（调用栈）**，是计算机内存里专门用来**管理函数调用和执行顺序**的一块区域。

如果把它想象成生活中的一个物件，它就像是一个**叠盘子的抽屉**：
* 你只能往最上面放盘子（**压栈 / Push**）。
* 你也只能从最上面把盘子拿走（**弹栈 / Pop**）。
* 先放进去的盘子被压在最底下，**永远最后才能拿出来**（所以叫 **LIFO**：Last In, First Out，后进先出）。

### 用生活中的例子来理解 Call Stack

假设你在公司，老板让你去查一份文件（**函数 A**）。
1. 你开始查文件（执行函数 A），查到一半，发现里面少了一个数据，需要先打个电话问财务（**函数 B**）。
2. 于是你**暂停**手头的工作（把函数 A 的现场保护好，封存起来），拿起电话开始打（去执行函数 B）。
3. 打电话时，财务说：“这事儿我得去翻账本，你等我一下。”（函数 B 又去调用了**函数 C**）。
4. 你只好让财务先去翻，自己在线等着。

这时候，在你的脑子（或者桌子）里，就形成了一个**调用栈**：
* 栈顶（正在干的活）：正在听财务翻账本（**函数 C**）
* 中间（被暂停的活）：在和财务打电话（**函数 B**）
* 栈底（最开始的活）：老板让你查的文件（**函数 A**）

当函数 C 查完账本，把结果告诉你，函数 C 的任务就结束了——**它从栈顶被拿走（Pop 掉）**。
接着你和财务通完电话，函数 B 结束——**函数 B 也被拿走（Pop 掉）**。
最后，你回到了老板交办的任务，函数 A 结束。栈空了，任务完成。

### 放到代码世界里，Call Stack 是怎么工作的？

当计算机运行 Python 或其他任何编程语言时，内存里都会有这样一个栈。

看一个最简单的嵌套函数：

```python
def func3():
    print("3")

def func2():
    func3()
    print("2")

def func1():
    func2()
    print("1")

func1()
```

当程序执行到 `func1()` 时，Call Stack 的“压栈”和“弹栈”过程是这样的：

* **调用 `func1()`**：
  * 压入栈底 👉 `[func1]`
* **在 `func1` 里调用了 `func2()`**：
  * `func1` 暂停，把 `func2` 压到它上面 👉 `[func1, func2]`
* **在 `func2` 里调用了 `func3()`**：
  * `func2` 暂停，把 `func3` 压到最顶上 👉 `[func1, func2, func3]`
* **`func3` 执行完毕 (`print("3")`)**：
  * `func3` 任务完成，从栈顶**弹出** 👉 剩下 `[func1, func2]`
* **回到 `func2` 继续执行 (`print("2")`)**：
  * `func2` 任务完成，从栈顶**弹出** 👉 剩下 `[func1]`
* **回到 `func1` 继续执行 (`print("1")`)**：
  * `func1` 任务完成，从栈顶**弹出** 👉 栈空，程序结束。

### 为什么递归（Recursion）最容易撑爆 Call Stack？

回到我们刚刚学的二叉树递归 `invertTree`。
递归的本质，就是**自己调用自己**。
* 如果是一棵正常的平衡二叉树，树的高度 $H$ 很小（比如 3 层），那么调用栈里最多同时叠 3 个盘子，内存轻松承受。
* 但如果这棵树不幸变成了一条**高达 10 万层的链表**：
  * 函数 1 调用函数 2，函数 2 调用函数 3……一直调用到函数 100,000。
  * 这意味着，计算机必须在内存里**连续叠 10 万个盘子**，每一个盘子都要记住上一层执行到哪了、局部变量是什么。
  * 当栈的空间被彻底耗尽时，系统就会报错：**RecursionError: maximum recursion depth exceeded**（这就是经典的**栈溢出 / Stack Overflow**）。

所以，**Call Stack 就是计算机用来记录“谁调用了谁、谁还没干完活”的专属记事本**。树有多深，这个记事本最多就要翻多厚。

### 开始 Dry Run（一步步看调用栈怎么变化）

#### 阶段一：一路向下（压栈 Push）

* **第 1 步：我们在外面调用 `invertTree(1)`**
  * 系统把 `invertTree(1)` 压入调用栈。
  * 控制台输出：`--> 进入节点: 1`
  * 代码走到 `left_inverted = invertTree(root.left)`，也就是去调用 `invertTree(2)`。
  * **当前 Call Stack（栈里有什么）**：
    ```text
    [ invertTree(1) 正在等左边出结果... ]
    ```

* **第 2 步：进入 `invertTree(2)`**
  * 系统把 `invertTree(2)` 压到栈顶。
  * 控制台输出：`--> 进入节点: 2`
  * 节点 `2` 的左孩子是空（`None`），它去调用 `invertTree(None)`。
  * 触发 `if not root: return None`，直接返回，不压栈。
  * 接着节点 `2` 去调用它的右孩子 `invertTree(None)`，也直接返回。
  * **当前 Call Stack（栈里叠了两个盘子）**：
    ```text
    [ invertTree(1) 正在等左边... ]
    [ invertTree(2) 正在处理自己的左右孩子... ]
    ```

* **第 3 步：节点 `2` 处理完毕，准备弹出**
  * 节点 `2` 把自己的左右孩子交换完。
  * 控制台输出：`<-- 离开节点: 2 (翻转完成)`
  * `invertTree(2)` 任务结束，从栈顶被 Pop（弹出）！
  * **当前 Call Stack（恢复成只剩 1 个）**：
    ```text
    [ invertTree(1) 刚才派出去的左边回来了，现在准备搞右边 ]
    ```

#### 阶段二：回到上一层，走向另一边

* **第 4 步：回到 `invertTree(1)`，开始搞右边**
  * 刚才 `invertTree(1)` 的左边 (`invertTree(2)`) 终于算完了。
  * 现在代码走到下一行：`right_inverted = invertTree(root.right)`，也就是去调用 `invertTree(3)`。
  * 系统把 `invertTree(3)` 压入栈顶。
  * 控制台输出：`--> 进入节点: 3`
  * **当前 Call Stack**：
    ```text
    [ invertTree(1) 正在等右边出结果... ]
    [ invertTree(3) 正在处理... ]
    ```

* **第 5 步：节点 `3` 处理完毕，弹出**
  * 节点 `3` 左右孩子为空，直接交换（相当于没变）。
  * 控制台输出：`<-- 离开节点: 3 (翻转完成)`
  * `invertTree(3)` 任务结束，从栈顶 Pop 掉。
  * **当前 Call Stack**：
    ```text
    [ invertTree(1) 左右两边都搞定了！ ]
    ```

#### 阶段三：收尾并退出

* **第 6 步：回到最初的 `invertTree(1)`**
  * 根节点 `1` 拿到左边翻好的结果、右边翻好的结果，把它们互相对调。
  * 控制台输出：`<-- 离开节点: 1 (翻转完成)`
  * `invertTree(1)` 结束，从栈顶弹出。
  * **当前 Call Stack**：`[]` （空了！）

### 💡 看完这个过程，你有什么感觉？

#### 为什么栈的最大高度就是树的高度？
* 在这个例子里，树的高度是 2（或者说有 2 层）。
* 你发现了吗？在**任何一个瞬间**，栈里面最多只同时存在 **2 个**正在执行的函数（比如执行到节点 2 时，栈里是 `[invertTree(1), invertTree(2)]`）。
* 绝不可能出现 `invertTree(2)` 和 `invertTree(3)` 同时在栈里的情况，因为左边的支路完全走完、**弹栈消失**之后，才轮到右边的支路进栈。
* 所以，内存里永远只需要开辟相当于“一条直路走到底”的深度空间。

## **所有的 DFS（深度优先搜索，不管是递归写法还是用栈模拟的非递归写法），其空间复杂度本质上全都是“递归深度 / 最大栈深度”。**

你可以把 DFS 想像成**“走迷宫”**：
1. 你永远是在一条路上**闷头往前走**，每走一步，就把当前的位置记录在手里的记事本上（压栈）。
2. 当你走到死胡同（触及终止条件）或者这一条路搜完了，你就**退回上一步**（弹栈/Pop），擦掉那个地方的记录，去试另一条岔路。
3. 因此，在任意一个瞬间，你的记事本上最多只需要记录**“从起点到当前最深处的那一条单链”**，而不需要把整个迷宫的所有路口全记下来。

### 不同结构的数据，DFS 的空间复杂度怎么变？

因为空间复杂度完全取决于**“DFS 最深能钻多深”**，所以针对不同的数据结构，它的空间复杂度表现为：

1. **二叉树 (Binary Tree)**：
   * **最好/平均情况（平衡树）**：深度是 $H = \log N$，空间复杂度就是 **$O(\log N)$**。
   * **最坏情况（退化成链表）**：深度是 $H = N$，空间复杂度就是 **$O(N)$**。

2. **图 (Graph / DFS 遍历)**：
   * 如果图是一个“长长的链条”，深度就是 $V$（顶点数），空间复杂度 **$O(V)$**。
   * 另外，为了防止图里有环导致无限死循环，我们通常还需要一个 `visited` 哈希表（或数组）来记录访问过的节点，这个 `visited` 也会占用 **$O(V)$** 的空间。所以图的 DFS 空间复杂度一般是 **$O(V)$**（由递归栈深度和 visited 共同决定）。

3. **回溯算法 (Backtracking，本质也是 DFS)**：
   * 比如全排列（Permutations）或子集（Subsets）问题，递归的最大深度就是数组的长度 $N$（或者题目要求的组合长度 $k$）。
   * 所以回溯算法的空间复杂度通常是 **$O(N)$**（系统递归栈的深度）再加上存放结果的临时路径数组空间。

### 总结一句话：
只要看到 **DFS**，你就不要去管总共有多少个元素（$N$ 很大没关系），你只需要盯着：**“它最多能往深处走几步？”**。这个“最大深度”，就是它雷打不动的空间复杂度！

# LeetCode 40. 组合总和 II (Combination Sum II)

## 题目描述

给定一个候选人编号的集合 `candidates` 和一个目标数 `target`，找出 `candidates` 中所有可以使数字和为 `target` 的唯一组合。

* `candidates` 中的每个数字在每个组合中**只能使用一次**。
* 解集不能包含重复的组合。
* `candidates` 中可能包含重复的数字。

## 解析与思路

这道题是经典的 **回溯（Backtracking / 属于带剪枝的 DFS）** 问题。与第 39 题相比，它有两个核心限制：
1. **每个数字只能用一次**：所以在递归时，传给下一层的索引必须是 `i + 1`。
2. **数组有重复、结果不能重复**：必须先对 `candidates` 进行**排序**，并在同一层的循环中进行**去重剪枝**：`if i > start and candidates[i] == candidates[i - 1]: continue`。

## 代码实现 (Python)

```python
class Solution:
    def combinationSum2(self, candidates: list[int], target: int) -> list[list[int]]:
        res = []
        # 1. 排序，让相同的数字聚在一起，方便后续去重
        candidates.sort()
        
        def backtrack(start, target_left, path):
            # 终止条件：如果剩余目标值为 0，说明找到一个合法组合
            if target_left == 0:
                res.append(list(path))
                return
            
            for i in range(start, len(candidates)):
                # 剪枝1：如果当前数字大于剩下的 target，后面的数字更大，直接break
                if candidates[i] > target_left:
                    break
                
                # 剪枝2（去重）：同一层循环中，如果当前数字和前一个数字相同，跳过
                if i > start and candidates[i] == candidates[i - 1]:
                    continue
                
                # 做选择
                path.append(candidates[i])
                # 递归：因为每个数字只能用一次，所以传入 i + 1
                backtrack(i + 1, target_left - candidates[i], path)
                # 撤销选择（回溯）
                path.pop()
        
        backtrack(0, target, [])
        return res
```

### 复杂度分析

* **时间复杂度**：$O(2^N)$，其中 $N$ 是数组的长度。在最坏情况下，每个元素都有选或不选两种状态，但由于有剪枝和去重，实际运行速度通常远快于这个理论上限。
* **空间复杂度**：$O(N)$。主要消耗在递归调用的系统栈深度（最深为 $N$）以及用来存储临时路径 `path` 的空间。

### 为什么要 `pop`？

在回溯算法（Backtracking / DFS）里，这个 `path.pop()` 简直就是灵魂所在。

简单一句话来回答：**因为 `path` 是一个“全局共享”的临时变量，如果不 `pop`，它在试完一条路之后就会变成一条废路，没办法再去试别的路了。**

我们用生活中的一个极具画面感的例子来拆解：

#### 用“试衣服”来理解 `path.pop()`
假设你面前有一个衣柜（`candidates`），里面有三件衣服：`[A, B, C]`。
现在你要挑选搭配：
* 你拿起了 `A` 衣服，试穿在身上。此时你的身上（`path`）是：`[A]`。
* 带着 `A`，你又去挑了第二件衣服 `B`。此时你身上是：`[A, B]`。
* 发现凑齐了，记录下来一个组合。
* **关键时刻到了**：现在你打算去试“拿 `A` 和 `C` 搭配”的可能性。
  * 如果你**不脱掉（不 `pop`）**刚才穿上的 `B`，你现在的状态是 `[A, B]`。
  * 你直接去拿 `C`，身上就会变成 `[A, B, C]`——这全乱套了！因为 `B` 还挂在你身上。
  * **正确做法**：你要先把刚才试的 `B` **脱掉（`path.pop()`）**。脱掉之后，你身上重新变回只有 **`[A]`** 的状态。
  * 这时候，你才可以开开心心地去拿起 `C`，试出 `[A, C]` 的组合。

#### 放到代码里，到底发生了什么？
在写回溯时，为了节省内存，我们通常不会在每次递归时去凭空创建一个全新的列表，而是共用同一个 `path` 列表。

看这段经典骨架：

```python
path.append(candidates[i])       # 1. 做选择：穿上这件衣服
backtrack(...)                   # 2. 带着这件衣服，继续往下深搜
path.pop()                       # 3. 撤销选择：脱掉这件衣服，换下一件！
```

* `path.append` 是“向前探索”：把当前的数字加进来。
* `backtrack` 是“顺着这条路往下走到底”。
* `path.pop()` 是“打扫战场（恢复现场）”：当这条路走完了（或者此路不通要回头了），必须把刚才加进去的那个数字从尾巴上**弹出去**，还原成没选它时的样子，这样代码才能安安心心地去循环测试下一个候选数字。

如果没有 `pop`，你的 `path` 就会一路膨胀、错乱，最后搜出来的全都是乱七八糟的错误组合。

所以，`pop` 的本质就是：**不留痕迹地撤销上一步的选择，好让大部队去探索别的可能性。**

为什么回溯算法（Backtracking）在讲的时候，大家永远离不开“树”（Tree）这个词？

因为回溯的整个搜索过程，在物理结构上就是一棵不断分叉、延伸、回头的“决策树”。
我们可以把回溯拆解成“怎么长成一棵树”的：

### 1. 为什么它是“树”？（结构形态）
树的核心特征是什么？有一个**根节点（Root）**，向下延伸出**分支（Branches）**，最后到达**叶子节点（Leaves）**。

在回溯算法里：
* **根节点**：代表你的初始状态（比如空的 `path = []`，什么还没选）。
* **每一层（Level）**：代表你做的第几次选择。比如第一层决定选哪个数，第二层决定选哪个数……
* **分支（Branches）**：代表你在当前状态下，**有哪些合法的候选可以选**（对应代码里的 `for i in range(start, len(candidates))` 循环，循环几次，就有几个分支）。
* **叶子节点**：代表一条路走到头了。要么是凑出了 `target`（成功），要么是超标了 / 没路走了（失败）。

所以，计算机在执行回溯时，它并不是盲目乱撞的，它在内存的递归调用栈里，实际上是在**一条路一条路地遍历这棵看不见摸不着的多叉树**。

### 2. 为什么它叫“决策”树？（动作含义）
因为在树的每一个节点上，你都在做一个**抉择（Decision）**：
* 面对候选池 `[1, 2, 5]`，你在根节点面临决策：
  * 选择走“选 1”这条分支？
  * 还是走“选 2”这条分支？
  * 还是走“选 5”这条分支？
* 当你选了 `1` 之后，你来到了子节点，又面临**新的决策**：在剩下的数字里，我接下来该选谁？

这就是为什么叫**决策树**——你的每一步代码执行（`path.append`），本质上都是在给未来的可能性“做决定”。

### 3. “回溯（Backtrack）”在树里是个什么动作？
这就能完美解释我们刚才讨论的 `path.pop()` 为什么是灵魂了：

* **顺着树往下走（DFS）**：
  从根节点出发，一路选到底（`1 -> 1 -> 6`），直到撞到南墙（发现加起来超过了 target）。
* **回溯（Backtrack / 退回上一步）**：
  撞南墙了，怎么办？**顺着树往回爬一层**。
  爬回上一层时，必须把刚才为了走到这条死胡同而做出的“错误决策”给擦掉（也就是执行 `path.pop()` 把刚才选的数吐出来），这样你才能站在原地，去尝试**同一层的另一条分支**（比如从选 2 改成选 5）。

### 用代码和树的视角做个映射：

```python
for i in range(start, len(candidates)): # 对应树的“分叉（宽度）”
    path.append(candidates[i])          # 做决定：往树的深处走一步
    backtrack(i + 1, ...)               # 递归：进入下一层决策
    path.pop()                          # 回溯：爬回上一层，擦掉决定，准备走下一个分叉
```

所以，回溯 = 深度优先搜索（DFS）遍历一棵隐式的决策树。
当你理解了“它其实是在遍历一棵树”，再去算时间复杂度（节点总数）、空间复杂度（树的最大深度），以及写 pop() 的时候，所有的代码逻辑就全都能在脑子里画成一幅生动的树形图了！

对排序的 $O(N \log N)$ 和回溯框架的理解也很到位！不过，关于回溯部分的时间复杂度以及最终的总体时间复杂度，有一个小细节需要修正。

### 1. 回溯部分的时间复杂度是 $O(2^N)$ 吗？
不完全准确。

* 如果是普通的子集问题（每个元素选或不选），总状态数确实是 $O(2^N)$。
* 但对于 **Combination Sum II（组合总和 II）**：
  * 数组中包含重复元素。
  * 我们加了剪枝（`candidates[i] > target_left` 且数组已排序），这会提前终止很多不可能的分支。
  * 即使在最坏情况下（所有数字都很小，能够组合出很多结果），子集树的高度和宽度也受限于 `target` 的大小以及数组的长度 $N$。

因此，回溯过程中的实际有效状态数通常远小于 $2^N$。在算法复杂度分析中，严格的最坏情况时间复杂度通常写为 **$O(2^N)$**（作为指数级的上界），但如果你加上了**将合法路径加入结果集时的拷贝开销**（把 `path` 放入 `res` 需要 $O(K)$ 的时间，其中 $K$ 是路径长度），精确的时间复杂度上界其实是 **$O(N \cdot 2^N)$**。

### 2. 最后的总体时间复杂度对吗？
你得出的结论是：“$O(N \log N)$（排序） + $O(N \cdot 2^N)$（回溯） = 总共 $O(N \cdot 2^N)$”，**这个最终结论在渐进意义上（Big-O notation）是完全正确的！**

* **排序**：$O(N \log N)$
* **回溯与结果拷贝**：$O(N \cdot 2^N)$
* **总时间复杂度**：因为当 $N$ 增大时，指数级 $O(N \cdot 2^N)$ 远大于对数级 $O(N \log N)$，所以根据大 O 记号的消去法则，**总时间复杂度确实是 $O(N \cdot 2^N)$**（或者宽松一点写成 $O(2^N)$）。

# **LeetCode 77. 组合 (Combinations)**！这道题是学习回溯算法（Backtracking）的经典入门和核心基础题。

### 1. 解题思路

题目要求：给定两个整数 $n$ 和 $k$，返回范围 $[1, n]$ 中所有可能的 $k$ 个数的组合。

* **核心模型**：这是一棵标准的“组合树/子集树”。
* **与 LeetCode 40 的区别**：
  * LeetCode 40 是元素可重复、有 target 限制、每个元素可选用一次或多次。
  * LeetCode 77 是从 $1$ 到 $n$ 中选 $k$ 个数，**元素无重复、不可复选、结果无序**（即 $[1, 2]$ 和 $[2, 1]$ 算同一个组合）。
* **关键剪枝优化（非常重要）**：
  * 如果当前路径已经选了 `len(path)` 个数，还差 `k - len(path)` 个数。
  * 剩下的候选区间 $[i, n]$ 中一共有 $n - i + 1$ 个数。
  * 如果剩下的数不够填满所需的空位（即 $n - i + 1 < k - \text{len}(path)$），那么后面的循环就完全没必要执行了，可以直接 `break`。

### 2. Python 代码实现

```python
class Solution:
    def combine(self, n: int, k: int) -> list[list[int]]:
        res = []
        
        def backtrack(start: int, path: list[int]):
            # 终止条件：当路径长度等于 k 时，找到一个合法组合
            if len(path) == k:
                res.append(list(path)) # 注意要做拷贝
                return
            
            # 遍历候选集
            for i in range(start, n + 1):
                # 剪枝优化：如果剩下的元素加上当前已经选的元素，连 k 个都凑不够，直接 break
                if n - i + 1 < k - len(path):
                    break
                
                # 做选择
                path.append(i)
                # 递归：下一个数从 i + 1 开始
                backtrack(i + 1, path)
                # 撤销选择（回溯）
                path.pop()
                
        backtrack(1, [])
        return res
```

### 3. 复杂度分析

* **时间复杂度**：$O(K \cdot \binom{N}{K})$
  * 总共有 $\binom{N}{K}$（即从 $N$ 个数中选 $K$ 个数的组合数）个合法解。
  * 每找到一个合法解，需要将其复制到结果集中，耗时 $O(K)$。
  * 因此总时间复杂度为 $O(K \cdot \binom{N}{K})$。
* **空间复杂度**：$O(K)$
  * 递归树的深度最大为 $K$（因为每个组合刚好包含 $K$ 个数）。
  * 临时路径 `path` 占用 $O(K)$ 空间（不计算最终存储结果的 `res` 所需空间）。
