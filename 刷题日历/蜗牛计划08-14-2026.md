# LeetCode 682. 棒球比赛 (Baseball Game)

## 🎯 一、 核心考点与物理直觉

- **题目大意**：
  你现在是一家棒球比赛的记分员。比赛以局为单位，记录员会按顺序收到一串操作字符串列表 `operations`。
  你需要根据以下规则实时计算并返回比赛结束时的总得分：
  - 整数 `x`：表示本局新获得分数 `x`。
  - `"+"`：表示本局得分是前两次有效得分的总和。
  - `"D"`：表示本局得分是前一次有效得分的两倍。
  - `"C"`：表示使前一次有效得分失效（从记录中移除）。
- **物理直觉**：
  - 这是一道典型的**“栈 (Stack) 模拟题”**。
  - 因为所有的得分规则（求前一次、前两次的总和，或者移除最近一次）全部具有极强的**“后进先出 (LIFO)”**特性。
  - 栈底到栈顶实时记录着当前有效的得分序列。每来一个操作符，我们只需要直接从栈顶弹出或窥探最近的元素进行计算，然后把新结果压入栈中即可。最后直接对栈内所有元素求和！

## 💻 二、 工业级 Python3 代码实现 (Solution)

```python
class Solution(object):
    def calPoints(self, operations):
        """:type operations: List[str]
        :rtype: int
        """
        stack = []
        
        for op in operations:
            if op == "+":
                # 本局得分是前两次有效得分的总和
                # stack[-1] 是前一次，stack[-2] 是前两次
                stack.append(stack[-1] + stack[-2])
            elif op == "D":
                # 本局得分是前一次有效得分的两倍
                stack.append(stack[-1] * 2)
            elif op == "C":
                # 移除前一次有效得分
                stack.pop()
            else:
                # 纯数字字符串，转化为整数后入栈
                stack.append(int(op))
                
        # 比赛结束，对栈内所有有效得分求和
        return sum(stack)
```

⏱️ 三、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：O(N)
  - 其中 N 是操作列表 operations 的长度。我们只需要对整个操作数组进行一次从头到尾的线性扫描，栈的 append、pop 和最后的 sum 均摊下来都是单次常数开销。
- **空间复杂度**：O(N)
  - 最坏情况下（全部都是数字操作），栈需要完整存下所有的 N 个得分记录。

# LeetCode 102. 二叉树的层序遍历 (Binary Tree Level Order Traversal)

## 🎯 一、 核心考点与物理直觉
- **题目大意**：给你一个二叉树的根节点 `root`，返回其节点值的**层序遍历**（即逐层地，从左到右访问所有节点）。
- **物理直觉**：
  - 如果说 DFS（深度优先搜索）像是“一个人拿手电筒在迷宫里一条路走到黑”，那么 BFS（广度优先搜索）就像是“救援人员呈横向扩展的人墙，从上到下一层一层平推过去”。
  - **核心痛点**：我们必须准确分清“哪些节点属于第 1 层，哪些节点属于第 2 层”，不能让上下两层的节点混在一起。
  - **降维打击秘籍**：借助 **队列 (`deque`)** 的先进先出（FIFO）特性，并在进入每一层的瞬间**用 `level_size = len(queue)` 死死锁定当前层的节点总数**，做到层与层之间泾渭分明！

## 💻 二、 工业级 Python3 代码实现 (Solution)

```python
# Definition for a binary tree node.
# class TreeNode(object):
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from collections import deque

class Solution(object):
    def levelOrder(self, root):
        """:type root: Optional[TreeNode]
        :rtype: List[List[int]]
        """
        if not root:
            return []
            
        res = []
        queue = deque([root])  # 初始化队列，将根节点放入
        
        while queue:
            level_size = len(queue)  # 🔑 灵魂微操：锁定当前层的节点总数
            current_level = []       # 收集当前层的节点值
            
            # 把当前层的节点全部出队，并把它们的左右孩子入队
            for _ in range(level_size):
                node = queue.popleft()
                current_level.append(node.val)
                
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
                    
            # 当前层大功告成，打包塞入最终结果集
            res.append(current_level)
            
        return res
```

## 三、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：O(N)
  - 其中 $N$ 是二叉树的节点总数。每一个节点在整个 BFS 过程中都恰好被压入队列一次、弹出队列一次，做到了绝对高效的线性扫描。
- **空间复杂度**：O(N)
  - 空间开销主要由队列（Queue）消耗。在二叉树的最底层（满二叉树形态），叶子节点数量大约占总节点数的一半，因此队列在峰值时最多容纳 O(N) 个节点。

# LeetCode 206. 反转链表 (Reverse Linked List)

## 🎯 一、 核心考点与物理直觉

- **题目大意**：给你单链表的头节点 `head`，请你反转链表，并返回反转后的新头节点。
- **物理直觉**：
  - 单向链表最大的局限在于：我们**只能从前往后走（`next`）**，没有回头路。
  - 要想把原本指向后面的箭头（`->`）强行掰过来指向前面（`<-`），我们需要动用三个核心指针：
    - **`prev`（前驱指针）**：初始化为 `None`。用来接住反转后的箭头。
    - **`curr`（当前指针）**：初始化为 `head`。负责冲锋陷阵、推进整条链表。
    - **`next_temp`（临时暂存指针）**：每次循环里用来**提前保存 `curr.next`** 的位置，防止后半截链表断联失踪！

## 💻 二、 Python3 完美通关代码 (Solution)

```python
# Definition for singly-linked list.
# class ListNode(object):
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution(object):
    def reverseList(self, head):
        """:type head: Optional[ListNode]
        :rtype: Optional[ListNode]
        """
        prev = None
        curr = head
        
        while curr:
            # 🔑 1. 暂存下一个节点，防止断链失联
            next_temp = curr.next
            
            # 🔑 2. 强行把箭头反转，指回前面
            curr.next = prev
            
            # 🔑 3. prev 和 curr 双双往前挪一步，准备下一轮迭代
            prev = curr
            curr = next_temp
            
        # 当 curr 变成 None 时，prev 正好稳稳停在了新链表的头节点上！
        return prev

```

⏱️ 三、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：O(N)
  - 其中 N 是链表的节点总数。我们对整条链表进行了一次从头到尾的线性扫描，每个节点恰好被访问和修改指针一次。
- **空间复杂度**：O(1)
  - 全程只用了 `prev`、`curr`、`next_temp` 三个常数级别的指针变量，没有开辟任何额外的存储空间，空间利用率拉满！


LeetCode 206. 反转链表 是链表题里的“hello world”，必须把它盘得透透的。
光看代码容易晕，我们采用 Dry Run（走读/模拟） 的方式，配合物理图解，把这三个指针（prev, curr, next_temp）在内存里的每一次位移都看得清清楚楚。
为了演示，我们准备了一个标准的链表：1 -> 2 -> 3 -> 4 -> 5 -> NULL
我们的目标是把它变成：NULL <- 1 <- 2 <- 3 <- 4 <- 5，并返回新的头节点 5。

## 🎬 反转链表 Dry Run 全过程图解

### 初始状态 (Before Loop)
在循环开始前，我们设置好初始阵型：
- `prev` 指向 `NULL` (用来接住反转后的第一个箭头)。
- `curr` 指向链表的原头节点 `1`。
- `next_temp` 暂时为空。

```text
(初始状态)

        |             |
      NULL   <-   [ 1 ] -> [ 2 ] -> [ 3 ] -> [ 4 ] -> [ 5 ] -> NULL
```

🛑 第一轮迭代 (Iteration 1: curr=1)
这轮的目标是把节点 1 的箭头掰弯，指向 NULL。

🔑 暂存：next_temp = curr.next。先把 2 记下来，防止 1 指向 NULL 后找不到 2 了。

💥 反转：curr.next = prev。把 1 的箭头从指向 2 改为指向 NULL (也就是 prev)。

🚶 推进：prev = curr，curr = next_temp。prev 和 curr 同时向后挪一步。

```text
(第一轮结束)

                      |             |
      NULL   <-   [ 1 ]       [ 2 ] -> [ 3 ] -> [ 4 ] -> [ 5 ] -> NULL
                                 ^
                                 |
                              next_temp

```

🛑 第二轮迭代 (Iteration 2: curr=2)
这轮的目标是把节点 2 的箭头掰弯，指向 1。

🔑 暂存：next_temp = curr.next。先把 3 记下来。

💥 反转：curr.next = prev。把 2 的箭头从指向 3 改为指向 1 (也就是当前的 prev)。

🚶 推进：prev = curr，curr = next_temp。prev 和 curr 同时向后挪一步。

```text
(第二轮结束)

                                    |             |

                                                next_temp
```

🛑 第三轮迭代 (Iteration 3: curr=3)
目标：把 3 的箭头掰弯，指向 2。 (以此类推，动作完全重复)

```text
(第三轮结束)
                                             prev          curr
                                               |             |
      NULL   <-   [ 1 ]   <-   [ 2 ]   <-   [ 3 ]       [ 4 ] -> [ 5 ] -> NULL
                                                              ^
                                                              |
                                                           next_temp
```

🛑 第四轮迭代 (Iteration 4: curr=4)
目标：把 4 的箭头掰弯，指向 3。

```text
                                                       prev          curr
                                                         |             |

                                                                        ^
                                                                        |
                                                                     next_temp
```

🛑 第五轮迭代 (Iteration 5: curr=5)
这是最后一轮。目标：把 5 的箭头掰弯，指向 4。

🔑 暂存：next_temp = curr.next。此时 next_temp 变成了 NULL。

💥 反转：curr.next = prev。把 5 的箭头改为指向 4 (当前的 prev)。

🚶 推进：prev = curr，curr = next_temp (此时 curr 为 NULL)。

🏁 终局状态 (After Loop)
循环结束时：

curr 停在 NULL。

prev 稳稳地停在了原链表的最后一个节点 5 上。

这正是我们要返回的新链表的头节点！我们最终返回 prev 即可。

# 💡 灵魂拷问：为什么 LeetCode 206 最后必须 `return prev`？

在初学“反转链表”时，大家最容易卡壳、也是最精妙的一个问题就是：
> **“为什么循环结束后，返回的是 `prev`，而不是 `curr` 呢？”**

咱们直接拉开内存物理沙盘，看看到底是怎么回事：

## 🔍 一、 看看循环结束的那一瞬间，`prev` 和 `curr` 分别在哪？

当整条链表刚好被完全反转后，最后一轮循环执行完毕：
- `curr` 指针因为已经走出了原链表的末尾（来到了 `NULL` 的位置），所以 **`curr` 此时变成了 `None`（空）**。
- 而 **`prev`** 因为刚刚把最后一个节点（比如节点 `5`）揽入怀中，它正**稳稳地停在整条新链表的头部（也就是原链表的最后一个节点）**！

## 💥 二、 错误示范：如果你返回了 `curr`

- 因为循环结束时 `curr` 已经是 `None` 了。
- 如果你写 `return curr`，函数就会直接返回一个空指针 `None`。
- 这意味着你的程序辛辛苦苦把链表反转完了，结果一交卷，交了个寂寞（空链表），评测机直接判定你解答错误！

## ✨ 三、 为什么必须返回 `prev`？

- 因为在整个反转过程中，`prev` 就像是一个永远跟在 `curr` 身后的“影子老大哥”。
- 每次 `curr` 向前挪一步之前，`prev` 都要先接住被反转过来的那个新头节点。
- 当 `curr` 最终掉出链表（变成 `None`）宣告工作结束时，`prev` 刚好停在了**新链表的最高统帅（新头节点）**位置上。

## 🎯 四、 军师给你的通关记忆口诀

> **“`curr` 是冲锋陷阵的探路先锋，当它跑到终点（变为空 `None`）时，殿后的 `prev` 刚好稳稳驻扎在了新阵地的最高峰（新头节点）！所以必须 `return prev`。”** 🚀🔥

在反转链表（LeetCode 206）的代码里，`temp`（也就是我们刚才图解里的 `next_temp`）扮演的正是**“保镖/接力棒”**的角色。

我们依然用标准的链表 `1 -> 2 -> 3 -> 4 -> 5 -> NULL` 来做实操演练。每一轮循环中，`temp = curr.next` 拿到的究竟是什么值？我们一五一十列出来：


### 🔍 逐轮循环中 `temp` 的取值演变表：

| 循环轮次 | 当前 `curr` 指向谁 | 执行 `temp = curr.next` 这一瞬间，`temp` 拿到了什么值？ | 为什么需要它？（物理直觉） |
| :--- | :--- | :--- | :--- |
| **第一轮** | 节点 **`1`** | 节点 **`2`** | 此时我们要把 `1` 的指针指回前面（`prev`）。如果没有 `temp` 把 `2` 提前死死抱住，`1` 一扭头，后面的 `2 -> 3 -> 4 -> 5` 就会直接**断联失踪**！ |
| **第二轮** | 节点 **`2`** | 节点 **`3`** | 把 `2` 的指针反转指回 `1` 之前，必须先用 `temp` 把后面的 `3` 记下来。 |
| **第三轮** | 节点 **`3`** | 节点 **`4`** | 把 `3` 的指针反转指回 `2` 之前，必须先用 `temp` 把后面的 `4` 记下来。 |
| **第四轮** | 节点 **`4`** | 节点 **`5`** | 把 `4` 的指针反转指回 `3` 之前，必须先用 `temp` 把后面的 `5` 记下来。 |
| **第五轮** | 节点 **`5`** | **`None`（即 `NULL`）** | 这是最后一轮。当 `curr` 指向 `5` 时，`5.next` 已经是链表的尽头 `NULL` 了。所以此时 `temp` 拿到了 **`None`**。这代表：“前方已经没有节点了，这是最后一棒！” |

### 💡 为什么必须有 `temp`？（一句话总结）

单向链表的残忍之处在于：**你一旦改变了当前的指针方向（`curr.next = prev`），你和后半截链表的物理连接就当场断开了。**

`temp` 存在的唯一意义，就是在大刀阔斧“断后路”之前，先把下一步要走的生路给提前死死攥在手里！当最后一轮 `temp` 变成 `None` 时，也就宣告了整条链表的大反转圆满收工。这个细节一通，反转链表的内功你就彻底大成了！🚀🔥
