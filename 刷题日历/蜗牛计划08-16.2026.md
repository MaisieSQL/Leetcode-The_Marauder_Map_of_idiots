# 225. Implement Stack using Queues (用队列实现栈)

## 📌 1. 核心设计思想
栈（Stack）的特点是 **LIFO (Last In, First Out)** —— 后进先出；
队列（Queue）的特点是 **FIFO (First In, Last Out)** —— 先进先出。

要用队列来实现栈，核心难点在于：**栈顶元素应该是最后压入的元素，但在队列中它在队尾，无法直接访问或弹出。**
我们可以通过**“每次压入新元素时，把前面的所有旧元素依次出队并重新入队到队列尾部”**这种巧妙的操作，让刚刚压入的新元素永远保持在队列的最前端（队头），从而实现 $O(1)$ 时间复杂度的 `pop` 和 `top` 操作。

## 💻 2. Python3 代码实现 (单队列高效解法)

```python
from collections import deque

class MyStack:

    def __init__(self):
        # 使用双端队列作为底层的队列
        self.queue = deque()

    def push(self, x: int) -> None:
        # 1. 先记录当前队列里原本的元素个数
        n = len(self.queue)
        # 2. 将新元素入队
        self.queue.append(x)
        # 3. 把前面的 n 个旧元素依次弹出并重新加到队列尾部
        for _ in range(n):
            self.queue.append(self.queue.popleft())

    def pop(self) -> int:
        # 此时队头就是栈顶元素，直接弹出即可
        return self.queue.popleft()

    def top(self) -> int:
        # 返回队头元素
        return self.queue[0]

    def empty(self) -> bool:
        return not self.queue
```

3. 复杂度分析
- 时间复杂度：
  - push 操作：$O(N)$，其中 $N$ 是当前栈中的元素个数。因为每压入一个新元素，都需要把队列里的所有元素重新转圈排队一次。
  - pop、top、empty 操作：$O(1)$，因为目标元素始终稳稳地停在队头。
- 空间复杂度：$O(N)$，需要使用一个队列来存储栈中的所有元素。

# 🚀 LeetCode 230. Kth Smallest Element in a BST (二叉搜索树中第K小的元素)

## 📌 1. 核心解题思路
- **BST 的天然性质**：二叉搜索树的**中序遍历（左 $\rightarrow$ 根 $\rightarrow$ 右）**得到的元素序列一定是**严格单调递增**的。
- **解法核心**：
  - 对 BST 进行中序遍历。
  - 每访问到一个节点，计数器 $k$ 减 1。
  - 当 $k == 0$ 时，当前节点的值即为第 $K$ 小的元素，可直接记录并终止遍历。

## 💻 2. Python3 代码实现 (中序遍历 + 剪枝)

```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right
class Solution:
    def kthSmallest(self, root: TreeNode, k: int) -> int:
        self.res = 0
        
        def inorder(node):
            if not node:
                return
            
            # 1. 遍历左子树
            inorder(node.left)
            
            # 2. 处理当前节点
            nonlocal k
            k -= 1
            if k == 0:
                self.res = node.val
                return
                
            # 3. 遍历右子树（若已找到则剪枝）
            if k > 0:
                inorder(node.right)
                
        inorder(root)
        return self.res
```

3. 复杂度分析
- 时间复杂度：$O(H + K)$，其中 $H$ 是树的高度。最坏情况下需要遍历到第 $K$ 个节点。
- 空间复杂度：$O(H)$，主要消耗在递归调用栈上，最坏情况下（链状树）为 $O(N)$，平均情况下（平衡树）为 $O(\log N)$。

我们用一个具体的例子来进行一次完整的 Dry Run（模拟演练），来看看这段中序遍历代码是如何一步步找到第 $K$ 小的元素的。

🌲 示例准备
假设我们有一棵如下的二叉搜索树（BST）：
```text
        3
       / \
      1   4
       \
        2
```

- 树的中序遍历顺序（左 $\rightarrow$ 根 $\rightarrow$ 右）：1 -> 2 -> 3 -> 4
- 目标：我们要寻找第 $K = 2$ 小的元素（即结果应该是 2）。
- 初始状态：$k = 2$, `self.res = 0`

🔄 逐步执行模拟 (Dry Run)

第一层：调用 `inorder(root=3)`
1. node 是 3，不为空。
2. 执行 `inorder(node.left)`，即去遍历节点 3 的左子树：进入 `inorder(1)`。

第二层：调用 `inorder(node=1)`
1. node 是 1，不为空。
2. 执行 `inorder(node.left)`，即去遍历节点 1 的左子树：
   - `inorder(None)` $\rightarrow$ 为空，直接 `return` 返回。
3. 回到节点 1，开始处理当前节点：
   - 执行 `nonlocal k`，此时外部的 k 是 2。
   - $k -= 1$ $\rightarrow$ k 变成 1。
   - 检查 `if k == 0:` $\rightarrow$ 当前 k 是 1，条件不成立。
4. 检查 `if k > 0:` $\rightarrow$ 当前 k 是 1，条件成立！
5. 执行 `inorder(node.right)`，即去遍历节点 1 的右子树：进入 `inorder(2)`。

第三层：调用 `inorder(node=2)`
1. node 是 2，不为空。
2. 执行 `inorder(node.left)` $\rightarrow$ `inorder(None)`，返回。
3. 回到节点 2，处理当前节点：
   - $k -= 1$ $\rightarrow$ k 变成 0。
   - 检查 `if k == 0:` $\rightarrow$ 成立！
   - 记录结果：`self.res = 2`。
   - 执行 `return` $\rightarrow$ 立刻退出当前层（`inorder(2)` 结束，返回上一层）。

逐层“退栈”与剪枝
1. 回到节点 1：`inorder(2)` 执行完毕并返回，节点 1 的右子树遍历结束，`inorder(1)` 顺利结束，返回上一层。
2. 回到根节点 3：此时控制权回到了根节点 3 的 `inorder(node.left)` 刚结束的那一行。
   - 接着往下执行：$k -= 1$ $\rightarrow$ k 变成 -1。
   - `if k == 0:` 不成立。
   - `if k > 0:`（此时 $k = -1 > 0$ 不成立）$\rightarrow$ 成功拦截，不再遍历根节点 3 的右子树（节点 4 被完美剪枝！）。
3. 整个递归顺利结束。

🎉 最终输出
主函数返回 `self.res`，结果为 2。

通过这个过程可以看到，利用 k 的实时递减和 $k == 0$ 时的提前 `return`，程序在数到第 2 个节点（即值 2）时就立刻停止了后续所有不必要的搜索，高效且优雅！

在这段代码中，“剪枝”（即提前终止、不再遍历无关子树）主要体现在这两行关键代码上：

```python
if k == 0:
    self.res = node.val
    return  # 1. 找到目标后立刻层层返回

if k > 0:
    inorder(node.right)  # 2. 核心剪枝拦截：只有当 k > 0 时才去遍历右子树
```

🔍 **它是如何实现剪枝的？**
1. **计数归零触发退出**：当遍历到第 $K$ 个节点时，`k` 减到 `0`，此时通过 `self.res = node.val` 记录下答案，并通过 `return` 退出当前的 `inorder` 函数。
2. **`if k > 0:` 拦截右子树**：当程序从深层递归返回到父节点时，`k` 已经是 `0` 了。此时代码中的 `if k > 0:` 条件不成立。
   - 这意味着：父节点的右子树（以及右子树底下的所有子孙节点）会被直接跳过，再也不会被访问！

💡 **如果没有这个剪枝会怎样？**
- **如果没有 `if k > 0:` 的拦截**：即使已经找到了第 $K$ 小的元素，代码依然会硬着头皮把整棵树剩下的所有右子树节点全部遍历完，时间复杂度会退化为固定的 $O(N)$。
- **有了这个剪枝**：一旦在第 $K$ 个节点命中，后续的所有多余搜索全部被“剪掉”，时间复杂度直接优化为 $O(H + K)$（在平衡树中表现为 $O(\log N + K)$），找到目标后就能以最快速度收工！

## 🔨 暴力解法核心思路
1. **中序遍历收集所有元素**：利用 BST 的中序遍历（左 $\rightarrow$ 根 $\rightarrow$ 右）会得到一个**严格递增的有序数组**这一天然性质。
2. **直接按下标取值**：我们把整棵树中序遍历的结果全部存到一个列表里，因为数组是有序的，第 $K$ 小的元素对应的就是列表索引为 `k - 1` 的那个元素。

## 💻 Python3 暴力解法代码实现

```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right
class Solution:
    def kthSmallest(self, root: TreeNode, k: int) -> int:
        res = []
        
        def inorder(node):
            if not node:
                return
            # 1. 递归遍历左子树
            inorder(node.left)
            # 2. 收集当前节点值
            res.append(node.val)
            # 3. 递归遍历右子树
            inorder(node.right)
            
        # 把整棵树的中序序列全部完整跑一遍
        inorder(root)
        
        # 返回第 k 小的元素（对应索引 k - 1）
        return res[k - 1]
```

暴力解法的复杂度分析
- 时间复杂度：$O(N)$，其中 $N$ 是树中的节点总数。因为不管 $K$ 是多少（哪怕 $K=1$），暴力法都会把整棵树的所有节点完整遍历一遍并存入列表。
- 空间复杂度：$O(N)$，需要开辟一个额外的列表来存储整棵树的所有节点值。

# 1448. Count Good Nodes In Binary Tree (统计二叉树中好节点的数目)

## 📌 1. 题目大意
给你一棵根为 `root` 的二叉树。如果一棵二叉树中，从根节点到某一个节点 $X$ 的路径上，**没有任何节点的值大于 $X$ 的值**，那么这个节点 $X$ 就被称为**“好节点” (Good Node)**。请你统计并返回这棵二叉树中好节点的总数。

## 🪓 2. 核心物理直觉 (Preorder Traversal + 动态最大值维护)
* **前序遍历 (Preorder)**：由于我们需要从根节点一路向下走到叶子节点来判定“祖先最大值”，这天然契合**自顶向下（Top-Down）**的前序遍历。
* **状态携带**：在递归遍历的过程中，我们需要顺便把“从根节点到当前父节点为止的路径上的最大值 (`max_val`)”作为参数向下传递。
* **判定规则**：
  * 如果当前节点的值 `node.val >= max_val`，说明它没有被任何祖先节点压制，它是一个**好节点**，计数器 `+1`。
  * 同时，更新向下传递的最大值：`max_val = max(max_val, node.val)`。

## 💻 3. Python3 代码实现

```python
class Solution:
    def goodNodes(self, root: TreeNode) -> int:
        def dfs(node: TreeNode, max_val: int) -> int:
            if not node:
                return 0
            
            count = 0
            # 1. 检查当前节点是否是好节点
            if node.val >= max_val:
                count = 1
                max_val = node.val  # 更新当前路径的历代最大值
                
            # 2. 递归遍历左右子树，并累加好节点数量
            count += dfs(node.left, max_val)
            count += dfs(node.right, max_val)
            
            return count
            
        # 从根节点开始，初始最大值设为负无穷

```

4. 复杂度分析
- 时间复杂度：$O(N)$，其中 $N$ 是二叉树的节点总数。每个节点恰好被访问一次。
- 空间复杂度：$O(H)$，其中 $H$ 是树的高度。主要消耗在递归调用栈上，最坏情况下（链状树）为 $O(N)$，平均情况下（平衡树）为 $O(\log N)$。

简短的回答是：直接用标准的“中序”或“后序”来做这道题是行不通的（或者说非常别扭且失去意义），因为它们无法满足这道题的核心约束。
但是，如果我们稍微修改一下策略，理论上我们可以强行改造它们，但通常我们绝对不推荐这样做。原因如下：
1. 为什么“标准中序（左-根-右）”不行？
- 冲突点：中序遍历的顺序是“先访问左子树 $\rightarrow$ 再访问根节点 $\rightarrow$ 最后访问右子树”。
- 致命问题：当我们进入左子树时，我们还没来得及访问根节点，也根本不知道根节点的值是多少，更无法在上层维护从根到当前节点的“路径最大值 (max_val)”。因此，左子树在往下走时会彻底失去祖先的约束条件。
2. 为什么“标准后序（左-右-根）”不行？
- 冲突点：后序遍历的顺序是“先访问左子树 $\rightarrow$ 再访问右子树 $\rightarrow$ 最后访问根节点”。
- 致命问题：后序遍历是典型的“自底向上（Bottom-Up）”汇总信息的模式（比如求树的高度）。而这道题恰恰相反，需要“自顶向下（Top-Down）”把祖先的最大值压给子孙。如果在后序遍历中，等左右子树都算完了才回到根节点，根节点早就错过向子树传递最大值的时机了。
