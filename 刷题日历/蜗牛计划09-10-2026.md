## 股票买卖问题对比：基础版 vs. 冷冻期版

这两道题虽然都属于动态规划中的股票系列，但由于规则的微调，状态的定义和转移方程发生了变化。

### 1. 题目信息对比表

| 题号 | 题目 (Problem) | 类型 (Topics) | 难度 (Difficulty) | LeetCode Link |
| :--- | :--- | :--- | :--- | :--- |
| 121 | Best Time to Buy and Sell Stock (基础版) | 数组、动态规划 | Easy | [Link](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/) |
| 309 | Best Time to Buy And Sell Stock With Cooldown (冷冻期版) | 数组、动态规划 | Medium | [Link](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-cooldown/) |

### 2. 核心规则差异

* **LeetCode 121 (只能买卖一次)**：
  * **规则**：你只能选择**买入一次**并在**未来某一个不同日子卖出**。
  * **直观解法**：可以用贪心，只需一路记录历史最低价格，然后用当天的价格减去历史最低价，更新最大利润即可。

* **LeetCode 309 (含冷冻期 Cooldown)**：
  * **规则**：你可以无限次买卖，但必须遵守以下限制：
    * 卖出股票后，你**无法在第二天买入股票**（即冷冻期为 1 天）。
    * 你不能同时参与多笔交易（你必须在再次购买前出售掉之前的股票）。
  * **直观解法**：由于有状态的延续和冷却限制，单纯的贪心无法解决，必须引入状态机模型（有限状态自动机）来进行动态规划。

### 3. 动态规划思路对比

#### LeetCode 121 (一次交易)
* **状态定义**：其实只需要记录当前的最低买入价 `min_price` 和到当前天为止的最大利润 `max_profit`。
* **状态转移**：
  * `min_price = min(min_price, prices[i])`
  * `max_profit = max(max_profit, prices[i] - min_price)`
* **复杂度**：时间复杂度 $O(N)$，空间复杂度 $O(1)$。

#### LeetCode 309 (含冷冻期无限次交易)
由于每一天结束时，我们可能处于不同的状态，因此需要精细化定义每天的几种可能状态：
1. **持有股票状态 (`hold`)**：当天结束时手里有股票。
2. **不持有股票且处于冷冻期状态 (`cooldown` / `sold`)**：当天刚卖出股票，处于冷冻期。
3. **不持有股票且不处于冷冻期状态 (`rest` / `free`)**：手里没股票，且不处于冷冻期，可以随时买入。

* **状态转移方程**（以第 $i$ 天为例）：
  * `hold[i] = max(hold[i-1], rest[i-1] - prices[i])` （延续昨天的持有，或者昨天是自由状态今天买入）
  * `sold[i] = hold[i-1] + prices[i]` （只能由昨天持有、今天卖出来达到）
  * `rest[i] = max(rest[i-1], sold[i-1])` （昨天就是自由状态，或者昨天刚解冻/卖出今天变成自由状态）

* **复杂度**：时间复杂度 $O(N)$，空间复杂度可以通过滚动变量优化到 $O(1)$。

## 309. 买卖股票的最佳时机含冷冻期 (Best Time to Buy and Sell Stock with Cooldown)

* **难度**：Medium
* **涉及话题**：数组、动态规划

### 题目描述

给定一个整数数组 `prices`，其中第 `prices[i]` 表示第 `i` 天股票的价格。

设计一个算法计算出最大利润。在满足以下约束条件下，你可以尽可能地完成更多的交易（多次买卖一支股票）：

* 卖出股票后，你无法在第二天买入股票（即冷冻期为 1 天）。
* 你不能同时参与多笔交易（你必须在再次购买前出售掉之前的股票）。

### 示例

* **示例 1**：
  * **输入**：`prices = [1, 2, 3, 0, 2]`
  * **输出**：`3`
  * **解释**：对应的交易状态为：[买入, 卖出, 冷冻期, 买入, 卖出]，总利润为 `(2 - 1) + (2 - 0) = 3`。

* **示例 2**：
  * **输入**：`prices = [1]`
  * **输出**：`0`

### 题目解析

这道题的核心难点在于**“冷冻期（Cooldown）”**的限制：卖出股票后，你无法在第二天买入股票（即冷静一天）。这就打破了普通的无限次买卖股票模型，让每一天的状态变得复杂起来。

为了理清每一天到底能做什么、不能做什么，我们需要使用**有限状态自动机（状态机 DP）**的思想。

### 状态定义

在每一天结束时，我们手里的状态可以被细分为以下 **3 种**：

1. **持有股票状态 (`hold`)**：
   * 当前手里**有**股票。
   * 可能是之前买的今天一直没动，也可能是今天刚买入的。
2. **不持有股票，且处于冷冻期 (`sold`)**：
   * 当前手里**没有**股票，且是在**今天刚卖出**的。
   * 因为刚卖出，所以明天强制进入冷冻期，不能买入。
3. **不持有股票，且不处于冷冻期（即自由/休息状态，`rest`）**：
   * 当前手里**没有**股票，且**不在冷冻期内**（冷冻期已经过了，或者压根没刚卖过股票）。
   * 这种状态下，明天随时可以买入股票。

### 状态转移方程

设第 $i$ 天结束时的三种状态最大利润分别为 `hold[i]`、`sold[i]`、`rest[i]`：

1. **`hold[i]` 的来源**：
   * 要么昨天就已经持有股票了，今天什么都不做：`hold[i-1]`
   * 要么昨天是自由状态（`rest[i-1]`），今天花钱买入了股票：`rest[i-1] - prices[i]`
   * **公式**：`hold[i] = max(hold[i-1], rest[i-1] - prices[i])`

2. **`sold[i]` 的来源**：
   * 只能由昨天持有股票（`hold[i-1]`），今天选择将其卖出得到：`hold[i-1] + prices[i]`
   * **公式**：`sold[i] = hold[i-1] + prices[i]`

3. **`rest[i]` 的来源**：
   * 要么昨天本来就是自由状态，今天继续休息：`rest[i-1]`
   * 要么昨天刚卖出股票（`sold[i-1]`），今天自然过渡到解除冷冻的自由状态：`sold[i-1]`
   * **公式**：`rest[i] = max(rest[i-1], sold[i-1])`

### 空间优化

因为每一天的状态只依赖于前一天，我们可以把数组省略，只用三个变量来滚动更新：
* `hold`：对应当前的 `hold`
* `sold`：对应当前的 `sold`
* `rest`：对应当前的 `rest`

### 完整代码 (Python)

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        if not prices:
            return 0
        
        # 初始化第 0 天结束时的状态
        hold = -prices[0]  # 第 0 天买入股票
        sold = 0           # 第 0 天不可能刚卖出
        rest = 0           # 第 0 天没买也没卖
        
        for i in range(1, len(prices)):
            prev_hold = hold
            prev_sold = sold
            prev_rest = rest
            
            # 状态转移
            hold = max(prev_hold, prev_rest - prices[i])
            sold = prev_hold + prices[i]
            rest = max(prev_rest, prev_sold)
            
        # 最后的最大利润一定是不持有股票的情况（刚卖出或者早就休息了）
        return max(sold, rest)
```

### 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是数组 `prices` 的长度，只需要遍历一次数组。
* **空间复杂度**：$O(1)$，只用了常数个变量来存储前一天的状态。

## 309. 买卖股票的最佳时机含冷冻期：其他常见解法

除了前面介绍的“三状态机 DP（空间优化到 $O(1)$）”之外，这道题还有其他几种常见的推导和实现方式，主要可以从**状态维度的精简**以及**记忆化搜索（DFS + Memo）**两个角度来看。

### 解法一：精简为 2 个状态的动态规划

细心的话你会发现，在严格的有限状态机中，其实可以将状态压缩得更少。如果不显式区分“刚卖出的冷冻期状态”和“完全空仓的休息状态”，只保留两个核心动作相关的状态：

1. **`dp[i][0]`（当前持有股票）**：
   * 可以由昨天持有，或者昨天没股票、今天刚买入推导出来。
   * 但这里要注意冷冻期的限制：如果今天想买入，**前一天必须不能是刚卖出状态**。
2. **`dp[i][1]`（当前不持有股票）**：
   * 可以由昨天不持有，或者昨天持有、今天刚卖出推导出来。

为了实现这一点，状态定义通常会细化为：
* `buy[i]`：第 $i$ 天结束时，**最后一次操作是买入**（或手里有股票）的最大收益。
* `sell[i]`：第 $i$ 天结束时，**最后一次操作是卖出**（或手里没股票且处于冷冻期/冷却完毕）的最大收益。

#### 状态转移方程：
* `buy[i] = max(buy[i-1], sell[i-2] - prices[i])` （注意这里由于有 1 天冷冻期，买入时要看前天卖出的状态 `sell[i-2]`）
* `sell[i] = max(sell[i-1], buy[i-1] + prices[i])`

这种写法的核心优势在于直接把“冷冻期隔天买入”的物理限制体现在了 `sell[i-2]` 的索引跳跃上。

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        if not prices or len(prices) < 2:
            return 0
        
        n = len(prices)
        # buy[i] 表示第 i 天结束时，最后一次操作是买入（或手里持有股票）的最大收益
        # sell[i] 表示第 i 天结束时，最后一次操作是卖出（或手里无股票且不在冷冻期）的最大收益
        buy = [0] * n
        sell = [0] * n
        
        # 初始化第 0 天
        buy[0] = -prices[0]
        sell[0] = 0
        
        # 初始化第 1 天
        buy[1] = max(-prices[0], -prices[1])
        sell[1] = max(0, prices[0] - prices[1] + prices[1]) # 即 max(0, prices[1] - prices[0])
        
        for i in range(2, n):
            # 第 i 天买入：要么昨天就已经买过了（buy[i-1]），要么前天卖出了解冻、今天刚买入（sell[i-2] - prices[i]）
            buy[i] = max(buy[i-1], sell[i-2] - prices[i])
            # 第 i 天卖出：要么昨天就已经卖过了（sell[i-1]），要么昨天持有、今天刚卖出（buy[i-1] + prices[i]）
            sell[i] = max(sell[i-1], buy[i-1] + prices[i])
            
        return sell[-1]
```

### 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是数组 `prices` 的长度，只需要对数组进行一次遍历。
* **空间复杂度**：$O(N)$，使用了大小为 $N$ 的 `buy` 和 `sell` 数组来存储每一天的状态。（由于每一天的状态只依赖于前一天和前两天，该空间还可以进一步优化到 $O(1)$ 常数级别）。


### 解法二：记忆化搜索（DFS + 递归）

如果你觉得从前往后的递推（Bottom-Up）不好想，可以从**自顶向下（Top-Down）**的递归视角来思考。

#### 核心思路：
设一个递归函数 `dfs(index, status)`：
* `index`：当前来到第几天。
* `status`：当前手里的状态（例如 `0` 表示可以买入，`1` 表示可以卖出）。

对于每一天，你有两种大选择：
1. **如果当前可以买入（`status == 0`）**：
   * 选择 1：今天买入股票，花掉钱，状态变为“持有”，天数 `+1`。
   * 选择 2：今天什么都不做（Rest），状态不变，天数 `+1`。
2. **如果当前持有股票、准备卖出（`status == 1`）**：
   * 选择 1：今天把股票卖了，赚钱，但因为有**冷冻期**，下一次能买入的天数必须是 `index + 2`。
   * 选择 2：今天什么都不做，天数 `+1`。

#### 伪代码骨架：
```python
def solve(prices):
    memo = {}
    
    def dfs(i, holding):
        if i >= len(prices):
            return 0
        if (i, holding) in memo:
            return memo[(i, holding)]
        
        # 选项 1：什么都不做
        do_nothing = dfs(i + 1, holding)
        
        if holding:
            # 当前持有，选择今天卖出（卖出后进入冷冻期，下一次操作跳到 i + 2）
            do_action = prices[i] + dfs(i + 2, False)
        else:
            # 当前没持有，选择今天买入
            do_action = -prices[i] + dfs(i + 1, True)
            
        memo[(i, holding)] = max(do_nothing, do_action)
        return memo[(i, holding)]
        
    return dfs(0, False)
```

### 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是数组 `prices` 的长度。因为状态由 `i`（有 $N$ 种可能）和 `holding`（有 2 种可能）共同决定，总状态数最多为 $2N$。每个状态只会被计算一次，其余情况直接从 `memo` 中命中返回。
* **空间复杂度**：$O(N)$，主要消耗在记忆化哈希表 `memo` 的存储空间（最多存储 $2N$ 个键值对）以及递归调用栈的深度（最大深度为 $N$）。

* **优缺点**：
  * **优点**：递归思维非常自然，符合人类“做决策”的直觉，不需要强行去推导复杂的二维状态转移方程。
  * **缺点**：递归有函数调用开销，且需要哈希表/数组做记忆化防止超时，实际运行效率通常比纯迭代的动态规划略慢一点点，但对于 $N \le 5000$ 的数据规模完全可以通过。

## 746. 使用最小花费爬楼梯 (Min Cost Climbing Stairs)

### 题目解析

这是一道非常经典的**线性动态规划**入门题。

* **题意简述**：给你一个整数数组 `cost`，其中 `cost[i]` 是从楼梯第 $i$ 个台阶向上爬需要支付的费用。一旦你支付了费用，你就可以选择向上爬一个或者两个台阶。你可以选择从下标为 `0` 或下标为 `1` 的台阶开始爬楼梯。请你计算到达楼梯顶部的最低花费。
* **核心思维**：
  * “到达楼梯顶部”意味着你需要跨过最后一个台阶（即到达索引为 `n` 的位置，其中 `n` 是数组长度）。
  * 每一个台阶的最低花费，只取决于**到达它前一步或前两步**的花费。

### 状态定义与转移方程

设 `dp[i]` 表示到达第 $i$ 个台阶所需要的最小花费。

* **状态转移方程**：
  来到第 $i$ 个台阶，你只能从第 $i-1$ 个台阶跨 1 步上来，或者从第 $i-2$ 个台阶跨 2 步上来。因此：
  $$\text{dp}[i] = \min(\text{dp}[i-1] + \text{cost}[i-1], \text{dp}[i-2] + \text{cost}[i-2])$$

* **初始状态**：
  * 题目说明你可以从下标 `0` 或 `1` 开始，且不需要支付起点本身的费用，所以：
  * $\text{dp}[0] = 0$
  * $\text{dp}[1] = 0$

### 完整代码 (Python)

```python
class Solution:
    def minCostClimbingStairs(self, cost: list[int]) -> int:
        n = len(cost)
        # dp[i] 表示到达第 i 个台阶的最小花费
        # 长度为 n + 1，因为楼顶是索引 n
        dp = [0] * (n + 1)
        
        for i in range(2, n + 1):
            dp[i] = min(dp[i - 1] + cost[i - 1], dp[i - 2] + cost[i - 2])
            
        return dp[n]
```

### 复杂度分析

* **时间复杂度**：$O(N)$，其中 $N$ 是数组 `cost` 的长度，只需要进行一次线性遍历。
* **空间复杂度**：$O(N)$（如果用滚动变量优化，可以把空间压缩到 $O(1)$）。

## 1049. 最后一块石头的重量 II (Last Stone Weight II)

### 题目解析

这道题表面上看是模拟砸石头（每次选两块石头相撞，计算差值），但如果直接用模拟或者回溯，面对数据规模会直接超时。我们需要进行**数学转化**。

* **核心转化（降维打击）**：
  * 假设所有石头的总重量是 `sum`。
  * 每次砸石头，其实就是给石头加上正负号。例如石头 `[a, b, c]`，砸完最后可能变成 `(a + b) - c` 或类似的形式。
  * 这本质上是在问：**能否把这堆石头分成两堆，让它们的重量和尽可能接近（即差值最小）？**
  * 设其中一堆的总重量为 $target$，另一堆的总重量就是 $\text{sum} - target$。我们要让两堆的差值 $\vert{}\text{sum} - 2 \times target\vert{}$ 最小。
  * 因为 $target \le \frac{\text{sum}}{2}$，这就完美转化成了经典的 **0-1 背包问题**：**在不超过 $\frac{\text{sum}}{2}$ 的容量下，背包最多能装下多少重量的石头。**

### 状态定义与转移方程

设 `dp[j]` 表示容量（或目标重量）为 `j` 的背包，最多能装下总重量为多少的石头。

* **状态转移方程**：
  对于每一块石头 `weight`：
  $$\text{dp}[j] = \max(\text{dp}[j], \text{dp}[j - \text{weight}] + \text{weight})$$

### 完整代码 (Python)

```python
class Solution:
    def lastStoneWeightII(self, stones: list[int]) -> int:
        total_sum = sum(stones)
        target = total_sum // 2
        
        # dp[j] 表示容量为 j 的背包能装的最大石头重量
        dp = [0] * (target + 1)
        
        for stone in stones:
            # 0-1 背包倒序遍历
            for j in range(target, stone - 1, -1):
                dp[j] = max(dp[j], dp[j - stone] + stone)
                
        # 设分出的两堆分别为 dp[target] 和 total_sum - dp[target]
        # 两者相减即为最后剩下的最小重量
        return total_sum - 2 * dp[target]
```

### 复杂度分析

* **时间复杂度**：$O(N \times \text{sum})$，其中 $N$ 是石头数量，$\text{sum}$ 是所有石头的总重量。
* **空间复杂度**：$O(\text{sum})$，使用了大小为 $\frac{\text{sum}}{2}$ 的一维滚动数组空间优化。

---
