## **LeetCode 21. 合并两个有序链表** (Merge Two Sorted Lists)

* **难度**：简单
* **题目描述**：
  将两个升序链表合并为一个新的 **升序** 链表并返回。新链表是通过拼接给定的两个链表的所有节点组成的。

* **示例 1**：
  * **输入**：`l1 = [1,2,4], l2 = [1,3,4]`
  * **输出**：`[1,1,2,3,4,4]`

* **示例 2**：
  * **输入**：`l1 = [], l2 = []`
  * **输出**：`[]`

* **示例 3**：
  * **输入**：`l1 = [], l2 = [0]`
  * **输出**：`[0]`

* **提示**：
  * 两个链表的节点数目范围是 `[0, 50]`
  * `-100 <= Node.val <= 100`
  * `l1` 和 `l2` 均按 **非递减顺序** 排列

## 解题思路与解析

1. **核心思想**：迭代法（双指针法）。通常使用迭代法更为直观且节省栈空间。
2. **具体步骤**：
   * 创建一个虚拟头节点（Dummy Head）`dummy`，用来简化边界条件的处理（避免处理头节点为空的繁琐逻辑），并用一个指针 `current` 指向当前合并后链表的末尾。
   * 使用两个指针 `p1` 和 `p2` 分别遍历 `l1` 和 `l2`。
   * 比较 `p1.val` 和 `p2.val` 的大小：
     * 如果 `p1.val <= p2.val`，将 `p1` 接到 `current` 后面，然后 `p1` 向后移动一位。
     * 否则，将 `p2` 接到 `current` 后面，然后 `p2` 向后移动一位。
     * 每次操作后，`current` 指针也向后移动一位。
   * 当其中一个链表遍历完后，只需将另一个未遍历完的链表直接接在 `current` 的后面即可。
   * 返回 `dummy.next` 作为合并后的链表头节点。

## 答案代码 (Python)

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class Solution:
    def mergeTwoLists(self, list1: ListNode, list2: ListNode) -> ListNode:
        # 创建虚拟头节点
        dummy = ListNode(-1)
        current = dummy
        
        p1 = list1
        p2 = list2
        
        # 遍历两个链表，直到其中一个为空
        while p1 and p2:
            if p1.val <= p2.val:
                current.next = p1
                p1 = p1.next
            else:
                current.next = p2
                p2 = p2.next
            current = current.next
            
        # 拼接剩余未遍历完的链表
        if p1:
            current.next = p1
        if p2:
            current.next = p2
            
        return dummy.next
```

复杂度分析：
- **时间复杂度**：O(n+m)，其中 n 和 m 分别为两个链表的长度。因为每次循环都会将 `p1` 或 `p2` 向后移动一位，最多循环 $n+m$ 次。
- **空间复杂度**：O(1)，只需要常数级别的额外指针空间。

在这道题中使用**虚拟头节点（Dummy Head）**，主要是为了**简化链表操作的边界条件**，避免处理“空链表”时的繁琐逻辑。

具体原因可以从以下几个方面来理解：

1. **避免对“新链表头部”进行单独的特殊判断**
   * **如果没有 Dummy**：
     当我们开始合并时，新链表的头节点（`head`）还不确定是来自 `l1` 还是 `l2`。我们必须写一段额外的代码来初始化第一个节点：
     ```python
     if l1.val <= l2.val:
         head = l1
         l1 = l1.next
     else:
         head = l2
         l2 = l2.next
     current = head  # 之后才能开始用 current 往下接
     ```
     而且还要时刻担心 `l1` 或 `l2` 一开始就是空链表（`None`）的情况，这会让代码充斥着各种 `if-else`。
   * **如果使用了 Dummy**：
     我们可以先创建一个值为 `-1`（或者任意值）的临时节点 `dummy`，让 `current` 指向它。
     ```python
     dummy = ListNode(-1)
     current = dummy
     ```
     此时，无论后面的节点怎么接，`current.next = ...` 永远都有地方可挂。最后只需要返回 `dummy.next` 即可，**完全不需要关心最终的头节点究竟是 `l1` 还是 `l2`**。

2. **统一操作逻辑，让代码更整洁**
   有了 `dummy` 之后，整个 `while` 循环里的逻辑变得完全一致：
   * 比较大小
   * `current.next` 指向较小的那个节点
   * `current` 向后移动
   
   如果没有 `dummy`，在处理第一个节点和后续节点时，逻辑会分裂成两套代码。

3. **安全处理空链表的情况**
   如果输入的 `l1` 或 `l2` 本身就是空链表 `[]`：
   * 如果没有 `dummy`，初始化 `head` 时就会直接报错（因为尝试访问空指针的 `.val`）。
   * 如果有了 `dummy`，`while p1 and p2` 循环直接跳过，最后直接执行 `current.next = p1 or p2`（或者代码里的 `if p1: current.next = p1` 等），完美兼容空链表的边界情况。

> **总结**：`dummy` 就像是一个“锚点”或“哨兵”，它让我们可以放心地把后续所有的操作都当成常规的链表拼接来处理，极大减少了边界判断的负担。

我们用一个生活中的小比喻来理解：**穿串儿**。

假设你要把两串不同的烤肉（`l1` 和 `l2`）按顺序串成一根新肉串。

### 如果没有 Dummy（没有准备一个“起手竹签”）
* 一开始，你手里**只有两堆散着的肉**（`l1` 和 `l2`），你连第一块肉都不知道该挂在哪里。
* 你必须先挑出最小的那块肉，拿在手里当成**“第一块肉（head）”**。
* 然后你才能拿出一根签子（`current`）插在上面，开始往下接第二块、第三块……
* **问题出在**：如果一开始 `l1` 和 `l2` 都是空盘子（空链表），你连第一块肉都挑不出来，手忙脚乱不知道该把签子插在哪，程序就会直接报错崩溃。

### 如果有了 Dummy（提前准备了一个“空气头节点”）
* 在开始串肉之前，你先拿了一个**空的、不属于肉串的塑料托盘**（这就是 `dummy`），让你的签子（`current`）先放在这个托盘上。
* 此时，`current` 是有地方依靠的（它靠在托盘上）。
* 接下来，不管 `l1` 的肉小还是 `l2` 的肉小，你只需要执行：`current.next = 挑出来的那块肉`。
* **为什么说“有地方挂”**：因为 `current` 永远指向“当前最后一个放好的东西”。当你想把新肉接上去时，直接写 `current.next = 新肉` 即可。如果没有 `dummy`，在放“第一块肉”的时候，`current` 压根还没被初始化，你连 `current.next` 这行代码都写不出来（因为没有 `current` 这个对象，或者 `current` 指向 `None`，对 `None` 点 `.next` 就会报错）。


### 用代码直观对比：

**【没有 dummy 的情况】**（必须先特殊处理第一块）：
```python
# 还要考虑 l1 或 l2 为空的情况，代码很臃肿
if not l1: return l2
if not l2: return l1

if l1.val <= l2.val:
    head = l1
    l1 = l1.next
else:
    head = l2
    l2 = l2.next

current = head # 此时才有 current，之前都没有！
while l1 and l2:
    # ... 正常接下去
```

**【有了 dummy 的情况】**（万物皆可从 dummy 开始）：

```python

dummy = ListNode(-1)  # 托盘
current = dummy       # 签子先放在托盘上

while l1 and l2:
    # 闭着眼睛直接挂，因为 current 一定不是 None，它前面有 dummy 兜底！
    if l1.val <= l2.val:
        current.next = l1
        l1 = l1.next
    else:
        current.next = l2
        l2 = l2.next
    current = current.next

```

dummy 的核心作用，就是充当一个永远存在的临时基座，让 current 在第一步时就有对象可以操作，不用去管真正的头节点到底花落谁家。


# LeetCode 21（合并两个有序链表）与 LeetCode 88（合并两个有序数组）的异同对比

老铁！刚刚我们盘完了这两道题。它们堪称算法面试里的**“绝代双骄”**：表面上看都在做同一件事（把两个有序序列合二为一），但由于底层**数据结构（链表 vs 数组）**完全不同，导致它们的解题思路有着**本质的对立**！

整套高频考点对比已经为你精心整理成纯净的 Markdown 格式，可直接一键复制到你的笔记中：👇

## 🥊 一、 核心维度终极对决表

| 维度对比 | LeetCode 21. 合并两个有序链表 | LeetCode 88. 合并两个有序数组 |
| :--- | :--- | :--- |
| **数据载体** | **链表 (Linked List)** | **数组 (Array)** |
| **物理内存特点** | 节点散落各处，靠指针（`next`）手拉手串联。 | 内存空间必须**连续紧挨着**。 |
| **空间痛点** | 无法随机访问，不能直接通过下标修改。 | `nums1` 前面装数据，后面**预留了巨大的空位（全是 0）**。 |
| **指针移动方向** | **从前往后（正向双指针）** | **从后往前（逆向双指针）** |
| **核心解题大招** | 虚拟头节点（Dummy） + 正向比对串链条 | 逆向双指针 + 利用末尾大空位倒着塞 |

## 🔍 二、 核心异同深度剖析

### 1. 相同点（它们的底层共性）
* **目标一致**：都是将两个已经按升序排好序的序列，合并成一个最终依然保持升序的完整序列。
* **双指针流派**：都离不开**双指针（Two Pointers）**的协同扫描，通过不断比对当前元素的大小来决定谁先“入驻”最终结果。
* **线性极速**：两道题的时间复杂度都达到了完美的 $\mathcal{O}(N + M)$ 线性效率。

### 2. 不同点（由于数据结构不同导致的战术对立）

* **第 21 题（链表）为什么必须“从前往后”？**
  * 链表的节点本来就散落在内存里，新生成的结果链表可以通过虚拟头节点（Dummy）从左到右一步步“凭空串起来”。
  * 因为不需要在原地覆盖旧数据，所以正向遍历、谁小挂谁，顺理成章。

* **第 88 题（数组）为什么必须“从后往前（偷家）”？**
  * 数组的内存是**紧密相连的**。`nums1` 为了实现原地修改（In-place），后面提前留好了 `n` 个大空位（全是 `0`）。
  * 如果你从前往后比大小、把 `nums2` 的大数硬塞到前面，`nums1` 原本右边的有效数字就会直接被**覆盖湮灭**！
  * 所以我们必须把指针按在两边有效数据的末尾，**谁大就往 `nums1` 右侧的大空位倒着填**，这样既不占用额外空间，又绝不会伤害左边还没比拼的数据。

## 💡 三、 核心口诀总结

* **链表合并（第 21 题）**：**“正向双指针 + 哑节点”**。从前往后，谁小串谁。
* **数组合并（第 88 题）**：**“逆向双指针 + 填大空位”**。从后往前，谁大往右边塞。

## 题目细节

**LeetCode 88. 合并两个有序数组** (Merge Sorted Array)

* **难度**：简单
* **题目描述**：
  给你两个按 **非递减顺序** 排列的整数数组 `nums1` 和 `nums2`，另有两个整数 `m` 和 `n`，分别表示 `nums1` 和 `nums2` 中的元素数目。
  
  请你将 `nums2` 合并到 `nums1` 中，使合并后的数组同样按 **非递减顺序** 排列。

  **注意**：最终，合并后数组不应由函数返回，而是存储在数组 `nums1` 中。为了应对这种情况，`nums1` 的初始长度为 `m + n`，其中前 `m` 个元素表示应合并的元素，后 `n` 个元素为 `0` ，应忽略。`nums2` 的长度为 `n` 。

* **示例 1**：
  * **输入**：`nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3`
  * **输出**：`[1,2,5,6,3,5,6]` —— *解释：合并后数组为 [1,2,2,3,5,6]*

* **示例 2**：
  * **输入**：`nums1 = [1], m = 1, nums2 = [], n = 0`
  * **输出**：`[1]` —— *解释：合并后数组为 [1]*

* **示例 3**：
  * **输入**：`nums1 = [0], m = 0, nums2 = [1], n = 1`
  * **输出**：`[1]` —— *解释：合并后数组为 [1]*

* **提示**：
  * `nums1.length == m + n`
  * `nums2.length == n`
  * `0 <= m, n <= 200`
  * `1 <= m + n <= 200`
  * `-10^9 <= nums1[i], nums2[i] <= 10^9`

## 解题思路与解析

1. **核心思想**：**逆向双指针法（从后往前比较）**。
   * 如果从前往后合并，为了把 `nums2` 的元素插入到 `nums1` 中，我们需要把 `nums1` 原有的元素往后挪，这会导致大量元素的移动，时间复杂度会升到 $O(m \times n)$。
   * 观察到 `nums1` 的后半部分是空的（有足够的空间 `n`），我们可以充分利用这一点：**从后往前**比较 `nums1` 和 `nums2` 的有效元素，把较大的那个直接放到 `nums1` 的最后面（即索引 `m + n - 1` 处），然后指针向前移动。这样完全不需要移动额外的数据。

2. **具体步骤**：
   * 定义三个指针：
     * `p1 = m - 1`：指向 `nums1` 有效元素的末尾。
     * `p2 = n - 1`：指向 `nums2` 的末尾。
     * `tail = m + n - 1`：指向 `nums1` 数组的最末尾（存放最终合并后的大元素的位置）。
   * 当 `p1 >= 0` 且 `p2 >= 0` 时，循环比较 `nums1[p1]` 和 `nums2[p2]`：
     * 如果 `nums1[p1] > nums2[p2]`，说明 `nums1[p1]` 更大，把它放到 `nums1[tail]` 处，然后 `p1` 和 `tail` 分别向前移动一位。
     * 否则，把 `nums2[p2]` 放到 `nums1[tail]` 处，然后 `p2` 和 `tail` 分别向前移动一位。
   * **边界情况处理**：
     * 如果循环结束时 `p2 >= 0`（说明 `nums1` 的有效元素已经全部放完了，但 `nums2` 还有剩），直接把 `nums2` 剩下的元素整体复制到 `nums1` 的头部（因为它们本来就是有序的且比 `nums1` 剩下的所有都小）。
     * 如果 `p1 >= 0`，说明 `nums2` 先放完了，`nums1` 剩下的元素本来就在它自己的正确位置上，不需要动。

## 答案代码 (Python)

```python
class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        """
        Do not return anything, modify nums1 in-place instead.
        """
        p1 = m - 1
        p2 = n - 1
        tail = m + n - 1
        
        # 从后往前双指针比较
        while p1 >= 0 and p2 >= 0:
            if nums1[p1] > nums2[p2]:
                nums1[tail] = nums1[p1]
                p1 -= 1
            else:
                nums1[tail] = nums2[p2]
                p2 -= 1
            tail -= 1
            
        # 如果 nums2 还有剩余，说明 nums2 的元素都比 nums1 剩下的最小元素还要小，直接拷过去
        if p2 >= 0:
            nums1[:tail + 1] = nums2[:p2 + 1]
```

复杂度分析：
- **时间复杂度**：O(m + n)，指针 `p1` 和 `p2` 最多各自遍历完自己的数组，总共执行的操作次数与 m + n 成正比。
- **空间复杂度**：O(1)，只需要常数级别的指针变量，直接在原地修改数组。

这道题之所以必须**从后往前**遍历和放置元素，核心原因在于：`nums1` 的后半部分是空的，而从前往后会覆盖掉 `nums1` 原本还没有参与比较的有效元素。

我们可以对比一下“从前往后”和“从后往前”的区别就明白了：

1. **如果尝试“从前往后”合并（会发生什么灾难？）**
   假设我们用常规的正向双指针，从前往后比较：
   * `nums1` 前面有有效的 $m$ 个数字，`nums2` 有 $n$ 个数字。
   * 如果你把 `nums2` 的某个较小元素插入到 `nums1` 的前面（比如插在索引 0 或 1 的位置）：
   * **问题来了**：为了腾出位置插入，`nums1` 原来在这个位置及后面的数字（那些还没来得及比较的有效数字）**必须全部往后平移**！
   * 这种频繁的数组元素搬移非常麻烦，不仅代码写起来复杂（容易索引越界或漏掉元素），而且最坏情况下的时间复杂度会恶化到 $O(m \times n)$。

2. **为什么要“从后往前”？（巧妙利用空白空间）**
   题目非常贴心地给了我们提示：`nums1` 的总长度是 `m + n`，并且**后半部分（从索引 `m` 开始到 `m+n-1`）全都是 `0`（也就是废弃的空白空间）**。
   * **大数先落户**：因为我们要排成**升序**（小的在前，大的在后），两组数据中**最大的那个元素**，理所应当地应该放在整个数组的最末尾（即索引 `m + n - 1` 的位置）。
   * 既然 `nums1` 的末尾正好是空的，我们就让 `p1`（指向 `nums1` 有效数字末尾）和 `p2`（指向 `nums2` 末尾）进行比较：
     * 谁大，就把谁直接填到 `nums1` 最右边的空位（`tail`）上去。
   * **完全不冲突**：因为我们是从最右边（最大的位置）开始往左填的，而 `nums1` 原有的有效数字都挤在左边（前面）。我们在用右边的空位时，**绝对不会覆盖**左边还没参与比较的数字！

### 用生活中的一个小例子理解：
想象你手里有两个按身高排好队的班级（A班和B班），现在要把B班的学生安插到A班排队。
* **A班后面正好有一大片空操场（空白格子）**。
* 如果你从**前面**开始排，把B班的一个高个子塞到A班队伍中间，A班后面的所有人都要往后挪一步，现场会乱成一团。
* 但如果你从**最后面（个子最高的人）**开始比：把A班当前最后一个人和B班当前最后一个人比较，谁更高，就让他直接去占领操场最右边的空位。这样一路从右往左排过去，前面的同学安稳站着根本不需要动，轻轻松松就把队伍合并好了！

## 题目细节

**LeetCode 621. 任务调度器** (Task Scheduler)

* **难度**：中等
* **题目描述**：
  给你一个用字符数组 `tasks` 表示的 CPU 需要执行的任务列表。其中每个字母表示一种不同种类的任务。任务可以以任意顺序执行，并且每个任务都可以执行 1 个单位时间。在任何一个单位时间，CPU 可以完成一个任务，或者处于冷却状态。

  然而，两个 **相同种类** 的任务之间必须有长度为整数 `n` 的冷却时间，因此至少有连续 `n` 个单位时间内 CPU 在执行不同的任务，或者在处于冷却状态。

  返回 CPU 完成所有任务所需要的**最少单位时间**数。

* **示例 1**：
  * **输入**：`tasks = ["A","A","A","B","B","B"], n = 2`
  * **输出**：`8`
  * **解释**：一种可能的执行顺序为：A -> B -> 闲置 -> A -> B -> 闲置 -> A -> B。
    在此情况下，两次相同任务（A 和 A）之间有长度为 2 的冷却时间，因此至少有 2 个单位时间，在这期间 CPU 可以执行其他任务或者处于闲置状态。

* **示例 2**：
  * **输入**：`tasks = ["A","A","A","B","B","B"], n = 0`
  * **输出**：`6`
  * **解释**：因为 `n = 0`，所以没有冷却时间，任务可以连续执行，总共 6 个任务需要 6 个单位时间。

* **示例 3**：
  * **输入**：`tasks = ["A","A","A", "A","A","A", "B","C","D","E","F","G"], n = 2`
  * **输出**：`16`
  * **解释**：一种可能的执行顺序为：A -> B -> C -> A -> D -> E -> A -> F -> G -> A -> 闲置 -> 闲置 -> A -> 闲置 -> 闲置 -> A。

* **提示**：
  * `1 <= task.length <= 10^4`
  * `tasks[i]` 是大写英文字母
  * `n` 的取值范围为 `[0, 100]`

## 解题思路与解析

1. **核心思想**：**贪心算法（桶思想 / 构造法）**。
   * 这道题如果用普通的模拟队列会比较复杂。我们可以换个角度思考：**数量最多的那个任务，决定了整个任务执行的“骨架”或“轮廓”**。
   * 假设所有任务中出现次数最多的是任务 `A`，它出现了 `max_count` 次。
   * 那么 `A` 和 `A` 之间必须间隔 `n` 个冷却时间。我们可以把 `A` 视为把时间分成了 `max_count - 1` 个“区块”（或称为“桶”），每个区块的长度为 `n + 1`（包含 `A` 本身占用的 1 个单位时间，以及后面的 `n` 个冷却/其他任务空位）。

2. **具体推导公式**：

* 前 `max_count - 1` 个区块总共占据的时间为：`(max_count - 1) * (n + 1)`。
   * 最后一个区块里，我们只需要把最后一次出现的 `A` 放进去即可，不需要算后面的冷却时间。同时，如果有其他任务的出现次数**和 `A` 一样多**（假设有 `p` 个任务并列最高），那么最后一个区块里除了 `A` 之外，还要并排塞进这 `p` 个任务。
   * 因此，核心公式计算出来的理论最少时间为：
`ans = (max_count - 1) * (n + 1) + p`
   * **特殊情况（任务种类极多，把冷却空位填满了）**：
     如果总任务数 `len(tasks)` 本身非常多，把这些“区块”之间的空位全部填满了，甚至还有多余的任务可以随时插入且不会冲突，那么总时间其实就是**所有任务的总数**（即 `len(tasks)`）。
   * 综合这两点，最终的答案就是两者的较大值：
     `ans = max(len(tasks), (max_count - 1) * (n + 1) + p)`

## 答案代码 (Python)

```python
from collections import Counter

class Solution:
    def leastInterval(self, tasks: list[str], n: int) -> int:
        # 统计每个任务出现的次数
        count = Counter(tasks)
        
        # 找出出现次数最多的次数
        max_count = max(count.values())
        
        # 计算有多少个任务的出现次数并列最高（即 p）
        p = sum(1 for v in count.values() if v == max_count)
        
        # 套用公式计算并取较大值
        return max(len(tasks), (max_count - 1) * (n + 1) + p)
```

复杂度分析：
- **时间复杂度**：$O(N)$，其中 $N$ 是任务数组的长度。统计词频和遍历哈希表的时间复杂度都与任务总数成正比（或者受限于大写字母总共 26 种，近似 $O(1)$）。
- **空间复杂度**：$O(1)$，哈希表最多存储 26 个大写英文字母的计数，占用常数级别的额外空间。

我们可以用你给出的**示例 3** 来把这个过程完整走一遍。这个例子非常经典，能帮你彻底看清当“任务种类极多、把空位全填满”时是怎么运作的。

---

### 题目已知条件
* **任务列表**：`tasks = ["A", "A", "A", "A", "A", "A", "B", "C", "D", "E", "F", "G"]`（总共有 12 个任务，即 `len(tasks) = 12`）
* **冷却时间**：`n = 2`

---

### 第一步：统计词频，找出“老大”
我们数一下每个字母出现几次：
* `A`：出现了 6 次（稳居榜首，绝对的老大）
* 其他字母（`B`, `C`, `D`, `E`, `F`, `G`）：各自都只出现了 1 次

**关键参数：**
* 最大出现次数 `max_count = 6`（因为 `A` 有 6 个）
* 并列第一的任务数量 `p = 1`（只有 `A` 自己最多）

---

### 第二步：用“老大 A”画出基础时间骨架
因为 `A` 出现了 6 次，前 `max_count - 1`（即 `6 - 1 = 5`）个 `A` 每个人都要带上长度为 `n + 1`（即 `2 + 1 = 3`）的格子：
* 前 5 个 `A`，每个后面跟着 2 个空位：
```text
  A -> [空] -> [空]
  A -> [空] -> [空]
  A -> [空] -> [空]
  A -> [空] -> [空]
  A -> [空] -> [空]
```

最后一个（第 6 个）`A` 单独站好：
```text
A
```

此时，如果只看框架，公式计算出来的骨架大小是：
`(max_count - 1) * (n + 1) + p`
= `(6 - 1) * (2 + 1) + 1`
= `5 * 3 + 1` = **16** 个单位时间。

### 第三步：把其他任务（B, C, D, E, F, G）塞进空位里
现在我们手里有一堆小弟任务：`B, C, D, E, F, G`（总共 6 个）。
我们要把它们依次塞进上面画出来的 `[空]` 里：

* 先塞第一行：把 `B` 和 `C` 塞进去 $\rightarrow$ `A -> B -> C`
* 再塞第二行：把 `D` 和 `E` 塞进去 $\rightarrow$ `A -> D -> E`
* 再塞第三行：把 `F` 和 `G` 塞进去 $\rightarrow$ `A -> F -> G`

哎？小弟们塞到这里，**全都被塞完了！**
剩下的第四行、第五行、第六行怎么办？对应的空位只能继续空着（变成真正的“闲置/发呆”时间）：


```text
A -> B -> C
A -> D -> E
A -> F -> G
A -> [闲置] -> [闲置]
A -> [闲置] -> [闲置]
A
```

数一下总格子数，正好是 **16** 个单位时间。

### 如果换一个更极端的任务组合呢？（体会“第二种情况”）
假设在这道题里，小弟任务非常多（比如除了 6 个 `A` 之外，还有一大堆 `B, C, D...` 总共几十个任务），把上面的 `[空]` 全都塞满甚至还装不下：
* 那么公式算出来的 `16` 就失效了，因为任务实在太多，CPU 根本不需要闲置。
* 最终答案就会直接取**总任务数**（比如 25 个任务，答案就是 25）。

回到我们这个具体的例子：
* 公式计算值 = **16**
* 实际任务总数 `len(tasks)` = **12**
* 取两者较大值：$\max(12, 16) = 16$

所以，最终算出来的最少执行时间就是 **16**！
