# 703. Kth Largest Element in a Stream

- **LeetCode 链接**: [Kth Largest Element in a Stream](https://leetcode.com/problems/kth-largest-element-in-a-stream/)
- **难度**: Easy
- **核心考点**: 数据流处理 / 堆 (Min-Heap) / Top-K 问题

## 1. 题目直觉与场景还原

> **用一句话解释**：设计一个实时排行榜，每次有新成绩加进来，立刻报出“第 $k$ 名”是谁。

### 场景推导（以 $k = 3$ 为例）
时刻追踪全场第 3 名的成绩：

1. **初始池子**：`[4, 5, 8, 2]`
   - 从大到小排序：`8, 5, 4, 2`
   - 前 3 名是 `[8, 5, 4]`，其中第 3 名是 **4**。
2. **调用 `add(3)`**：新加入一个成绩 3
   - 当前所有成绩：`8, 5, 4, 3, 2`
   - 前 3 名依然是 `[8, 5, 4]`，第 3 名依然返回 **4**。
3. **调用 `add(5)`**：新加入一个成绩 5
   - 当前所有成绩：`8, 5, 5, 4, 3, 2`
   - 前 3 名变成了 `[8, 5, 5]`，第 3 名被刷新为 **5**。
4. **调用 `add(10)`**：新加入一个高分 10
   - 前 3 名变成了 `[10, 8, 5]`，第 3 名依然是 **5**。
5. **调用 `add(9)`**：新加入一个高分 9
   - 前 3 名变成了 `[10, 9, 8]`，第 3 名被刷新为 **8**。

## 2. 为什么暴力解法不行？

- **暴力做法**：每次调用 `add()`，把新数字追加到数组末尾，然后重新整体排序 `sort()`，返回倒数第 $k$ 个数。
- **致命缺陷**：数据流会不断调用 `add()`。假设调用 $M$ 次，每次排序耗时 $O(N \log N)$，总时间复杂度高达 $O(M \cdot N \log N)$，直接引发超时（TLE）。

## 3. 核心破局点：维护大小为 $k$ 的“最小堆”（Min-Heap）

求“第 $k$ 大”，直觉上容易联想到大顶堆，但**最优解法是维护一个容量上限为 $k$ 的最小堆**：

- **逻辑本质**：
  - 我们根本不关心比第 $k$ 名更差的人（第 $k+1$ 名及之后可以直接丢弃）。
  - 我们只维护一个“VIP 俱乐部”，这个俱乐部**永远只保留全场最强的 $k$ 个人**。
- **为什么用最小堆？**
  - 在这 $k$ 个顶尖元素的集合中，堆顶存放的是**该集合中的最小值**。
  - 这个处于门槛位置的最小值，在全局视角下正好就是**全场第 $k$ 大的元素**。

## 4. 算法运转流程

1. **初始化 `__init__`**：
   - 将现有数组转为堆结构，多余的元素弹出，直到堆的大小缩小到 $k$。
2. **调用 `add(val)`**：
   - 将新元素入堆：`heapq.heappush(self.min_heap, val)`。
   - 检查堆容量：若堆大小超过 $k$，弹出堆顶最小值：`heapq.heappop(self.min_heap)`。
   - 此时堆顶 `self.min_heap[0]` 即为当前流中的第 $k$ 大元素。

## 5. 代码实现 (Python3)

```python
import heapq
from typing import List

class KthLargest:

    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.min_heap = nums
        heapq.heapify(self.min_heap)
        
        # 保持堆的容量不超过 k
        while len(self.min_heap) > self.k:
            heapq.heappop(self.min_heap)

    def add(self, val: int) -> int:
        heapq.heappush(self.min_heap, val)
        
        # 超过容量则淘汰最小值
        if len(self.min_heap) > self.k:
            heapq.heappop(self.min_heap)
            
        # 堆顶即为第 k 大元素
        return self.min_heap[0]
```

## 6. 复杂度分析

- **时间复杂度**:
  - **初始化 `__init__`**: $O(N \log k)$ 或建堆 $O(N) + (N - k) \log N$。总耗时可控制在 $O(N \log k)$。
  - **单次 `add` 操作**: 堆的大小恒定 $\le k$，入堆与出堆耗时均为 $O(\log k)$，读取堆顶为 $O(1)$。若调用 $M$ 次 `add`，总耗时为 $O(M \log k)$。
- **空间复杂度**: $O(k)$。堆中仅保留 $k$ 个元素，消耗与数据流总长度无关的固定空间。

### 一、 单次 add 操作为什么是 $O(\log k)$？

因为我们限制了堆的最大容量永远只有 $k$：

* **二叉堆的高度**：一个拥有 $k$ 个元素的完全二叉树（堆），其树的高度是 $\log_2 k$。
* **入堆与出堆机制**：
  * `heappush(val)`：把新元素放在树底，沿路径向上调整（Sift Up），最多走整棵树的高度，即 $\log k$ 步。
  * `heappop()`：把堆顶拿走，将末尾元素移到堆顶并向下调整（Sift Down），同样最多走整棵树的高度，即 $\log k$ 步。
* **读取堆顶**：堆顶就是数组第 0 个元素 `heap[0]`，直接寻址，耗时 $O(1)$。
* **总耗时**：单次 `add` 做了常数次堆操作，所以单次代价是 $O(\log k)$；如果调用了 $M$ 次，总代价就是 $O(M \log k)$。

### 二、 初始化 __init__ 的复杂度是怎么来的？

初始数组有 $N$ 个元素，我们有两种构建方式：

**方式 1：逐个插入（动态维护大小为 $k$ 的堆）**
* 从前往后遍历 $N$ 个数，每来一个数就 push 进堆，一旦大小超过 $k$ 就 pop 掉。
* 堆的大小始终被压制在 $k$ 以内，因此每次插入/弹出的成本都不会超过 $O(\log k)$。
* 一共处理 $N$ 个数，总耗时就是稳稳的 $O(N \log k)$。

**方式 2：先原地建堆，再弹出多余元素（即上面写的第二种推导）**
* **原地建堆 `heapq.heapify(nums)`**：
  Python 底层使用的是 Floyd 建堆算法（自底向下调整），直接把包含 $N$ 个元素的列表在原地调整成堆，这一步耗时是 $O(N)$（而不是很多人直觉上的 $N \log N$）。
* **弹出多余元素**：
  堆里原来有 $N$ 个数，我们要保留前 $k$ 个，就需要连续执行 $(N - k)$ 次 `heappop()`。
  每次 pop 时，堆的大小在从 $N$ 逐渐缩减到 $k$。每次弹出需要走树高 $O(\log N)$。
  所以弹出多余元素消耗的时间是 $(N - k) \log N$。
* **两者相加**：
  $$\text{总耗时} = O(N) + (N - k) \log N$$

### 两种写法的本质对比

* 当 $k \ll N$（比如 $N = 10^5, k = 5$）：
  * 方式 1 只需要 $O(N \log 5)$，非常轻量。
  * 方式 2 要 pop 掉几乎全部元素，花了大量的 $(N - k) \log N$ 时间。
* 两种方式在大量工业库或面试手写中都很常见，但结论是一致的：只要在初始化阶段把堆的规模压到 $k$ 以内，后续所有的 `add` 就能稳定享受 $O(\log k)$ 的低开销。

| 操作类型 | 常见方法 / 函数 (以 Python `heapq` 为例) | 时间复杂度 | 空间复杂度 | 核心机制与说明 |
| :--- | :--- | :--- | :--- | :--- |
| **访问堆顶** | `heap[0]`（查看最值） | $O(1)$ | $O(1)$ | 根节点固定在数组第 0 位，直接寻址 |
| **插入元素** | `heapq.heappush(heap, val)` | $O(\log N)$ | $O(1)$ | 放入数组末尾，向上调整（Sift Up），最多走树高 |
| **删除堆顶** | `heapq.heappop(heap)` | $O(\log N)$ | $O(1)$ | 末尾换到根部并弹出，向下调整（Sift Down） |
| **替换堆顶并弹出** | `heapq.heapreplace(heap, val)` | $O(\log N)$ | $O(1)$ | 先弹堆顶再压新值，只需一次向下调整，比先 pop 再 push 更快 |
| **压入并弹出最值** | `heapq.heappushpop(heap, val)` | $O(\log N)$ | $O(1)$ | 若新值比堆顶小/大直接返回新值，否则替换后向下调整 |

| **查找任意元素** | `val in heap` / 遍历查找 | $O(N)$ | $O(1)$ | 堆仅保证父子偏序关系，兄弟节点间无序，只能线性扫描 |
| **删除任意指定节点** | 定位位置后将其与末尾交换并调整 | $O(N)$ | $O(1)$ | 查找耗时 $O(N)$，找到后位置重调（Sift）耗时 $O(\log N)$ |

### 原地建堆时间复杂度为 $O(n)$ 的数学推导

原地建堆（即自底向上使用 `sift-down` 调整，从最后一个非叶子节点开始依次向下下沉）的时间复杂度是 **$O(n)$** 而非直觉上的 $O(n \log n)$。核心原因在于：**绝大多数节点集中在二叉树的最底层，而这些底层节点所需下沉的最大高度极小。**

#### 1. 直觉与实际的差异

* **直觉误区（$O(n \log n)$）**：
  整棵树有 $n$ 个节点，树高约为 $\log n$，若假设每个节点都下沉 $\log n$ 次，则总时间为 $n \times \log n$。
* **实际情况**：
  只有根节点这单独 1 个节点需要下沉 $\log n$ 层；约占总节点数一半的叶子节点完全不需要下沉（下沉高度为 0）。

#### 2. 节点层级分布与下沉步数

假设二叉树为满二叉树，树高为 $h$（根节点高度为 $h$，叶子节点高度为 $0$），总节点数 $n = 2^{h+1} - 1$：

| 节点所在深度（从根往下） | 该层节点数量 | 该层节点最多下沉步数 |
| :--- | :--- | :--- |
| **第 $0$ 层（根节点）** | $2^0 = 1$ | $h$ |
| **第 $1$ 层** | $2^1 = 2$ | $h - 1$ |
| **第 $i$ 层** | $2^i$ | $h - i$ |
| **第 $h-1$ 层** | $2^{h-1}$ | $1$ |
| **第 $h$ 层（叶子节点）** | $2^h \approx \frac{n}{2}$ | $0$ |

#### 3. 数学推导过程

将所有层节点的最多操作步数累加，可得总操作上限 $S$：

$$S = \sum_{i=0}^{h} 2^i \cdot (h - i)$$

设 $k = h - i$（即节点的高度，从下往上数），求和公式可以重写为：

$$S = \sum_{k=0}^{h} 2^{h-k} \cdot k = 2^h \sum_{k=0}^{h} \frac{k}{2^k}$$

令括号内的求和项为 $T$：

$$T = \sum_{k=0}^{h} \frac{k}{2^k} = \frac{1}{2} + \frac{2}{4} + \frac{3}{8} + \frac{4}{16} + \dots + \frac{h}{2^h}$$

使用**错位相减法**计算差比数列的和：

两边同乘 $\frac{1}{2}$：

$$\frac{1}{2} T = \frac{1}{4} + \frac{2}{8} + \frac{3}{16} + \dots + \frac{h-1}{2^h} + \frac{h}{2^{h+1}}$$

原式 $T$ 减去 $\frac{1}{2}T$：

$$T - \frac{1}{2} T = \frac{1}{2} + \left( \frac{1}{4} + \frac{1}{8} + \frac{1}{16} + \dots + \frac{1}{2^h} \right) - \frac{h}{2^{h+1}}$$

中间的括号为一个公比为 $\frac{1}{2}$ 的等比数列：

$$\frac{1}{2} + \left( \frac{1}{4} + \frac{1}{8} + \dots + \frac{1}{2^h} \right) = 1 - \frac{1}{2^h}$$

代回等式：

$$\frac{1}{2} T = 1 - \frac{1}{2^h} - \frac{h}{2^{h+1}} < 1$$

两边同乘 2：

$$T < 2$$

将 $T < 2$ 代回最初的总操作数 $S$：

$$S = 2^h \cdot T < 2 \cdot 2^h$$

由于总节点数 $n = 2^{h+1} - 1 = 2 \cdot 2^h - 1$，即 $2 \cdot 2^h = n + 1$：

$$S < n + 1$$

因此，总比较与交换步数被限制在 $n$ 的常数倍以内，时间复杂度为：

$$\mathcal{O}(n)$$

#### 4. 核心对比

* **自顶向下建堆（逐个 `push` / `sift-up`）**：
  * 节点多的层（底层）往上爬的高度最长（$O(\log n)$）。
  * 加权累加结果为 **$O(n \log n)$**。
* **自底向上建堆（`heapify` / `sift-down`）**：
  * 节点多的层（底层）往下沉的高度最短（$0 \sim 1$ 步）。
  * 加权累加收敛于 **$O(n)$**。

### 单次 `push` 时间复杂度为 $O(\log n)$ 的原理推导

单次向二叉堆中插入元素（`push`）的时间复杂度为 **$O(\log n)$**。核心原因在于：**为了维护完全二叉树的结构，新元素必须先放在树底，随后沿着唯一通往根节点的路径向上爬升，而树的最大高度严格受制于 $\log_2 n$。**

#### 1. `push` 的操作步骤（Sift-Up / 上浮）

以大顶堆为例，当堆中已有 $n$ 个元素时，插入新元素的过程如下：

1. **追加至末尾**：
   新元素直接写入数组的末尾（即**完全二叉树最底层的最左空位**），以保证堆的结构性不被破坏。
2. **向上比较与交换（Sift-Up）**：
   * 将新元素与其父节点（索引为 $\lfloor \frac{i-1}{2} \rfloor$）进行数值比较；
   * 若新元素大于父节点，则二者交换位置；
   * 重复上述过程，直至新元素小于等于其当前父节点，或已经抵达**堆顶（根节点）**。

#### 2. 数学推导：为什么上限是 $\log n$？

一个包含 $n$ 个节点的**完全二叉树（Complete Binary Tree）**，其高度 $h$（从根节点到最底层叶子节点的路径长度）具有严格的数学上下界：

$$2^h \le n < 2^{h+1}$$

对不等式取以 2 为底的对数：

$$h \le \log_2 n < h + 1 \implies h = \lfloor \log_2 n \rfloor$$

在执行 `sift-up` 时：
* **路径唯一性**：二叉树中除根节点外，**任何一个节点有且仅有唯一的一个父节点**。因此，从任何叶子节点爬升到根节点，只有一条长度至多为 $h$ 的单向路径。
* **最坏情况代价**：如果新插入的值是当前堆中的全局最大值，它必须沿着这条唯一的路径一路交换至根节点，总共执行的比较与交换步数为树的高：

$$\text{最坏步数} = h = \lfloor \log_2 n \rfloor$$

由于每一次与父节点的比较和交换均为 $O(1)$ 操作，因此单次插入操作的最坏时间复杂度为：

$$\mathcal{O}(\log n)$$

#### 3. 核心对比：为什么建堆不是 $n \times \log n$？

| 操作类型 | 起点位置 | 移动方向 | 规模分布 | 最终复杂度 |
| :--- | :--- | :--- | :--- | :--- |
| **单次 `push`** | 树的最底叶子节点 | 向上（`sift-up`） | 单个孤立节点，必须跨越整棵树的高度 | **$O(\log n)$** |
| **连续 $n$ 次 `push` 建堆** | 每个新节点都从底部进 | 向上（`sift-up`） | 约 $50\%$ 的节点需要爬 $\approx \log n$ 步 | **$O(n \log n)$** |
| **原地建堆（`heapify`）** | 从非叶子节点自底向上 | 向下（`sift-down`） | 约 $50\%$ 的底层节点走 $0$ 步，仅 $1$ 个根节点走 $\log n$ 步 | **$O(n)$** |

### 题目分析：LeetCode 752. Open the Lock（打开转盘锁）

这是一道标准的**无权图最短路径问题**，最优解法是 **广度优先搜索（BFS）**，进阶优化为 **双向 BFS（Bidirectional BFS）**。

#### 1. 核心模型抽象

* **状态表示**：每个状态是一个 4 位数字字符串（如 `"0000"`），总共有 $10^4 = 10,000$ 种可能状态。
* **状态转移（边）**：每个拨轮可以向上转（+1）或向下转（-1），4 个拨轮共有 $4 \times 2 = 8$ 个相邻状态。
* **障碍物**：`deadends` 集合中的状态是死锁点，不能访问。
* **目标**：求从起点 `"0000"` 到 `target` 的最少旋转次数（最短步数）。

#### 2. 标准单向 BFS 解法

```python
from collections import deque

class Solution:
    def openLock(self, deadends: list[str], target: str) -> int:
        dead_set = set(deadends)
        if "0000" in dead_set:
            return -1
        if target == "0000":
            return 0
        
        queue = deque([("0000", 0)])
        visited = set(["0000"])
        
        while queue:
            status, step = queue.popleft()
            
            if status == target:
                return step
            
            # 生成 8 个相邻状态
            for i in range(4):
                digit = int(status[i])
                # +1 和 -1（带模 10 循环）
                for diff in (-1, 1):
                    new_digit = (digit + diff) % 10
                    neighbor = status[:i] + str(new_digit) + status[i+1:]
                    
                    if neighbor not in dead_set and neighbor not in visited:
                        visited.add(neighbor)
                        queue.append((neighbor, step + 1))
                        
        return -1
```

### 3. 进阶优化：双向 BFS（Bidirectional BFS）

在图搜索中，如果起点和终点都已知，单向 BFS 的搜索空间随深度呈指数级发散（像一个巨大的圆锥体）。采用双向 BFS 从起点和终点同时向中间扩散，可以大幅剪枝，将搜索空间从 $b^d$ 减少到 $2 \times b^{d/2}$。

```python
class Solution:
    def openLock(self, deadends: list[str], target: str) -> int:
        dead_set = set(deadends)
        if "0000" in dead_set or target in dead_set:
            return -1
        if target == "0000":
            return 0
        
        # 使用哈希集合替代队列，方便交集判断与交换优化
        start_set = {"0000"}
        end_set = {target}
        visited = set(deadends)  # 直接将 deadends 当作已访问
        visited.add("0000")
        
        step = 0
        
        while start_set and end_set:
            # 贪心选择更小的集合进行扩展，保持两端平衡
            if len(start_set) > len(end_set):
                start_set, end_set = end_set, start_set
            
            next_set = set()
            
            for status in start_set:
                for i in range(4):
                    digit = int(status[i])
                    for diff in (-1, 1):
                        neighbor = status[:i] + str((digit + diff) % 10) + status[i+1:]
                        
                        # 两端相遇，找到最短路径
                        if neighbor in end_set:
                            return step + 1
                        
                        if neighbor not in visited:
                            visited.add(neighbor)
                            next_set.add(neighbor)
            
            step += 1
            start_set = next_set
            
        return -1
```

### 4. 复杂度分析

* **时间复杂度**：$\mathcal{O}(D \cdot A^N + |\text{deadends}|)$
  * 其中 $N=4$ 为拨轮位数，$A=10$ 为每个拨轮的状态数（总节点数 $10^4$）。
  * 每个节点生成 $2N = 8$ 个邻居，字符串切片耗时 $\mathcal{O}(N)$。
  * 最坏情况下遍历全部状态，耗时受常数上限约束（约在毫秒级内完成）。
* **空间复杂度**：$\mathcal{O}(A^N + |\text{deadends}|)$
  * 哈希表与集合存储访问过的状态，最多 $10,000$ 项。

## 这道题在数学本质上就是一个**“无权图求最短路径（Shortest Path in an Unweighted Graph）”**问题。

题目虽然披了一层“密码锁拨轮”的生活外衣，但只要把生活语言翻译成数据结构语言，整张图就完全浮现出来了：

### 1. 生活语言 $\to$ 图论语言的精准映射

* **图的节点（Vertex / Node）**：
  * 密码锁上的每一个 4 位数状态（如 `"0000"`、`"0001"`、`"1000"`）。
  * 全图总共有 $10 \times 10 \times 10 \times 10 = 10,000$ 个独立的节点。
* **图的边（Edge）**：
  * 旋转一次转盘的操作。
  * 比如 `"0000"` 向上拨一下变成 `"0001"`，或者向下拨一下变成 `"0009"`，就代表节点 `"0000"` 与 `"0001"`、`"0009"` 之间**存在一条双向相连的边**。
  * 每个节点只有 8 条边（4 个轮子 $\times$ 向上/向下 2 种拨法）。
* **边的权重（Weight）**：
  * 每转动一次算作 1 步，所有边的长度都严格等于 $1$（**标准的无权图 / 等权图**）。
* **障碍物（Obstacle）**：
  * `deadends` 就是图里被“炸毁”或者“封路”的死节点，遍历时绝对不能踩进去。
* **目标**：
  * 求从起点节点 `"0000"` 走到终点节点 `target` 的**最少旋转次数**（即图论里的**最短路径长度**）。

### 2. 为什么必须是 BFS，而不是 DFS？

面对图的搜索，通常只有深度优先（DFS）和广度优先（BFS）两种选择：

* **为什么不能用 DFS（深度优先）？**
  * DFS 是一条路走到黑，可能会在图里顺着某条长路径转几十圈才到达终点，必须把整张图的所有路径全部搜完、穷举出所有可能，才能比较出哪条最短。这会导致严重的递归超时或栈溢出。
* **为什么 BFS（广度优先）天生是解药？**
  * BFS 是**像水波一样一层一层向外同心圆扩散**：
    * 第 0 层：起点 `"0000"`（步数 0）
    * 第 1 层：转 1 次能到达的所有节点（共 8 个）
    * 第 2 层：转 2 次能到达的所有节点……
  * **数学性质保证**：因为每条边的代价都是 1，**队列中第一次把 `target` 弹出来的那个瞬间，所经历的层数必然就是全局最短步数**，找到即可直接返回，连多余的边都不用搜。

### 一句话看透

当你看到题目要求：**“最少步数 / 最短距离”** 且 **“每一步的代价都相等（都是 1）”** 时，条件反射就是**把状态抽象成图的节点，直接上 BFS**。

## 在高阶算法和实际工程里，图分为两种：**显式图（Explicit Graph）** 和 **隐式图（Implicit Graph）**。

### 1. 显式图 vs 隐式图

* **显式图（如 Copy Graph）**：
  * **先建好再给你**。内存里已经有 `Node` 对象，所有的边（邻接表/指针）都预先画好了，你拿着指针顺藤摸瓜。
* **隐式图（如 Open the Lock / 华容道 / 迷宫 / 走围棋）**：
  * **内存里根本没有 `Node` 对象，也没有画好的边，但逻辑上它完全符合图的公理定义**。
  * 节点是**状态（State）**，边是**合法操作（Action/Transition）**。
  * 邻居节点不需要存在数组里，而是靠你**现算出来的**！

### 2. 数学上对“图”的严格定义是什么？

在离散数学里，只要一个系统能定义出两样东西，它在数学上就是一个**图 $G = (V, E)$**：

* **顶点集 $V$（Vertices / 节点）**：
  * 只要是系统的一个**确定状态**，就是一个节点。
  * 在锁的题目里，当前屏幕显示什么数字？`"0000"` 是一个状态，`"0239"` 是一个状态。全宇宙一共有 10,000 个可能的状态，这就是 $10,000$ 个顶点。
* **边集 $E$（Edges / 连线）**：
  * 两个状态之间，**如果能通过一步合法操作相互转换，那它们之间就存在一条边**。
  * 你手里拿着 `"0000"`，手指向上拨动第一位，变成了 `"1000"`。
  * 这意味着什么？意味着 `"0000"` 和 `"1000"` 之间**存在一条通路**。

### 3. 用“Copy Graph 的视角”看“Open the Lock”

如果你非要用 `Node` 类来写这道题，它完全可以等价写成下面这样：

```python
# 假设系统在后台预先偷偷帮你建好了这一万个 Node：
node_0000 = Node("0000")
node_1000 = Node("1000")
node_9000 = Node("9000")
...

# 然后把每个节点的 neighbors 连好：
node_0000.neighbors = [node_1000, node_9000, node_0100, node_0900, ...]
```

如果题目先把这一万个对象在内存里建好、连好，然后把 `node_0000` 作为入口传给你：

> “给你一个图的起点 `node_0000`，请问走几步能走到 `node_target`？”

这时候你绝对一眼就认出它是图了，对吧？

**为什么题目不这么给？**  
因为根本没必要浪费内存去建这一万个对象！当你在遍历到 `"0000"` 时，写一个简单的循环做加减法：

```python
# 这段代码，本质上就是在动态生成它的 neighbors！
neighbors = []
for i in range(4):
    neighbors.append(turn_up(status, i))
    neighbors.append(turn_down(status, i))
```

这和去读 `node.neighbors` 没有任何区别，只是邻居由“内存指针”变成了“算术函数”。

### 总结

* **不要被没有 `class Node` 迷惑**。
* **只要一道题在做“状态转移”**（从一个状态通过某些规则变到下一个状态，问最少几步能变到目标状态），它的骨子里就是一张**图**。
* 每一种状态是一个节点，每一次操作就是一条边。求最少步数，就是在图上找最短路径，所以必须用 **BFS**。
