### LeetCode 1071. 字符串的最大公因子 (Greatest Common Divisor of Strings)

#### 📝 题目描述 (Description)
对于字符串 `s` 和 `t`，只有在 `s = t + t + t + ... + t`（即 `t` 自身连接 1 次或多次）时，我们才认定 **“`t` 能除尽 `s`”**。

给定两个字符串 `str1` 和 `str2`，返回 **最长字符串 `x`**，要求满足 `x` 能除尽 `str1` 且 `x` 能除尽 `str2`[cite: 1]。

**示例 1：**
* **输入：** `str1 = "ABCABC"`, `str2 = "ABC"`
* **输出：** `"ABC"`

**示例 2：**
* **输入：** `str1 = "ABABAB"`, `str2 = "ABAB"`
* **输出：** `"AB"`[cite: 1]

**示例 3：**
* **输入：** `str1 = "LEET"`, `str2 = "CODE"`
* **输出：** `""`[cite: 1]

#### 🧠 一、 核心直觉与解题思路

##### 💡 方法一：前缀长度倒序枚举（直观暴力法）
1. **寻找最大上限**：如果存在公共“基准积木” `x`，它能同时拼出 `str1` 和 `str2`，那么 `x` 的长度 `L` 绝对不可能超过较短的那个字符串（即 `min(len(str1), len(str2))`）。
2. **从大到小试探**：因为题目要求**最长**的公因子，我们让长度 `L` 从 `min(len1, len2)` 开始**倒序递减**到 `1`。
3. **整除与拼接验证**：
   * 只有当 `L` 能同时整除 `len(str1)` 和 `len(str2)` 时，才有可能拼齐。
   * 截取前缀 `candidate = str1[:L]`，验证 `candidate * (len1 // L) == str1` 且 `candidate * (len2 // L) == str2`。
   * **只要遇到第一个满足条件的长度，立刻返回**（倒序枚举保证了第一个命中即最大）。

##### ⚡ 方法二：数学降维规律（最优秒杀法）
1. **存在性检测（基因检测）**：如果 `str1` 和 `str2` 确实由同一块积木 `x` 重复拼接而成（设 `str1 = m个x`，`str2 = n个x`），那么无论谁拼在前面，结果都是 `(m + n)个x`[cite: 1]：
   $$\text{str1} + \text{str2} == \text{str2} + \text{str1}$$
   若不相等，说明根本不存在公共积木，直接返回 `""`[cite: 1]。
2. **长度锁定**：只要通过了上述检测，最长公共积木的长度在数学上严格等于两字符串长度的最大公约数[cite: 1]：
   $$\text{L} = \gcd(\text{len}(\text{str1}), \text{len}(\text{str2}))$$
   直接截取 `str1[:L]` 返回即可[cite: 1]。

#### 💻 二、 Python 3 通关代码 (Solution)

##### 解法 1：前缀倒序枚举（易理解）
```python
class Solution:
    def gcdOfStrings(self, str1: str, str2: str) -> str:
        len1, len2 = len(str1), len(str2)
        
        # 从可能的最大长度开始，倒序暴力枚举
        for L in range(min(len1, len2), 0, -1):
            # 1. 长度必须能同时整除两个字符串
            if len1 % L == 0 and len2 % L == 0:
                candidate = str1[:L]
                # 2. 验证无缝拼接后是否等于原字符串
                if candidate * (len1 // L) == str1 and candidate * (len2 // L) == str2:
                    return candidate
                    
        return ""
```

### 三、 复杂度分析 (Complexity Analysis)

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| :--- | :---: | :---: | :--- |
| **方法一：倒序枚举** | $O(\min(N, M) * (N + M))$ | $O(N + M)$ | 最坏遍历 $\min(N, M)$ 个长度，每次切片与拼接耗时 $O(N + M)$ |
| **方法二：数学 GCD** | $O(N + M)$ | $O(N + M)$ | 拼接对比字符串耗时 $O(N + M)$，欧几里得求 $\gcd$ 耗时 $O(\log(\min(N, M)))$ |

设 `str1` 的长度为 `N`，`str2` 的长度为 `M`。

### 1. 方法一：倒序枚举为什么是 `O(min(N, M) * (N + M))`？

* **外层循环次数**：`for L in range(min(N, M), 0, -1)` 最多遍历从 `min(N, M)` 到 `1` 的所有长度，最坏情况下要执行 `min(N, M)` 次。
* **内层每次操作的耗时**：
  1. `candidate = str1[:L]`：切片创建长度为 `L` 的新字符串，耗时 `O(L)`。
  2. `candidate * (N // L) == str1`：把 `candidate` 重复拼接成长度为 `N` 的字符串并逐字符比对，耗时 `O(N)`。
  3. `candidate * (M // L) == str2`：同理，拼接并比对长度为 `M` 的字符串，耗时 `O(M)`。
  * 单次循环总耗时为 `O(L + N + M)`，由于 `L <= min(N, M)`，简化后就是 `O(N + M)`。
* **总时间复杂度**：外层循环次数 × 单次循环耗时 = `O(min(N, M) * (N + M))`。

*(注：严格按数论分析，只有当 `L` 同时是 `N` 和 `M` 的公约数时才会进入内层拼接，因此最坏情况是 `O(d(gcd(N, M)) * (N + M))`，其中 `d` 为约数个数。但在面试和常规刷题中，通常直接用循环上限估成 `O(min(N, M) * (N + M))`。)*

### 2. 方法二：数学 GCD 为什么是 `O(N + M)`？

代码里一共做了三件事，把它们的耗时加起来取最大量级即可：
1. `str1 + str2 != str2 + str1`：需要分别拼接出两个长度为 `N + M` 的新字符串，并从头到尾逐字符对比一遍，耗时 `O(N + M)`。
2. `math.gcd(N, M)`：底层用的是欧几里得辗转相除法，每次取模都会让数字规模至少减半，耗时 `O(log(min(N, M)))`。
3. `str1[:gcd_len]`：切片截取前 `gcd_len` 个字符，耗时 `O(gcd(N, M))`（不超过 `min(N, M)`）。

因为线性阶 `O(N + M)` 远大于对数阶 `O(log(min(N, M)))`，所以总时间复杂度由字符串拼接和对比主导，就是 `O(N + M)`。

### 1. 为什么这三步分别是 `O(L)`、`O(N)`、`O(M)`？

在 Python 里，**字符串是不可变对象**，不管是切片、乘法拼接还是相等对比，底层都需要一个字符一个字符地去搬运或检查：

* **第 1 步：`candidate = str1[:L]` 为什么是 `O(L)`？**
  计算机要在内存里新开辟一块长度为 `L` 的空间，然后从 `str1` 的第 `0` 个字符开始，一个一个复制到第 `L-1` 个字符。复制了 `L` 个字符，所以耗时是 **`O(L)`**。
* **第 2 步：`candidate * (N // L) == str1` 为什么是 `O(N)`？**
  * **乘法拼接 (`*`)**：`candidate` 长度为 `L`，重复 `N // L` 次，拼出来的新字符串总长度刚好是 `L * (N // L) = N`。计算机需要把这 `N` 个字符一个个填进新内存，耗时 `O(N)`。
  * **双等号比对 (`==`)**：拼好之后，还要拿这个长度为 `N` 的新字符串和原本的 `str1` 从头到尾逐个字符对比是否一样，最坏情况又要看 `N` 个字符，耗时 `O(N)`。
  * 两步加起来是 `O(2N)`，大 O 表示法去掉常数 `2`，就是 **`O(N)`**。
* **第 3 步：`candidate * (M // L) == str2` 为什么是 `O(M)`？**
  和第 2 步完全同理！拼出长度为 `M` 的新字符串，再和 `str2` 逐字符对比一遍，总计耗时 **`O(M)`**。

### 2. 为什么 `O(L + N + M)` 简化后变成了 `O(N + M)`？

这一步纯属**大 O 表示法的“抓大放小”原则**（只保留增长最快、量级最大的项，吞掉较小的项）：

1. 因为 `L` 是从较短的字符串里截取出来的长度，所以 `L` 一定小于等于 `min(N, M)`。
2. 既然 `L` 连 `N` 和 `M` 中较小的那个都比不过，那它肯定也比 `N` 小（`L <= N`）。
3. 所以：
   `L + N + M <= N + N + M = 2N + M`
4. 在大 O 复杂度分析里，所有的常数系数（比如 `2`）都会直接忽略掉，因此 `O(2N + M)` 就直接简化成了 **`O(N + M)`**。

**一句话总结**：每一轮循环都要把 `str1`（长 `N`）和 `str2`（长 `M`）重新拼一遍、比一遍，而截取小积木 `candidate`（长 `L`）的这点工作量被它们完全盖过去了，所以单轮总耗时就是 `O(N + M)`。

### LeetCode 55. 跳跃游戏 (Jump Game)

#### 📝 一、 题目描述 (Description)
给你一个非负整数数组 `nums`，你最初位于数组的 **第一个下标**。数组中的每个元素代表你在该位置可以跳跃的 **最大长度**。

判断你是否能够到达最后一个下标，如果可以，返回 `true`；否则，返回 `false`[cite: 2]。

* **示例 1：**
  * **输入：** `nums = [2,3,1,1,4]`
  * **输出：** `true`
  * **解释：** 可以先跳 1 步，从下标 0 到达下标 1, 然后再从下标 1 跳 3 步到达最后一个下标。

* **示例 2：**
  * **输入：** `nums = [3,2,1,0,4]`
  * **输出：** `false`
  * **解释：** 无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0 ， 所以永远不可能到达最后一个下标。

#### 🧠 二、 核心直觉与贪心策略 (Greedy)

##### 💡 为什么不用暴力或 DP？
* 如果去穷举“第 `i` 格跳 1 步还是 2 步”，会产生 $O(2^N)$ 的指数级路径分支[cite: 2]；即便用动态规划记录每个格子的可达性，也需要双重循环回溯，时间复杂度为 $O(N^2)$[cite: 1, 2]。

##### ⚡ 贪心降维：维护“最远可达右边界 `max_reach`”
其实我们根本不需要关心具体怎么跳、从哪一格跳过来，只需要像推土机一样维护一个指针 **`max_reach`**，记录**当前所能覆盖的最远下标边界**[cite: 1, 2]：

1. **熔断检查 (`if i > max_reach: return False`)**[cite: 2, 4]：
   * 顺次遍历数组 `i`，在利用当前格子的跳跃力之前，**必须先检查当前格子能不能踩到**[cite: 2, 4]。
   * 如果当前下标 `i` 已经超出了之前能到达的最远边界 `max_reach`，说明中间出现了无法逾越的 `0` 陷阱（断层），直接返回 `False`[cite: 2, 4]。
2. **贪心刷新 (`max_reach = max(max_reach, i + jump)`)**[cite: 2, 4]：
   * 只要当前格子能到达，就计算从这里起跳能摸到的最远位置 `i + jump`，并更新全局最远边界 `max_reach`[cite: 2, 4]。
3. **提前剪枝 (`if max_reach >= len(nums) - 1: return True`)**[cite: 2, 4]：
   * 一旦最远覆盖范围已经摸到甚至越过了最后一个下标 `len(nums) - 1`，无需继续遍历剩余元素，直接提前返回 `True`[cite: 2, 4]。
4. **兜底返回 (`return True`)**：
   * 处理如 `nums = [0]`（长度为 1，起点即终点）等单元素边界情况。

#### 💻 三、 Python 3 通关代码 (Solution)

```python
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        max_reach = 0

        for i, jump in enumerate(nums):
            # 1. 熔断检查：如果当前格子根本走不到，直接返回 False
            if i > max_reach:
                return False
            
            # 2. 贪心刷新：更新当前能覆盖的最远右边界
            max_reach = max(max_reach, i + jump)

            # 3. 提前剪枝：最远边界已覆盖终点，直接提前返回 True
            if max_reach >= len(nums) - 1:
                return True
                
        return True
```

### LeetCode 134. 加油站 (Gas Station)

#### 📝 一、 题目描述 (Description)
在一条环路上有 `n` 个加油站，其中第 `i` 个加油站有汽油 `gas[i]` 升[cite: 1, 2]。

你有一辆油箱容量无限的汽车，从第 `i` 个加油站开往第 `i+1` 个加油站需要消耗汽油 `cost[i]` 升[cite: 1, 2]。你从其中的一个加油站出发，开始时油箱为空[cite: 1, 2]。

给定两个整数数组 `gas` 和 `cost`，如果你可以按顺序绕环路行驶一周，则返回出发时加油站的编号，否则返回 `-1`[cite: 1, 2]。如果存在解，则 **保证** 它是 **唯一** 的[cite: 1, 2]。

* **示例 1：**
  * **输入：** `gas = [1,2,3,4,5]`, `cost = [3,4,5,1,2]`[cite: 1, 2]
  * **输出：** `3`[cite: 1, 2]
  * **解释：**
    * 从 3 号加油站出发，装满 4 升油，开往 4 号站消耗 1 升，剩余 3 升。
    * 在 4 号站加 5 升，开往 0 号站消耗 2 升，剩余 6 升。
    * 依次经过 0、1、2 号站，最终顺利开回 3 号站，恰好绕环路行驶一周[cite: 2]。

* **示例 2：**
  * **输入：** `gas = [2,3,4]`, `cost = [3,4,3]`
  * **输出：** `-1`
  * **解释：** 总油量（9 升）小于总消耗（10 升），无论从哪个站出发都无法绕行一周。

#### 🧠 二、 解题思路演进

##### 1. 暴力模拟法（Brute Force）
* **直觉思路**：枚举每一个加油站 `start`（从 `0` 到 `n-1`）作为起点，利用环形取模 `(start + step) % n` 模拟顺时针跑满 `n` 步。如果中途油箱小于 `0` 则该起点失败；若能跑完一圈则直接返回 `start`[cite: 1]。
* **局限性**：双重循环导致时间复杂度为 $O(N^2)$，在大规模测试用例下会超时（TLE）[cite: 1]。

##### 2. 贪心最优解（一维迭代推进）
通过两个核心推论，可以将时间复杂度降至 $O(N)$[cite: 2, 3]：
1. **全局可行性校验（总账检查）**：
   * 如果所有加油站的总油量小于总耗油量，即 `sum(gas) < sum(cost)`，那么无论从哪里出发都必然断油，直接返回 `-1`[cite: 1, 2]。
   * 反之，只要 `sum(gas) >= sum(cost)`，数学上一定存在至少一个合法起点（题目保证唯一）[cite: 1, 2]。
2. **局部断层剪枝（重置起点）**：
   * 假设从 `start_station` 出发，沿途累加净收益 `current_tank += gas[i] - cost[i]`[cite: 2]。
   * 一旦在某一站 `i` 出现 `current_tank < 0`（油箱破产），说明**从 `start_station` 到 `i` 之间的任何一个站点都不可能作为合法起点**（因为从起点出发到中途任意站 `k` 时油箱余量 $\ge 0$，连带着余量都撑不过 `i`，单独从 `k` 零油量出发更不可能撑过 `i`）[cite: 1, 2, 3]。
   * 因此直接跳过中间所有站点，将起点更新为 `start_station = i + 1`，并将 `current_tank` 清零重新累计，一趟线性迭代即可锁定唯一真命起点[cite: 1, 2]。

#### 💻 三、 Python 3 通关代码 (Solution)

##### 解法 1：贪心迭代最优解（推荐）
```python
from typing import List

class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        # 1. 全局总账检查：总油量小于总消耗，必然无解
        if sum(gas) < sum(cost):
            return -1
            
        current_tank = 0
        start_station = 0
        
        # 2. 单趟线性迭代，断层重置起点
        for i in range(len(gas)):
            current_tank += gas[i] - cost[i]
            
            # 当前油箱破产，[start_station, i] 区间内全部排除
            if current_tank < 0:
                start_station = i + 1
                current_tank = 0
                
        return start_station
```

##### 解法 2：暴力模拟法（辅助理解）
```python
from typing import List

class Solution:
    def canCompleteCircuit(self, gas: List[int], cost: List[int]) -> int:
        n = len(gas)
        
        for start in range(n):
            current_tank = 0
            success = True
            
            for step in range(n):
                curr_station = (start + step) % n
                current_tank += gas[curr_station] - cost[curr_station]
                if current_tank < 0:
                    success = False
                    break
                    
            if success:
                return start
                
        return -1
```

#### ⏱️ 四、 复杂度分析 (Complexity Analysis)

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| :--- | :---: | :---: | :--- |
| **方法一：贪心迭代（最优）** | $O(N)$ | $O(1)$ | 求和校验与单趟 `for` 循环均为线性扫描，仅使用常数个变量[cite: 1]。 |
| **方法二：暴力模拟** | $O(N^2)$ | $O(1)$ | 外层枚举 $N$ 个起点，内层最多模拟 $N$ 步，双重循环会超时[cite: 1]。 |

### LeetCode 57. 插入区间 (Insert Interval)

#### 📝 一、 题目描述 (Description)
给你一个 **无重叠的**，按照区间起始端点排序的区间列表 `intervals`，其中 `intervals[i] = [start_i, end_i]` 表示第 `i` 个区间的开始和结束，并且 `intervals` 按照 `start_i` 升序排列。同样给定一个区间 `newInterval = [start, end]` 表示另一个区间的开始和结束[cite: 3]。

在 `intervals` 中插入区间 `newInterval`，使得 `intervals` 依然按照 `start_i` 升序排列，且区间之间不重叠（如果有必要的话，可以合并区间）[cite: 3]。

返回插入之后的 `intervals`[cite: 3]。

* **示例 1：**
  * **输入：** `intervals = [[1,3],[6,9]]`, `newInterval = [2,5]`
  * **输出：** `[[1,5],[6,9]]`

* **示例 2：**
  * **输入：** `intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]]`, `newInterval = [4,8]`
  * **输出：** `[[1,2],[3,10],[12,16]]`
  * **解释：** 这是因为新的区间 `[4,8]` 与 `[3,5],[6,7],[8,10]` 重叠。

#### 🧠 二、 解题思路演进

##### 1. 暴力排序合并法（Brute Force）
* **直觉思路**：直接把 `newInterval` 追加到 `intervals` 末尾，调用 `sort()` 重新按起点升序排列，然后套用 LeetCode 56（合并区间）的逻辑逐个合并重叠区间。
* **局限性**：忽略了原数组**已经按起始位置排好序**的关键条件，排序操作导致时间复杂度退化为 $O(N \log N)$[cite: 1]。

##### 2. 三阶段线性扫描法（一次迭代最优解）
由于原数组已经有序且互不重叠，我们只需维护一个单向指针 `i = 0` 从左到右扫描一次，就能把整个数轴劈成完美的三个阶段[cite: 1, 3]：

1. **第一阶段：左侧安全区（完全在左侧，不相交）**
   * **条件**：`intervals[i][1] < newInterval[0]`（当前老区间的右端点严格小于新区间的左起点）[cite: 1, 3]。
   * **动作**：说明两者完全不挨着，直接将 `intervals[i]` 放入结果集 `res`，指针 `i += 1`[cite: 1, 3]。
2. **第二阶段：重叠交战区（碰撞吞噬，合体扩张）**
   * **条件**：`intervals[i][0] <= newInterval[1]`（在过滤掉左侧区间的前提下，只要当前老区间的左起点小于等于新区间的右终点，就必定发生重叠）[cite: 1, 3]。
   * **动作**：不急着输出，用当前老区间不断扩张 `newInterval` 的左右边界[cite: 1, 3]：
     * `newInterval[0] = min(newInterval[0], intervals[i][0])`[cite: 1, 3]
     * `newInterval[1] = max(newInterval[1], intervals[i][1])`[cite: 1, 3]
     * 指针 `i += 1` 继续吞噬下一个重叠区间，直到不再重叠后，将最终合体的 `newInterval` 放入 `res`[cite: 1, 3]。
3. **第三阶段：右侧安全区（完全在右侧，直接收尾）**
   * **动作**：剩下的老区间全部位于合体后 `newInterval` 的右侧且互不重叠，用 `while i < n` 依次追加进 `res` 即可[cite: 1, 3]。

#### 💻 三、 Python 3 通关代码 (Solution)

##### 解法 1：三阶段单向迭代最优解（推荐）
```python
from typing import List

class Solution:
    def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]:
        res = []
        i = 0
        n = len(intervals)
        
        # 阶段 1：添加所有在新区间左侧且不重叠的区间
        while i < n and intervals[i][1] < newInterval[0]:
            res.append(intervals[i])
            i += 1
            
        # 阶段 2：合并所有与新区间重叠的区间
        while i < n and intervals[i][0] <= newInterval[1]:
            newInterval[0] = min(newInterval[0], intervals[i][0])
            newInterval[1] = max(newInterval[1], intervals[i][1])
            i += 1
        res.append(newInterval)
        
        # 阶段 3：添加右侧剩余的所有区间
        while i < n:
            res.append(intervals[i])
            i += 1
            
        return res
```

##### 解法 2：暴力排序合并法（辅助对比）
```python
from typing import List

class Solution:
    def insert(self, intervals: List[List[int]], newInterval: List[int]) -> List[List[int]]:
        intervals.append(newInterval)
        intervals.sort(key=lambda x: x[0])
        
        merged = []
        for interval in intervals:
            if not merged or merged[-1][1] < interval[0]:
                merged.append(interval)
            else:
                merged[-1][1] = max(merged[-1][1], interval[1])
                
        return merged
```
