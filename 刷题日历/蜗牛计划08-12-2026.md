# LeetCode 20. Valid Parentheses (有效的括号)

## 📌 题目描述
给定一个只包括 `'('`，`')'`，`'{'`，`'}'`，`'['`，`']'` 的字符串 `s`，判断字符串是否有效。

有效字符串需满足：
1. 左括号必须用相同类型的右括号闭合。
2. 左括号必须以正确的顺序闭合。
3. 每个右括号都有一个对应的相同类型的左括号。

## 💡 解题思路：栈 (Stack) + 哈希表 (Hash Map)

括号匹配问题是典型的**栈（Stack）**应用场景。核心思想是**“后进先出（LIFO）”**：
1. 遍历字符串中的每一个字符：
   - 如果是**左括号**（不在右括号映射表中），将其压入栈中。
   - 如果是**右括号**：
     - 检查栈是否为空。如果为空，说明没有对应的左括号与当前右括号匹配，直接返回 `false`。
     - 弹出栈顶元素，检查它是否与当前右括号通过哈希表相匹配。如果不匹配，直接返回 `false`。
2. 遍历结束后，检查栈是否为空。如果栈为空，说明所有左括号都被完美闭合，返回 `true`；如果不为空，说明还残留未闭合的左括号，返回 `false`。

## 💻 Python3 标准答案代码

```python
class Solution:
    def isValid(self, s: str) -> bool:
        stack = []
        # 建立右括号到左括号的映射字典
        mydict = {")": "(", "]": "[", "}": "{"}

        for i in s:
            if i not in mydict:
                # 如果是左括号，压入栈中
                stack.append(i)
            else:
                # 如果是右括号：
                # 1. 栈为空说明没有左括号对应
                # 2. 弹出栈顶元素与当前右括号不匹配
                if not stack or stack.pop() != mydict[i]:
                    return False
                    
        # 最终栈必须为空才算完全匹配
        return len(stack) == 0
```

⏱️ 复杂度分析
- 时间复杂度：O(n)，其中 n 是字符串 s 的长度。我们只需要对字符串进行一次单向遍历，每个字符入栈和出栈一次。
- 空间复杂度：O(n)，在最坏情况下（例如全部都是左括号 (((((），栈需要存储所有的字符。

# LeetCode 2. Add Two Numbers (两数相加)

## 📌 题目描述
给你两个非空的链表，表示两个非负的整数。它们每位数字都是按照逆序的方式存储的，并且每个节点只能存储一位数字。
请你将两个数相加，并以相同形式返回一个表示和的链表。
你可以假设除了数字 0 之外，这两个数都不会以 0 开头。

## 💡 解题思路：模拟竖式加法 + 哑节点 (Dummy Node)

这道题本质上是模拟我们小学学过的**竖式加法**：
1. **对齐与相加**：从两个链表的头部（个位）开始相加，对应位相加的结果再加上来自低位的**进位 (carry)**。
2. **处理进位**：当前位的数值为 `total % 10`，新的进位为 `total // 10`（通常为 0 或 1）。
3. **长度不等处理**：如果两个链表长度不一致，短的链表遍历完后可以视其值为 0，继续与长的链表相加，直到两个链表都遍历完且没有进位。
4. **使用哑节点 (Dummy Node)**：由于结果链表是动态创建的，我们无法预知头节点是谁。使用一个虚拟的 `dummy` 节点作为起点，可以避免繁琐的头节点边界判断，最后直接返回 `dummy.next` 即可。

## 💻 Python3 标准答案代码

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def addTwoNumbers(self, l1: Optional[ListNode], l2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)  # 创建哑节点
        tail = dummy         # 尾指针，用于向新链表追加节点
        carry = 0            # 进位标志
        
        while l1 or l2 or carry:
            # 获取当前位的值，若链表为空则补 0
            val1 = l1.val if l1 else 0
            val2 = l2.val if l2 else 0
            
            # 计算总和、当前位数值与新进位
            total = val1 + val2 + carry
            carry = total // 10
            new_digit = total % 10
            
            # 创建新节点并接入结果链表
            tail.next = ListNode(new_digit)
            tail = tail.next
            
            # 移动原链表指针
            if l1: l1 = l1.next
            if l2: l2 = l2.next
            
        return dummy.next
```

⏱️ 复杂度分析
- 时间复杂度：O(max(m,n))，其中 m 和 n 分别代表两个链表的长度。我们需要完整遍历两个链表中较长的那一个。
- 空间复杂度：O(max(m,n))，新构建的结果链表的长度最多为 max(m,n)+1。

# LeetCode 287. Find the Duplicate Number (寻找重复数)

📌 题目描述
给定一个包含 $n + 1$ 个整数的数组 nums，其数字都在 [1, n] 范围内（包括 1 和 n），可知至少存在一个重复的整数。
假设 nums 只有 一个重复的整数 ，找出 这个重复的数 。
你设计的解决方案必须不修改原数组 nums 且只用常量级 $O(1)$ 的额外空间。

💡 解题思路：快慢指针（Floyd 判圈算法 / 链表环检测）
在不能修改原数组且只能使用 $O(1)$ 额外空间的情况下，我们可以将数组视为一个隐式的链表：
1. 下标与指针映射：将数组的下标（Index）看作链表的节点，将数组的值（Value）看作指向下一个节点的指针（即 next = nums[index]）。
2. 环的形成：由于数组中存在重复的数字，这意味着会有两个不同的下标指向同一个值，从而在“虚拟链表”中必然会形成一个环。
3. 寻找环的入口：我们要找的那个重复的数字，恰好就是这个环的入口节点。可以通过经典的 Floyd 判圈算法（快慢指针） 来解决：
  - 第一阶段（相遇）：快慢指针从起点（下标 0）出发，慢指针每次走一步（slow = nums[slow]），快指针每次走两步（fast = nums[nums[fast]]）。当它们在环内相遇时，停止循环。
  - 第二阶段（找入口）：将其中一个指针重新拨回起点（下标 0），另一个指针留在相遇点。两个指针改成同频同步每次各走一步（slow = nums[slow]，fast = nums[fast]）。它们再次相遇的地方就是环的入口，即重复的数。

💻 Python3 标准答案代码
```python
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # 阶段 1：利用快慢指针找到环内的相遇点
        slow = nums[0]
        fast = nums[nums[0]]
        
        while slow != fast:
            slow = nums[slow]
            fast = nums[nums[fast]]
            
        # 阶段 2：一个指针回到起点，另一个留在相遇点，同步前进寻找环入口
        slow = 0
        while slow != fast:
            slow = nums[slow]
            fast = nums[fast]
            
        return slow
```

⏱️ 复杂度分析
- 时间复杂度：$O(n)$，在最坏情况下，快慢指针遍历的步数与数组长度成正比。
- 空间复杂度：$O(1)$，只使用了两个整型变量作为指针，满足常数空间限制。

我们以经典的测试用例 `nums = [1, 3, 4, 2, 2]` 来进行一次完整的 **Dry Run（模拟演练）**，看看快慢指针是如何一步步精准抓到重复数字 `2` 的。

### 📥 初始准备
* **数组内容**：`nums = [1, 3, 4, 2, 2]`
* **下标映射关系**（`index -> nums[index]`）：
  * 下标 `0` $\rightarrow$ 值 `1`
  * 下标 `1` $\rightarrow$ 值 `3`
  * 下标 `2` $\rightarrow$ 值 `4`
  * 下标 `3` $\rightarrow$ 值 `2`
  * 下标 `4` $\rightarrow$ 值 `2`（可见下标 `3` 和 `4` 都指向了值 `2`，形成环）

### 🔄 阶段一：寻找环内相遇点 (`slow` vs `fast`)
代码初始设置：
* `slow = nums[0] = 1`
* `fast = nums[nums[0]] = nums[1] = 3`

| 循环次数 | 慢指针操作 (`slow = nums[slow]`) | 快指针操作 (`fast = nums[nums[fast]]`) | 当前 `slow` 值 | 当前 `fast` 值 | `slow != fast` 状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **初始状态** | - | - | `1` | `3` | `1 != 3` (True) |
| **第 1 次** | `nums[1] = 3` | `nums[nums[3]] = nums[2] = 4` | `3` | `4` | `3 != 4` (True) |
| **第 2 次** | `nums[3] = 2` | `nums[nums[4]] = nums[2] = 4` | `2` | `4` | `2 != 4` (True) |
| **第 3 次** | `nums[2] = 4` | `nums[nums[4]] = nums[2] = 4` | `4` | `4` | **`4 == 4` (False，相遇停下！)** |

👉 **第一阶段结束**：两个指针在值 **`4`** 处相遇。

### 🏁 阶段二：寻找环的入口（即重复的数）
代码调整：
* 将 `slow` 重新拨回起点：`slow = 0`
* `fast` 留在相遇点：`fast = 4`
* 之后两个指针**同频同步**：`slow = nums[slow]`，`fast = nums[fast]`

| 循环次数 | 慢指针操作 (`slow = nums[slow]`) | 快指针操作 (`fast = nums[fast]`) | 当前 `slow` 值 | 当前 `fast` 值 | `slow != fast` 状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **初始状态** | - | - | `0` | `4` | `0 != 4` (True) |
| **第 1 次** | `nums[0] = 1` | `nums[4] = 2` | `1` | `2` | `1 != 2` (True) |
| **第 2 次** | `nums[1] = 3` | `nums[2] = 4` | `3` | `4` | `3 != 4` (True) |
| **第 3 次** | `nums[3] = 2` | `nums[4] = 2` | `2` | `2` | **`2 == 2` (False，再次相遇停下！)** |

👉 **第二阶段结束**：两个指针在值 **`2`** 处相遇。
函数最终返回 `slow`，即 **`2`**。

### 🎉 结论
完美命中！整个过程不需要开辟额外的内存空间（$O(1)$），也没有修改原数组，仅仅通过巧妙的下标跳跃就找出了重复的数字。这个数学推导和代码逻辑是不是非常严丝合缝？

这种**“快慢指针 / Floyd 判圈算法”**或者**“将数据结构隐式转化为图/链表找环”**的思想，在 LeetCode 里面是非常经典的一类降维打击技巧。

当你觉得这种“转圈找环”的思路很妙时，通常是因为它命中了以下几类高频经典题：

### 1. 链表环检测系列（同宗同源的祖师爷）
* **LeetCode 141. 环形链表 (Linked List Cycle)**
  * **玩法**：最基础的链表判环。让快慢指针在真实链表里跑，只要 `fast == slow` 就说明有环，直接返回 `true`。
* **LeetCode 142. 环形链表 II (Linked List Cycle II)**
  * **玩法**：这道题和 287 题的**第二阶段逻辑一模一样**！不仅要判断有没有环，还要找出**环的入口节点**。数学推导（$X = Z$）完全通用。

### 2. 数学与数论推导类（思维同构）
* **LeetCode 202. 快乐数 (Happy Number)**
  * **玩法**：给你一个数，把它的每一位平方求和，得到新数，再重复这个过程。如果无限循环下去最后变成 1 就是快乐数；如果陷入无限循环（进不了 1）就不是。
  * **为什么能用快慢指针**：把每次计算出来的结果看作链表的一个节点，数字的变换过程就是“指针的指向”。如果陷入循环，就相当于链表有环！用快慢指针（一个每次算一步，一个每次算两步）就能完美检测它会不会相遇在 1 或者在环里死循环。

### 3. 数组中的状态机 / 坐标跳跃类
* **LeetCode 457. 环形数组是否存在循环 (Circular Array Loop)**
  * **玩法**：数组中的元素代表前进或后退的步数（正数往前跳，负数往后跳）。让你判断里面有没有一个方向一致、长度大于 1 的循环。
  * **为什么能用快慢指针**：数组天然就是带有方向索引的，通过 `i = (i + nums[i]) % n` 的方式在数组里跳格子，本质上就是一个有向图/链表。快慢指针是解决这类“判断数组中是否存在路径循环”的唯一利器。

### 💡 总结这类题的共同特征：
当你看到以下关键词或限制时，脑子里就可以立刻亮起警报灯，想想能不能用“快慢指针/判圈算法”：
1. **题目里带有“循环”、“环”、“重复”**。
2. **要求 $O(1)$ 空间复杂度**，导致你不能用 Hash Set 去记录历史访问过的位置。
3. **数据之间存在隐式的“指向/映射关系”**（比如下标指到下一个值，或者数字变幻到下一个数字），让你可以像走迷宫一样一路跳过去。
