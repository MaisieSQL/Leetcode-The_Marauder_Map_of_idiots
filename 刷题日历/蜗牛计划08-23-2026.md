# 📝 LeetCode 69. Sqrt(x) (简单)

## 💡 核心思路与解题痛点

1. **题目要求**：
   - 给你一个非负整数 `x`，计算并返回 `x` 的算术平方根（只保留整数部分，小数部分会被舍去）。
2. **为什么用二分查找？**
   - 假设我们要找数字 `8` 的平方根。它的整数结果肯定在 `0` 到 `8` 之间。
   - 如果我们挨个从 `1`、`2`、`3`、`4`……去试，时间复杂度是 O(root x)。但如果把这个范围看作一个有序数组，我们完全可以用**二分查找（Binary Search）**，像猜数字一样每次把搜索范围对半砍，速度会飞快！

## 🐍 完整 Python 3 代码

```python
class Solution:

    def mySqrt(self, x: int) -> int:
        # 特殊情况处理：如果 x 是 0 或 1，平方根就是它自己
        if x < 2:
            return x

        # 初始化二分查找的左右边界
        left = 0
        right = x
        ans = -1

        # 开始二分查找
        while left <= right:
            # 取中间值
            mid = left + (right - left) // 2

            # 如果 mid 的平方小于等于 x，说明 mid 可能是候选答案
            if mid * mid <= x:
                ans = mid  # 先把当前合法的 mid 记下来
                left = mid + 1  # 尝试往右找看有没有更大的整数解
            else:
                # 如果 mid 的平方大于 x，说明太大了，往左缩小范围
                right = mid - 1

        return ans
```

- **时间复杂度**：$O(\log n)$（对数阶，每次将搜索区间减半）
- **空间复杂度**：$O(1)$（仅需几个变量存储指针，常数空间）

### 🔍 代码分步解析与 Dry Run (以 x = 8 为例)

1. **初始化**：
   - `left = 0`, `right = 8`, `ans = -1`。
2. **第一轮循环**：
   - `mid = 0 + (8 - 0) // 2 = 4`。
   - 检查 `4 * mid = 16`。因为 `16 > 8`（太大），执行 `right = mid - 1 = 3`。
3. **第二轮循环**：
   - `left = 0`, `right = 3`。
   - `mid = 0 + (3 - 0) // 2 = 1`。
   - 检查 `1 * 1 = 1 <= 8`。合法！记录 `ans = 1`，然后向右试探：`left = mid + 1 = 2`。
4. **第三轮循环**：
   - `left = 2`, `right = 3`。
   - `mid = 2 + (3 - 2) // 2 = 2`。
   - 检查 `2 * 2 = 4 <= 8`。合法！记录 `ans = 2`，然后向右试探：`left = mid + 1 = 3`。
5. **第四轮循环**：
   - `left = 3`, `right = 3`。
   - `mid = 3 + (3 - 3) // 2 = 3`。
   - 检查 `3 * 3 = 9 > 8`。太大！执行 `right = mid - 1 = 2`。
6. **循环结束**：
   - 此时 `left (3)` 大于 `right (2)`，跳出 `while` 循环。
   - 返回记录的 `ans = 2`（8 的平方根向下取整确实是 2）。

### 📊 复杂度分析

- **时间复杂度**：O(log x)
  - 因为每次循环都把搜索区间对半砍，搜索次数是对数级别的，效率极高。
- **空间复杂度**：O(1)
  - 只需要几个常数级别的指针变量（`left`, `right`, `mid`, `ans`），不消耗额外空间。

# 📝 LeetCode 211. Design Add And Search Words Data Structure (中等)

## 💡 核心思路与解题痛点

1. **为什么不用普通 HashMap？**
   * 如果题目只有精确查询，用哈希表（HashSet）非常快。但本题引入了**通配符 `.`**（例如查询 `".ad"` 或 `"b.d"`）。如果用哈希表，遇到 `.` 时根本无法确定该查哪个键，只能全表遍历，数据量大时会直接超时。
2. **为什么选择字典树 (Trie) + DFS？**
   * **字典树**把所有单词按字母前缀重叠合并，查询效率极高。
   * **DFS (深度优先搜索)** 专门用来对付通配符 `.`。当遇到普通字母时，顺着树的唯一通道走；当遇到 `.` 时，利用递归把当前节点的所有子分支全部试探一遍，只要有一条路通关，即算成功。

## 🐍 完整 Python 3 代码

```python
class TrieNode:

    def __init__(self):
        # 内部用字典（HashMap）来存子节点：key 是字符，value 是下一个 TrieNode
        self.children = {}
        # 标记是否是一个完整单词的结尾
        self.is_end = False


class WordDictionary:

    def __init__(self):
        # 初始化时，先建一个空的根节点作为大本营
        self.root = TrieNode()

    def addWord(self, word: str) -> None:
        curr = self.root
        for char in word:
            # 如果当前节点的孩子里还没有这个字母，就为它新建一个节点
            if char not in curr.children:
                curr.children[char] = TrieNode()
            # 顺着通道走到下一个节点
            curr = curr.children[char]

        # 单词走完了，把最后一个节点标记为“这是一个完整单词”
        curr.is_end = True

    def search(self, word: str) -> bool:
        # 调用辅助函数进行 DFS 搜索，从根节点和单词的第 0 个字符开始
        return self._dfs_search(self.root, word, 0)

    def _dfs_search(self, curr: TrieNode, word: str, index: int) -> bool:
        # 递归终止条件：如果已经把单词的所有字符都匹配完了
        if index == len(word):
            # 只有当前节点确实是一个单词的结尾，才算真正匹配成功
            return curr.is_end

        char = word[index]

        # 情况一：当前字符是普通字母
        if char != ".":
            # 如果这条路断了（没有这个字母），直接返回 False
            if char not in curr.children:
                return False
            # 顺着这条路递归到下一个节点，匹配下一个字符
            return self._dfs_search(curr.children[char], word, index + 1)

        # 情况二：当前字符是通配符 '.'
        else:
            # 点号可以代表任意字母，所以需要遍历当前节点的所有子分支
            for child_node in curr.children.values():
                # 只要有一条分支递归下去最终成功了，就直接返回 True
                if self._dfs_search(child_node, word, index + 1):
                    return True

            # 所有子分支都试过了，没有一条能通关，返回 False
            return False
```

## 🔍 代码分步解析

1. **`TrieNode` 节点设计**：
   - 每个节点包含一个 `children` 字典（用来存通往下一个字母的路线）和一个 `is_end` 开关（标记单词是否到此结束）。
2. **`addWord` 添加单词**：
   - 从根节点出发，逐个字符检查。没有就新建节点，有就直接复用，最后在末尾把 `is_end` 设为 `True`。
3. **`search` 与 `_dfs_search` 搜索**：
   - **普通字母**：像正常导航一样，去 `curr.children` 里找对应的字母，找不到就返回 `False`。
   - **`'.'` 通配符**：触发多路分叉。用一个显式的 `for` 循环遍历当前节点的所有孩子（`curr.children.values()`），挨个派兵去递归探路。只要有一个返回 `True`，整个搜索就胜利结束。

## 📊 复杂度分析

- **`addWord(word)`**
  - **时间复杂度**：O(m)，其中 m 为单词的长度。需要遍历单词的每一个字符，在字典树中进行查找或新建节点。
  - **空间复杂度**：O(m)（最多新建 m 个节点）。

- **`search(word)`**
  - **时间复杂度**：
    - **无通配符 `.` 的情况**：O(m)，其中 m 为单词长度。
    - **含通配符 `.`（最坏情况）**：由于通配符需要遍历当前节点的所有子分支进行 DFS 回溯，最坏情况下可达 O(26^m)（26 为英文字母总量，m 为单词长度）。
  - **空间复杂度**：O(m)，递归调用的最大深度由单词长度 m 决定（即递归栈的开销）。

- **整体 Trie 树存储空间**
  - **空间复杂度**：O(∑M)，其中 ∑M 表示所有已插入单词的长度总和。

# 📝 LeetCode 200. Number of Islands (中等)

## 💡 核心思路与解题痛点

1. **核心直觉**：
   * 这道题要求我们计算网格中“岛屿”的总数。岛屿由水平方向或垂直方向上相邻的 `'1'`（陆地）连接而成。
   * 我们可以把整个二维网格看作一张无向图。外层通过双重循环扫描全图，一旦发现某个格子是 `'1'`，就说明发现了一座新岛屿（计数器加 1），然后立刻启动 **DFS（深度优先搜索）** 或 **BFS（广度优先搜索）**，把与这座岛相连的所有陆地全部“淹没”（改成 `'0'`），防止重复计算。

## 🐍 解法一：深度优先搜索 (DFS) 代码与解析

```python
class Solution:

    def numIslands(self, grid: list[list[str]]) -> int:
        if not grid:
            return 0

        rows = len(grid)
        cols = len(grid[0])
        count = 0

        # 定义 DFS：负责把相连的一整座岛全部“淹没”
        def dfs(r, c):
            # 1. 越界检查，或者遇到水（'0'）就直接返回
            if r < 0 or c < 0 or r >= rows or c >= cols or grid[r][c] == "0":
                return

            # 2. 把当前格子“淹没”（改成 '0'），防止重复遍历
            grid[r][c] = "0"

            # 3. 用显式循环朝四个方向继续递归探索
            for dr, dc in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
                dfs(r + dr, c + dc)

        # 外层双重循环扫全图
        for r in range(rows):
            for c in range(cols):
                # 发现一块未被开发的陆地
                if grid[r][c] == "1":
                    count += 1  # 岛屿总数 +1
                    dfs(r, c)  # 启动 DFS，把这整座岛的陆地全部“淹没”

        return count
```

### 🌊 解法二：广度优先搜索 (BFS) 代码与解析

```python
from collections import deque

class Solution:
    def numIslands(self, grid: list[list[str]]) -> int:
        if not grid:
            return 0

        rows = len(grid)
        cols = len(grid[0])
        count = 0

        # 定义 BFS 函数：用队列把整座岛“淹没”
        def bfs(start_r, start_c):
            # 1. 创建队列，把起点放进去
            queue = deque([(start_r, start_c)])
            # 起点立刻置为 '0'，标记为已访问
            grid[start_r][start_c] = '0'

            # 2. 只要队列里还有陆地坐标，就继续向外扩张
            while queue:
                r, c = queue.popleft()

                # 3. 用显式循环遍历四个方向
                for dr, dc in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
                    nr = r + dr
                    nc = c + dc

                    # 4. 边界检查：没有越界，且新位置确实是陆地 ('1')
                    if (
                        0 <= nr < rows
                        and 0 <= nc < cols
                        and grid[nr][nc] == '1'
                    ):
                        # 立刻把它置为 '0'！防止后面重复入队
                        grid[nr][nc] = '0'
                        # 把新坐标加进队列，等待下一轮处理
                        queue.append((nr, nc))

        # 外层双重循环扫全图
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == '1':
                    count += 1  # 发现新岛屿
                    bfs(r, c)  # 用 BFS 把整座岛连根拔起

        return count
```

### 📊 复杂度分析

- **时间复杂度**：O(M * N)
  - 其中 M 是网格的行数，N 是网格的列数。
  - 外层循环需要遍历整个网格的每一个格子。每个格子一旦被访问并修改为 '0' 之后，就不会再被重复处理，因此每个格子最多被访问一次。
- **空间复杂度**：O(M * N)
  - 在最坏情况下（比如整个网格全都是陆地），BFS 的队列长度可能会达到网格中格子总数的量级。

# 🚀 动态规划与回溯进阶：单词拆分 (Word Break) 系列全解析

接下来我们迎来了动态规划和回溯算法的重头戏：**LeetCode 139. 单词拆分 (Word Break)** 和 **LeetCode 140. 单词拆分 II (Word Break II)**。

这两道题虽然名字很像，但问法不同，解法也有明显的升级：
* **139 问“能不能”** $\rightarrow$ 用**动态规划 (DP)**。
* **140 问“所有方案是什么”** $\rightarrow$ 需要在 139 的基础上加上**回溯 (DFS) + 记忆化搜索**。

---

## 📝 LeetCode 139. Word Break (中等)

### 💡 核心思路与解题痛点
1. **核心痛点**：
   * 字符串 `s` 可能会很长，如果用纯递归暴力搜索，会重复计算大量的子串，导致超时。
2. **动态规划 (DP) 解法**：
   * **定义状态**：创建一个布尔型数组 `dp`，长度为 `n + 1`。其中 `dp[i]` 表示字符串 `s` 的前 `i` 个字符组成的子串（即 `s[0...i-1]`）是否能被成功拆分成字典里的单词。
   * **状态转移**：对于每一个位置 `i`，我们去遍历它前面的所有分割点 `j`（从 `0` 到 `i-1`）。如果前 `j` 个字符可以被拆分（即 `dp[j] == True`）**并且** 剩下的子串 `s[j:i]` 刚好在单词字典里，那么 `dp[i]` 就为 `True`。

### 🐍 完整 Python 3 代码
```python
class Solution:

    def wordBreak(self, s: str, wordDict: list[str]) -> bool:
        # 把字典转成集合，查询速度提升到 O(1)
        word_set = set(wordDict)
        n = len(s)

        # dp[i] 表示前 i 个字符组成的子串是否能被成功拆分
        dp = [False] * (n + 1)
        # 边界条件：空字符串默认可以拆分
        dp[0] = True

        # 外层循环：遍历字符串的每一个结束位置 i
        for i in range(1, n + 1):
            # 内层循环：寻找切分点 j
            for j in range(i):
                # 如果前 j 个字符可行，且剩下的子串 s[j:i] 在字典里
                if dp[j] and s[j:i] in word_set:
                    dp[i] = True
                    break  # 只要当前 i 确认可达，就可以跳出内层循环了

        # 返回整个字符串是否能被拆分
        return dp[n]
```

## 📝 LeetCode 140. Word Break II (困难)

### 💡 核心思路与解题痛点

1. **核心差异**：
   * 139 只需要返回 `True/False`，而 140 要求把所有可能的句子组合全部列出来。
   * 既然要找“所有可能”，单纯的 DP 就不够用了，我们需要用 **DFS (深度优先搜索/回溯)** 把路径拼出来。
2. **防止超时的秘诀：记忆化搜索 (Memoization)**：
   * 在递归拆分的过程中，同一个后缀字符串（比如 `s[5:]`）可能会被重复访问很多次。如果我们用一个字典 `memo` 把“某个后缀能拼出哪些句子”缓存起来，遇到相同的后缀直接拿结果，就能避免指数级别的重复计算。

### 🐍 完整 Python 3 代码

```python
class Solution:

    def wordBreak(self, s: str, wordDict: list[str]) -> list[str]:
        word_set = set(wordDict)
        # 记忆化字典：key 是剩余的子串，value 是该子串能组成的所有合法句子列表
        memo = {}

        def dfs(remaining_s):
            # 如果这个子串已经算过了，直接返回缓存的结果
            if remaining_s in memo:
                return memo[remaining_s]

            # 递归终止条件：如果字符串空了，说明成功拼完一条完整句子
            # 返回一个包含空字符串的列表作为基底
            if not remaining_s:
                return [""]

            res = []
            # 遍历所有可能的切割前缀
            for i in range(1, len(remaining_s) + 1):
                prefix = remaining_s[:i]

                # 如果前缀在字典里，再去递归处理剩下的后缀
                if prefix in word_set:
                    sub_sentences = dfs(remaining_s[i:])
                    # 把当前前缀拼接到后面所有子句的前面
                    for sub in sub_sentences:
                        if sub:
                            res.append(prefix + " " + sub)
                        else:
                            res.append(prefix)

            # 把计算结果存入缓存，再返回
            memo[remaining_s] = res
            return res

        return dfs(s)
```

其实严格来说，140 题用的 **“DFS + 记忆化（Memoization）”** 本质上依然是动态规划——它属于 **自顶向下（Top-Down）的动态规划**，而 139 题用的是 **自底向上（Bottom-Up）的表格型动态规划**。

那为什么 140 题我们不用像 139 那样建一个一维数组循环递推，而是换成了递归呢？主要原因有以下两点：

### 1. 输出需求变了：从“布尔值”变成了“组合列表”
- **139 题问的是“行不行”**：状态只需要记录 `True` 或 `False`。`dp[i]` 代表前 `i` 个字符能不能拆，是一个简单的布尔值。
- **140 题问的是“有哪些”**：要求把所有合法的句子组合全部列出来。如果硬要用自底向上的表格型 DP，`dp[i]` 里面存的就不再是 `True/False` 了，而必须是一个包含所有合法子句的字符串列表 (`list[str]`)。这样一来，表格里的每个格子都要维护庞大的字符串集合，不仅代码写起来极其繁琐，内存开销也会爆炸。

### 2. 递归（Top-Down）更适合“路径拼装”
- 字符串的切割和组合天生带有 **树形结构** 的特征。
- 用递归（DFS）写的时候，思路是顺理成章的：“我把当前字符串切一刀，只要前缀在字典里，剩下的交给递归去解，最后把结果拿回来拼接”。这种自顶向下、顺着路径组装答案的逻辑，比在脑子里硬去推导底向上的表格要直观得多。
- 加上 `memo` 字典做记忆化之后，它既保留了动态规划“避免重复计算”的核心优势，又完美解决了组合路径收集的难题。

> **简而言之**：139 用自底向上是为了高效做可行性判断；140 用自顶向下（递归+记忆化）则是为了顺理成章地把所有复杂的路径组合拼出来。它们本质上都是动态规划，只是换了一套最适合当前题目需求的形态！

从代码的外表来看，它确实就是一个标准的 **DFS + 记忆化**。如果你平时和别人交流或者刷题，大家也确实更习惯直接叫它 **“带记忆化的 DFS”** 或 **“回溯 + 缓存”**。

那为什么计算机教科书里会把它归为动态规划呢？这里面主要是叫法视角的区别：

1. **理论上的归属**：
   - 动态规划（Dynamic Programming）在学术定义上有两种实现方式：
     - **自底向上 (Bottom-Up DP)**：也就是 139 题那种用循环填表的常规 DP。
     - **自顶向下 (Top-Down DP)**：也就是 140 题这种递归 (DFS) + 缓存 (Memo)。
   - 因此，在算法理论中，“递归 + 记忆化”本质上就是动态规划的自顶向下形态。
2. **核心灵魂是一致的**：
   - 它们解决的都是同一个痛点：**重叠子问题**。如果没有 `memo` 这个字典，这个 DFS 遇到相同的后缀会疯狂重复递归导致超时；而一旦有了 `memo` 记住算过的结果，它就具备了动态规划“空间换时间、避免重复计算”的核心灵魂。

所以在日常写代码时，你把它当成 **DFS + 记忆化** 没有任何问题，这完全就是它最直观的写法；而在算法原理上，它又恰好属于动态规划的大家庭。你的直觉非常敏锐，直接抓住了代码最本质的执行形态！

## 🔄 什么是自顶向下 (Top-Down DP)？

自顶向下还有另一个更接地气的名字：**带记忆化的递归（Recursion + Memoization）**。

它的核心逻辑就像它的名字一样，是从最顶层的全局目标开始往下拆，遇到不会的就递归去问小一号的子问题，同时用一个备忘录（`memo`）把答案记下来。

我们可以用一个生活中的经典例子来对比这两种 DP：

### 🧗 形象的比喻：爬楼梯（算斐波那契数）
假设你要计算第 10 层台阶的走法：
- **自顶向下 (Top-Down / 递归 + 记忆化)**：
  - 你站在 **第 10 层**，你想知道怎么走，于是你问：“我需要知道第 9 层和第 8 层的走法。”
  - 你又去问第 9 层：“我需要知道第 8 层和第 7 层的走法……”
  - 就这样从上往下问到底，触底（第 1 层或第 0 层）之后，开始往上交作业。
  - **聪明点**：如果在问的过程中，你发现“第 7 层”的答案刚才已经算过了，就直接从备忘录里拿出来，绝对不重复算第二遍。这就是 LeetCode 140 用 `memo` 的精髓！
- **自底向上 (Bottom-Up / 循环填表)**：
  - 你老老实实从最底下的 **第 0 层和第 1 层** 开始算。
  - 算出第 2 层 -> 算出第 3 层 -> 一步步往上推 -> 最后平稳推到第 10 层。这就是 LeetCode 139 用 `dp` 数组循环的套路。

## ⚖️ 自顶向下 vs 自底向上：怎么选？

| 维度 | 自顶向下 (Top-Down / 记忆化搜索) | 自底向上 (Bottom-Up / 循环填表) |
| :--- | :--- | :--- |
| **思维方向** | 从大到小（顺着人类思考的直觉） | 从小到大（顺着机器递推的逻辑） |
| **实现方式** | 递归 + 哈希表/数组（Memo） | 循环 + 一维/二维表格（DP Table） |
| **优点** | **写起来直观**。只需要写出状态转移的递归式，不用纠结遍历顺序。而且如果有些子问题根本不用访问到，它压根不会去算（天然具备局部剪枝优势）。 | **空间和时间效率通常更高**。没有函数递归调用的开销（不会爆栈），也没有哈希表查找的额外耗时。 |
| **代表题目** | LeetCode 140 (Word Break II) | LeetCode 139 (Word Break) |

> **简而言之**：
> - **自顶向下** 像是“遇到问题再解决、顺便记笔记”（DFS 的思维外壳 + DP 的记忆内核）。
> - **自底向上** 像是“按部就班打地基、一步步盖大楼”（纯粹的循环填表）。

---

为了让你一眼看清它们的本质区别，我们用一个最经典、最简单的算法题——“爬楼梯 (Climbing Stairs)”来分别写出这两种写法的代码模板。

题目很简单：假设你正在爬楼梯。需要 n 阶你才能到达楼顶。每次你可以爬 1 或 2 个台阶。你有多少种不同的方法可以爬到楼顶呢？

1️⃣ 模板一：自顶向下 (Top-Down / 递归 + 记忆化搜索)
核心思维：顺着人类直觉，从终点（第 n 阶）往回看，用递归拆解问题，并用一个字典 memo 记录算过的结果，避免重复。

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        # 定义一个备忘录，用来存算过的值
        memo = {}

        def dfs(i):
            # 1. 递归终止条件（基准情况）
            if i <= 2:
                return i

            # 2. 如果备忘录里有，直接拿来用，不重复计算
            if i in memo:
                return memo[i]

            # 3. 状态转移：当前台阶的方法数 = 前一步的方法数 + 前两步的方法数
            res = dfs(i - 1) + dfs(i - 2)

            # 4. 把计算结果存入备忘录，再返回
            memo[i] = res
            return res

        # 从最顶层开始触发递归
        return dfs(n)
```

2️⃣ 模板二：自底向上 (Bottom-Up / 循环填表)
核心思维：顺着机器递推的逻辑，从最底下（第 1 阶、第 2 阶）开始打地基，用一个 dp 数组一步步往上推导，直到推到第 n 阶。

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        # 特殊情况处理
        if n <= 2:
            return n

        # 创建一个 dp 表格，长度为 n + 1
        # dp[i] 表示到达第 i 阶楼梯的方法总数
        dp = [0] * (n + 1)

        # 1. 初始化最底层的已知状态
        dp[1] = 1
        dp[2] = 2

        # 2. 自底向上，用显式循环从小到大依次填表
        for i in range(3, n + 1):
            dp[i] = dp[i - 1] + dp[i - 2]

        # 3. 表格填到头，返回最终答案
        return dp[n]
```

核心对比一目了然
代码骨架：

自顶向下是用 def dfs(...) 写的递归函数，里面带着 memo 缓存。

自底向上是用 for 循环写的迭代填表，里面带着 dp 数组。

执行方向：

自顶向下是“带着大问题去找小答案”（从 n 问到 1）。

自底向上是“拿着小答案去拼大问题”（从 1 算到 n）。
