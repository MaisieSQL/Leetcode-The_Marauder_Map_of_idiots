# LeetCode 682. 棒球比赛 (Baseball Game)

## 🎯 一、 核心考点与物理直觉

- **题目大意**：
  你现在是一家棒球比赛的记分员。比赛以局为单位，记录员会按顺序收到一串操作字符串列表 `operations`。
  你需要根据以下规则实时计算并返回比赛结束时的总得分：
  - 整数 `x`：表示本局新获得分数 `x`。
  - `"+"`：表示本局得分是前两次有效得分的总和。
  - `"D"`：表示本局得分是前一次有效得分的两倍。
  - `"C"`：表示使前一次有效得分失效（从记录中移除）。
- **物理直觉**：
  - 这是一道典型的**“栈 (Stack) 模拟题”**。
  - 因为所有的得分规则（求前一次、前两次的总和，或者移除最近一次）全部具有极强的**“后进先出 (LIFO)”**特性。
  - 栈底到栈顶实时记录着当前有效的得分序列。每来一个操作符，我们只需要直接从栈顶弹出或窥探最近的元素进行计算，然后把新结果压入栈中即可。最后直接对栈内所有元素求和！

## 💻 二、 工业级 Python3 代码实现 (Solution)

```python
class Solution(object):
    def calPoints(self, operations):
        """:type operations: List[str]
        :rtype: int
        """
        stack = []
        
        for op in operations:
            if op == "+":
                # 本局得分是前两次有效得分的总和
                # stack[-1] 是前一次，stack[-2] 是前两次
                stack.append(stack[-1] + stack[-2])
            elif op == "D":
                # 本局得分是前一次有效得分的两倍
                stack.append(stack[-1] * 2)
            elif op == "C":
                # 移除前一次有效得分
                stack.pop()
            else:
                # 纯数字字符串，转化为整数后入栈
                stack.append(int(op))
                
        # 比赛结束，对栈内所有有效得分求和
        return sum(stack)
```

⏱️ 三、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：O(N)
  - 其中 N 是操作列表 operations 的长度。我们只需要对整个操作数组进行一次从头到尾的线性扫描，栈的 append、pop 和最后的 sum 均摊下来都是单次常数开销。
- **空间复杂度**：O(N)
  - 最坏情况下（全部都是数字操作），栈需要完整存下所有的 N 个得分记录。

# LeetCode 102. 二叉树的层序遍历 (Binary Tree Level Order Traversal)

## 🎯 一、 核心考点与物理直觉
- **题目大意**：给你一个二叉树的根节点 `root`，返回其节点值的**层序遍历**（即逐层地，从左到右访问所有节点）。
- **物理直觉**：
  - 如果说 DFS（深度优先搜索）像是“一个人拿手电筒在迷宫里一条路走到黑”，那么 BFS（广度优先搜索）就像是“救援人员呈横向扩展的人墙，从上到下一层一层平推过去”。
  - **核心痛点**：我们必须准确分清“哪些节点属于第 1 层，哪些节点属于第 2 层”，不能让上下两层的节点混在一起。
  - **降维打击秘籍**：借助 **队列 (`deque`)** 的先进先出（FIFO）特性，并在进入每一层的瞬间**用 `level_size = len(queue)` 死死锁定当前层的节点总数**，做到层与层之间泾渭分明！

## 💻 二、 工业级 Python3 代码实现 (Solution)

```python
# Definition for a binary tree node.
# class TreeNode(object):
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from collections import deque

class Solution(object):
    def levelOrder(self, root):
        """:type root: Optional[TreeNode]
        :rtype: List[List[int]]
        """
        if not root:
            return []
            
        res = []
        queue = deque([root])  # 初始化队列，将根节点放入
        
        while queue:
            level_size = len(queue)  # 🔑 灵魂微操：锁定当前层的节点总数
            current_level = []       # 收集当前层的节点值
            
            # 把当前层的节点全部出队，并把它们的左右孩子入队
            for _ in range(level_size):
                node = queue.popleft()
                current_level.append(node.val)
                
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
                    
            # 当前层大功告成，打包塞入最终结果集
            res.append(current_level)
            
        return res
```

## 三、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：O(N)
  - 其中 $N$ 是二叉树的节点总数。每一个节点在整个 BFS 过程中都恰好被压入队列一次、弹出队列一次，做到了绝对高效的线性扫描。
- **空间复杂度**：O(N)
  - 空间开销主要由队列（Queue）消耗。在二叉树的最底层（满二叉树形态），叶子节点数量大约占总节点数的一半，因此队列在峰值时最多容纳 O(N) 个节点。

# LeetCode 206. 反转链表 (Reverse Linked List)

## 🎯 一、 核心考点与物理直觉

- **题目大意**：给你单链表的头节点 `head`，请你反转链表，并返回反转后的新头节点。
- **物理直觉**：
  - 单向链表最大的局限在于：我们**只能从前往后走（`next`）**，没有回头路。
  - 要想把原本指向后面的箭头（`->`）强行掰过来指向前面（`<-`），我们需要动用三个核心指针：
    - **`prev`（前驱指针）**：初始化为 `None`。用来接住反转后的箭头。
    - **`curr`（当前指针）**：初始化为 `head`。负责冲锋陷阵、推进整条链表。
    - **`next_temp`（临时暂存指针）**：每次循环里用来**提前保存 `curr.next`** 的位置，防止后半截链表断联失踪！

## 💻 二、 Python3 完美通关代码 (Solution)

```python
# Definition for singly-linked list.
# class ListNode(object):
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution(object):
    def reverseList(self, head):
        """:type head: Optional[ListNode]
        :rtype: Optional[ListNode]
        """
        prev = None
        curr = head
        
        while curr:
            # 🔑 1. 暂存下一个节点，防止断链失联
            next_temp = curr.next
            
            # 🔑 2. 强行把箭头反转，指回前面
            curr.next = prev
            
            # 🔑 3. prev 和 curr 双双往前挪一步，准备下一轮迭代
            prev = curr
            curr = next_temp
            
        # 当 curr 变成 None 时，prev 正好稳稳停在了新链表的头节点上！
        return prev

```

⏱️ 三、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：O(N)
  - 其中 N 是链表的节点总数。我们对整条链表进行了一次从头到尾的线性扫描，每个节点恰好被访问和修改指针一次。
- **空间复杂度**：O(1)
  - 全程只用了 `prev`、`curr`、`next_temp` 三个常数级别的指针变量，没有开辟任何额外的存储空间，空间利用率拉满！


LeetCode 206. 反转链表 是链表题里的“hello world”，必须把它盘得透透的。
光看代码容易晕，我们采用 Dry Run（走读/模拟） 的方式，配合物理图解，把这三个指针（prev, curr, next_temp）在内存里的每一次位移都看得清清楚楚。

# 💡 灵魂拷问：为什么 LeetCode 206 最后必须 `return prev`？

在初学“反转链表”时，大家最容易卡壳、也是最精妙的一个问题就是：
> **“为什么循环结束后，返回的是 `prev`，而不是 `curr` 呢？”**

咱们直接拉开内存物理沙盘，看看到底是怎么回事：

## 🔍 一、 看看循环结束的那一瞬间，`prev` 和 `curr` 分别在哪？

当整条链表刚好被完全反转后，最后一轮循环执行完毕：
- `curr` 指针因为已经走出了原链表的末尾（来到了 `NULL` 的位置），所以 **`curr` 此时变成了 `None`（空）**。
- 而 **`prev`** 因为刚刚把最后一个节点（比如节点 `5`）揽入怀中，它正**稳稳地停在整条新链表的头部（也就是原链表的最后一个节点）**！

## 💥 二、 错误示范：如果你返回了 `curr`

- 因为循环结束时 `curr` 已经是 `None` 了。
- 如果你写 `return curr`，函数就会直接返回一个空指针 `None`。
- 这意味着你的程序辛辛苦苦把链表反转完了，结果一交卷，交了个寂寞（空链表），评测机直接判定你解答错误！

## ✨ 三、 为什么必须返回 `prev`？

- 因为在整个反转过程中，`prev` 就像是一个永远跟在 `curr` 身后的“影子老大哥”。
- 每次 `curr` 向前挪一步之前，`prev` 都要先接住被反转过来的那个新头节点。
- 当 `curr` 最终掉出链表（变成 `None`）宣告工作结束时，`prev` 刚好停在了**新链表的最高统帅（新头节点）**位置上。

## 🎯 四、 军师给你的通关记忆口诀

> **“`curr` 是冲锋陷阵的探路先锋，当它跑到终点（变为空 `None`）时，殿后的 `prev` 刚好稳稳驻扎在了新阵地的最高峰（新头节点）！所以必须 `return prev`。”** 🚀🔥

`next_node` 存在的唯一意义，就是在大刀阔斧“断后路”之前，先把下一步要走的生路给提前死死攥在手里！当最后一轮 `next_node` 变成 `None` 时，也就宣告了整条链表的大反转圆满收工。这个细节一通，反转链表的内功你就彻底大成了！🚀🔥

# LeetCode 146. LRU 缓存 (Least Recently Used Cache)

# LeetCode 146. LRU Cache (LRU 缓存) 官方原题与精解

## 📋 一、 官方题目描述 (Problem Description)

Design a data structure that follows the constraints of a **Least Recently Used (LRU) cache**.

Implement the `LRUCache` class:
- `LRUCache(int capacity)` Initialize the LRU cache with positive size `capacity`.
- `int get(int key)` Return the value of the `key` if the key exists, otherwise return `-1`.
- `void put(int key, int value)` Update the value of the `key` if the key exists. Otherwise, add the `key-value` pair to the cache. If the number of keys exceeds the `capacity` from this operation, evict the **least recently used** key.

The functions `get` and `put` must each run in **$O(1)$ average time complexity**.

### 二、 架构设计：双剑合璧 ($O(1)$ 的破局密码)

要实现 $O(1)$ 的读写性能，必须同时利用两种数据结构的优势：

1.  **哈希表 (Hash Map)**
    *   **职责**：负责 $O(1)$ 极速定位。
    *   **存储**：键是 `key`，值是链表中的具体节点对象 (`Node`)。

2.  **双向链表 (Doubly Linked List)**
    *   **职责**：维护数据的“新鲜度顺序”。
    *   **逻辑**：
        *   **头部 (Head)**：代表“最近使用”。
        *   **尾部 (Tail)**：代表“即将淘汰”。
        *   **优势**：双向链表允许我们在 $O(1)$ 时间内删除任意节点（只要知道该节点指针），这正是哈希表配合实现高效 LRU 的关键。

这道题不仅是 LeetCode 的中高频门面，更是一道“数据结构组合拳”的巅峰之作。只要你把这道题彻底盘通，以后去面试不管遇到什么缓存淘汰、高并发内存设计，全都能降维打击！

## 🏛️ 一、 物理直觉：什么是 LRU？

LRU 的全称是 **Least Recently Used**（最近最少使用）。
把它想象成你办公桌上的一摞文件：
- **拿新文件 / 查阅已有文件**：你从文件堆里抽出一份文件看了一眼，看完之后，为了顺手，你绝不会把它塞回底下，而是**直接把它拍到最上面**（Most Recently Used）。
- **空间满了要扔东西（Capacity Exceeded）**：当你的桌子只能叠 3 份文件，来了第 4 份新文件时，桌子满了，你必须扔掉一份。扔哪一份？当然是**最底下、压箱底、已经好久没翻开过的那份文件**（Least Recently Used）！

数一数它的核心操作要求：
- `get(key)`：如果关键字 `key` 存在于缓存中，则返回关键字的值，并将其标记为最近使用。如果不存在，返回 `-1`。
- `put(key, value)`：如果关键字 `key` 已经存在，则变更其数据值；如果不存在，则向缓存中插入该组 `key-value`。当缓存容量达到上限时，它应该在写入新数据之前**淘汰最近最少使用的数据**。
- **终极硬性指标**：`get` 和 `put` 必须在 $\mathcal{O}(1)$ 平均时间复杂度内完成！

## 🧱 二、 破局密码：为什么单靠一种数据结构会当场卡死？

如果我们想做到 $\mathcal{O}(1)$ 的时间复杂度，各种基础数据结构会立刻暴露出它们的致命软肋：

- **如果只用哈希表（Hash Map / Dict）**：
  - 查找极其快（$\mathcal{O}(1)$），但哈希表是**无序**的！它根本不知道谁是最早来的、谁是最近用的，没法实现“按最近最少使用淘汰”。
- **如果只用双向链表（Doubly Linked List）**：
  - 增删节点极其快（$\mathcal{O}(1)$），但如果要找某一个 `key`，你必须从头到尾顺着指针线性遍历，查找时间直接退化成 $\mathcal{O}(N)$。

👉 **大厂架构师的终极解法 —— “双剑合璧”**：
- **哈希表（Hash Map）**：负责 $\mathcal{O}(1)$ 极速定位，里面存的键是 `key`，值是链表中的具体节点对象（Node）。
- **双向链表（Doubly Linked List）**：负责**维护数据的“新鲜度顺序”**。靠近头部的节点是最近刚使用的，靠近尾部的节点是即将被淘汰的倒霉蛋。

## 💻 三、 Python3 工业级标准实现 (Solution)

我们手写一个标准的双向链表节点，并配合哈希表将 LRU 完美落地：

```python
class Node:
    def __init__(self, key=0, val=0):
        self.key = key
        self.val = val
        self.prev = None
        self.next = None

class LRUCache:

    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = {} # 哈希表：key -> Node
        
        # 伪造头部 (head) 和尾部 (tail) 哨兵节点，避免繁琐的边界判空
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    # 内部微操：把某个节点从链表中彻底摘除
    def _remove(self, node: Node):
        node.prev.next = node.next
        node.next.prev = node.prev

    # 内部微操：把某个节点硬塞到链表头部（代表最新使用）
    def _add_to_head(self, node: Node):
        node.prev = self.head
        node.next = self.head.next
        self.head.next.prev = node
        self.head.next = node

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        
        node = self.cache[key]
        # 1. 把它从原来位置摘除
        self._remove(node)
        # 2. 重新拍到头部去（标记为最近使用）
        self._add_to_head(node)
        
        return node.val

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            # 如果 key 存在，更新它的值，并把它移动到头部
            node = self.cache[key]
            node.val = value
            self._remove(node)
            self._add_to_head(node)
        else:
            if len(self.cache) >= self.capacity:
                # 超载了！淘汰双向链表倒数第二个节点（即 tail 的前驱）
                lru = self.tail.prev
                self._remove(lru)
                del self.cache[lru.key] # 从哈希表中抹去
            
            # 创建新节点，存入哈希表并挂到头部
            new_node = Node(key, value)
            self.cache[key] = new_node
            self._add_to_head(new_node)
```

⏱️ 四、 复杂度核验 (Complexity Analysis)

- **时间复杂度**：`get` 和 `put` 均为 $\mathcal{O}(1)$
  - 哈希表的查找、插入、删除是 $\mathcal{O}(1)$。
  - 双向链表的节点摘除、插到头部，由于我们手里直接持有该节点的引用，仅需修改前后指针，也是绝对的 $\mathcal{O}(1)$。
- **空间复杂度**：$\mathcal{O}(\text{capacity})$
  - 哈希表和双向链表最多同时容纳 `capacity` 个键值对。
