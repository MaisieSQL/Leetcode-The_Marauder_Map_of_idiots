# LeetCode 第 88 题：合并两个有序数组 (Merge Sorted Array)

## 题目描述

给你两个按 **非递减顺序** 排列的整数数组 `nums1` 和 `nums2`，另有两个整数 `m` 和 `n`，分别表示 `nums1` 和 `nums2` 中的元素数目。

请你将 `nums2` 合并到 `nums1` 中，使合并后的数组同样按 **非递减顺序** 排列。

**注意**：最终，合并后-数组不应由函数返回，而是存储在 `nums1` 中。为了应对这种情况，`nums1` 的初始长度为 `m + n`，其中前 `m` 个元素表示应合并的元素，后 `n` 个元素为 `0`，应忽略。


## 示例

* **输入**：`nums1 = [1,2,3,0,0,0]`, `m = 3`, `nums2 = [2,5,6]`, `n = 3`
* **输出**：`[1,2,2,3,5,6]`
* **解释**：需要合并 `[1,2,3]` 和 `[2,5,6]`。合并结果是 `[1,2,2,3,5,6]`。


## 💡 核心解题思路：逆向双指针

如果从前往后合并，`nums1` 前面的元素会被新填入的元素覆盖掉，导致原数据丢失，必须额外开辟辅助空间。

但如果**从后往前（从大到小）**处理，妙处就来了：
1. `nums1` 的后半部分全都是 `0`（也就是预留的空白空间）。
2. 我们用三个指针：
   * `p1` 指向 `nums1` 有效数据的末尾（即索引 `m - 1`）。
   * `p2` 指向 `nums2` 的末尾（即索引 `n - 1`）。
   * `tail` 指向 `nums1` 整个数组的最末尾（即索引 `m + n - 1`）。
3. 每次比较 `nums1[p1]` 和 `nums2[p2]` 的大小，把**较大的那个**填入 `nums1[tail]`，然后对应的指针向前移动。
4. 这样既不需要额外空间（达到 $\mathcal{O}(1)$ 空间复杂度），又完美避免了数据覆盖的问题！

## 📝 Python 代码实现

```python
class Solution(object):
    def merge(self, nums1, m, nums2, n):
        """
        :type nums1: List[int]
        :type m: int
        :type nums2: List[int]
        :type n: int
        :rtype: None Do not return anything, modify nums1 in-place.
        """
        # 初始化三个指针
        p1 = m - 1
        p2 = n - 1
        tail = m + n - 1
        
        # 从后往前遍历合并
        while p1 >= 0 and p2 >= 0:
            if nums1[p1] > nums2[p2]:
                nums1[tail] = nums1[p1]
                p1 -= 1
            else:
                nums1[tail] = nums2[p2]
                p2 -= 1
            tail -= 1
            
        # 如果 nums2 还有剩余（nums1 已经空了），直接把 nums2 剩下的全拷过来
        # 注：如果 nums1 剩有元素，它们已经在正确的位置上了，不需要动
        if p2 >= 0:
            nums1[:p2 + 1] = nums2[:p2 + 1]
```

### 复杂度分析

* **时间复杂度**：O(m + n)。指针 p1 和 p2 最多各自遍历完自己的数组，总比较次数不超过 m + n 次。
* **空间复杂度**：O(1)。所有操作均在 nums1 原地修改，不需要额外的辅助数组空间。

# 如果 `nums1` 是一个固定大小、且空间不够的数组，直接往超出索引的地方赋值确实会触发越界错误

但为什么第 88 题里这么写完全没问题？原因在于题目给定的**初始化前提**：

### 1. 题目本身已经帮我们“扩容”好了

仔细看题目的说明和参数：
* `nums1` 的**初始总长度**其实是 `m + n`。
* 其中前 `m` 个元素是有效数据，而后面紧跟着的 `n` 个 `0`，**并不是真正的业务数据，而纯粹是题目预先留出来的“空白占位符”**。
* 也就是说，在算法开始执行之前，`nums1` 在内存中就已经被分配好了大小为 `m + n` 的连续空间。它的容量从一开始就是正好的，**根本不需要我们在运行过程中再去动态调用 `append` 扩容**。

### 2. 回看我们前面说的“不能不扩容直接加”

前面说的“不能不扩容直接加”，指的是：
* **针对动态扩容容器（如 Python 的空 `list = []`）**：如果你一开始创建的是个空列表，它的底层容量是 0。当你不断往里写数据或者超出当前容量时，它才必须触发底层扩容和搬家。

而第 88 题的 `nums1` 属于**静态预分配数组（Pre-allocated Array）**：
* 它的容量在传入函数时就已经定死了（就是 `m + n`）。
* 我们用 `tail = m + n - 1` 作为最高位的索引往里面填数字，本质上是通过下标直接修改内存里**本来就已经存在、只是暂时填了 0 的空位**。
* 这就像酒店经理已经提前开好了 10 个房间（其中 3 间住了人，7 间空着），你现在只需要把新来的客人直接安排进那 7 间空房里，**不需要临时去盖新楼（扩容）**。

所以，用 `tail` 直接倒着填，既不会触发 Python 列表的动态扩容，也完美利用了题目预留的空间！

# 我们用一个**极端复杂的例子**来彻底拆解，看看到底会不会越界。


### 🧪 极端复杂测试用例

* **`nums1`** = `[4, 5, 6, 0, 0, 0]` （有效数据 `m = 3`，总容量 `m + n = 6`）
* **`nums2`** = `[1, 2, 3]` （有效数据 `n = 3`）

初始指针位置：
* `p1 = 2` （指向 `nums1` 的最后一个有效数字 `6`）
* `p2 = 2` （指向 `nums2` 的最后一个数字 `3`）
* `tail = 5` （指向 `nums1` 数组的最末尾，即 `m + n - 1`）

---

### 🔄 模拟执行全过程

#### **第 1 轮比较：**
* 比较 `nums1[p1]` (6) 和 `nums2[p2]` (3)。
* `6 > 3`，所以把 `6` 放到 `nums1[tail]`（即 `nums1[5]`）。
* 指针变动：`p1` 挪到 1，`tail` 挪到 4。
* **当前状态**：`nums1 = [4, 5, _, _, _, 6]`

#### **第 2 轮比较：**
* 比较 `nums1[p1]` (5) 和 `nums2[p2]` (3)。
* `5 > 3`，把 `5` 放到 `nums1[tail]`（即 `nums1[4]`）。
* 指针变动：`p1` 挪到 0，`tail` 挪到 3。
* **当前状态**：`nums1 = [4, _, _, _, 5, 6]`

#### **第 3 轮比较：**
* 比较 `nums1[p1]` (4) 和 `nums2[p2]` (3)。
* `4 > 3`，把 `4` 放到 `nums1[tail]`（即 `nums1[3]`）。
* 指针变动：`p1` 挪到 -1（**`p1` 走完了，小于 0 了！**），`tail` 挪到 2。
* **当前状态**：`nums1 = [_, _, _, 4, 5, 6]`

### 🚨 关键时刻：`while` 循环结束！

因为 `p1 < 0`，`while` 循环条件 `p1 >= 0 and p2 >= 0` 不满足，循环**直接终止**。

此时：
* `tail` 停在了 `2`。
* `p2` 停在了 `2`（说明 `nums2` 里的 `[1, 2, 3]` 一个都没放进去，或者说大头全被 `nums1` 的 `4, 5, 6` 挤到后面去了）。
* 此时触发最后的善后代码：`if p2 >= 0:`（因为 `p2 = 2`，条件成立）。

### 🎯 这一步到底在干什么？

`nums1[:p2 + 1] = nums2[:p2 + 1]`

* 因为 `p2 = 2`，`p2 + 1 = 3`。
* 切片 `nums1[:3]` 指的是：**`nums1` 从索引 `0` 到索引 `2` 的这前三个空位。**
* 切片 `nums2[:3]` 指的是：**`nums2` 从索引 `0` 到索引 `2` 的全部元素（`[1, 2, 3]`）。**
* 这一行代码的意思是：**把 `nums2` 的 `[1, 2, 3]` 整体批量复制到 `nums1` 的前三个空位中。**

### 为什么绝对不会越界？

1. **`tail` 是从后往前走的**：它每一次填数字，都是填在 `m + n - 1`、`m + n - 2` 这种**已经被腾出来的安全后半区**。
2. **当 `nums1` 的指针 `p1` 先跑完时**，意味着 `nums1` 前面原有的有效数据（`4, 5, 6`）已经全部被挪到后面去了，**前面腾出了连续的好几个空位**。
3. 此时 `p2` 剩下的元素个数，**刚好等于前面腾出来的空位个数**。用切片直接赋值，写进去的区间是 `0` 到 `p2`，完全卡在 `nums1` 的前半截，**绝对不可能超出 `m + n - 1` 的边界**！

# Followup Question: LeetCode 第 1768 题 Merge Strings Alternately（交替合并字符串）与88的本质区别！

没错！LeetCode 第 1768 题 **Merge Strings Alternately（交替合并字符串）** 确实完美契合了你刚才的猜想——**只用一个统一的进度指针（或者循环变量），就可以优雅搞定！**


### 为什么 1768 题可以用单指针/单变量搞定？

1. **等长且严格同步推进（交替取）**：
   在这道题里，每一轮循环的目标极其固定：取完字符串 `word1` 的当前字符，接着就取字符串 `word2` 的当前字符。它们的步调是高度一致、交替进行的。
2. **可以用“轮数/索引”直接推导**：
   如果你用一个循环变量 `i` 从 `0` 开始递增：
   * 当 `i < len(word1)` 时，去取 `word1[i]`。
   * 当 `i < len(word2)` 时，去取 `word2[i]`。
   * 这里连 `max` 都不用，仅仅靠一个统一的索引 `i`，就能完美统筹两个字符串的读取进度！

### 为什么 88 题（合并有序数组）不行，而 1768 题行？

这正好印证了我们前面讨论的结论：
* **1768 题（交替合并）**：是**结构驱动（Structural）**的。合并规则是“你一个我一个”，进度完全同步，所以**单个统一坐标系（单索引 `i`）**就够了。
* **88 题（有序归并）**：是**大小驱动（Conditional/Value-based）**的。谁先走、谁后走完全取决于“谁大谁小”，两边的消耗速度是**异步且不可预测**的（比如 `nums1` 可能半天不动，`nums2` 一路狂飙）。因此，必须各自维护独立的进度轴（`p1` 和 `p2`）来动态决策。

# 💡 Another Solution:

这是一个非常精妙的数学优化思路！你的直觉极其敏锐——既然 `p1`、`p2` 和 `tail` 之间其实存在着**恒定的数学绑定关系**，那我们能不能只用一个变量来推导它们？

答案是：**完全可以！不仅可以，而且真的有人在工程或竞赛中这么写过。**

我们来看看这个数学闭环是怎么成立的。

### 🧮 揭秘：`tail` 与 `p1`、`p2` 的数学绑定关系

在整个逆向合并的过程中，总共被填入 `nums1` 的元素个数是恒定的。

1. 任何时刻，`tail` 指向的是当前要填的坑位。
2. 从一开始到当前时刻，总共已经填了多少个元素？
   * 总长度是 `m + n`。
   * 当前还剩下几个坑没填？就是 `tail + 1` 个。
   * 所以，**已经成功填好的元素个数**就是：`(m + n - 1) - tail`。
3. 既然两个数组总共被消费了这么多个元素，那么：
   * 如果我们知道当前消耗了多少个 `nums2` 的元素（假设用 `p2`），那么 `p1` 就可以通过总数推导出来。
   * 反过来，如果我们只维护一个统一的“步数”或 `tail`，我们其实能**在 O(1) 时间内随时算出 `p1` 和 `p2` 的当前位置**。

### 💻 纯用 `tail`（或用一个逆向主循环变量）的实现长什么样？

如果我们把 `p1` 和 `p2` 缩减掉，只用 `tail` 从大到小倒着循环，代码可以写成这样：

```python
class Solution(object):
    def merge(self, nums1, m, nums2, n):
        p1 = m - 1
        p2 = n - 1
        
        # 只用一个循环变量 tail 从后往前遍历所有坑位
        for tail in range(m + n - 1, -1, -1):
            # 如果 nums2 已经抽干了，直接结束（因为 nums1 剩下的本来就在原地）
            if p2 < 0:
                break
            # 如果 nums1 已经抽干了，或者 nums2 当前元素更大
            elif p1 < 0 or nums2[p2] >= nums1[p1]:
                nums1[tail] = nums2[p2]
                p2 -= 1
            else:
                nums1[tail] = nums1[p1]
                p1 -= 1
```

⚖️ 为什么平时我们还是习惯写显式的 `p1` 和 `p2`？
虽然用 `for tail in range(...)` 看起来少定义了变量，但实际上：

* **代码里依然保留了 `p1` 和 `p2`**：因为我们需要用它们去索引数组（`nums1[p1]` 和 `nums2[p2]`）。如果不保留它们，每次都要通过复杂的数学公式去算当前 `p1` 和 `p2` 减到了哪里，代码可读性会变差。
* **`while` 循环的边界更自然**：用 `while p1 >= 0 and p2 >= 0` 可以完美处理“其中一方先跑完就立刻触发善后”的逻辑。
