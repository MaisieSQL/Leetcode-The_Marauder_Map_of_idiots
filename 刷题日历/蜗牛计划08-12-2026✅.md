# LeetCode 20. Valid Parentheses (有效的括号)

## 📌 题目描述
给定一个只包括 `'('`，`')'`，`'{'`，`'}'`，`'['`，`']'` 的字符串 `s`，判断字符串是否有效。

有效字符串需满足：
1. 左括号必须用相同类型的右括号闭合。
2. 左括号必须以正确的顺序闭合。
3. 每个右括号都有一个对应的相同类型的左括号。

## 💡 解题思路：栈 (Stack) + 哈希表 (Hash Map)

括号匹配问题是典型的**栈（Stack）**应用场景。核心思想是**“后进先出（LIFO）”**：
1. 遍历字符串中的每一个字符：
   - 如果是**左括号**（不在右括号映射表中），将其压入栈中。
   - 如果是**右括号**：
     - 检查栈是否为空。如果为空，说明没有对应的左括号与当前右括号匹配，直接返回 `false`。
     - 弹出栈顶元素，检查它是否与当前右括号通过哈希表相匹配。如果不匹配，直接返回 `false`。
2. 遍历结束后，检查栈是否为空。如果栈为空，说明所有左括号都被完美闭合，返回 `true`；如果不为空，说明还残留未闭合的左括号，返回 `false`。

## 💻 Python3 标准答案代码

```python
class Solution:
    def isValid(self, s: str) -> bool:
        stack = []
        # 建立右括号到左括号的映射字典
        mydict = {")": "(", "]": "[", "}": "{"}

        for i in s:
            if i not in mydict:
                # 如果是左括号，压入栈中
                stack.append(i)
            else:
                # 如果是右括号：
                # 1. 栈为空说明没有左括号对应
                # 2. 弹出栈顶元素与当前右括号不匹配
                if not stack or stack.pop() != mydict[i]:
                    return False
                    
        # 最终栈必须为空才算完全匹配
        return len(stack) == 0
```

⏱️ 复杂度分析
- 时间复杂度：O(n)，其中 n 是字符串 s 的长度。我们只需要对字符串进行一次单向遍历，每个字符入栈和出栈一次。
- 空间复杂度：O(n)，在最坏情况下（例如全部都是左括号 (((((），栈需要存储所有的字符。

# LeetCode 2. Add Two Numbers (两数相加)

## 📌 题目描述
给你两个非空的链表，表示两个非负的整数。它们每位数字都是按照逆序的方式存储的，并且每个节点只能存储一位数字。
请你将两个数相加，并以相同形式返回一个表示和的链表。
你可以假设除了数字 0 之外，这两个数都不会以 0 开头。

## 💡 解题思路：模拟竖式加法 + 哑节点 (Dummy Node)

这道题本质上是模拟我们小学学过的**竖式加法**：
1. **对齐与相加**：从两个链表的头部（个位）开始相加，对应位相加的结果再加上来自低位的**进位 (carry)**。
2. **处理进位**：当前位的数值为 `total % 10`，新的进位为 `total // 10`（通常为 0 或 1）。
3. **长度不等处理**：如果两个链表长度不一致，短的链表遍历完后可以视其值为 0，继续与长的链表相加，直到两个链表都遍历完且没有进位。
4. **使用哑节点 (Dummy Node)**：由于结果链表是动态创建的，我们无法预知头节点是谁。使用一个虚拟的 `dummy` 节点作为起点，可以避免繁琐的头节点边界判断，最后直接返回 `dummy.next` 即可。

## 💻 Python3 标准答案代码

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def addTwoNumbers(self, l1: Optional[ListNode], l2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)  # 创建哑节点
        tail = dummy         # 尾指针，用于向新链表追加节点
        carry = 0            # 进位标志
        
        while l1 or l2 or carry:
            # 获取当前位的值，若链表为空则补 0
            val1 = l1.val if l1 else 0
            val2 = l2.val if l2 else 0
            
            # 计算总和、当前位数值与新进位
            total = val1 + val2 + carry
            carry = total // 10
            new_digit = total % 10
            
            # 创建新节点并接入结果链表
            tail.next = ListNode(new_digit)
            tail = tail.next
            
            # 移动原链表指针
            if l1: l1 = l1.next
            if l2: l2 = l2.next
            
        return dummy.next
```

⏱️ 复杂度分析
- 时间复杂度：O(max(m,n))，其中 m 和 n 分别代表两个链表的长度。我们需要完整遍历两个链表中较长的那一个。
- 空间复杂度：O(max(m,n))，新构建的结果链表的长度最多为 max(m,n)+1。

这是一个在组合数学和概率论中非常经典的推导。我们用最直观的“指示器随机变量（Indicator Random Variables）”和期望的线性性质，来把它一步步拆解清楚。

### 🧩 第一步：把“数环”转化成“数元素”
假设全排列里一共有 $N$ 个元素。如果我们想求“总共有多少个置换环”，直接整体去统计环的数量比较困难。
但我们可以换一个极其聪明的视角：**每一个元素，其实都属于且仅属于某一个置换环。**

我们可以定义一个非常巧妙的指示变量：
* 对于元素 $i$ 来说，如果它是一个置换环里的“领头羊”（即该环中编号最小的元素），我们就记 $I_i = 1$；否则记 $I_i = 0$。

那么，全排列中**置换环的总数 $C$**，就可以表示为所有元素“领头羊身份”的总和：
$$C = \sum_{i=1}^{N} I_i$$

根据数学中**期望的线性性质（Linearity of Expectation）**（总期望等于各自期望之和）：
$$\mathbb{E}[C] = \mathbb{E}\left[\sum_{i=1}^{N} I_i\right] = \sum_{i=1}^{N} \mathbb{E}[I_i]$$

因为 $I_i$ 是一个 0/1 变量，它的期望 $\mathbb{E}[I_i]$ 就等于**元素 $i$ 成为某个环的“最小编号元素（领头羊）”的概率**！

### 🔍 第二步：计算“元素 $i$ 成为环中最小元素”的概率
现在问题变成：在一个包含 $N$ 个元素的随机全排列中，任意挑选一个数字 $i$，它所在的那个置换环里，它刚好是最小那个数字的概率是多少？

我们反过来想：假设这个环的长度是 $k$（$1 \le k \le N$）。
* 在这 $k$ 个数中（包括 $i$ 在内），要让 $i$ 成为里面最小的那一个，概率是多少？
* 因为这 $k$ 个数在随机全排列中是完全对等、随机排列的，它们各自成为这群人里最小值的概率是完全均等的，也就是 $\frac{1}{k}$。

更严谨一点，如果我们从 $N$ 个元素里挑出任意 $k$ 个元素，让他们首尾相连构成一个长度为 $k$ 的环，总共有 $(k-1)!$ 种排法；而把这 $k$ 个元素全排列的总方案数是 $k!$。因此，一个环长度为 $k$ 且 $i$ 在其中的概率经过化简后，恰好就是 $\frac{1}{k}$。

把所有可能的环长度 $k$（从 $1$ 到 $N$）加起来，元素 $i$ 成为其所在环最小元素的总概率，就是：
$$\mathbb{E}[I_i] = \sum_{k=1}^{N} \frac{1}{k} \cdot P(i\text{所在的环长度为 } k)$$

数学上有一个漂亮的对称性证明：元素 $i$ 成为其所在环最小元素的概率，与 $i$ 的具体编号无关，且每一个特定长度 $k$ 的全排列平均贡献刚好是 $\frac{1}{k}$。

最终，每个元素 $i$ 成为其环中最小元素的概率，精确等于 **$\frac{1}{i}$**。（也就是说，编号越小的元素越容易成为领头羊，编号越大的元素概率越小）。

### 📊 第三步：把所有期望加起来
既然每个元素 $i$ 成为环首领的概率是 $\frac{1}{i}$：
$$\mathbb{E}[C] = \sum_{i=1}^{N} \mathbb{E}[I_i] = \sum_{i=1}^{N} \frac{1}{i} = 1 + \frac{1}{2} + \frac{1}{3} + \dots + \frac{1}{N} = H_N$$

这个和 $H_N$ 在数学上被称为**调和级数（Harmonic Series）**。

### 📈 第四步：调和级数的渐进估计（$\ln(N)$ 的由来）
当 $N$ 很大时（比如 100 甚至更大），怎么快速估算 $H_N$ 的大小呢？
我们可以通过画积分图像（把每个矩形 $\frac{1}{x}$ 的面积加起来）来逼近曲线 $\int_{1}^{N} \frac{1}{x} \, dx$：

$$\sum_{i=1}^{N} \frac{1}{i} \approx \int_{1}^{N} \frac{1}{x} \, dx = \ln(N) - \ln(1) = \ln(N)$$

因为离散求和比连续积分多出了微小的误差累积，数学家们证明了当 $N \to \infty$ 时，差值会收敛到一个常数，也就是**欧拉-马歇罗尼常数（Euler-Mascheroni constant）**：
$$\gamma \approx 0.57721$$

所以，最终的期望公式就完美出炉了：
$$\text{Expected Cycles} = H_N \approx \ln(N) + \gamma$$

这就是为什么 100 个罪犯的置换环平均数量大约是 $\ln(100) + 0.577 \approx 5.18$ 的底层数学大厦！逻辑是不是严丝合缝、极其优美？🚀🔥

# LeetCode 287. Find the Duplicate Number (寻找重复数)

📌 题目描述
给定一个包含 $n + 1$ 个整数的数组 nums，其数字都在 [1, n] 范围内（包括 1 和 n），可知至少存在一个重复的整数。
假设 nums 只有 一个重复的整数 ，找出 这个重复的数 。
你设计的解决方案必须不修改原数组 nums 且只用常量级 $O(1)$ 的额外空间。

💡 解题思路：快慢指针（Floyd 判圈算法 / 链表环检测）
在不能修改原数组且只能使用 $O(1)$ 额外空间的情况下，我们可以将数组视为一个隐式的链表：
1. 下标与指针映射：将数组的下标（Index）看作链表的节点，将数组的值（Value）看作指向下一个节点的指针（即 next = nums[index]）。
2. 环的形成：由于数组中存在重复的数字，这意味着会有两个不同的下标指向同一个值，从而在“虚拟链表”中必然会形成一个环。
3. 寻找环的入口：我们要找的那个重复的数字，恰好就是这个环的入口节点。可以通过经典的 Floyd 判圈算法（快慢指针） 来解决：
  - 第一阶段（相遇）：快慢指针从起点（下标 0）出发，慢指针每次走一步（slow = nums[slow]），快指针每次走两步（fast = nums[nums[fast]]）。当它们在环内相遇时，停止循环。
  - 第二阶段（找入口）：将其中一个指针重新拨回起点（下标 0），另一个指针留在相遇点。两个指针改成同频同步每次各走一步（slow = nums[slow]，fast = nums[fast]）。它们再次相遇的地方就是环的入口，即重复的数。

💻 Python3 标准答案代码
```python
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # 阶段 1：利用快慢指针找到环内的相遇点
        slow = nums[0]
        fast = nums[nums[0]]
        
        while slow != fast:
            slow = nums[slow]
            fast = nums[nums[fast]]
            
        # 阶段 2：一个指针回到起点，另一个留在相遇点，同步前进寻找环入口
        slow = 0
        while slow != fast:
            slow = nums[slow]
            fast = nums[fast]
            
        return slow
```

⏱️ 复杂度分析
- 时间复杂度：$O(n)$，在最坏情况下，快慢指针遍历的步数与数组长度成正比。
- 空间复杂度：$O(1)$，只使用了两个整型变量作为指针，满足常数空间限制。

我们以经典的测试用例 `nums = [1, 3, 4, 2, 2]` 来进行一次完整的 **Dry Run（模拟演练）**，看看快慢指针是如何一步步精准抓到重复数字 `2` 的。

### 📥 初始准备
* **数组内容**：`nums = [1, 3, 4, 2, 2]`
* **下标映射关系**（`index -> nums[index]`）：
  * 下标 `0` $\rightarrow$ 值 `1`
  * 下标 `1` $\rightarrow$ 值 `3`
  * 下标 `2` $\rightarrow$ 值 `4`
  * 下标 `3` $\rightarrow$ 值 `2`
  * 下标 `4` $\rightarrow$ 值 `2`（可见下标 `3` 和 `4` 都指向了值 `2`，形成环）

### 🔄 阶段一：寻找环内相遇点 (`slow` vs `fast`)
代码初始设置：
* `slow = nums[0] = 1`
* `fast = nums[nums[0]] = nums[1] = 3`

| 循环次数 | 慢指针操作 (`slow = nums[slow]`) | 快指针操作 (`fast = nums[nums[fast]]`) | 当前 `slow` 值 | 当前 `fast` 值 | `slow != fast` 状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **初始状态** | - | - | `1` | `3` | `1 != 3` (True) |
| **第 1 次** | `nums[1] = 3` | `nums[nums[3]] = nums[2] = 4` | `3` | `4` | `3 != 4` (True) |
| **第 2 次** | `nums[3] = 2` | `nums[nums[4]] = nums[2] = 4` | `2` | `4` | `2 != 4` (True) |
| **第 3 次** | `nums[2] = 4` | `nums[nums[4]] = nums[2] = 4` | `4` | `4` | **`4 == 4` (False，相遇停下！)** |

👉 **第一阶段结束**：两个指针在值 **`4`** 处相遇。

### 🏁 阶段二：寻找环的入口（即重复的数）
代码调整：
* 将 `slow` 重新拨回起点：`slow = 0`
* `fast` 留在相遇点：`fast = 4`
* 之后两个指针**同频同步**：`slow = nums[slow]`，`fast = nums[fast]`

| 循环次数 | 慢指针操作 (`slow = nums[slow]`) | 快指针操作 (`fast = nums[fast]`) | 当前 `slow` 值 | 当前 `fast` 值 | `slow != fast` 状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **初始状态** | - | - | `0` | `4` | `0 != 4` (True) |
| **第 1 次** | `nums[0] = 1` | `nums[4] = 2` | `1` | `2` | `1 != 2` (True) |
| **第 2 次** | `nums[1] = 3` | `nums[2] = 4` | `3` | `4` | `3 != 4` (True) |
| **第 3 次** | `nums[3] = 2` | `nums[4] = 2` | `2` | `2` | **`2 == 2` (False，再次相遇停下！)** |

👉 **第二阶段结束**：两个指针在值 **`2`** 处相遇。
函数最终返回 `slow`，即 **`2`**。

### 🎉 结论
完美命中！整个过程不需要开辟额外的内存空间（$O(1)$），也没有修改原数组，仅仅通过巧妙的下标跳跃就找出了重复的数字。这个数学推导和代码逻辑是不是非常严丝合缝？

这种**“快慢指针 / Floyd 判圈算法”**或者**“将数据结构隐式转化为图/链表找环”**的思想，在 LeetCode 里面是非常经典的一类降维打击技巧。

当你觉得这种“转圈找环”的思路很妙时，通常是因为它命中了以下几类高频经典题：

### 1. 链表环检测系列（同宗同源的祖师爷）
* **LeetCode 141. 环形链表 (Linked List Cycle)**
  * **玩法**：最基础的链表判环。让快慢指针在真实链表里跑，只要 `fast == slow` 就说明有环，直接返回 `true`。
* **LeetCode 142. 环形链表 II (Linked List Cycle II)**
  * **玩法**：这道题和 287 题的**第二阶段逻辑一模一样**！不仅要判断有没有环，还要找出**环的入口节点**。数学推导（$X = Z$）完全通用。

### 2. 数学与数论推导类（思维同构）
* **LeetCode 202. 快乐数 (Happy Number)**
  * **玩法**：给你一个数，把它的每一位平方求和，得到新数，再重复这个过程。如果无限循环下去最后变成 1 就是快乐数；如果陷入无限循环（进不了 1）就不是。
  * **为什么能用快慢指针**：把每次计算出来的结果看作链表的一个节点，数字的变换过程就是“指针的指向”。如果陷入循环，就相当于链表有环！用快慢指针（一个每次算一步，一个每次算两步）就能完美检测它会不会相遇在 1 或者在环里死循环。

### 3. 数组中的状态机 / 坐标跳跃类
* **LeetCode 457. 环形数组是否存在循环 (Circular Array Loop)**
  * **玩法**：数组中的元素代表前进或后退的步数（正数往前跳，负数往后跳）。让你判断里面有没有一个方向一致、长度大于 1 的循环。
  * **为什么能用快慢指针**：数组天然就是带有方向索引的，通过 `i = (i + nums[i]) % n` 的方式在数组里跳格子，本质上就是一个有向图/链表。快慢指针是解决这类“判断数组中是否存在路径循环”的唯一利器。

### 💡 总结这类题的共同特征：
当你看到以下关键词或限制时，脑子里就可以立刻亮起警报灯，想想能不能用“快慢指针/判圈算法”：
1. **题目里带有“循环”、“环”、“重复”**。
2. **要求 $O(1)$ 空间复杂度**，导致你不能用 Hash Set 去记录历史访问过的位置。
3. **数据之间存在隐式的“指向/映射关系”**（比如下标指到下一个值，或者数字变幻到下一个数字），让你可以像走迷宫一样一路跳过去。

# LeetCode 206. 反转链表 (Reverse Linked List) 完整题解

## 📌 一、 题目描述
给你单链表的头节点 `head`，请你反转链表，并返回反转后的新链表。

- **示例**：
  - 输入：`1 -> 2 -> 3 -> 4 -> 5 -> None`
  - 输出：`5 -> 4 -> 3 -> 2 -> 1 -> None`

## 💡 二、 解题思路（三指针原地迭代法）
单链表最大的局限在于：我们**只能单向从前往后走（`next`）**，没有回头路。
要想把原本指向后面的箭头（`->`）强行掰过来指向前面（`<-`），我们需要动用三个核心指针：
1. **`prev`（前驱指针）**：初始化为 `None`。用来接住反转过来的箭头。
2. **`curr`（当前指针）**：初始化为 `head`。负责冲锋陷阵、推进整条链表。
3. **`next_temp`（临时暂存指针）**：每次循环里用来**提前保存 `curr.next`** 的位置，防止等会儿断开后后面半截链表失联。

## 💻 三、 Python3 标准答案代码

```python
# Definition for singly-linked list.
# class ListNode(object):
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution(object):
    def reverseList(self, head):
        """:type head: Optional[ListNode]
        :rtype: Optional[ListNode]
        """
        prev = None
        curr = head
        
        while curr:
            # 1. 暂存下一个节点，防止断链失联
            next_temp = curr.next
            
            # 2. 强行把箭头反转，指回前面
            curr.next = prev
            
            # 3. prev 和 curr 双双往前挪一步，准备下一轮迭代
            prev = curr
            curr = next_temp
            
        # 当 curr 变成 None 时，prev 正好稳稳停在了新链表的头节点上！
        return prev
```

四、 复杂度分析
- 时间复杂度：O(N)，其中 N 是链表的节点总数。我们对整条链表进行了一次从头到尾的线性扫描，每个节点恰好被访问和修改指针一次。
- 空间复杂度：O(1)，全程只使用了 prev、curr、next_temp 三个常数级别的指针变量，没有开辟任何额外的存储空间。

# LeetCode 206. 反转链表 (Reverse Linked List) —— 物理手办拆解法

## 🧸 一、 想象你在拆一列“火车”
假设我们的原始链表是：
`1 -> 2 -> 3 -> None`
（也就是：车厢 1 连着车厢 2，车厢 2 连着车厢 3，车厢 3 后面没车了）。

我们的终极目标：**把所有的钩子全部调个头**，变成：
`None <- 1 <- 2 <- 3`（最后让车头指向 3）。

为了完成这个任务，我们需要在现场安排 **3 个工人（指针）**：
1. **`prev`（前驱/保镖）**：站在当前车厢的**后面**，负责接住反转过来的钩子。一开始后面空空如也，所以 `prev = None`。
2. **`curr`（当前/主角）**：站在当前要干活的车厢上。一开始它站在 **`1`** 号车厢。
3. **`next_temp`（临时工/防断链专员）**：负责在旁边**提前抱住**后面的车厢，防止等会儿钩子一断，后面的车厢集体失联。

## 🎬 二、 慢动作拆解（以 `1 -> 2 -> 3` 为例）

### 🛑 【初始状态】
* `prev = None`
* `curr = 1`
* 现场长这样：
  `None` 👈 (prev)
  `[ 1 ] -> [ 2 ] -> [ 3 ] -> None` （curr 站在 1 上）

### 🛑 【第 1 轮干活：处理车厢 1】
1. **防断链（抱住后面）**：
   `next_temp = curr.next` $\rightarrow$ 临时工赶紧把 **`2`** 号车厢抱住，免得等下 1 跟 2 断开后找不到 2 了。
2. **掰弯钩子（反转）**：
   `curr.next = prev` $\rightarrow$ 把 1 号车厢原本指向 2 的钩子**强行掰断**，改成指向 `prev`（也就是指向 `None`）。
   *此时状态：`None <- [ 1 ]`，而 2 和 3 在旁边依然连着 `2 -> 3`*
3. **全体向右挪一步（准备下一轮）**：
   * `prev = curr`（保镖往前挪，现在站到 `1` 上）
   * `curr = next_temp`（主角往前挪，走到刚才被临时工抱住的 `2` 上）

### 🛑 【第 2 轮干活：处理车厢 2】
现在现场位置变成了：
* `prev` 站在 `1` 上
* `curr` 站在 `2` 上
* 链表现状：`None <- [ 1 ]`，后面还剩 `[ 2 ] -> [ 3 ] -> None`

重复刚才的三步微操：
1. **防断链**：`next_temp = curr.next` $\rightarrow$ 临时工把 **`3`** 抱住。
2. **掰弯钩子**：`curr.next = prev` $\rightarrow$ 把 2 号车厢的钩子掰过来，指着当前的 `prev`（也就是指向 `1`）。
   *此时状态：`None <- [ 1 ] <- [ 2 ]`*
3. **全体向右挪一步**：
   * `prev = curr`（保镖挪到 `2` 上）
   * `curr = next_temp`（主角挪到 `3` 上）

### 🛑 【第 3 轮干活：处理车厢 3】
现在现场位置变成了：
* `prev` 站在 `2` 上
* `curr` 站在 `3` 上
* 链表现状：`None <- [ 1 ] <- [ 2 ]`，后面还剩 `[ 3 ] -> None`

重复微操：
1. **防断链**：`next_temp = curr.next` $\rightarrow$ 临时工发现后面是 `None`，没车了，记下 `None`。
2. **掰弯钩子**：`curr.next = prev` $\rightarrow$ 把 3 号车厢的钩子掰过来，指着 `2`。
   *此时状态：`None <- [ 1 ] <- [ 2 ] <- [ 3 ]`*
3. **全体向右挪一步**：
   * `prev = curr`（保镖挪到 `3` 上）
   * `curr = next_temp`（主角挪到 `None` 上）

## 🏁 【收工时刻】
当 `curr` 走到 `None` 时，`while curr:` 循环条件不成立，**收工下班！**

此时你抬头一看：
* 主角 `curr` 已经跑出轨道掉进 `None` 里了。
* 但是保镖 `prev` 正稳稳地站在全新车头 **`3`** 的上面！
* 看看身后：`None <- 1 <- 2 <- 3` 已经连得整整齐齐。

所以，我们只需要 **`return prev`**，就把新车头给交出去了！

💡 **一句话总结 206 的核心精髓**：
> “用 `next_temp` 护住后面的路，用 `curr.next = prev` 把当前箭头反过来，然后两个指针一起往后挪。”

# LeetCode 92. 反转链表 II (Reverse Linked List II) 完整题解与核心区别剖析

## 📌 一、 题目描述
给你单链表的头节点 `head` 和两个整数 `left` 和 `right`，其中 `left <= right`。请你反转从位置 `left` 到位置 `right` 的链表节点，返回**反转后的链表**。

- **示例**：
  - 输入：`head = [1, 2, 3, 4, 5], left = 2, right = 4`
  - 输出：`[1, 4, 3, 2, 5]`

## 🔍 二、 核心解法区别：92 题 vs 206 题

| 维度 | LeetCode 206. 反转链表 (全量反转) | LeetCode 92. 反转链表 II (局部精准爆破) |
| :--- | :--- | :--- |
| **反转范围** | **整条链表**从头反转到尾。 | 仅反转从第 `left` 到第 `right` 的**局部区间**。 |
| **起点处理** | 直接从头节点开始，`prev = None`，`curr = head`。 | 必须先走到 `left` 的**前一个节点**（即 `left - 1` 的位置），将前后两端隔离开。 |
| **边界痛点** | 简单直接，循环到 `curr` 变成 `None` 结束。 | 如果 `left = 1`（即从第一个节点开始反转），原链表头部会发生变化，必须引入 **`dummy` 虚拟头节点** 来统一逻辑。 |
| **收尾缝合** | 直接返回最终停在末尾的 `prev` 即可。 | 局部反转完成后，必须把断开的“前后车厢”重新接回原链表，最后依然返回 `dummy.next`。 |

👉 **一句话总结**：206 题是“全员大调头”，而 92 题是在一条长链表中**“精准截取一段进行头插法局部反转，再完美缝合前后两端”**。

## 💡 三、 解题思路（虚拟头节点 + 穿针引线头插法）

1. **引入虚拟头节点 `dummy`**：
   - 挂在 `head` 前面（`dummy.next = head`），用来防止 `left = 1` 时找不到前驱节点的尴尬。
2. **定位前驱节点 `pre`**：
   - 用一个指针从 `dummy` 出发，走 `left - 1` 步，停在反转区间的**前一个节点（`pre`）**上。
3. **局部精准头插法**：
   - 让 `curr` 指向要反转的第一个节点（即 `pre.next`）。
   - 循环 `right - left` 次，每次把 `curr` 后面的那个节点（`next_temp`）“摘下来”，通过指针重定向，**插到 `pre` 的后面**。
   - 这样循环下来，区间内的节点顺序就被完美逆转了！

## 💻 四、 Python3 标准答案代码

```python
# Definition for singly-linked list.
# class ListNode(object):
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution(object):
    def reverseBetween(self, head, left, right):
        """:type head: Optional[ListNode]
        :type left: int
        :type right: int
        :rtype: Optional[ListNode]
        """
        # 1. 创建虚拟头节点，防止 left = 1 时的边界特判
        dummy = ListNode(0)
        dummy.next = head
        
        # 2. 将 pre 移动到反转区间的前一个节点（即第 left - 1 个节点）
        pre = dummy
        for _ in range(left - 1):
            pre = pre.next
            
        # 3. curr 指向反转区间的第一个节点
        curr = pre.next
        
        # 4. 使用“头插法”在区间内循环反转 right - left 次
        for _ in range(right - left):
            next_temp = curr.next          # 暂存下一个节点
            curr.next = next_temp.next     # 将 curr 指向跳过 next_temp
            next_temp.next = pre.next      # 将 next_temp 插到 pre 的后面
            pre.next = next_temp           # 更新 pre 的指向，使其指向新的区间头部
            
        # 5. 返回虚拟头节点之后的真实头节点
        return dummy.next
```

五、 复杂度分析
- 时间复杂度：O(N)，最坏情况下我们需要遍历到 right 位置，线性耗时与链表长度成正比。
- 空间复杂度：O(1)，全程只使用了几个固定的常数级指针变量（dummy、pre、curr、next_temp），原地修改指针，没有开辟额外的辅助存储空间。

# LeetCode 92. 反转链表 II —— “头插法” 核心 4 行代码指针拆解图

这段**“头插法”**的代码可以说是整道题最精妙、但也最容易把脑子绕晕的地方。为了让你一眼看穿它是怎么像“穿针引线”一样把后面的节点摘下来并插到前面的，我们用具体的例子来画一幅**指针指向变化的动态推演图**！

---

### 📥 准备工作：设定一个局部例子
假设我们的链表局部结构是这样的：
* 前驱节点 `pre` 停在 **`1`** 上。
* 要反转的区间里，当前节点 `cur` 停在 **`2`** 上。
* `2` 的后面跟着 **`3`**，`3` 的后面跟着 **`4`**。

当前局部的指针初始状态：
```text
pre         cur     next_pre (稍后定义)
 |           |
[ 1 ] --> [ 2 ] --> [ 3 ] --> [ 4 ] --> None
```

🔄 核心 4 行代码的“慢动作连环画”
现在，我们把这 4 行代码拆开，一步步看指针是怎么被“掰弯”和重连的：

第 1 行：`next_pre = cur.next`
- 动作：把 `cur`（也就是 `2`）后面的那个节点（`3`）用临时变量 `next_pre` 抱住，防止等下链表断开后失联。
- 指针图示：
```text
pre         cur
 |           |
[ 1 ] --> [ 2 ] --> [ 3 ] --> [ 4 ] --> None
                     ^
                     |
                  next_pre
```

第 2 行：`cur.next = next_pre.next`
- 动作：让 `cur`（`2`）越过紧挨着它的 `next_pre`（`3`），直接去勾住 `3` 后面的那个节点（`4`）。
- 效果：把 `3` 这个节点从原本的链条里给“摘”（抽）出来了！
- 指针图示：
```text
pre         cur
 |           |
[ 1 ] --> [ 2 --------+
                     |
                     v
                    [ 4 ] --> None
                     
    (被摘出来的孤立节点)
    [ 3 ] <--- next_pre

```

第 3 行：`next_pre.next = pre.next`
- 动作：把刚刚被摘出来的 `next_pre`（`3`），让它的 `next` 指向原本 `pre`（`1`）身后紧挨着的那个旧节点（也就是现在的 `2`）。
- 指针图示：
```text
pre         cur
 |           |
[ 1 ] --> [ 2 --------+
              ^      |
              |      v
            [ 3 ]   [ 4 ] --> None
              ^
              |
           next_pre
```

第 4 行：`pre.next = next_pre`
- 动作：把 `pre`（`1`）的 `next` 强行改道，让它直接指向这个刚被插进来的 `next_pre`（`3`）。
- 效果：大功告成！节点 `3` 成功被“插”到了 `pre`（`1`）的后面！
- 指针图示：
```text
pre                 cur
 |                   |
[ 1 ] ------+       [ 2 ] --> [ 4 ] --> None
            |        ^
            v        |
           [ 3 ] ----+
             ^
             |
          next_pre
```

理一理现在的顺序：从 `pre`（`1`）出发，现在可以直接走到 `3`，再从 `3` 走到 `2`，再从 `2` 走到 `4`！
也就是说，原本排在 `2` 后面的 `3`，被巧妙地挪到了 `2` 的前面（即 `pre` 的后面）。

💡 为什么这种操作叫“头插法”？
如果你多循环几次就会发现：
每执行一次这 4 行代码，就像是从后面（`cur` 后面）“抽出一张牌”，然后“插到队头（`pre` 的后面）”。
- 每次抽走的都是当前 `cur` 身后的那个节点。
- 把它插到最前面，原先在后面的节点就会一个个逆序翻到前面去。
- 等循环结束时，这一小段区间里的节点就被完美地反转逆序了！
