# 399. Evaluate Division (除法求值) - DFS 路径相乘解法

# 399. Evaluate Division (除法求值)

- **难度**：Medium
- **分类**：图论 (Graph) / 深度优先搜索 (DFS) / 广度优先搜索 (BFS) / 带权并查集 (Weighted DSU)
- **LeetCode 链接**：[LeetCode 399. Evaluate Division](https://leetcode.com/problems/evaluate-division/)

---

### 题目描述

给你一个变量对数组 `equations` 和一个实数数组 `values` 作为已知条件，其中 `equations[i] = [Ai, Bi]` 和 `values[i]` 共同表示等式 $A_i / B_i = values[i]$。每个 $A_i$ 或 $B_i$ 是一个表示单个变量的字符串。

另给你一个数组 `queries`，其中 `queries[j] = [Cj, Dj]` 表示第 $j$ 个查询，你需要求出 $C_j / D_j = ?$ 的值。

返回所有查询的答案。如果某个答案无法根据已知条件计算得出，请返回 `-1.0`。

**说明**：
* 输入总是有效的。你可以假设除法运算中不会出现除以 0 的情况，且等式之间不存在矛盾。
* 变量如果从未在 `equations` 中出现过，则视为未定义，无法计算其答案。

---

### 示例

#### 示例 1
* **输入**：
  * `equations = [["a","b"],["b","c"]]`
  * `values = [2.0, 3.0]`
  * `queries = [["a","c"],["b","a"],["a","e"],["a","a"],["x","x"]]`
* **输出**：`[6.00000, 0.50000, -1.00000, 1.00000, -1.00000]`
* **解释**：
  * 给定：$a / b = 2.0,\ b / c = 3.0$
  * 查询：
    * $a / c = (a / b) \times (b / c) = 2.0 \times 3.0 = 6.0$
    * $b / a = 1 / (a / b) = 1 / 2.0 = 0.5$
    * $a / e = -1.0$（变量 `e` 未定义）
    * $a / a = 1.0$
    * $x / x = -1.0$（变量 `x` 未定义）

#### 示例 2
* **输入**：
  * `equations = [["a","b"],["b","c"],["bc","cd"]]`
  * `values = [1.5, 2.5, 5.0]`
  * `queries = [["a","c"],["c","b"],["bc","cd"],["cd","bc"]]`
* **输出**：`[3.75000, 0.40000, 5.00000, 0.20000]`

#### 示例 3
* **输入**：
  * `equations = [["a","b"]]`
  * `values = [0.5]`
  * `queries = [["a","b"],["b","a"],["a","c"],["x","y"]]`
* **输出**：`[0.50000, 2.00000, -1.00000, -1.00000]`

### 提示约束

* $1 \le \text{equations.length} \le 20$
* $\text{equations}[i].\text{length} == 2$
* $1 \le A_i.\text{length}, B_i.\text{length} \le 5$
* $\text{values.length} == \text{equations.length}$
* $0.0 < \text{values}[i] \le 20.0$
* $1 \le \text{queries.length} \le 20$
* $\text{queries}[i].\text{length} == 2$
* $1 \le C_j.\text{length}, D_j.\text{length} \le 5$
* $A_i, B_i, C_j, D_j$ 仅由小写英文字母与数字组成。

### 一、 题意与图论建模大白话

题目给出已知除法算式：
* $a / b = 2.0$
* $b / c = 3.0$

**在图论中，这对应带权重的有向边**：
* 从 $a$ 走向 $b$，倍率是 $\times 2.0$（即 $a = 2.0 \times b$）。
* 隐含反向关系：$b / a = 1 / 2.0 = 0.5$，即从 $b$ 走向 $a$ 权重为 $0.5$。
* 同理，$b \to c$ 权重为 $3.0$；反向 $c \to b$ 权重为 $1 / 3.0$。

求 $a / c$ 本质是在有向图中寻找一条从 $a$ 到 $c$ 的路径，并将沿途边权累乘：

$$a \xrightarrow{\times 2.0} b \xrightarrow{\times 3.0} c \implies a / c = 2.0 \times 3.0 = 6.0$$

### 二、 边界判死规则（返回 `-1.0`）

1. **未定义变量**：查询的起点或终点未在已知条件中出现。
2. **非连通分量**：起点与终点分属不同连通块，路径无法到达。

### 三、 Python 标准实现（DFS 路径相乘）

```python
from collections import defaultdict


class Solution:

  def calcEquation(
      self,
      equations: list[list[str]],
      values: list[float],
      queries: list[list[str]],
  ) -> list[float]:
    # 1. 构建邻接表：graph[u] = [(v, weight), ...]
    # u / v = val  =>  u 到 v 的权重是 val；v 到 u 的权重是 1.0 / val
    graph = defaultdict(list)
    for (u, v), val in zip(equations, values):
      graph[u].append((v, val))
      graph[v].append((u, 1.0 / val))

    # 2. DFS 搜索函数：从 curr 出发找 target，同时累乘倍率
    def dfs(curr: str, target: str, visited: set) -> float:
      if curr == target:
        return 1.0

      visited.add(curr)

      for neighbor, weight in graph[curr]:
        if neighbor not in visited:
          sub_result = dfs(neighbor, target, visited)
          if sub_result != -1.0:
            return weight * sub_result

      return -1.0

    # 3. 处理每个 query
    results = []
    for u, v in queries:
      if u not in graph or v not in graph:
        results.append(-1.0)
      elif u == v:
        results.append(1.0)
      else:
        results.append(dfs(u, v, set()))

    return results
```

### 四、 复杂度分析

* **时间复杂度**：$O(E + Q \cdot (V + E))$
  * 建图耗时 $O(E)$，其中 $E$ 为方程总数。
  * 单次 DFS 最坏需遍历当前连通图，耗时 $O(V + E)$；共有 $Q$ 次查询。
* **空间复杂度**：$O(V + E)$，用于存储图邻接表与 DFS 递归调用栈。

第一次看到这道题的人，几乎没有不震惊的——一个做加减乘除的小学算术题，怎么会和走迷宫的 DFS 扯上关系？！

这正是 LeetCode 经典题最“贼”的地方：给题目套上一层厚厚的业务外衣（算术、求值），把图论的骨架死死藏在里面。

### 1. 为什么你的大脑第一反应不是 DFS？

* **习惯性思维定势**：看到 $a / b = 2.0$ 和 $b / c = 3.0$，正常人的第一直觉是代数消元法或者解多元一次方程组，想着用数学库或解方程思维去做。
* **信息隔阂**：如果只有 3 个变量，心算代入一秒就出来了；但如果给你 20 个变量：
  * $a / b = 2$
  * $b / c = 3$
  * $c / d = 4$
  * $x / y = 5$
  * 问你：$a / d = ?$，$a / y = ?$
* 这时候你其实在做的动作是：**顺着 $a$ 去找谁跟它有关系，找到 $b$，再顺着 $b$ 找谁跟它有关系，找到 $c$，再找 $d$……**
* “顺藤摸瓜，一条路走到黑，走不通换一条路”——这不就是图的深度优先搜索（DFS）的本质吗？

### 2. 数学等式在计算机里的“图论真身”

只要把“除法”翻译成“地图”，整件事就豁然开朗：

* **变量名（$a, b, c$）** $\to$ **地图上的城市（节点）**
* **等式（$a / b = 2.0$）** $\to$ **连接两座城市的单向收费公路（带权重的边）**
  * 从 $a$ 到 $b$，过路费是“乘以 2.0”
  * 从 $b$ 到 $a$，过路费是“乘以 0.5”（倒数反向边）
* **提问（$a / c = ?$）** $\to$ **问你能不能从城市 $a$ 开车到城市 $c$？如果能，沿途过路费一共是多少？**

一旦看穿了这个映射，所谓“求除法”，彻底变成了**“在有向图里找一条连通路径，并把沿途边权乘起来”**。而找路径最原汁原味的做法，就是 DFS。

### 3. 这类“披着羊皮的狼”有什么通用识别特征？

以后在面试中遇到满足以下两个特征的题，直接在脑子里亮起“图论 / 搜索”的红灯：

* **两两关系传递**：题目给出成对的二元关系（如 $A \to B$，$B \to C$），且这种关系具有传递性（汇率兑换、亲戚血缘、先修课程、除法倍率）。
* **多源多查询**：给你一堆已知对，然后抛出任意两点让你求关系或求通路。

这道题是把“汇率兑换模型”（1 美元换 7 人民币，1 人民币换 20 日元，求 1 美元换多少日元）换成了除法符号。拆穿这层伪装后，它就只是一道平平无奇的图遍历模版题了。

# 图论核心分类与 5 大经典模型

在刷题和面试体系中，图论如果剥离掉纯粹的爆搜（DFS/BFS/回溯），剩下的核心题型边界非常清晰，主要被划分为以下 5 大经典模型：

| 分类 | 核心解决的问题 | 典型算法与数据结构 | 高频代表题 |
| :--- | :--- | :--- | :--- |
| **1. 连通性与动态并集** | 动态加边、判环、图连通块合并、传递闭包 | **并查集 (DSU)** / 矩阵连通分量 | 684 冗余连接、721 账户合并、200 岛屿数量 |
| **2. 依赖顺序与可达性** | 有向无环图 (DAG) 判环、线性依赖排序、分层推进 | **拓扑排序 (Kahn BFS / DFS 三色标记)** | 207/210 课程表、310 最小高度树、802 安全状态 |
| **3. 最短路径问题** | 带权图中“代价最小 / 距离最短 / 概率最高”的通路 | **Dijkstra** (正权堆优化) / **Bellman-Ford / SPFA** / **Floyd-Warshall** | 743 网络延迟时间、787 K站中转便宜航班、1334 阈值距离内邻居最少城市 |
| **4. 最小生成树 (MST)** | 连通所有节点且总边权代价最小（无环生成树） | **Kruskal** (边贪心 + 并查集) / **Prim** (点贪心 + 堆) | 1584 连接所有点的最小费用、1489 关键与伪关键边 |
| **5. 二分图与网络流** | 冲突着色（红蓝双色两派互不冲突）、任务配对调度 | **染色法 (Bipartite Coloring)** / 匈牙利算法 / 最大流最小割 | 785 判断二分图、886 可能的二分法 |

### 5 大模型背后的题型识别直觉

* **并查集模型（连通性 / 朋友圈）**：
  * **题面暗号**：“谁和谁属于同一个群体”、“加了这条边会不会闭环”、“合并两个账号/网络”。
  * **核心思维**：只需要维护**“谁和谁是一伙的”**，不关心路径具体怎么走。只要看到无向图、动态加边、求连通块个数，优先调取并查集。

* **拓扑排序模型（依赖 / 穿衣上课）**：
  * **题面暗号**：“做 B 之前必须先做 A”、“先后工序排期”、“树的层层剪枝（洋葱剥皮）”。
  * **核心思维**：面向**有向无环图 (DAG)**。找“入度为 0”（没有前置阻碍）的节点开始消耗，消除后暴露出下一批入度为 0 的节点。

* **最短路径模型（导航 / 最小花费）**：
  * **题面暗号**：“从 A 到 B 至少耗时多久”、“经过最多 K 次中转的最便宜价格”、“成功概率最高的一条路”。
  * **核心思维**：边上带有**非负权重**（时间、费用、距离）。
    * 单源单终点、非负边权 $\to$ **Dijkstra + 优先队列（堆）**；
    * 有步数限制或存在负权边 $\to$ **Bellman-Ford / 动态规划**；
    * 全源所有点对之间的距离（点很少） $\to$ **Floyd-Warshall 三层循环**。

* **最小生成树模型（修路修水管）**：
  * **题面暗号**：“把所有城市用电缆连起来，求最低造价”、“保证所有点连通，砍掉最昂贵的多余边”。
  * **核心思维**：全图所有点必须连通，一共选出 $N-1$ 条边，且权重和最小。
    * 绝大多数题目直接用 **Kruskal（边权升序排序 + 并查集贪心选边判环）** 搞定。

* **二分图模型（非友即敌 / 阵营划分）**：
  * **题面暗号**：“把所有人分成两组，使得同一组内的人互不喜欢”、“能否用两种颜色涂满整个图且相邻节点颜色不同”。
  * **核心思维**：用 1 和 -1 两种标记给邻居交替染色。如果染色过程中发现相邻节点已经被涂成了同一种颜色，说明图里存在**奇数长度的环**，二分图失败。

### 399. Evaluate Division 属于哪类经典模型？

这道题在本质上横跨并贯通了两个经典模型：

* **首要归属：模型 3【最短路径 / 路径乘积传递问题】（对应图遍历 / DFS / Floyd 解法）**
  * **为什么算这个模型**：虽然题目求的是“乘积”而非“求和”，但数学上取对数后 $\log(a/b) = \log(a) - \log(b)$，就彻底退化成了标准的**带权有向图路径问题**。
  * **解法映射**：在图上顺藤摸瓜找一条从起点到终点的通路，并沿途累乘权重，本质就是在求**全源连通路径的权值传递**（因此可以直接套用 Floyd-Warshall 跑全源传递闭包）。

* **进阶归属：模型 1【连通性与动态并集】（对应带权并查集 Weighted DSU 解法）**
  * **为什么算这个模型**：换个视角，所有能相互通过除法算出来的变量（如 $a, b, c$），其实同属于**同一个连通块（同一个帮派）**。
  * **解法映射**：带权并查集不仅维护“谁和谁是一伙的”，还在每个节点上挂一个相对大掌门的“倍率权重”。查询时只要看两节点是否在同一集合，若是，直接用两者对根节点的权值相除即可 $O(1)$ 得出答案。

> **一句话定性**：如果按纯图论算法的主流分类，它最核心的骨架是**带权图的连通路径权值计算（模型 3 的变体）**；如果按高级数据结构解法划分，它是经典的**带权并查集（模型 1 的进阶版）**。
