# LeetCode 14. 最长公共前缀 (Longest Common Prefix) 专题通关卡片

## 🎯 一、 核心考点与物理直觉

* **题目大意**：
  编写一个函数来查找字符串数组中的最长公共前缀。如果不存在公共前缀，返回空字符串 `""`。

* **物理直觉与“纵向扫描法”**：
  * 想象一下，我们把字符串数组排成一列。如果要求所有字符串的**最长公共前缀**，最直观的做法是**纵向列扫描**：
    1. 我们以数组中的**第一个字符串 (`strs[0]`)** 为标杆，依次遍历它的每一个字符（从第 0 个字符开始）。
    2. 拿这个字符去和其他所有字符串（`strs[1]`, `strs[2]`...）在相同位置上的字符进行比对。
    3. 如果所有字符串在当前位置的字符都一样，说明这个字符是安全的公共前缀的一部分，继续比对下一列。
    4. **一旦遇到以下两种情况之一，比对立刻终止**：
       * 某个字符串的长度已经走到了尽头（超出了边界）。
       * 某个字符串在当前位置的字符和标杆字符对不上。
    此时，标杆字符串从开头到当前位置之前的切片，就是全场唯一的最长公共前缀！

## 💻 二、 Python3 高效通关代码 (Solution)

```python
from typing import List

class Solution:
    def longestCommonPrefix(self, strs: List[str]) -> str:
        if not strs:
            return ""
        
        # 以第一个字符串为标杆，纵向遍历它的每一个字符
        for i in range(len(strs[0])):
            char = strs[0][i]
            
            # 拿这个字符去和其余所有字符串的第 i 个字符比对
            for j in range(1, len(strs)):
                # 边界条件：如果当前索引 i 已经超出了某个字符串的长度
                # 或者字符不匹配，说明公共前缀到此为止，直接截断返回
                if i >= len(strs[j]) or strs[j][i] != char:
                    return strs[0][:i]
                    
        # 如果第一个字符串本身就是最短的且完全匹配，直接返回它自己
        return strs[0]
```

三、 复杂度核验 (Complexity Analysis)

- 时间复杂度：O(S)，其中 S 是所有字符串中字符数量的总和。在最坏情况下（比如所有字符串完全相同，或者前缀很长），我们需要把每个字符串的所有字符都扫描一遍。
- 空间复杂度：O(1)，因为我们在原地进行纵向扫描和指针比对，只需要常数级别的额外变量开销，没有开辟任何额外的大型辅助数据结构。

## Question: 第二个致命错误：“短路求值（Short-circuit Evaluation）”引发的定时炸弹！

你的代码：if strs[i][i] != char or i >= len(strs[j]):

问题所在：

在 Python（以及绝大多数编程语言）中，or 运算符是从左向右执行的。如果左边为真，右边就不看了。

想象一下这个灾难场景：假设外层循环的 i 已经比短字符串 strs[j] 的长度还要大了（比如 i = 3，而 strs[j] 长度是 2）。

如果你把 strs[i][i] != char 写在左边：

Python 会先去执行 strs[j][3]（试图访问第 3 个下标）。

⚠️ 瞬间崩溃！ 因为 strs[j] 根本没有下标 3，Python 直接在执行左边时就抛出 IndexError: string index out of range 崩掉了，根本连走到右边 i >= len(strs[j]) 保护罩的机会都没有！

破解法则：一定要把“防越界保护罩”写在左边！ 先检查长度够不够，如果不够，直接短路熔断，绝不给它去访问 strs[j][i] 越界报错的机会。

# 🧩 算法辨析：公共前缀 (Prefix) vs 公共子串 (Substring)

## 🧪 1. 经典测试用例剖析
假设输入的字符串数组是：
```python
strs = ["aflower", "abflow", "flo"]
```
老铁敏锐地发现：这三个字符串的内部，每一个里面都连续包含了字母 `'f'`, `'l'`, `'o'`（也就是它们都含有 `"flo"` 这个子串）。

🔍 **2. 深度拆解：为什么它们的最长公共前缀是 `""` (空字符串)？**

这里有一个极其关键的概念误区，咱们必须瞬间拉直：

- **题目要求的是什么？**
  题目求的是“最长公共前缀 (Longest Common Prefix)”——必须是从下标 0（最开头）开始连续匹配的字符！

- **来看看我们的测试用例在绝对位置上的对齐情况：**
  - 第一个字符串 `strs[0] = "aflower"` $\rightarrow$ 开头第一个字母是 `'a'`
  - 第二个字符串 `strs[1] = "abflow"` $\rightarrow$ 开头第一个字母是 `'a'`
  - 第三个字符串 `strs[2] = "flo"` $\rightarrow$ 开头第一个字母却是 `'f'`

虽然它们内部都长了 `"flo"` 这三个字母，但：
- 第三个字符串 `"flo"` 的开头是 `'f'`，它没有以 `'a'` 开头。
- 因此，从下标 0（开头）这个绝对位置看过去：
  - 第一个字符串从 `'a'` 开始。
  - 第二个字符串从 `'a'` 开始。
  - 第三个字符串从 `'f'` 开始。
- **它们三个在“开头位置”根本没有交集！** 所以它们的最长公共前缀依然是 `""`（空字符串）。

💡 **3. 为什么“子串 (Substring)”和“前缀 (Prefix)”天差地别？**

- **公共子串（Common Substring）**：可以出现在字符串的任何地方（开头、中间、结尾都行）。比如 `"flo"` 确实是这三个字符串的公共子串。
- **公共前缀（Common Prefix）**：必须顶格从第一个字符（index = 0）开始算起，中间断掉一点都不行！

# LeetCode 347. 前 K 个高频元素 (Top K Frequent Elements) 专题通关卡片

## 🎯 一、 核心考点与物理直觉

* **题目大意**：
  给你一个整数数组 `nums` 和一个整数 `k`，请你返回其中出现频率前 `k` 高的元素。你可以按任意顺序返回答案。

* **物理直觉与核心流派**：
  这道题是 **“哈希统计 + 极值裁剪（堆/桶排序）”** 的殿堂级母题：
  1. **第一步（统计频次）**：必须先用哈希表（HashMap / Counter）把每个数字及其出现的次数完整统计出来。
  2. **第二步（Top K 裁剪）**：
     * **解法 A（小顶堆 Min-Heap）**：维持一个大小为 `k` 的小顶堆。遍历所有频次，如果堆的大小超过 `k`，立刻把堆顶（频率最小的元素）弹出去！这样堆里面永远留着最大的 `k` 个元素。
     * **解法 B（桶排序 Bucket Sort）**：利用“没有任何元素的出现次数会超过数组总长度 `N`”的物理规律，开辟一个大小为 `N+1` 的桶数组。桶的下标代表**“出现频次”**，桶里面挂着**“在这个频次下出现的所有数字”**。最后从后往前倒序收集前 `k` 个高频元素。

---

## 💻 二、 Python3 高效通关代码 (两种工业级解法)

### 方法一：小顶堆法 (Min-Heap)
```python
from typing import List
import heapq
from collections import Counter

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        # 1. 统计每个数字的频率
        count = Counter(nums)
        
        # 2. 使用小顶堆维护前 k 个高频元素
        # heapq 默认是小顶堆，里面存入元组 (frequency, num)
        min_heap = []
        for num, freq in count.items():
            heapq.heappush(min_heap, (freq, num))
            # 如果堆的大小超过了 k，弹出频率最小的堆顶元素
            if len(min_heap) > k:
                heapq.heappop(min_heap)
                
        # 3. 提取堆中剩下的数字
        return [num for freq, num in min_heap]
```

### 方法二：桶排序法 (Bucket Sort) ── 绝对的线性时间复杂度神器

```python
from typing import List
from collections import defaultdict

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        # 1. 统计频次
        count = {}
        for num in nums:
            count[num] = count.get(num, 0) + 1
            
        # 2. 初始化桶：下标代表频次，最大频次不会超过 len(nums)
        bucket = [[] for _ in range(len(nums) + 1)]
        for num, freq in count.items():
            bucket[freq].append(num)
            
        # 3. 从后往前（从高频到低频）倒序遍历桶，收集前 k 个元素
        res = []
        for i in range(len(bucket) - 1, -1, -1):
            for num in bucket[i]:
                res.append(num)
                if len(res) == k:
                    return res
        return res
```

### 三、 复杂度核验 (Complexity Analysis)

| 解法名称 | 时间复杂度 | 空间复杂度 | 说明 |
| :--- | :---: | :---: | :--- |
| **小顶堆法 (Min-Heap)** | $\mathcal{O}(N \log K)$ | $\mathcal{O}(N)$ | $N$ 为不重复元素的总数。每次堆操作耗时 $\log K$，当 $K$ 较小时极度高效。 |
| **桶排序法 (Bucket Sort)** | $\mathcal{O}(N)$ | $\mathcal{O}(N)$ | 彻底避开了堆排序的 $\log$ 开销，利用频次作为索引实现真正的线性时间复杂度。 |

# LeetCode 271. 字符串的编码与解码 (Encode and Decode Strings) 专题通关卡片

## 🎯 一、 核心考点与物理直觉

* **题目大意**：
  设计一个算法，把一个字符串列表（List of Strings）**编码**成一个单独的字符串（String）；同时，能够把这个单独的字符串**解码**回原来的字符串列表。要求编码和解码必须是完全可逆的，且能处理任何可能出现的特殊字符。

* **物理直觉与“长度前缀 + 显式分隔符”协议**：
  * **为什么普通的拼接会翻车？** 如果用简单的分隔符（比如逗号 `,`）把字符串拼起来：`["hel,lo", "world"]` $\rightarrow$ `"hel,lo,world"`。解码时遇到逗号会直接切错，导致数据污染！
  * **工业级解决方案 —— 长度前缀协议（Length-Prefix Protocol）**：
    为每个字符串设计一个明确的护照：`[字符串长度] + [#] + [字符串本体]`。
    * 例如：长度为 5 的 `"apple"`，我们编码为 **`"5#apple"`**。
    * 这样一来，无论字符串内部包含多少个 `#` 或奇怪的字符，解码器只认开头的数字和 `#` 后面的长度，绝对不会发生错位！

## 💻 二、 Python3 高效通关代码 (Solution)

```python
from typing import List

class Codec:
    def encode(self, strs: List[str]) -> str:
        """将字符串列表编码为一个单一的字符串。
        协议格式：每个单词转为 "长度#单词本体"，然后直接拼接。
        例如：["neet", "code"] -> "4#neet4#code"
        """
        res = []
        for s in strs:
            res.append(f"{len(s)}#{s}")
        return "".join(res)

    def decode(self, s: str) -> List[str]:
        """将编码后的字符串解码回原来的字符串列表。
        """
        res = []
        i = 0
        n = len(s)
        
        while i < n:
            # 1. 寻找分隔符 '#' 的位置
            j = i
            while s[j] != '#':
                j += 1
                
            # 2. 解析出当前单词的长度（从 i 到 j 之间的数字）
            length = int(s[i:j])
            
            # 3. 根据长度精准切片，拿到单词本体
            word = s[j + 1 : j + 1 + length]
            res.append(word)
            
            # 4. 指针 i 跃迁到下一个单词的起点
            i = j + 1 + length
            
        return res
```

- **编码阶段（Encode）**：

  - 处理 `"code"`：长度为 4 $\rightarrow$ 变成 `"4#code"`
  - 最终返回的编码字符串：`s = "4#neet4#code"`

- **解码阶段（Decode）**：
  - 初始指针 `i = 0`：
    - 寻找 `#`：发现 `s[1] == '#'`（此时 `j = 1`）。
    - 提取长度：`s[0:1]` $\rightarrow$ `"4"` $\rightarrow$ `length = 4`。

    - 类似地解析出 `length = 4`，切片拿到 `"code"`。
  - 指针 `i` 走到头，循环结束，完美还原！

# LeetCode 239. 滑动窗口最大值 (Sliding Window Maximum) 专题通关卡片

## 🎯 一、 核心考点与物理直觉

* **题目大意**：
  给你一个整数数组 `nums`，和一个大小为 `k` 的滑动窗口从数组的最左侧移动到最右侧。返回滑动窗口中的最大值。

* **物理直觉与单调队列协议（Monotonic Queue）**：
  * **为什么普通的暴力循环会超时？** 如果每移动一步都在窗口里重新找最大值，时间复杂度会飙升到 $\mathcal{O}(N \times K)$ 从而超时。
  * **单调队列的残酷竞技场模型**：
    我们要维持一个**从左到右单调递减**的双端队列（`deque`），里面存的是元素的**下标（Index）**：
    1. **新人入场前**：把队列尾部比自己小的所有“弱者”（数值小、又老又没潜力的元素）无情淘汰（`pop()`）。
    2. **窗口划走后**：如果队头的最大值下标已经超出了当前窗口的左边界（即 `q[0] < i - k + 1`），立刻把过气的队头淘汰（`popleft()`）。
    3. **永远的霸主**：此时，队列的**队头（`q[0]`）**永远是当前窗口里绝对的最高峰（最大值）！无需任何 `max()` 扫描，直接取值即可！

---

## 💻 二、 Python3 高效通关代码 (Solution)

```python
from typing import List
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        # 存的是元素的“下标（Index）”
        q = deque()
        res = []
        
        for i in range(len(nums)):
            # 1. 淘汰队尾所有比当前元素小的“弱者”，维持单调递减
            while q and nums[q[-1]] <= nums[i]:
                q.pop()
                
            # 2. 将当前元素的下标压入队尾
            q.append(i)
            
            # 3. 检查队头元素是否已经滑出了当前窗口的左边界 (i - k + 1)
            if q[0] < i - k + 1:
                q.popleft()
                
            # 4. 当窗口形成后（i 至少达到 k - 1），直接抓取队头作为当前窗口的最大值
            if i >= k - 1:
                res.append(nums[q[0]])
                
        return res
```

`if i >= k - 1:` 的意思就是：

> “在数组刚开始遍历的前面几步（当 `i` 还小于 `k - 1` 时），窗口还在长身体、没凑够 `k` 个数，咱们只管往单调队列里塞数据、调整队形，先不急着输出结果；一旦 `i` 达到了 `k - 1`（即窗口第一次长满），立刻开闸放水，开始源源不断地从队头收集每个窗口的最大值！”

### 🧪 三、 Step-by-Step Dry Run（手把手演练）

假设输入：`nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3`

- `i = 0, 元素 1`：队列空，直接入队 $\rightarrow$ `q = [0]`。
- `i = 1, 元素 3`：队尾 `1 <= 3` 被淘汰；`3` 入队 $\rightarrow$ `q = [1]`。
- `i = 2, 元素 -1`：`-1` 入队 $\rightarrow$ `q = [1, 2]`（对应值 `3, -1`）。窗口满，收集队头 `nums[1]` $\rightarrow$ `3`。
- `i = 3, 元素 -3`：`-3` 入队 $\rightarrow$ `q = [1, 2, 3]`。队头下标 1 没有越界，收集队头 $\rightarrow$ `3`。
- `i = 4, 元素 5`：队尾 `-3, -1, 3` 全部比 `5` 小，被无情清空；`5` 入队 $\rightarrow$ `q = [4]`。收集队头 $\rightarrow$ `5`。
- ……以此类推，完美线性推进！

### 📊 四、 复杂度核验 (Complexity Analysis)

| 解法名称 | 时间复杂度 | 空间复杂度 | 说明 |
| :--- | :---: | :---: | :--- |
| **单调双端队列法 (Monotonic Queue)** | $\mathcal{O}(N)$ | $\mathcal{O}(K)$ | 每个元素最多进一次队、出一次队，均摊单次操作为 $\mathcal{O}(1)$；队列中最多只存窗口大小（$K$）个下标。 |

咱们来把**暴力解法（Brute Force）**的执行过程拆解开，看看这个 $\mathcal{O}(N \times K)$ 的时间复杂度到底是怎么像滚雪球一样乘出来的。

### 🔍 暴力解法的运算逻辑拆解

假设：
- 整个数组 `nums` 的总长度是 $N$（比如有 100,000 个数字）。
- 滑动窗口的大小是 $K$（比如每组看 3 个数字）。

如果你用最直观、最符合人类直觉的暴力方式去写代码：

```python
res = []
# 1. 外部大循环：窗口一共要向右滑动多少次？
for i in range(N - K + 1):
    # 2. 内部小循环/切片：每次都要把当前窗口里的 K 个数字全部过一遍、找最大值
    window = nums[i : i + K]
    res.append(max(window))
```

### 📐 为什么时间复杂度是 $\mathcal{O}(N \times K)$？

咱们把这两层嵌套看作是**“外圈转动”与“内圈苦力”**的结合：

1. **外圈频次（关于 $N$）**：
   - 窗口从最左边一路滑到最右边，总共大约需要滑动 $N$ 次（严谨地说是 $N - K + 1$ 次，但在大 O 表示法中，常数和减法直接忽略，看作 $N$）。
   - 这就意味着外层循环要跑 $N$ 轮。
2. **内圈代价（关于 $K$）**：
   - 每一轮滑动中，计算机为了找出这一个窗口里的最大值，必须把窗口内部的 $K$ 个元素从头到尾挨个比较一遍（不管是切片、还是写 `for` 循环找 `max`，本质上都要遍历 $K$ 个格子）。
   - 这就意味着每一轮内层都需要干 $K$ 次苦力。
3. **合流相乘**：
   - 外圈有 $N$ 轮，每一轮内圈都要付出 $K$ 次比较的代价。
   - 总计算量 = $(\text{外圈次数 } N) \times (\text{每轮内圈代价 } K) = \mathbf{\mathcal{O}(N \times K)}$。

### 🚨 为什么当 $N$ 和 $K$ 很大时它会崩溃？

- 假设数组长度 $N = 10^5$（十万），窗口大小 $K = 50,000$（五万）。
- $N \times K = 10^5 \times 5 \times 10^4 = 5 \times 10^9$（足足 **50 亿次**计算机底层运算！）。
- 在 LeetCode 规定的 1 秒钟时限内（通常计算机一秒只能跑约 $10^8$ 次操作），50 亿次计算绝对会超管预算，直接被系统无情判处 **Time Limit Exceeded（超时）**。

这就是为什么我们必须用前面学的**单调队列（Monotonic Queue）**来开辟外挂：单调队列通过“动态裁剪弱者”，让每个元素平均只进队一次、出队一次，把内层的 $K$ 彻底抹掉，生生把复杂度压榨到了绝对线性的 $\mathcal{O}(N)$！

为了让你一秒钟醍醐灌顶，咱们把代码里那两句抽象的 `pop()` 和 `popleft()` 放到一个绝对真实的物理沙盘里去慢动作演练。

### 🏟️ 物理场景：公司的“技术大牛排位赛”

假设公司要组建一个项目组，窗口大小 $K = 3$（代表项目组最多只能容纳 3 个人）。
现在按入职顺序，来了这么一波程序员（对应数组）：`nums = [1, 3, -1, -3, 5]`。

我们的单调队列（`deque`）里存的是他们的工号（下标），规则是：从左到后，工号对应的技术实力必须**“从强到弱（单调递减）”**。谁技术弱、又老又没有晋升空间，立刻被开除！

咱们来看看当“新人入职”和“老人过期”时，这两下子到底是怎么操作的：

### 🎬 慢动作推演（一步步走查）

#### 1. 新人 `1` 入职：
- 队列是空的。
- `1` 直接入队。
- **队列状态（存下标）**：`[0]` （对应数值 `1`）

#### 2. 新人 `3` 入职（触发 `pop()` 机制的时刻到了！）：
- `3` 进公司了，大家一看：`3` 比已经在队列里的 `1` 强太多了！
- 按照“优胜劣汰”的残酷规则：在 `3` 面前，前面那个只有 `1` 战斗力的 `1` 号员工已经没有任何意义了（因为只要有 `3` 在，最大值绝对轮不到 `1`）。
- **执行 `pop()`（清理队尾）**：把 `1` 号无情开除（弹出队尾）。
- `3` 入队。
- **队列状态**：`[1]` （对应数值 `3`）

#### 3. 新人 `-1` 入职：
- `-1` 进公司了，大家一看：`-1` 比队列里的 `3` 弱。
- `3` 会开除它吗？不会！因为 `3` 还在当打之年，而 `-1` 以后万一 `3` 退休了（滑出窗口），它还能当个备选。
- 所以不触发 `pop()`。
- `-1` 直接在队尾排队。
- **队列状态**：`[1, 2]` （对应数值 `3, -1`）
- 💡 **此时窗口满了（3个元素）**，队头是 `3`，得出当前最大值 **`3`**。

#### 4. 新人 `-3` 入职：
- `-3` 比队列里的 `-1` 还要弱。
- `-1` 不会开除它，大家安安静静在队尾排队。
- `-3` 入队。
- **队列状态**：`[1, 2, 3]` （对应数值 `3, -1, -3`）
- 队头依然是 `3`，得出当前最大值 **`3`**。

#### 5. 重头戏：新人 `5` 入职（`pop()` 与 `popleft()` 双剑合璧爆发！）
当 `5` 走进公司大门的一瞬间，全场迎来了最刺激的两步动作：

* **第一步：无情清退队尾比自己弱的（`pop()` 机制）**
  - `5` 开始审视排在自己前面的那些人：
    - 倒数第 1 个是 `-3`：`5` 比它强，淘汰 `-3`（`q.pop()`）！
    - 倒数第 2 个是 `-1`：`5` 比它强，淘汰 `-1`（`q.pop()`）！
    - 倒数第 3 个是 `3`：`5` 比它强，淘汰 `3`（`q.pop()`）！
  - 队列瞬间被 `5` 一个人清空了！因为在 `5` 面前，前面这三个人在争夺最大值时全变成了“战渣”。
* **第二步：检查队头是不是过气了（`popleft()` 机制）**
  - 除了看新入职的，还得看左边界：随着 `5` 的到来，最初的那个 `1`、`3`、`-1` 的时代已经过去了。
  - 队列里那些超出了当前窗口范围（左边界滑走了）的过气元老，必须被踢出车厢（`q.popleft()`）。
- 最终，`5` 自己舒舒服服地进了空队列。
- **队列状态**：`[4]` （对应数值 `5`）
- 得出当前最大值 **`5`**。

### 🎯 核心结论总结

你看，所谓的：
- **“新人入场时，把前面所有比自己小的元素无情清退（pop()）”**：
  就像大牛入职，直接把公司里那些技术不如他、尸位素餐的庸才全开除，保证队列里从前往后永远是“强者在前，弱者在后（而且弱者心甘情愿给强者垫背）”。
- **“在过气时自动抛弃队头（popleft()）”**：
  就像车厢往前开，最前面那个年纪最大、到了退休年龄的老同志，虽然他曾经是老大，但因为超出了窗口范围，必须无情请下车。

通过这一进一出的极致裁剪，队头永远是当前窗口的绝对霸主（最大值），而维护这个队列的时间复杂度被死死压榨在了惊人的 $\mathcal{O}(N)$！

咱们来揭秘为什么**不需要 `max()`，最大值却自己“憋”在队头**：

### 👑 奥秘所在：队头就是天然的最大值

因为我们在前面维护这个双端队列（`deque`）时，施加了两个极其严格的铁律：

# 🏛️ 专题核心复习：deque（双向队列）与双向链表的本质区别

## 一、 什么是 deque（双向队列）？

* **全称**：Double-Ended Queue（双端队列）。
* **核心物理特性**：
  * 普通队列（Queue）只能在队尾进（`append`）、队头出（`popleft`），是典型的先进先出（FIFO）结构。
  * **deque** 则是**两头通吃**！它的**头部**和**尾部**都支持以 **$\mathcal{O}(1)$** 的恒定时间复杂度执行添加和删除操作。


## 二、 Python 中 deque 的核心高频 API 速查

```python
from collections import deque

# 1. 初始化
q = deque()

# 2. 尾部操作（O(1)）
q.append(10)       # 队尾塞入
q.pop()            # 队尾弹出

# 3. 头部操作（O(1) - 核心绝招，普通 list 的 pop(0) 需要 O(N)）
q.appendleft(5)    # 队头塞入
q.popleft()        # 队头弹出

# 4. 常用属性查看（O(1)）
print(q[0])        # 查看队头元素
print(q[-1])       # 查看队尾元素
```

### 三、 深度辨析：deque 是双向链表吗？

**答案：绝对不是！** 虽然它们名字里都有“双”，逻辑上都支持两端操作，但它们的**底层物理结构和内存表现**完全不同：

| 比较维度 | 双向链表 (Doubly Linked List) | Python 的 deque (双端队列) |
| :--- | :--- | :--- |
| **底层内存结构** | 散落在内存各个角落的**离散节点（Node）**，靠指针（`prev`/`next`）串联。 | 一组**连续内存块构成的环形缓冲区（Block-based memory chunks / 块状动态数组）**。 |
| **内存开销** | 巨大。每个节点除了存数据外，还要额外耗费内存去存前后指针。 | 较小。按块连续分配，极大地减少了指针带来的额外内存开销。 |
| **CPU 缓存命中率** | **极低**。因为节点在内存里东一个西一个，CPU 读数据时频繁发生“缓存未命中（Cache Miss）”。 | **极高**。由于底层是分块连续的内存，对 CPU 缓存极度友好，批量访问速度极快。 |
| **应用场景** | 需要在任意中间位置频繁 $\mathcal{O}(1)$ 插入/删除指针的场景。 | 需要在**两端**（头尾）高频进行 $\mathcal{O}(1)$ 增删（如单调队列、BFS 双向扩展、滑动窗口）。 |

### 四、 为什么在 LeetCode 239（滑动窗口最大值）中必须用 deque？

- 如果用普通的 Python 列表（`list`）在头部执行 `pop(0)`，由于底层是连续数组，会导致后面所有元素整体前移，单次操作时间复杂度为 $\mathcal{O}(N)$，从而直接超时。
- 而 Python 的 `deque` 凭借其块状缓冲区设计和完美的 $\mathcal{O}(1)$ 头尾增删能力，成功支撑了单调队列在滑动窗口中达到绝对线性的 $\mathcal{O}(N)$ 时间复杂度！

### ⛓️ 双向链表（Doubly Linked List）核心精要

#### 一、 什么是双向链表？
如果说单向链表（Singly Linked List）是一个“只能单向单行道、一条路走到黑”的队伍（每个节点只认识后面的邻居 `next`），那么**双向链表**就是一个**“双向通行、前后拉手”的精锐小分队**。

每一个节点（Node）内部，都包含三个核心要素：
1. **`val`（数据域）**：存的具体数值。
2. **`next`（后继指针）**：指向右边的下一个兄弟。
3. **`prev`（前驱指针）**：指向左边的前一个兄弟。

正是因为多了这个 `prev` 指针，双向链表具备了单向链表望尘莫及的特异功能：**不仅能顺着往后走，还能随时随地掉头往回走！**

#### 二、 双向链表的核心微操与时间复杂度

| 操作行为 | 对应动作 | 时间复杂度 | 为什么？ |
| :--- | :--- | :---: | :--- |
| **头部/尾部插入** | `addAtHead` / `addAtTail` | **$\mathcal{O}(1)$** | 只要你手里抓着 `head` 和 `tail` 哨兵指针，直接修改几个邻居的指针指向即可，不需要遍历。 |
| **已知节点时的删除** | `deleteNode` | **$\mathcal{O}(1)$** | **双向链表的封神点！** 如果面试官直接给你一个要删除的节点对象，在单向链表中你必须从头遍历找到它的前驱；而在双向链表中，因为自带 `prev`，你可以瞬间反向找到前驱，直接断开指针删除！ |
| **按索引查找** | `get(index)` | **$\mathcal{O}(N)$** | 没办法，内存里是离散卡片，哪怕有双向指针，也必须从头（或从尾）一步一步跳指针数格子。 |

#### 三、 手写双向链表的核心代码范式（Python 实现）

在手撕算法题（比如实现一个 LRU 缓存淘汰机制 `LRUCache`）时，双向链表的**虚拟头结点（Dummy Head）和虚拟尾结点（Dummy Tail）**是标配。这俩家伙就像是大门的两根顶梁柱，能彻底避免对 `head` 和 `tail` 进行判空的繁琐边界讨论：

```python
class Node:
    def __init__(self, key=0, val=0):
        self.key = key
        self.val = val
        self.prev = None
        self.next = None

class DoublyLinkedList:
    def __init__(self):
        # 初始化虚拟头尾哨兵，免去繁琐的 None 判断
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    def add_node_to_tail(self, node: Node):
        """把一个新节点雷打不动地塞在尾部哨兵的前面"""
        prev_node = self.tail.prev
        prev_node.next = node
        node.prev = prev_node
        node.next = self.tail
        self.tail.prev = node

    def remove_node(self, node: Node):
        """将任意一个已知节点从链表中完美摘除（O(1) 核心操作）"""
        node.prev.next = node.next
        node.next.prev = node.prev
```

### 四、 核心总结：双向链表 VS 数组 / deque

1. **什么时候用双向链表？**
   - 当你需要实现诸如 **LRU Cache（最近最少使用缓存）** 这种需要在 $\mathcal{O}(1)$ 时间内对任意已知节点进行“删除、移动到最前/最后”的业务场景时，双向链表是绝对的唯一真神！

2. **它和 deque 的区别：**
   - 虽然双向链表支持头尾 $\mathcal{O}(1)$ 增删，但它的节点在内存中是离散碎片化的，CPU 缓存命中率极低。
   - 而 Python 的 `deque` 底层用了连续的块状缓冲区（Block-based chunks），既保留了双向操作的爽感，又兼顾了数组对 CPU 缓存的极致友好。所以在纯队列场景下，`deque` 是性能怪兽；而在需要频繁断开指针、重新洗牌的复杂数据结构中（如 LRU、LFU），双向链表则是无可替代的结构骨架！
